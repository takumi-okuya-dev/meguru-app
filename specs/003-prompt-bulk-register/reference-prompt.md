# 参考プロダクトのプロンプトの型（Threads Growth OS）

**対象feature**：[spec.md](./spec.md)（FR-008）

2026-10-03に、参考プロダクト（Threads Growth OS）の投稿ストック画面のAI用プロンプトを読み取り、ユーザーのデータを`{…}`に伏せて型にしたもの。実運用で調整されてきた指示なので、003のプロンプトはこの構成と言い回しを土台にする（ユーザーの指示）。

## 各節の扱い

| 節 | 003での扱い | 材料 |
|---|---|---|
| 導入 | 使う | 作る件数 |
| ■話者・ブランド情報 | 使う（表示名だけ。目的・ブランド説明などは課題の項目で代える） | Accountの表示名 |
| ■絶対に守るルール（CORE RULES） | 使わない（004でNGワード・投稿ルールと一緒に足す） | — |
| ■参照してよい事実情報 | 使わない（ナレッジベースは範囲外） | — |
| ■文体の参考（過去の投稿例） | 使わない（投稿済みの投稿ができる005以降で足す） | — |
| ■アカウントの戦略設計 | 使う | 課題（002） |
| ■今回組み込む宣伝内容 | 使う（「1日の投稿数」は005の投稿時間の設定ができるまで、割合だけで書く） | 宣伝の対象の宣伝内容・宣伝投稿の割合（002） |
| ■過去に却下された投稿 | 使わない（004で却下ができてから足す） | — |
| ■リサーチで見つけた「伸びている投稿」とその分析 | 使う | 参考投稿（002） |
| ■重複防止 | 使う（比べる相手に、投稿ストックの直近の下書きを加える） | 下書き |
| ■短文・中文・長文 | 使う | — |
| ■文字数・バイト数 | 使う（「150文字以内・絵文字3個まで」の目安だけ。「日本語は1文字3バイト」「上限は500バイト」という説明は誤りなので書き換える。公式ドキュメントでは上限は500文字で、絵文字だけUTF-8のバイト数で数える。2026-10-03に確認） | — |
| ■出力形式 | 使う（最後の案内は、このアプリの貼り付け欄に合わせて書き換える） | — |

## 型（原文の言い回しのまま）

```text
以下の情報をもとに、Threadsに投稿する文章を{件数}件作ってください。

■話者・ブランド情報
表示名: {表示名}
目的: {目的}
ターゲット: {ターゲット}
ブランド説明: {ブランド説明}
CTA方針: {CTA方針}

■絶対に守るルール(CORE RULES)
・{CORE RULES の各行}

■参照してよい事実情報(日付・数字・固有名詞など、ここに書かれていないことは絶対に作らないこと)
- {ナレッジベースの各項目}

■文体の参考(過去の投稿例。内容や具体的なエピソードはそのままコピーせず、あくまでトーン・言葉遣いの参考にすること)
1. {過去の投稿本文}
2. …

■アカウントの戦略設計(設定済みの項目。方向性として必ず踏まえること)
最終的に取ってほしい行動: {…}
ターゲットの本音の悩み: {…}
ターゲットのなりたい姿: {…}
このアカウントのどう見られたいか: {…}
発信テーマの掛け合わせ: {…}
来てほしくない人: {…}
投稿ジャンル: {…}
他アカウントとの違い: {…}

■今回組み込む宣伝内容(1日の投稿は{1日の投稿数}件の設定で、そのうち{宣伝の件数}件({割合}%)を宣伝内容にする設定です。今回生成する{件数}件のうち{宣伝に絡める件数}件程度に自然に絡めること。残りは宣伝色のない共感・気づき系の投稿にすること)
掲載期限が近い順に並んでいます。【優先度:最高・締切間近】のものはやや多めに扱ってよいが、優先度が高いものだけに偏らせないこと。優先度が低いもの・期限未設定のものも含め、登録されている宣伝内容全体をきちんと扱うこと。期限が過ぎたものは扱わないこと。
下に{宣伝内容の件数}件掲載している宣伝内容のうち、特定の1〜2件だけに偏らせず、まだ一度も投稿に使っていない会が残っている場合はそれを優先して選ぶこと。登録されている宣伝内容は最終的にすべてきちんと扱われることが最優先で、一部の会だけが繰り返し使われて他が一切使われない状態は避けること。
1. {宣伝したい内容}(届けたい相手: 場所: {場所} / どんな人: {どんな人} / 年齢: {年齢}) / 行動喚起: {CTA}
2. …

宣伝を含む投稿でも、押し売り・広告っぽい言い回しにはせず、上記のCORE RULES・トーンをそのまま守ること。「届けたい相手」に書かれた属性を意識した切り口にすること。


■過去に却下された投稿(この傾向は繰り返さないこと)
1. {却下された投稿の本文}(却下理由: {却下理由})
2. …


■リサーチで見つけた「伸びている投稿」とその分析(型・構成の最重要参考資料)
これは実際にThreadsで見つかった、反応が良かった他アカウントの投稿と、その分析結果です。以下の手順で必ず活用すること。

手順1: 一覧の中から、今回のテーマに合いそうなものを何件か選ぶ。
手順2: 選んだ投稿の分析結果(フック・構成・感情の動かし方)を読み、そこで使われている「型」を言葉で抜き出す。
       例: 「疑問形で終わる」「具体的な数字から入る」「結論を先に言ってから理由を続ける」「あるあるを2〜3個並べてから本題に入る」など。
手順3: 抜き出した「型」に、このアカウント自身の知識・エピソード・言葉遣いを当てはめて新しい投稿を書く。
       元の投稿の文章・具体的なエピソード・固有名詞はそのまま使わない(著作権・盗用の問題になるため絶対禁止)。あくまでフックの作り方・構成の順番・テンポだけを借りること。
手順4: {件数}件のうち、最低でも3件はこの手順で明確に「型」を踏襲した投稿にすること。どの型を使ったかが分かるように、フック文の作り方に反映させること。

1. [検索語:{検索語}] 元の投稿(参考: 内容はコピーしない): {参考投稿の本文}
   なぜ良いか: {なぜ良いか}
2. …



■重複防止(絶対厳守。最も重要なルールの1つ)
- {件数}件それぞれ、言いたい核(結論・メッセージ)を1行で要約したときに、他のどれとも被らないこと。書き出しや言い回しを変えただけの「実質同じ投稿」は禁止。
- 上に書かれている過去の投稿例・却下された投稿・宣伝内容・リサーチ内容とも、核となる話題やエピソードが重複しないこと。同じテーマを扱う場合も、切り口・具体例・結論を変えて別物にすること。
- 生成の最後に、{件数}件同士を見比べて「言いたいことが似すぎているペア」が無いか自分で確認し、あれば書き直してから出力すること。

■短文・中文・長文は「長さ」だけでなく「役割」も変える(必ず守ること)
{件数}件の中に、次の3タイプをバランス良く混ぜること(目安比率: 短文3〜4割・中文4〜5割・長文2〜3割)。同じ役割の投稿を3件以上連続させないこと。
いずれのタイプも、下の「■文字数・バイト数について」の上限(150文字)を必ず守ること。「長文」は文字数を増やすのではなく、改行の使い方・構成で「長さ・重み」を感じさせること。
- 短文(1〜2文、40〜70文字前後): 説明せず言い切るタイプ。一撃で「わかる」「それな」と思わせる一言・あるある・問いかけだけで完結させる。背景説明やオチの解説はつけない。
- 中文(3〜5文、80〜120文字前後): 「気づき→展開→軽い着地」の小さな流れを作る。最初の一文で状況や違和感を提示し、そこから思ったことを1段展開し、最後に前向きな一言か問いかけで締める。
- 長文(改行多め、120〜150文字前後): 「状況→心境の変化→今どう思っているか」のミニストーリー構成を、短い文を細かく改行で区切ることで作る。文字数自体は中文とあまり変えず、行間の余白・テンポで「読ませる長さ」を演出する。説明的にならず、実体験を話しているような温度感にする。
- 冒頭の切り口(フック)も毎回変えること。例: 断言から始める/問いかけから始める/具体的な場面描写から始める/数字から始める/「〜な人へ」という呼びかけから始める/意外性のある一言から始める/エピソードの結末から先に言う、など。同じフックのパターンを{件数}件のうち3件以上連続で使わないこと。

■文字数・バイト数について(必ず守ること。今回の最重要ルールの1つ。これを破ると投稿エラーになる)
Threadsの実際の上限は「文字数」ではなく500バイト(UTF-8)。日本語(ひらがな・カタカナ・漢字・全角記号「、」「。」「【」等)は1文字=3バイト、絵文字は1文字=4バイトでカウントされる(半角英数字・半角記号・改行は1文字=1バイト)。そのため日本語中心の文章では、文字数が少なくてもすぐバイト数は膨らむ。
- 改行・絵文字・記号もすべて含めた本文全体の文字数を、必ず150文字以内におさめること(目安ではなく上限。130文字前後を目標にし、150文字を絶対に超えないこと。ぎりぎりを狙わず、余裕を持って短くすること)。
- 絵文字は1投稿につき合計3個までにすること(絵文字を多用すると文字数が少なくてもバイト数だけ超過するため)。
- 生成の最後に、{件数}件それぞれの本文を改行・絵文字含めて数え、150文字を超えているものが無いか自分で確認し、超えていれば必ず削って出力すること。この確認を飛ばさないこと。

■出力形式(必ず守ること。最後の1件まで絶対に崩さないこと。今回最も間違えやすいルールなので特に注意すること)
- 説明文・前置き・タイトル・番号付けは不要。投稿本文だけを出力すること。
- 各投稿の間には、必ず「@@@」だけの行(半角アットマークを3つだけ、前後にスペースや他の文字を一切付けない、独立した1行)を挟むこと。
  - "@@@"を指定している理由: "---"のような記号は、AIのチャット画面によってはMarkdownの装飾(区切り線)として画面上に表示され、コピーした時にその区切り線自体が消えてしまうことがある(結果、複数の投稿が1件にくっついてしまう)。"@@@"はそのような装飾として扱われないため、必ずこちらを使うこと。
  - 使ってよい区切りはこの半角アットマーク3つだけ。ハイフン「---」、全角ハイフン「－」、emダッシュ「—」、アスタリスク「***」、太字「**@@@**」、コード表記「`@@@`」、「1.」「①」のような番号付け、見出し記号は絶対に使わないこと。
  - 正しい例:
    投稿Aの本文はここまで。
    @@@
    投稿Bの本文はここから。
  - 間違った例(絶対にしないこと): 「1. 投稿Aの本文」「投稿A

投稿B」(空行だけで区切る)「---」「―――」(全角・emダッシュ)「**@@@**」
  - {件数}件なら区切り線はちょうど{件数-1}個になる。出力の最後に区切り線の数を自分で数え、{件数-1}個になっているか必ず確認すること。足りない・多い場合は出力し直すこと。この確認は絶対に省略しないこと。
- 投稿本文の中でも、見出し「# 」「## 」、太字「**text**」「__text__」、インラインコード「`text`」などのMarkdown装飾は一切使わないこと。Threadsはこれらを装飾として表示せず、そのまま記号として表示してしまうため、記号だけが本文に残って見苦しくなる。強調したい場合は記号を使わず、言葉選びや改行だけで表現すること。
- 上から目線で教えない。「〜すべき」「〜しなさい」は使わない。「〜な気がする」「〜かもしれない」など柔らかい語尾を使う。
- 存在しないエピソード・実績・日時・会話を作らない。事実は上記の情報にあるものだけを使う。
- 炎上商法・対立煽り・断定的な誇張はしない。
- 読者を否定せず、ネガティブなまま終わらせない。着地点は必ず前向きな一言、または気軽に答えられる質問にする。
- AIっぽい整いすぎた文章にしない。改行を増やし、人間の話し言葉に近づける。

生成できたら、この出力をまるごとコピーして、管理画面の「投稿を手動で追加する」欄に1回で貼り付けてください。"@@@"の行で自動的に{件数}件に分割して登録されます(1件ずつコピーし直す必要はありません)。
```
