# プロンプトの文面の契約：AIプロンプトの生成

**対象feature**：[spec.md](../spec.md)（FR-002・FR-003・FR-008）／ **判断**：[research.md](../research.md) R1・R2・R12 ／ **土台**：[reference-prompt.md](../reference-prompt.md)

`packages/shared`の`buildPrompt(input)`が組み立てる文面の正。参考プロダクトの言い回しを土台にし、R2の修正を入れている。

## 入力

| 名前 | 内容 |
|---|---|
| `count` | 作る件数（1〜50） |
| `displayName` | Accountの表示名（なければ`@ユーザー名`） |
| `strategy` | 課題の値（002の`StrategyValues`）。空の項目は使わない |
| `promotions` | 宣伝の対象の宣伝内容（状態が有効で期限切れでないもの）。掲載期限の近い順（期限なしは最後）、同じなら優先度の高い順 |
| `promotionRatioPercent` | 宣伝投稿の割合（0〜100） |
| `referencePosts` | 参考投稿。新しい順に最大10件 |
| `recentDrafts` | 投稿ストックの直近の下書き（要確認）。新しい順に最大20件 |

## 組み立ての規則

1. 下の節を、この順に並べる。節と節の間は空行1つ。
2. 「（条件）」のある節は、条件を満たすときだけ含める。満たさなければ見出しごと省く。
3. `{…}`は入力で置き換える。`{件数-1}`は`count - 1`、`{宣伝に絡める件数}`は`round(count × promotionRatioPercent ÷ 100)`。
4. 課題・宣伝内容・参考投稿・下書きの本文は、入力された文字のまま埋め込む（改行も保つ）。
5. 全文が30,000文字を超える場合は、直近の下書き → 参考投稿の順に、古いものから1件ずつ減らす（R12）。

## 文面

### 導入（常に）

```text
以下の情報をもとに、Threadsに投稿する文章を{件数}件作ってください。
```

### 話者（常に）

```text
■話者
表示名: {表示名}
```

### アカウントの戦略設計（条件：課題の項目が1つ以上入力済み）

入力済みの項目だけを、次の順・見出しで1行ずつ並べる（値に改行があればそのまま）。プロフィール文・固定投稿の下書きは含めない。

```text
■アカウントの戦略設計(設定済みの項目。方向性として必ず踏まえること)
最終的に取ってほしい行動: {finalAction}
ターゲット: {targetPersona}
ターゲットの本音の悩み: {realWorries}
ターゲットのなりたい姿: {desiredSelfImage}
このアカウントのどう見られたいか: {perceivedImage}
発信テーマの掛け合わせ: {contentThemeMix}
来てほしくない人: {antiPersona}
ベンチマークにしたい他アカウント: {benchmarkAccounts}
集客導線の設計: {funnelDesign}
投稿ジャンル: {postGenres}
DM返信の型: {dmReplyTemplate}
問い合わせの質を上げるコツ: {inquiryQualityTips}
人柄(近い人間性): {tonePresetの表示名}
文体の条件: {toneNotes}
他アカウントとの違い: {differentiation}
成功の指標: {successMetrics}
```

### 今回組み込む宣伝内容（条件：宣伝の対象が1件以上、かつ宣伝投稿の割合が1%以上）

```text
■今回組み込む宣伝内容(宣伝投稿の割合は{割合}%の設定です。今回生成する{件数}件のうち{宣伝に絡める件数}件程度に自然に絡めること。残りは宣伝色のない共感・気づき系の投稿にすること)
掲載期限が近い順に並んでいます。期限が近いものはやや多めに扱ってよいが、一部だけに偏らせないこと。期限未設定のものも含め、下に掲載している宣伝内容全体をきちんと扱うこと。
下に{宣伝内容の件数}件掲載している宣伝内容のうち、特定の1〜2件だけに偏らせないこと。
1. {宣伝したい内容}(届けたい相手: 場所: {場所} / どんな人: {どんな人} / 年齢: {年齢}) / 行動喚起: {CTA}
2. …

宣伝を含む投稿でも、押し売り・広告っぽい言い回しにはせず、トーンをそのまま守ること。「届けたい相手」に書かれた属性を意識した切り口にすること。
```

- 届けたい属性は、入力済みのものだけを「場所: … / どんな人: … / 年齢: …」の形で並べる。どれもなければ「(届けたい相手: …)」ごと省く。CTAがなければ「 / 行動喚起: …」を省く。
- 専用URLがあれば、行の末尾に「 / 専用URL: {URL}」を足す。
- `{宣伝に絡める件数}`が0になる場合（件数が少なく割合が小さい）は、1とする。

### リサーチで見つけた「伸びている投稿」とその分析（条件：参考投稿が1件以上）

```text
■リサーチで見つけた「伸びている投稿」とその分析(型・構成の最重要参考資料)
これは実際にThreadsで見つかった、反応が良かった他アカウントの投稿と、その分析結果です。以下の手順で必ず活用すること。

手順1: 一覧の中から、今回のテーマに合いそうなものを何件か選ぶ。
手順2: 選んだ投稿の分析結果(フック・構成・感情の動かし方)を読み、そこで使われている「型」を言葉で抜き出す。
       例: 「疑問形で終わる」「具体的な数字から入る」「結論を先に言ってから理由を続ける」「あるあるを2〜3個並べてから本題に入る」など。
手順3: 抜き出した「型」に、このアカウント自身の知識・エピソード・言葉遣いを当てはめて新しい投稿を書く。
       元の投稿の文章・具体的なエピソード・固有名詞はそのまま使わない(著作権・盗用の問題になるため絶対禁止)。あくまでフックの作り方・構成の順番・テンポだけを借りること。
手順4: {件数}件のうち、最低でも{型を使う件数}件はこの手順で明確に「型」を踏襲した投稿にすること。どの型を使ったかが分かるように、フック文の作り方に反映させること。

1. [検索語:{検索語}] 元の投稿(参考: 内容はコピーしない): {参考投稿の本文}
   なぜ良いか: {なぜ良いか}
2. …
```

- `{型を使う件数}`は`min(3, count)`。
- 検索語がなければ「[検索語:…] 」を省く。「なぜ良いか」がなければ「なぜ良いか: (未記入。投稿の構成から型を読み取ること)」とする。

### 重複防止（常に。ただし下書きの一覧は条件：直近の下書きが1件以上）

```text
■重複防止(絶対厳守。最も重要なルールの1つ)
- {件数}件それぞれ、言いたい核(結論・メッセージ)を1行で要約したときに、他のどれとも被らないこと。書き出しや言い回しを変えただけの「実質同じ投稿」は禁止。
- 上に書かれている宣伝内容・リサーチ内容、下に並べた投稿ストックの下書きとも、核となる話題やエピソードが重複しないこと。同じテーマを扱う場合も、切り口・具体例・結論を変えて別物にすること。
- 生成の最後に、{件数}件同士を見比べて「言いたいことが似すぎているペア」が無いか自分で確認し、あれば書き直してから出力すること。

投稿ストックにある直近の下書き(これらと核が被らないこと):
1. {下書きの本文}
2. …
```

- 直近の下書きがなければ、最後の「投稿ストックにある直近の下書き…」以下を省き、2つ目の箇条の「、下に並べた投稿ストックの下書き」も省く。

### 短文・中文・長文（常に）

参考プロダクトの「■短文・中文・長文は「長さ」だけでなく「役割」も変える」の節を、次の2点だけ変えてそのまま使う（[reference-prompt.md](../reference-prompt.md)）。

- 「30件」→「{件数}件」
- 「下の「■文字数・バイト数について」の上限(150文字)」→「下の「■文字数について」の目安(150文字)」

### 文字数について（常に）

```text
■文字数について(必ず守ること)
Threadsの1投稿の上限は500文字で、絵文字だけは1文字ではなくUTF-8のバイト数(多くは4)で数えられる。上限を超えると投稿できない。
- 改行・絵文字・記号もすべて含めた本文全体を、150文字以内におさめること(130文字前後を目標にし、余裕を持って短くすること)。
- 絵文字は1投稿につき合計3個までにすること。
- リンク(URL)は1投稿につき5個までにすること。
- 生成の最後に、{件数}件それぞれの本文を改行・絵文字含めて数え、150文字を超えているものが無いか自分で確認し、超えていれば必ず削って出力すること。
```

### 出力形式（常に）

参考プロダクトの「■出力形式」の節を、次の点だけ変えてそのまま使う。

- 「30件なら区切り線はちょうど29個になる」→「{件数}件なら区切り線はちょうど{件数-1}個になる」
- 「上記の情報にあるもの」→「上記に書かれているもの」
- 最後の案内を次の文に差し替える。

```text
生成できたら、この出力をまるごとコピーして、ThreadsGrowerの投稿ストックの画面にある貼り付け欄に1回で貼り付けてください。"@@@"の行で自動的に{件数}件に分割して登録されます(1件ずつコピーし直す必要はありません)。
```

## 要約（プロンプトのカードに出す）

`buildPrompt`は全文とあわせて、実際に含めた次の数を返す（FR-006）。

| 名前 | 内容 |
|---|---|
| `strategyFilledCount` | 含めた課題の項目の数（16項目のうち。002の入力済み項目数と同じ数え方） |
| `promotionCount` | 含めた宣伝内容の件数 |
| `referencePostCount` | 含めた参考投稿の件数 |
| `recentDraftCount` | 含めた直近の下書きの件数 |
| `length` | 全文の文字数（コードポイントの数） |
