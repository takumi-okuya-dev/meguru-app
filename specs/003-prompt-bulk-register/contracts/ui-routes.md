## サイドバー（docs/ui-design.md「2. 画面の骨格」）

- Accountの切り替えのすぐ下に「投稿をつくる」（`SquarePen`）を置く。押すと投稿ストックの画面へ移動し、貼り付け欄にフォーカスを当てる。
- 見出しなしの欄に「ホーム」「投稿ストック」（`Inbox`）の順で並べる。承認待ちの件数の表示は004で足す。

## 投稿ストックの画面（型C）

### 上部バー

`PageHeader`に画面名「投稿ストック」。主な操作は置かない（コピーはカード、登録は貼り付け欄）。

### プロンプトのカード（US1。`canGeneratePrompt: true`のとき）

- 見出し：「プロンプトをコピーして、ChatGPTやClaudeに送る」
- 要約（1行）：「課題 {strategyFilledCount}/16・宣伝の対象 {promotionCount}件・参考投稿 {referencePostCount}件を反映」。課題が0項目なら、代わりに「課題を入力すると、投稿の精度が上がります」と課題の画面へのリンク（FR-006）。
- 作る件数：「作る件数」と1〜50の数値の入力欄（`md`未満は見出しの下の行）。変えたら`PUT /prompt-settings`で保存し、プロンプトを取り直す（入力が止まってから0.5秒後）。
- 操作：「コピー」（主な操作。丸いボタン）と「プロンプトを見る」（開閉）。
- 「プロンプトを見る」を開くと、全文の欄（複数行、読み書きできる）と「元に戻す」が出る。欄を書き換えた場合は、書き換えた内容をコピーする。書き換えは保存しない（FR-005）。
- コピー：
  - 成功したら、トーストで「コピーしました。ChatGPTやClaudeに貼り付けて送ってください」。
  - 失敗したら、全文の欄を開いて全選択し、カードの中に「自動でコピーできませんでした。選択された文字を手でコピーしてください」と出す（research.md R13）。
- プロンプトの取得に失敗したら、カードの中に原因と「再読み込み」を出す（画面全体は止めない）。

### プロンプトのカード（`canGeneratePrompt: false`のとき。FR-024）

- 見出し：「AIプロンプトの生成はプラン2以上で使えます」
- 説明：「自分で用意した投稿も、「@@@」だけの行で区切って下の欄に貼り付ければ、まとめて登録できます。」と、002の`PLAN_CHANGE_CONTACT`（「プランの変更は運営者にお問い合わせください。」）。

### 状態のタブと下書きの一覧（US2・US3）

- タブ：「要確認 {件数}」（003では1つだけ。004で「承認済み」「却下」を足す）。
- 並び順：新しい登録が上、同じ登録の中は貼り付けた順（spec Clarifications Q2）。登録のまとまりごとに、小さな見出し「{登録日時}に登録した{n}件」を挟む。
- 各下書き：
  - 左にチェックボックス（タッチ操作では押せる範囲を44px角以上）。
  - 本文（改行を保つ。6行まで。続きは「もっと見る」）。
  - 長さの表示（FR-013、spec Clarifications Q3）：「{threadsLength}文字」と、上限（500）までの使用量の細いバー。80%を超えたらバーを注意の色の手前の色、上限を超えたら注意の色にし、「Threadsの上限を超えています（500文字まで）」と出す。リンクが6個以上なら「リンクは5個までです」と出す。
  - 「⋯」メニュー：「編集」「削除」。
- 空の状態：「まだ下書きがありません。上のプロンプトをChatGPTやClaudeに送り、返ってきた回答を下の欄に貼り付けてください。」（`canGeneratePrompt: false`のときは「…投稿を「@@@」だけの行で区切って、下の欄に貼り付けてください。」）
- 件数の上限（500件）に達したら、一覧の上に「要確認の下書きが上限（500件）に達しています。不要な下書きを削除してから登録してください。」を出し、貼り付け欄の送るボタンを無効にする。

### 貼り付け欄（US2。画面下部に固定）

- 複数行の入力欄（記入例：「AIの返信をここに貼り付け…」）と、送るボタン（`ArrowUp`、丸いボタン、読み上げ名「投稿ストックに登録する」）。
- 欄は、内容に合わせて最大8行まで高さが伸び、それ以上はスクロールする。
- 下に小さく「「@@@」で区切られた投稿が、まとめて「要確認」に登録されます」。
- 空・空白だけのときは送るボタンを無効にする。送信中は送るボタンと欄を無効にする。
- 送る前に、`splitDrafts`の結果で上限（50件・50,000文字・1件2,000文字）を確かめ、超えていれば送らずに欄の上に案内を出す（APIの`400 PASTE_TOO_LARGE`を受けた場合も同じ）。
- 書きかけの内容があるとき、002の未保存の変更として登録する（FR-022）。
- `md`未満では、画面下端の操作バーの領域を避けて固定する（docs/ui-design.md 型C）。

### 登録直後の案内（FR-016、FR-016a）

貼り付け欄のすぐ上に、閉じるまで（または次の登録・画面の移動まで）出す。

- 「{draftCount}件を登録しました」
- 区切りがなかった場合：「区切り（@@@）が見つからなかったため、1件として登録しました」
- 上限を超える下書きがある場合：「そのうち{overLimitCount}件はThreadsの上限を超えています」
- 操作：「取り消す」「閉じる」。「取り消す」は`DELETE /draft-batches/:batchId`を呼び、成功したら貼り付けた内容を欄に戻して、トーストで「{deletedCount}件の登録を取り消しました」。

### 選択とまとめての削除（US3）

- 下書きを1件でも選ぶと、貼り付け欄の位置に選択のバーを出す：「{n}件を選択中」「選択を解除」「選んだ下書きを削除」。要確認のタブの見出しには「すべて選択」。
- 「選んだ下書きを削除」は、確認なしで下の「下書きの削除」を行う。

### 下書きの削除（US3。spec Clarifications 2026-10-04）

「⋯」の「削除」と「選んだ下書きを削除」は同じ動きにする。

1. 確認のダイアログは出さず、すぐ一覧から消し（選択も解除し）、トーストで「{n}件の下書きを削除しました」と「元に戻す」を出す（1件のときも「1件の下書きを削除しました」）。
2. `POST /post-drafts/delete`は、トーストが消える約5秒後に呼ぶ。「元に戻す」が押されたら呼ばずに一覧に戻す。
3. 5秒以内に次の削除をしたら、前の削除はその時点で確定する。画面を離れたときも、その時点で確定する。タブを閉じた場合は確定せず、下書きは残る（消えるべきものが残るだけで、安全な側に倒れる）。
4. 確定の呼び出しが失敗したら、一覧を取り直して下書きを戻し、トーストで失敗を伝える。

### 下書きの編集（US3）

- 002の追加・編集のダイアログの枠（`FormDialogFrame`・`useItemForm`）を使う。見出し「下書きを編集」、項目は本文（必須、2,000文字まで）。
- 本文の欄の下に、一覧と同じ長さの表示（文字数と使用量のバー）を出す。
- 保存の`409`・`404`・`403`の扱いは002と同じ。

## ホーム（002の「次にやること」の変更）

002の「次にやること」の4つ目（「投稿の材料がそろっています」）を、次に変える。

| 条件 | 大見出し | 説明 | 案内する画面 |
|---|---|---|---|
| 課題・宣伝内容・参考投稿がどれも1件以上 | 投稿をつくりましょう | プロンプトをChatGPTやClaudeに送り、返ってきた投稿案を投稿ストックに登録します。 | 投稿ストック（大見出しの下に「投稿ストックへ」のボタン） |

## エラー文言（`packages/shared`に足す）

| code | 文言 | 次に取れる操作 |
|---|---|---|
| `PASTE_TOO_LARGE` | 一度に登録できるのは50件・50,000文字まで、1件は2,000文字までです。分けて貼り付けてください。 | 貼り付けを分ける |
| `ITEM_LIMIT_REACHED`（投稿ストック） | 要確認の下書きが上限（500件）に達しています。不要な下書きを削除してから登録してください。 | 一覧で削除する |
