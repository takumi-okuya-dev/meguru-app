# 動作確認ガイド（Quickstart）：重複検知・承認/却下・NGワード（CORE RULES）

**対象feature**：[spec.md](./spec.md) ／ **契約**：[contracts/api.md](./contracts/api.md)、[contracts/ui-routes.md](./contracts/ui-routes.md)、[contracts/prompt-template.md](./contracts/prompt-template.md)、[contracts/policy-cautions.md](./contracts/policy-cautions.md)

本featureが端から端まで動くことを確かめる手順。実装コードは含めない。

## 前提

- 003までのセットアップ（[003 quickstart.md](../003-prompt-bulk-register/quickstart.md)）が済んでいる。
- 本featureもThreads APIを呼ばないので、`pnpm dev:fake`で確認できる。

## セットアップ

```bash
pnpm install
docker compose up -d
pnpm --filter api db:migrate        # 本featureのマイグレーション（列挙型の値、post_drafts と accounts の列、ng_words）
pnpm dev:fake
```

## 自動テスト

```bash
pnpm --filter @threads-grower/shared test
pnpm --filter api test
pnpm --filter web test
```

## 手動の確認

`pnpm dev:fake`で起動した画面で確かめる。003の手順で、要確認の下書きを10件ほど登録しておく。

### 1. NGワードと投稿ルール（US2・US4）

1. 「このアカウントの設定」を開く。「投稿のルール」の区分が、Threadsとの接続より上にある。
2. NGワードの「編集」で「絶対、必ず儲かる」と入れて追加する。2つのチップが並ぶ。
3. 投稿ルールの「編集」で「断定口調は使わない」「医療・投資の効果をうたわない」の2行を書いて保存する。
4. 「Threadsの規約への備え」の「見る」で、規約上のルール6つと、4つの分類が読める。編集の手段はない。

### 2. 承認・却下（US1・US2）

1. 投稿ストックを開く。サイドバーの「投稿ストック」の右に要確認の件数が出ている。
2. 1件の本文を「絶対に伸びる方法」に編集して保存する。「NGワード：絶対」のラベルと強調が出て、「承認」が押せない。
3. 本文から「絶対」を消して保存すると、承認できるようになる。「承認」を押すと承認済みのタブに移り、トーストの「元に戻す」で戻る。
4. 別の1件の「却下」を押し、「トーンが違う」を選んで却下する。却下のタブに理由つきで並ぶ。
5. 3件を選び「まとめて承認」を押す。承認済みのタブの件数が3増える。
6. 承認済みの1件を「編集」で直して保存すると、要確認に戻る。
7. 承認済みの下書きに含まれる言葉をNGワードに足すと、トーストで要確認に戻した件数が出て、その下書きが要確認に戻っている。

### 3. 重複検知（US3）

1. 承認済みの下書きの本文をコピーし、1文字だけ変えて貼り付け欄から登録する。
2. その下書きに「類似度 9x%」が注意の色で出て、「似ている投稿があります」が添えられている。
3. ラベルを押すと、似ている相手（承認済み）の本文が出る。押すと承認済みのタブのその下書きに移る。
4. 「却下」を押すと、「似た投稿がある」が最初から選ばれている。

### 4. 規約に注意（US5）

1. 「この投稿にいいねした人の中から抽選でプレゼント」を登録する。「規約に注意：見返りでの反応集め」が出る。ラベルを押すと、関わる規約へのリンクと言い換えの方向が出る。
2. 「承認」を押すと確認のダイアログが出る。キャンセルすると要確認のまま。「承認する」で承認済みになる。
3. ラベルのない下書きに「安全」などの表示が出ていない。

### 5. プロンプトへの反映（US4）

1. 投稿ストックのプロンプトのカードの要約に「ルール 2件・NGワード 2語・却下 1件」が足されている。
2. 「プロンプトを見る」で全文を開く。次を確かめる。
   - 話者の後に「■絶対に守るルール(CORE RULES)」がある
   - その中が、規約上のルール → 投稿ルール → 「次の言葉は使わないこと: 絶対、必ず儲かる」の順
   - 宣伝内容の後に「■過去に却下された投稿(この傾向は繰り返さないこと)」があり、却下した下書きが「(却下理由: トーンが違う)」つきで入っている
3. 却下した下書きを要確認に戻すと、プロンプトの却下の節が消える。

### 6. プランと画面幅

1. `pnpm --filter api db:psql`で、ユーザーの`users.created_at`を1か月以上前にし、Accountのプランを`auto-only`にする。
   - 承認・却下・NGワードの追加はできる
   - 投稿ルールのダイアログは読み取り専用で、案内が出る
2. 375・768・1024・1440pxで、次が崩れないことを確かめる。
   - タブ、ラベルの行、却下・承認のボタン、選択のバー、却下理由の入力、設定の画面
   - 375pxでは、却下・承認のボタンが横幅いっぱいに2つ並び、却下理由の入力が全画面のシートになる
