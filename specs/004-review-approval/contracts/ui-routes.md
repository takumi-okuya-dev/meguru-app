# 画面契約：重複検知・承認/却下・NGワード（CORE RULES）

**対象feature**：[spec.md](../spec.md) ／ **API**：[api.md](./api.md) ／ **規約の注意**：[policy-cautions.md](./policy-cautions.md) ／ **UI全体設計**：[docs/ui-design.md](../../../docs/ui-design.md) ／ **003の画面契約**：[003 contracts/ui-routes.md](../../003-prompt-bulk-register/contracts/ui-routes.md)

画面の骨格・型・見た目・スマートフォン対応はdocs/ui-design.mdに従う。002・003の規則はそのまま使う。
- 保存・未保存の警告・他の場所での更新・入力欄の検証（002）
- 下書きの削除の「元に戻す」（003）

ここには、003からの変更と追加だけを書く。

## サイドバー（FR-013）

- 「投稿ストック」の右に、要確認の件数（`GET /post-drafts/counts`の`needsReview`）を小さな数字で出す。0件のときは出さない。
- 件数は、投稿ストックでの操作（登録・取り消し・削除・承認・却下・戻す・編集）とNGワードの追加の後に読み直す。
- 「投稿をつくる」（FR-013a）：投稿ストックの画面に移り、プロンプトを読み込んだ後に、プロンプトのカードまで移って「コピー」にフォーカスを当てる。grower機能を使えないAccountでは、貼り付け欄にフォーカスを当てる（003のまま）。押すたびに同じ動きをする（すでに投稿ストックの画面にいても）。
  - 押したときは、下書きの選択を解除する（選択のバーで貼り付け欄が隠れたままにしない）。
  - プロンプトの読み込みに失敗して「コピー」が出ていない間は待ち、「再読み込み」で出た時点でフォーカスを当てる。
  - 画面を開いた後にプロンプトが使えなくなった（無料体験の終了など）場合は、貼り付け欄にフォーカスを当てる。

## 投稿ストックの画面（型C）

### プロンプトのカード（003の変更）

要約の1行に、投稿ルール・NGワード・却下を足す（FR-025）。0件の項目は出さない。

- 例：「課題 11/16・宣伝の対象 1件・参考投稿 3件・ルール 3件・NGワード 2語・却下 5件を反映」

### 状態のタブ（FR-001）

- 「要確認 {n}」「承認済み {n}」「却下 {n}」の3つ。件数は`counts`の値。
- 選んだタブはURLのクエリ（`?tab=approved`など）に持ち、再読み込みしても保つ。既定は要確認。
- 承認済みのタブの上に、1行の案内：「承認した投稿は、自動投稿の設定ができると順に投稿されます」（FR-011）。
- 却下のタブで`counts.rejected`が500件を超えるときは、一覧の最後に「新しい500件を表示しています」。

### 下書きのカード（003の変更）

上から順に次を並べる。

1. チェックボックス、本文（003と同じ）。NGワード・規約に注意に当たった範囲は、本文の中で背景の色を付けて強調する（NGワードは`--destructive`系、規約に注意は`--warning`系）。
2. **ラベルの行**（当てはまるものだけ。この順）：
   - 「NGワード：{言葉}、{言葉}」：`--destructive`の文字。要確認のタブ（承認済みには、NGワードの追加で要確認に戻るため残らない。FR-016a）
   - 「規約に注意：{分類の名前}」：注意の色。要確認・承認済みのタブ。押すと説明のポップオーバー（policy-cautions.md「画面に出す文言」）。承認済みのタブでは、ラベルの下に「規約に注意の表現があります。要確認に戻して確かめることをおすすめします」と「要確認に戻す」のボタンを出す（spec エッジケース。承認は自動では取り消さない）
   - 「Threadsの上限を超えています（500文字まで／リンクは5個まで）」（003）
   - 「類似度 {n}%」：要確認のタブだけ。80%以上なら注意の色にして「似ている投稿があります」を添える。押すと、似ている相手の一覧のポップオーバー（下記）。計算が終わるまでは「類似度 計算中」
3. 長さの表示（003と同じ）。
4. **操作**：
   - 要確認：「却下」（枠線のボタン）と「承認」（主なボタン）。PCは右下に小さく、`md`未満は横幅いっぱいに2つ並べる（docs/ui-design.md 型C）
   - 承認済み：承認した日時「{日時}に承認」
   - 却下：却下した日時と、却下理由「却下理由：{表示名・…} / {自由記述}」
   - 「⋯」メニュー（タブごと）：
     - 要確認：「編集」「削除」
     - 承認済み：「編集」「要確認に戻す」
     - 却下：「要確認に戻す」「削除」
5. 「承認」を押せないとき（NGワードを含む・Threadsの上限を超える）は、ボタンを無効にし、ボタンの下に理由を1行で出す。
   - 「NGワードを含むため承認できません。本文を直すか却下してください」
   - 「Threadsの上限を超えるため承認できません」

### 似ている相手のポップオーバー（FR-028）

- 見出し：「似ている投稿」
- 似ている順に最大3件。各行に、類似度、状態のラベル（要確認・承認済み・却下）、本文の先頭3行。
- 行を押すと、その下書きのタブに切り替えて、その下書きまでスクロールし、枠を一瞬強調する。

### 承認（FR-002、FR-005、FR-040）

1. 規約に注意の下書きなら、確認のダイアログを出す。
   - 見出し：「Threadsの規約に触れるおそれのある表現があります」
   - 本文：「内容を確かめたうえで承認しますか？」と、当たった分類の名前
   - 操作：「キャンセル」「承認する」
2. `POST /post-drafts/review`（`action: "approve"`）を送る。規約に注意の下書きなら、`confirmPolicyCaution: true`を付ける。
3. 成功したら、その下書きを要確認の一覧から消し、トースト「承認しました」と「元に戻す」を出す（約5秒）。
4. `skipped`だったら、理由ごとに次の文言をトーストで出し、一覧を取り直す。

| reason | 文言 |
|---|---|
| `NG_WORD` | NGワードを含むため承認できませんでした。 |
| `OVER_THREADS_LIMIT` | Threadsの上限を超えるため承認できませんでした。 |
| `POLICY_CONFIRM_REQUIRED` | 規約に注意の表現があるため、確認してから承認してください。 |
| `STALE` | 他の場所で更新されています。最新の内容を表示しました。 |
| `NOT_FOUND` | この下書きは削除されています。 |
| `LIMIT`（承認） | 承認済みの下書きが上限（500件）に達しています。 |
| `LIMIT`（戻す） | 要確認の下書きが上限（500件）に達しています。 |

### 却下理由の入力（FR-003、FR-029、FR-040）

- 002の`FormDialogFrame`を使う（PCは中央のダイアログ、`md`未満は全画面のシート）。
- 見出し：「却下の理由」（まとめて却下では「{n}件を却下する理由」）
- 説明：「理由は次のプロンプトに「繰り返さないこと」として入ります」
- 候補のチップ（複数選べる。`aria-pressed`）：似た投稿がある／トーンが違う／内容が薄い／事実と違う／宣伝っぽすぎる／規約に触れそう
- 最初から選んでおく候補（research.md R10）：
  - 類似度が80%以上なら「似た投稿がある」
  - 規約に注意なら「規約に触れそう」
- 自由記述の欄（任意、200文字まで、文字数の表示つき。記入例「例：語尾がきつい」）
- 操作：「キャンセル」「却下する」。候補も自由記述もないときは「却下する」を無効にし、「理由を1つ以上選ぶか、書いてください」を出す。
- 成功したら、トースト「却下しました」と「元に戻す」。
- 自由記述を書きかけのときは、未保存の変更として扱う（FR-032）。

### 選択のバー（FR-004。003の変更）

貼り付け欄の位置に出す。中身はタブで変える。

| タブ | 操作 |
|---|---|
| 要確認 | 「{n}件を選択中」「選択を解除」「削除」「まとめて却下」「まとめて承認」（主なボタン） |
| 承認済み | 「{n}件を選択中」「選択を解除」「要確認に戻す」 |
| 却下 | 「{n}件を選択中」「選択を解除」「削除」「要確認に戻す」 |

- 「すべて選択」は各タブの見出しの右に置く（表示している下書きをすべて選ぶ）。
- **まとめての操作の分割**：まとめて承認・却下・要確認に戻すは、APIの上限（1回500件）に合わせて500件ずつに分けて順に送り、結果をまとめて1つのトーストにする（NGワードの追加で要確認が500件を超えることがあるため。PR #5 のCodexレビュー）。
- **選び方のメニュー**（要確認のタブだけ。FR-004a、spec Clarifications 2026-10-05）：「すべて選択」の右に「選び方」のボタン（`ChevronDown`）を置き、メニューに次を並べる。
  - 「すべて選択」
  - 「承認できるものを選択（{n}件）」：NGワード・Threadsの上限・規約に注意・類似度80%以上のどれにも当たらない下書き。0件なら押せない
  - 「選択を解除」
- **登録のまとまりの選択**（要確認のタブ）：まとまりの小見出し「{日時}に登録した{n}件」の右に「この{n}件を選択」（文字のボタン）を置く。押すと、そのまとまりの下書きを選択に足す。
- **まとめて承認**：
  1. 確認のダイアログを出す（FR-004b。1件ずつの承認では出さない）。
     - 見出し：「選んだ{n}件を承認します」
     - 本文：「承認した投稿は、自動投稿の設定に従ってThreadsに公開されます。投稿の内容は、あなた（アカウントの運用者）の責任のもとで公開されます。内容を確かめたうえで承認してください。」
     - 選んだ中に承認できないもの（NGワード・Threadsの上限）があれば：「うち{k}件はNGワード・Threadsの上限に当たるため、承認されません」
     - 承認済みの上限（500件）の残りの枠が足りなければ：「承認済みの下書きが上限（500件）に近いため、承認されるのは{m}件までです」
     - 選んだ中に規約に注意のものがあれば：「うち{k}件に、Threadsの規約に触れるおそれのある表現があります」（規約に注意の確認は、この1回で済ませる）
     - 操作：「キャンセル」「{m}件を承認する」（{m}は実際に承認される件数。NGワード・Threadsの上限と、承認済みの残りの枠を差し引く）
  2. 送る（規約に注意のものがあれば `confirmPolicyCaution: true`）。
  3. 結果をトーストで出す。
     - すべて承認できた：「{n}件を承認しました」と「元に戻す」
     - 飛ばしたものがある：「{n}件を承認しました。{m}件は承認できませんでした（NGワード {a}件・Threadsの上限 {b}件・…）」
  4. 飛ばした下書きは選んだまま残す（spec エッジケース）。
- **まとめて却下**：却下理由の入力を開き、選んだ全件に同じ理由で送る。
- **要確認に戻す**：確認なしで送る。トースト「{n}件を要確認に戻しました」と「元に戻す」。
- **「元に戻す」**：`updated`に入った下書きに、逆の操作を送る（research.md R2）。
  - 承認を戻す、却下を戻す：`reopen`
  - 要確認に戻すのを戻す：元の`approve`（`confirmPolicyCaution: true`）、または`reject`（元の理由）

### 下書きの編集（FR-007。003の変更）

- 承認済みの下書きでも「編集」を開ける。ダイアログの上に「保存すると要確認に戻り、もう一度承認が必要になります」と出す。
- 保存の結果が`reopened: true`なら、トースト「直したので、要確認に戻しました。もう一度承認してください」。
- 編集のダイアログでも、本文の欄の下にNGワード・規約に注意のラベルを、入力に合わせて出す（保存の前に気づけるように）。

### 空の状態

- 承認済み：「承認した下書きはまだありません。要確認のタブで内容を確かめて「承認」を押してください。」
- 却下：「却下した下書きはありません。」

## このアカウントの設定（FR-031）

001の画面の、既存の区分（Threadsとの接続、Accountの削除）より上に「投稿のルール」の区分を足す。区分の見た目は型Dの右側にそろえる（小見出し、角の丸い枠、枠の中を線で区切った行。001の`SettingRow`）。

| 行 | 名前・説明 | 操作 |
|---|---|---|
| NGワード | 「NGワード」／「この言葉を含む下書きは承認できません。{n}語」 | 「編集」 |
| 投稿ルール | 「投稿ルール（CORE RULES）」／「AIプロンプトに「絶対に守るルール」として入ります。{n}件」または「未入力」 | 「編集」（プラン1で無料体験の終了後は「見る」） |
| Threadsの規約への備え | 「Threadsの規約への備え」／「規約に触れやすい表現に「規約に注意」と表示し、プロンプトにルールを入れます」 | 「見る」 |

### NGワードのダイアログ（FR-014）

- 見出し：「NGワード」、説明：「全角・半角、大文字・小文字の違いは同じ言葉として扱います」
- 入力欄（記入例「例：絶対、必ず儲かる」）と「追加」。Enterでも追加する。改行・「、」・「,」で区切った複数の語を一度に追加できる。
- 追加の結果：
  - 重複した語：「{語}はすでにあります」
  - 承認済みを戻した：トースト「NGワードを含む承認済みの下書き{n}件を、要確認に戻しました」（FR-016a）
- 登録済みの語は、チップで古い順に並べる。各チップに「×」（読み上げ名「{語}を削除」）。押すと確認なしで削除し、トースト「「{語}」を削除しました」と「元に戻す」を出す。「元に戻す」は同じ語を`POST /ng-words`で足し直す（足し直すと、その語を含む承認済みの下書きは要確認に戻る）。
- 件数「{n}/200語」。上限に達したら入力欄を無効にし、「上限（200語）に達しています」を出す。
- ダイアログは「閉じる」だけ（追加・削除はその場で保存する）。

### 投稿ルールのダイアログ（FR-019〜FR-021）

- 002の`FormDialogFrame`・`useItemForm`を使う。見出し「投稿ルール（CORE RULES）」、説明「1行に1つのルールを書きます。AIプロンプトの「絶対に守るルール」に、上から順に入ります」。
- 複数行の欄（2,000文字まで、文字数の表示つき）。記入例：「断定口調は使わない\n医療・投資の効果をうたわない」
- 保存の`409 STALE_UPDATE`・`403`は002と同じ扱い。
- grower機能を使えないAccountでは、欄を読み取り専用にし、上に「投稿ルールはAIプロンプトの生成（プラン2以上）で使われます」と002の`PLAN_CHANGE_CONTACT`を出す（FR-020）。

### Threadsの規約への備えのダイアログ（FR-042・FR-043）

読むだけ。`packages/shared`の定数から表示する。

- 説明：「アプリが用意しているルールです。変更・無効化はできません。規約に触れないことを保証するものではありません。」
- 「AIプロンプトに入れるルール」：規約上のルール6つの箇条書き
- 「「規約に注意」と表示する表現」：4つの分類の名前・説明（言い換えの方向）・関わる規約へのリンク（新しいタブ）
- 最後に「{POLICY_LIST_VERSION}時点のMetaコミュニティ規定をもとにしています」

## エラー文言（`packages/shared`に足す）

| code | 文言 | 次に取れる操作 |
|---|---|---|
| `ITEM_LIMIT_REACHED`（NGワード） | NGワードは200語まで登録できます。 | 不要な語を削除する |
| `STALE_UPDATE`（投稿ルール） | 002と同じ「他の場所で更新されています」のダイアログ | 読み込み直す／上書きする |
