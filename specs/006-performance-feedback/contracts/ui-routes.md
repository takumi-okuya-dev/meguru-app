# 画面の契約：パフォーマンス

**対象feature**：[spec.md](../spec.md) FR-011〜FR-024・FR-028・FR-031 ／ **UI全体設計**：[docs/ui-design.md](../../../docs/ui-design.md) ／ **画面案**：[006 パフォーマンス画面案](https://claude.ai/artifact/57YMJcqBj1o8Y5AsQGvqBA)（非公開）

## ルートとサイドバー

| 項目 | 内容 |
|---|---|
| ルート | `/accounts/:accountId/performance`（`AccountLayout`の子） |
| サイドバー | 見出し「分析」の下に「パフォーマンス」（アイコン`ChartColumnIcon`）。UI全体設計の「まだ作っていない機能は出さない」に従い、本featureで足す |
| 画面の型 | UI全体設計の型C（作業画面型）に近い1カラム。上部バーに画面名と主な操作（CSVで書き出す） |

## 画面の構成（上から）

1. **上部バー**：「パフォーマンス」、右に「反応数の最終更新 {M/D H:MM}」と「CSVで書き出す」（メニュー）。スマートフォンでは最終更新を基準値の欄に移し、CSVはアイコンだけのボタンにする。
2. **案内の帯**（当てはまるときだけ）：
   - 要再接続：001の再接続のバナー（既存）
   - 権限がない（`insightsDenied`）：「反応数を読む許可がありません。再接続して、インサイトの許可をオンにしてください」と「再接続」
3. **説明の1文**：「投稿ごとの反応数と、このアカウントの基準値と比べた判定です。反応数は投稿の24時間後から取り込み、約7日後に値が確定したら判定します。」
4. **基準値の欄**：
   - 「基準値（閲覧数）」と値（小数第1位まで。5件未満は「—」）
   - 説明：「確定した直近30件の閲覧数の中央値です。判定は、投稿から約7日後に値が確定してから行います。」
   - 5件未満：「確定した投稿が5件たまると判定を始めます（いま{n}件）」を太字で
   - 基準値が0：「基準値が0のため判定できません」
   - 3つのアイコンの意味：「基準値の2倍以上」「その間」「基準値の半分以下」
5. **タブ**：すべて／好調／普通／低調／確定待ち。好調〜確定待ちは、アイコンと件数だけ（`aria-label`に「伸びた 7件」など）。
6. **低調のタブの説明**（低調のタブだけ）：「閲覧数が基準値の半分以下だった投稿は、新しい順に5件まで次のプロンプトに『反応が低かった投稿』として入ります。傾向メモを書くと、本文と一緒に入ります。」「入れたくない投稿は『プロンプトに入れる』を外してください。外すと次の投稿が繰り上がります。」
7. **投稿のカードの一覧**（50件ずつ、「さらに表示する」）。

## 判定のアイコン（FR-013・FR-014）

| 判定 | アイコン（lucide） | 色（ライト／ダーク） | 文字での説明（`title`・読み上げ） |
|---|---|---|---|
| 好調 | `TrendingUpIcon` | オレンジの地 #FFF0DC・文字 #8F4700 ／ #3B2A12・#FFB866 | 伸びた（基準値の{倍率}倍） |
| 普通 | `ArrowRightIcon` | グレー（`muted`） | いつも通り（基準値の{倍率}倍） |
| 低調 | `TrendingDownIcon` | 青の地 #E3EEFB・文字 #0B4F9E ／ #16304F・#8EC2FF | 伸びなかった（基準値の{倍率}倍） |
| 確定待ち | `ClockIcon`（点線の枠） | 地なし | 確定待ち（値が確定してから判定します） |
| 計測できません | `BanIcon`（点線の枠） | 地なし | 反応数を取れない投稿 |

色はトークン（`--perf-good-*`・`--perf-poor-*`）としてテーマに足す。アイコンの横に倍率「×3.4」を出す（確定待ち・計測できませんは文字「確定待ち」「計測できません」）。

## 投稿のカード

| 部分 | 内容 |
|---|---|
| 1行目 | 判定のバッジ、投稿した日時（`M/D(曜) H:MM`）、（すべてのタブで、次のプロンプトに入る低調の投稿に）「✓ 次のプロンプトに入ります」、右端に「Threadsで開く」（URLがあるときだけ） |
| 本文 | 4行で省略 |
| 反応数 | 閲覧（太字）・いいね・返信・リポスト・引用・シェア。返らなかった数は「−」。PCは6列、スマートフォンは3列×2行 |
| 確定待ち（値あり） | 「暫定の値です。{M/D}ごろ値が確定して判定します。」 |
| 確定待ち（値なし） | 反応数の代わりに「反応数は {M/D H:MM} ごろに取り込みます。」 |
| 遅れて確定 | 「投稿から{n}日後に取り込んだ値です（ほかの投稿より長い期間の数のため、基準値には含めません）」 |
| 計測できません | 反応数の代わりに「Threadsでこの投稿を見つけられないため、反応数を取れません。Threads側で消した投稿などが当たります。判定と基準値には含めません。」 |
| 低調（すべてのタブ） | 傾向メモの要約（なければ「傾向メモはまだありません」、外していれば「プロンプトから外しています」）と「改善メモを開く」（低調のタブに移る） |
| 低調（低調のタブ） | 「傾向メモ（任意・なぜ伸びなかったと思うか）」の入力欄（200文字、右下に「{n}/200」、例「前置きが長く、結論が最後まで出てこない」）、「プロンプトに入れる」のチェック、入るかどうかの説明（「次のプロンプトに入ります」「新しい5件に入っていないため、今は入りません」「外しています。以降のプロンプトには入りません」） |

## 傾向メモと切り替えの保存（FR-021）

- メモは入力欄から離れたとき（`blur`）、変わっていれば`PATCH …/feedback`。切り替えは押したとき。
- 保存中・保存済みは、入力欄の下に小さく「保存しました」を出す（2秒で消す）。
- 失敗したら「保存できませんでした。もう一度お試しください」と、入力した内容を残す。
- 応答の`promptIds`で、ほかのカードの「次のプロンプトに入ります」を更新する（繰り上がり）。

## CSVで書き出す（FR-028〜FR-030）

- ボタンを押すとメニュー：
  - 「投稿ごと」：「1投稿1行。確定（または最新）の値と、24時間時点の値・投稿時点のフォロワー数など」
  - 「取り込みごと」：「取り込み1回1行。投稿からの経過時間ごとの伸び方（推移）を見るとき」
- 選ぶと、`GET …/performance/export`を続きがなくなるまで読み、[csv.md](./csv.md)の形でファイルを保存させる。読んでいる間はボタンを「書き出し中…」にして押せなくする。失敗したら「書き出せませんでした。もう一度お試しください」。

## grower機能を使えないとき（FR-031）

`403 GROWER_FEATURE_REQUIRED`を受けたら、一覧の代わりに中央に：
- 見出し「パフォーマンス分析は有料の契約で使えます」
- 本文「無料体験が終わりました。契約すると、投稿ごとの反応数・伸びたかどうかの判定・改善メモ・CSVの書き出しを使えます。これまでの記録は残っているので、契約すると続きから見られます。」
- 「プランの変更は運営者にお問い合わせください。」（既存の`PLAN_CHANGE_CONTACT`。課金のfeatureで「契約する」ボタンに置き換える）

CSVのボタンは出さない。
