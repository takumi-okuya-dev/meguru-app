# プロンプトの文面の契約（006の差分）：反応が低かった投稿

**対象feature**：[spec.md](../spec.md) FR-025〜FR-027 ／ **これまで**：[003](../../003-prompt-bulk-register/contracts/prompt-template.md)・[004](../../004-review-approval/contracts/prompt-template.md)・[005](../../005-auto-post/contracts/prompt-template.md)

## 入力（足すもの）

`buildPrompt`（`packages/shared/src/prompt.ts`）の入力に足す。

```ts
type PromptPoorPost = { body: string; memo: string | null };
// BuildPromptInput に
poorPosts: PromptPoorPost[]; // 投稿した日時の新しい順。prompt-service が最大 PROMPT_POOR_POSTS（5）件を渡す
```

`prompt-service`の材料（research.md R8）：`post_metrics.judgment = 'poor'`、`include_in_prompt = true`、`state`が`confirmed`か`late_confirmed`の投稿を、`post_drafts.published_at`の新しい順に5件。

## 節の位置

「■過去に却下された投稿」の節（004 FR-023）の**直後**。却下の節がない（却下が0件）場合も、同じ並びの位置（宣伝内容の節の後）に置く。

```text
…
■今回組み込む宣伝内容(…)            ← 002・005
■過去に却下された投稿(…)            ← 004（0件なら省く）
■反応が低かった投稿(…)              ← 006（0件なら省く）
■リサーチで見つけた「伸びている投稿」…  ← 002
…
```

## 文面

```text
■反応が低かった投稿(このアカウントで閲覧数が基準の半分以下だった投稿。同じ書き方・切り口は避けること)
1. {本文}
2. {本文}(傾向メモ: {メモ})
…
```

- 本文は、却下の節（004）と同じく、保存している本文をそのまま入れる。
- 傾向メモがある投稿だけ、本文の直後に`(傾向メモ: …)`を付ける。
- **長さの調整で減らさない**：全文が`PROMPT_LENGTH_TARGET`を超えたとき、003・004は直近の下書き → 却下 → 参考投稿の順に減らす。この節は、CORE RULESの節と同じく減らさない（最大5件で短く、Constitution原則VIの「必ず反映」を守るため）。
- 0件なら、見出しを含めて節ごと出さない。
- 好調・普通・確定待ち・計測できません・「プロンプトに入れる」を外した低調の投稿は入らない（FR-027）。

## 例（spec US2の受け入れの例）

```text
■反応が低かった投稿(このアカウントで閲覧数が基準の半分以下だった投稿。同じ書き方・切り口は避けること)
1. AI初心者の人ほど、
最初から完璧なプロンプトを作ろうとしなくていいと思ってます。…
2. AIに文章を書いてもらうとき、
最初の出力をそのまま使うより
「自分ならここは違うな」を直す工程がけっこう大事。…(傾向メモ: 前置きが長く、結論が最後まで出てこない)
3. コミュニティをやっていて面白いのは、
入口と出口が同じじゃなくていいこと。…
4. AI時代だからこそ、
「誰に聞けばいいか分かる」って結構強い気がする。…
5. AIを使うと仕事が全部ラクになる。

…というより、
ラクになる仕事と、そうでもない仕事を見つけていく感じなのかもしれない。(傾向メモ: 「…というより」で始まる書き出しが続いている)
```

（「…」は例を短くするための省略。実際のプロンプトには本文の全文が入る。）

## 要約（`summary`）

003の`summary`（材料の件数）に`poorPosts`（入れた件数）を足す。投稿ストックのプロンプトのカードの「材料」の表示に、「反応が低かった投稿 {n}件」を出す。
