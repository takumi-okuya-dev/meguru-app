## 日時の書き方（`apps/web/src/lib/format.ts`に足す）

予定・投稿した日時は日本時間で、今日・明日を言葉にする（FR-021）。

| 条件 | 例 |
|---|---|
| 今日 | 「今日 12:00」 |
| 明日 | 「明日 7:30」 |
| それより先・前 | 「10月8日 21:00」 |

## このアカウントの設定（FR-001〜FR-004）

004の「投稿のルール」の区分の**上**に「投稿のスケジュール」の区分を足す。見た目は004と同じく、`SettingRow`の行。

| 行 | 名前・説明 | 右側 |
|---|---|---|
| 自動投稿 | 「自動投稿」／オン：「承認済みの下書きを、下の時刻に1件ずつ投稿します」、オフ：「オフです。承認済みの下書きは投稿されません」 | 「オン」「オフ」の表示 |
| 投稿する時刻 | 「投稿する時刻」／「7:30・12:00・21:00（1日3件）」または「未設定」 | |
| 時刻を少しずらす | 「時刻を少しずらす」／「機械的に見えないよう、前後10分の中でずらして投稿します」 | 「オン」「オフ」の表示 |

- 区分の右上に「編集」を1つ置き、`PostingScheduleDialog`を開く。
- 区分の下に「接続を確かめる」（枠線のボタン）を置く（FR-002b）。押すと`POST /threads-check`を呼び、ボタンの右に結果を1行で出す。

  | 結果 | 表示 |
  |---|---|
  | `ok` | 「投稿できる状態です（直近24時間の投稿 {quotaUsage}/{quotaTotal}件）」（成功の色） |
  | `needs_reconnect` | 「Threadsとの接続が切れています。再接続してください」と「再接続」 |
  | `no_publish_permission` | 「Threadsへの投稿の権限がありません。再接続して、投稿の許可をオンにしてください」と「再接続」 |
  | `unknown` | 「Threadsとの接続を確認できませんでした。時間をおいてもう一度お試しください」 |

  - 確かめている間は、ボタンを無効にし「確かめています…」と出す。
  - `needs_reconnect`のときは、Accountの情報（接続の状態）も読み直す。
- 要再接続のAccountでは、区分の上に「Threadsとの接続が切れているため、自動投稿は止まっています」と「再接続」を出す（設定の編集はできる）。

### 投稿のスケジュールのダイアログ（`PostingScheduleDialog`）

- 見出し：「投稿のスケジュール」
- **自動投稿**：`Switch`。説明は上の表と同じ。
- **投稿する時刻**：
  - 時刻の一覧（昇順）。各行の右に「削除」（×）。
  - 一覧の下に`<input type="time">`と「追加」。Enterでも足せる。
  - 10件になったら、入力と「追加」を無効にし、「時刻は10件まで登録できます」と出す。
  - 一覧の上に「1日 {n}件 投稿します」。
- **深夜の案内**（FR-001b）：2:00〜4:59の時刻の行の下に、情報の色で「深夜の時間帯です。見られにくい可能性があります」。検証のエラーではなく、保存は止めない。範囲は`packages/shared`の定数（`LATE_NIGHT_HINT_MINUTES`＝[120, 300)）。
- **時刻を少しずらす**：`Switch`。既定はオン。
- **検証**（入力のたびに、`packages/shared`の`validatePostingSchedule`で）：

  | 理由 | 文言（該当する時刻の行の下、または一覧の下） |
  |---|---|
  | `duplicate` | 「同じ時刻がすでにあります」 |
  | `too_close` | 「時刻を少しずらすときは、時刻どうしを30分以上あけてください（{時刻}と{時刻}）」 |
  | `required` | 「自動投稿をオンにするには、時刻を1つ以上追加してください」 |
  | `too_many` | 「時刻は10件まで登録できます」 |

- **保存**：主なボタン「保存」。検証に通らない間は無効にする。
  - 保存できたら、ダイアログを閉じて「投稿のスケジュールを保存しました」と通知する。
  - オンにしたときは「次の投稿は{日時}の予定です」と添える（API`GET /auto-post`の`next.at`。承認済みが0件なら「承認済みの下書きを用意してください」）。
- **投稿の権限の確認**（FR-002a）：自動投稿をオンにして「保存」を押すと、保存の前にAPIが確かめる。その間は「保存」を無効にし「Threadsとの接続を確かめています…」と出す。
  - `409 THREADS_NOT_READY`：ダイアログを閉じず、上部にエラーの色で理由（上の表の`needs_reconnect`・`no_publish_permission`の文言）と「再接続」を出す。入力は消さない。自動投稿をオフにすれば、そのまま保存できる。
  - `connectionCheck.status`が`unknown`：保存して閉じ、通知に「保存しました。Threadsとの接続は確認できませんでした。「接続を確かめる」で、あとで確かめてください」と出す。
- **競合**：`409 STALE_UPDATE`は002の`ConflictDialog`（読み込み直す／上書きする）。
- **未保存の警告**：002と同じ（ダイアログを閉じる・画面を離れるとき）。
- 時刻の入力は、`<input type="time">`をスマートフォンでもそのまま使う（OSの時刻の選択が出る）。

## 投稿ストックの画面（型C）

### 知らせ（`AutoPostNotices`。FR-018）

プロンプトのカードの上に、`GET /auto-post`の`notices`を並べる。ホームと同じ部品を使う。

| kind | 色 | 文言 | 操作 |
|---|---|---|---|
| `needs_reconnect` | `--destructive` | 「Threadsとの接続が切れているため、自動投稿を止めています。再接続してください」 | 「再接続」（001の再接続の操作） |
| `rate_limited` | 注意 | 「Threadsの投稿数の上限に達したため、今日の投稿を止めました。{日時}から再開します」 | なし |
| `publish_failed` | `--destructive` | 「{n}件の投稿に失敗しました（{理由の文言}）」 | 「確認する」（承認済みのタブの失敗のまとまりへ） |
| `blocked` | 注意 | 「投稿の直前に{理由}が見つかったため、{n}件を要確認に戻しました」 | 「確認する」（要確認のタブへ）、「閉じる」（`dismiss`） |
| `no_approved` | 情報 | 「承認済みの下書きがありません。次の投稿の時刻（{日時}）までに承認してください」 | なし |

- `{理由}`：`ng_word`は「NGワード（{言葉}、…）」、`over_threads_limit`は「Threadsの上限を超える本文」。
- 知らせは、投稿ストックでの操作（承認・もう一度投稿の順に入れる・要確認に戻す・編集）の後に読み直す。

### 状態のタブ（004の変更。FR-020）

- 「要確認 {n}」「承認済み {n}」「却下 {n}」「投稿済み {n}」の4つ。`?tab=published`。
- 承認済みの件数は`counts.approved`（処理中を含む）。投稿に失敗の件数は、タブの数字に足さない（知らせと、承認済みのタブの先頭で伝える）。
- `md`未満でタブが画面の幅に収まらないときは、タブの行を横にスクロールできるようにする（ページ全体は横にスクロールさせない）。

### 承認済みのタブ（004の変更。FR-021）

上から順に次を並べる。

1. **案内の1行**（004の`APPROVED_TAB_NOTICE`を置き換える）：
   - オン：「上から順に、投稿する時刻に1件ずつThreadsへ投稿します」
   - オフ：「自動投稿はオフです。」と「投稿のスケジュールを設定する」（設定の画面へのリンク）
   - 停止中：知らせ（上記）と同じ内容を短く
2. **投稿に失敗**のまとまり（`publishFailed`が1件以上のとき）：
   - 見出し「投稿に失敗（{n}件）」、各カードに「{日時}に失敗：{理由の文言}」。
   - 操作は、主なボタン「もう一度投稿の順に入れる」（`review`の`requeue`）と、「⋯」の「要確認に戻す」（`reopen`）。
   - このまとまりは選択のバーの対象外。
3. **投稿の順の一覧**（`approved`の並びのまま）：
   - 各カードの、004の「{日時}に承認」の右に予定を出す。
     - 予定がある：「{日時}に投稿予定」
     - 処理中：「投稿の処理中」（スピナー。操作はすべて無効）
     - 持ち越し：「前回の投稿に失敗したため、次の時刻にもう一度試します」（注意の色）
     - 予定がない（オフ・停止中）：何も出さない
   - 「⋯」メニュー：「次に投稿する」（先頭のカードでは出さない）・「編集」・「要確認に戻す」。
   - 「次に投稿する」の後は、一覧を読み直し、移したカードまでスクロールして枠を一瞬強調する。「次の投稿にしました（{日時}の予定）」と通知する。

### 要確認のタブ（004の変更。FR-007、US2-2）

- `blockedReason`がある下書きは、ラベルの行の先頭に、注意の色で「投稿の直前に{理由}が見つかったため、要確認に戻しました（{日時}）」を出す。
- 下書きの状態が変わると（編集・承認・却下・削除）、この表示は消える（API側で`blocked_*`を消す）。

### 投稿済みのタブ（新規。FR-020）

- タブを開いたときに`GET /post-drafts/published`で50件を読む。ほかのタブを開いている間は読まない（research.md R14）。
- 投稿した日時の新しい順。各カードは次のとおり。
  - 本文
  - 「{日時}に投稿」
  - 「Threadsで開く」（`threadsPermalink`へのリンク。`target="_blank" rel="noopener noreferrer"`）。URLがまだないときは「URLを取得中」
- チェックボックス・「⋯」・選択のバーはない（編集・削除・要確認に戻すことができない）。
- 続きがあるときは、一覧の最後に「もっと見る」（次の50件を足す）。
- 投稿済みの一覧は、状態の変更の後に読み直さない（自動投稿でしか増えないため）。タブを開き直したときと、投稿ストックの画面を開いたときに読み直す。
- 空の状態：「まだ投稿はありません。承認した下書きは、投稿のスケジュールに沿って投稿されます」。

### 処理中の下書きへの操作（FR-008）

`409 DRAFT_PUBLISHING`・`skipped: PUBLISHING`のときは、「投稿の処理中です。少し待ってからもう一度お試しください」と通知し、一覧を読み直す。

## ホーム（FR-022）

既存の「次にやること」のカードの下に、「次の投稿」のカードを足す。カードの上に知らせ（`AutoPostNotices`）を出す。

| 状態 | カードの中身 |
|---|---|
| オンで予定あり | 「次の投稿」／「{日時}」（大きめの文字）／本文の書き出し（40文字まで、2行で切る）／「承認済み {n}件・あと{d}日分」／「投稿ストックを開く」 |
| オンで承認済み0件 | 「次の投稿」／「承認済みの下書きがありません」／「投稿ストックを開く」 |
| オンで停止中 | 「次の投稿」／停止の理由（知らせと同じ文言）／再接続のボタン（要再接続のとき） |
| オフ | 「自動投稿はオフです」／「承認済みの下書きを、決めた時刻に自動で投稿できます」／「投稿のスケジュールを設定する」 |

- 「あと{d}日分」は、時刻が0件のときは出さない。

## エラー・失敗の文言（`packages/shared`に足す）

| code | 文言 |
|---|---|
| `DRAFT_PUBLISHING` | 投稿の処理中です。少し待ってからもう一度お試しください。 |
| `THREADS_NOT_READY` | `details`ごとに、「接続を確かめる」の表の`needs_reconnect`・`no_publish_permission`の文言 |
| `STALE_UPDATE`（投稿のスケジュール） | 002と同じ「他の場所で更新されています」のダイアログ |
| 失敗の理由`network` | Threadsとの通信に失敗しました |
| 失敗の理由`threads_server` | Threads側でエラーが起きました |
| 失敗の理由`invalid_request` | Threadsが投稿を受け付けませんでした。本文を確かめてください |
| 失敗の理由`container_error` | Threadsでの投稿の処理に失敗しました |
| 失敗の理由`unknown` | 投稿に失敗しました |
