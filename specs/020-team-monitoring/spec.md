# Feature Specification:チームの運用状況を見る

**Feature Branch**: `feature/020-team-monitoring`

**Created**: 2026-11-04

**Status**: Draft

**Input**: 2026-11-04に、ユーザーが追加機能のアイデアとして挙げた（[docs/next-features.md](../../docs/next-features.md) §H）。チームの管理者が、チームで運用しているアカウントの状況をまとめて見られるようにしたい。手が止まっている人（サボっている人）と、投稿が伸びていないアカウントが、すぐわかるようにする。

**Source**: [docs/next-features.md](../../docs/next-features.md) §H、[011のspec](../011-team-revision/spec.md)（チーム・ロール・担当・チームに見せる）、[008のspec](../008-team-operations/spec.md)（操作の記録）、[006のspec](../006-performance-feedback/spec.md)（反応数・好調・普通・低調・確定）、[019のspec](../019-feature-switches/spec.md)（機能のまとまり「チーム」）、[Constitution](../../.specify/memory/constitution.md) 4.2.0 原則IV・V。

## Clarifications

### Session 2026-11-04

- Q: 管理者に、どのアカウントの運用状況を見せるか？ → A: チームに入っているアカウントすべて（「チームに見せる」に関わらず）。出すのは数と日付だけ。招待の確認の画面とチームの画面に、管理者が運用状況（数）を見られることを出す。原則IV・Vの改定が要る。
- Q: 「止まっている」の印は、何日動きがないと付けるか？ → A: 7日。人は案を作る・直す・承認・却下、アカウントは投稿がないことを数える。
- Q: 編集者にも運用状況を見せるか？見せるなら、どこまでか？ → A: 見せる。担当のアカウントと、そのオーナーの行だけ。担当の外の人とアカウントは見せない。メンバーには見せない。
- Q: 「伸びていない」は、何と比べて決めるか？ → A: そのアカウントの前の期間と比べる。直近30日の確定した閲覧数の中央値を、その前の30日と比べ、下がっていたら印を付ける。

## 用語

- **運用状況**：チームに入っているアカウントごと・チームの人ごとの、動きと伸びの数。管理者はすべて、編集者は担当のアカウントとそのオーナーの分を見る。投稿の本文・戦略・設定の中身は含まない。
- **止まっている**：7日のあいだ、動きがないこと。人は案を作る・直す・承認・却下、アカウントは投稿（FR-010・FR-011）。
- **伸びていない**：アカウントの直近30日の確定した閲覧数の中央値が、その前の30日より決めた割合以上下がっていること（FR-020）。
- **管理者・メンバー・編集者・オーナー・担当・チームに見せる**：011の用語のまま。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理者が、手が止まっている人とアカウントを見つける (Priority: P1)

チームの管理者が、チームの画面の「運用状況」を開く。チームの人ごとに、最後に動いた日と、この7日の動きの数が並ぶ。7日より長く動いていない人とアカウントには「止まっている」の印が付き、一覧の上に来る。管理者は、誰に声をかければいいかを1画面で知る。

**Why this priority**: ユーザーが挙げた一番のねらい（サボっている人がよくわかる）。動きの数は、今ある記録（操作の記録・投稿済み）から作れる。

**Independent Test**: 3人のチームで、1人は今日案を作り、1人は8日前に最後に承認し、1人は一度も操作していない状態を作る。管理者が「運用状況」を開き、後の2人に「止まっている」の印が付き、上に並ぶことを確かめる。

**Acceptance Scenarios**:

1. **Given** 管理者がチームの画面を開いている、**When** 「運用状況」を開く、**Then** チームの人ごとに、名前・ロール・最後に動いた日・この7日の動きの数（案を作る・直す・承認・却下）が並ぶ。
2. **Given** 最後に動いた日から、7日より長くたっている人、**When** 一覧を見る、**Then** その人に「止まっている」の印が付き、印のない人より上に並ぶ。
3. **Given** 一度も動いていない人、**When** 一覧を見る、**Then** 最後に動いた日は「まだありません」と出て、「止まっている」の印が付く。
4. **Given** 承認済みの案が残っていて自動投稿は続いているが、オーナーが操作していない、**When** 一覧を見る、**Then** アカウントの投稿は動いていると出て、人のほうに「止まっている」の印が付く（人の動きと投稿の動きを分けて見せる）。

---

### User Story 2 - 管理者が、投稿が伸びていないアカウントを見つける (Priority: P1)

同じ「運用状況」に、チームに入っているアカウントごとの伸びが並ぶ。伸びていないアカウントには印が付く。

**Why this priority**: ユーザーが挙げたもう1つのねらい（投稿が伸びていない）。

**Independent Test**: 2つのアカウントで、1つは直近30日の確定した閲覧数の中央値がその前の30日より下がり、1つは上がっている状態を作る。管理者が「運用状況」を開き、前のアカウントにだけ「伸びていない」の印が付くことを確かめる。

**Acceptance Scenarios**:

1. **Given** チームに入っているアカウント、**When** 管理者が「運用状況」を開く、**Then** アカウントごとに、オーナー名・最後に投稿した日・この7日の投稿数・承認済みの残り・要確認の数・伸び（FR-020）が並ぶ。
2. **Given** 伸びていないアカウント、**When** 一覧を見る、**Then** そのアカウントに「伸びていない」の印が付き、前の30日との比（例：×0.6）が出る。
3. **Given** どちらかの30日の確定した投稿が5件に満たず、伸びを判定できないアカウント、**When** 一覧を見る、**Then** 伸びは「まだ判定できません」と出て、印は付かない。

---

### User Story 3 - チームの人が、管理者に運用状況が見えることを知っている (Priority: P2)

招待の確認の画面とチームの画面に、管理者と担当の編集者が運用状況（数と日付だけ）を見られることが出る。チームの人は、入る前と入った後に、何が誰に見えるかを知っている。

**Why this priority**: 「チームに見せる」がオフでも数が管理者と担当の編集者に見えるようになる。入る人の同意を、今の「できること」の案内と同じ場所で取る（011 FR-012）。

**Independent Test**: 招待のリンクを開き、確認の画面に案内があることを確かめる。入った後、メンバーとしてチームの画面を開き、同じ案内があることを確かめる。

**Acceptance Scenarios**:

1. **Given** 招待のリンクを開いた人、**When** 確認の画面を見る、**Then** できることの説明に「管理者と、あなたのアカウントの担当の編集者は、運用状況（投稿の数・伸び・最後に動いた日）を見られます。投稿の本文や戦略は見られません」が入っている。
2. **Given** 本featureの前から入っている人、**When** チームの画面を開く、**Then** 同じ案内が見られる（閉じたトグルの中の箇条書き）。

---

### User Story 4 - 編集者が、担当のアカウントの運用状況を見る (Priority: P2)

編集者がチームの画面の「運用状況」を開くと、担当のアカウントと、そのオーナーの行だけが並ぶ。手伝っているお店の手が止まっていないか、伸びているかがわかる。

**Why this priority**: 編集者は担当のアカウントで投稿の案と戦略を作る。手伝う先の様子がわかると、声をかけたり、案を足したりできる。担当の外のお店の数は見せない。

**Independent Test**: 4つのアカウントが入ったチームで、編集者に2つを担当にする。編集者で「運用状況」を開き、その2つのアカウントと、そのオーナーの行だけが出ることを確かめる。担当を1つ外し、次に開いたときに出なくなることを確かめる。

**Acceptance Scenarios**:

1. **Given** 担当のアカウントが1つ以上ある編集者、**When** チームの画面を開く、**Then** 「運用状況」が出る。
2. **Given** その編集者、**When** 「運用状況」を開く、**Then** 担当のアカウントと、そのオーナーの行だけが、管理者と同じ形で並ぶ。担当の外の人とアカウントは出ない。
3. **Given** 担当が1つもない編集者、**When** チームの画面を開く、**Then** 「運用状況」は出ない。
4. **Given** 担当を外されたアカウント、**When** 編集者が次に開く、**Then** そのアカウントとオーナーの行は出ない。

---

### User Story 5 - メンバーと関わりのない人には、運用状況を出さない (Priority: P2)

メンバーには「運用状況」を出さない。個人運用の人にも出さない。

**Why this priority**: チームはお店どうしの集まりにもなる。ほかの人の動きと伸びを、管理者と担当の編集者のほかには見せない（原則IV・V）。

**Independent Test**: 同じチームのメンバーでチームの画面を開き、「運用状況」が出ないこと、運用状況を直接求めても断られることを確かめる。編集者で、担当の外のアカウントの運用状況を直接求めても断られることを確かめる。

**Acceptance Scenarios**:

1. **Given** メンバー、**When** チームの画面を開く、**Then** 「運用状況」は出ない。
2. **Given** メンバー・別のチームの人・関わりのない人、**When** 運用状況を直接求める、**Then** 断られ、数は返らない。
3. **Given** 編集者、**When** 担当の外のアカウントの運用状況を直接求める、**Then** 数は返らない。
4. **Given** 管理者・編集者でも、機能のまとまり「チーム」がOFF、**When** チームの画面を開こうとする、**Then** 019のとおり開けない。

---

### Edge Cases

- チームに入って日が浅い人：入った日から数え、入る前の動きは数えない。最後に動いた日が入る前なら、入った日から日数を数える。
- チームを抜けた・外れた人：一覧から消える。数は残さない。
- 操作の記録は90日で消える：記録がなく、入って90日を過ぎた人は「90日以内にありません」と出し、「止まっている」の印を付ける（research.md R2）。
- 管理者自身：一覧に自分も並ぶ（自分のアカウントの状況も同じ形で見られる）。
- 編集者自身：担当の外なので、自分の行と自分のアカウントは出さない（自分のアカウントは、今のホームとパフォーマンスで見られる）。
- 担当のアカウントのオーナーが、機能のまとまり「チーム」をOFFにされている（019：手伝ってもらえない）：編集者には、そのアカウントとオーナーの行を出さない。担当がすべてそうなら、編集者に「運用状況」を出さない。管理者には、チームの画面と同じく出す（research.md R6）。
- 1人のオーナーが、担当のアカウントと担当の外のアカウントを両方持つ：編集者には、オーナーの行を出し、アカウントは担当のものだけ出す。オーナーの行の動きは、担当のアカウントでの動きだけを数える。
- オーナーが自動投稿のまとまりをOFFにされている（019）：反応数を取り込まないので、伸びは「取り込んでいません」と出し、印は付けない。
- Threadsとの接続が切れているアカウント：「接続が切れています」と出す。投稿が止まっていても、理由がわかるようにする。
- 担当の編集者の動き：担当のアカウントで案を作った・直した動きは、その編集者の動きとして数える。
- チームに入っているアカウントが20件ある：スマートフォンの幅でも、すべての行に、横にスクロールせずに届く。

## Requirements *(mandatory)*

### Functional Requirements

#### 見られる人と範囲

- **FR-001**: System MUST 運用状況を、そのチームの管理者と、担当のアカウントが1つ以上ある編集者に見せる。メンバー・別のチームの人・関わりのない人には、画面を出さず、直接求めても断る。判定は今の判定の1か所に足す（原則V）。
- **FR-002**: System MUST 管理者には、そのチームに入っているアカウントとチームの人をすべて出す。「チームに見せる」のオン・オフに関わらない。
- **FR-002a**: System MUST 編集者には、その人の担当のアカウントと、そのオーナーの行だけを出す。オーナーの行の動きは、FR-010の動きのうち、担当のアカウントでの動きだけを数える（担当の外のアカウントでの動きは、行にも件数にも入れない）。担当の外の人とアカウントは、行も件数も出さない。担当の変化は、次に開いたときから反映する（011 FR-004）。
- **FR-003**: System MUST 運用状況には数と日付だけを出し、投稿の本文・戦略・設定の中身・操作の記録の中身は出さない。アカウントを開けるかどうかは、今のルール（011 FR-002）のまま変えない。
- **FR-004**: System MUST 機能のまとまり「チーム」が使えない管理者には、運用状況を出さない（019）。
- **FR-005**: System MUST 招待の確認の画面（011 FR-012）の「できること」に、管理者と、そのアカウントの担当の編集者が運用状況（投稿の数・伸び・最後に動いた日）を見られ、投稿の本文や戦略は見られないことを足す。チームの画面にも、同じ説明を、閉じたトグルの箇条書きで置く。

#### 手が止まっている

- **FR-010**: System MUST 人ごとに「最後に動いた日」と「この7日の動きの数」を出す。動きは、そのチームに入っているアカウントでの、その人の案を作る・直す・承認・却下とする（担当を外される前の動きも数える）。最後に動いた日から7日より長くたった人（一度も動いていない人を含む）に「止まっている」の印を付ける。
- **FR-011**: System MUST アカウントごとに「最後に投稿した日」「この7日の投稿数」「承認済みの残り」「要確認の数」を出し、最後に投稿した日から7日より長くたったアカウント（一度も投稿していないアカウントを含む）に「止まっている」の印を付ける。日数は、チームに入った日より前には数えない。
- **FR-012**: System MUST 印の付いた人・アカウントを、印のないものより上に並べる。同じ印の中は、止まっている日数の長い順にする。

#### 伸びていない

- **FR-020**: System MUST アカウントごとに、直近30日に確定した投稿の閲覧数の中央値を、その前の30日の中央値と比べた比（例：×0.6）を出す。比が0.8以下（`[ASSUMPTION]`）のアカウントに「伸びていない」の印を付ける。
- **FR-020a**: System MUST どちらかの30日に確定した投稿が5件に満たないアカウントは、比を出さず「まだ判定できません」とする（006の判定を始める件数にそろえる）。
- **FR-021**: System MUST 伸びには、006の確定した値だけを使い、確定した日ではなく投稿した日で30日に分ける。確定待ち・計測できない投稿は使わない。
- **FR-022**: System MUST 自動投稿のまとまりがOFFのオーナーのアカウントは、伸びを「取り込んでいません」とし、印を付けない。

#### 画面

- **FR-030**: System MUST チームの画面に、FR-001の人にだけ「運用状況」を出す。人ごとの一覧とアカウントごとの一覧を、同じ画面に分けて出す。
- **FR-031**: System MUST 印は今ある見た目（バッジ・色）を使い、新しい強調は足さない（docs/ui-design.md）。例外は、チームの画面の「運用状況」のボタンの件数の印（止まっている人とアカウントの数。注意の色）で、2026-11-04 のモックで決めた。説明は閉じたトグルに箇条書きで置く。
- **FR-032**: System MUST スマートフォンの幅でも、横にスクロールせずに、すべての行と数に届くようにする。
- **FR-033**: System MUST 個人運用（チームに入っていない人）には、運用状況に関わる画面や項目を出さない（原則V）。

### Key Entities *(include if feature involves data)*

- **人の運用状況**：チームの人ごと。名前、ロール、最後に動いた日、この7日の動きの数、止まっているか（7日）。今ある操作の記録から作り、新しく保存しない想定。
- **アカウントの運用状況**：チームに入っているアカウントごと。オーナー名、接続の状態、最後に投稿した日、この7日の投稿数、承認済みの残り、要確認の数、前の30日との閲覧数の比、止まっている・伸びていないの印。今ある投稿ストック・投稿済み・反応数から作る想定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理者が、チームの画面から1回の操作で、止まっている人とアカウントをすべて見つけられる（印の付いたものが一覧の上にそろう）。
- **SC-002**: 20件のアカウントが入ったチームでも、運用状況が3秒以内に出る。
- **SC-003**: メンバー・関わりのない人が運用状況を求めたとき、100%断られ、数が1つも返らない。編集者には、担当の外のアカウントとその人の数が1つも返らない。
- **SC-004**: 運用状況に、投稿の本文・戦略・設定の中身が1つも出ない。
- **SC-005**: 個人運用の人の画面と操作の手数が、本featureの前と変わらない。
- **SC-006**: チームに入る人の全員が、入る前の確認の画面で、管理者と担当の編集者に見える範囲の説明を目にする。

## Assumptions

- 見るのは管理者と、担当のある編集者だけ。メンバーが自分の数を見る画面は作らない（必要なら後で足す）。
- 知らせ（メール・アプリ内の通知）は作らない。管理者が画面を開いて見る。
- 期間は「この7日」（動き・投稿の数）と「30日どうし」（伸び）に固定する。期間や日数を選ぶ機能は作らない。
- 「伸びていない」のしきい値0.8は仮の値。計画の段階で、テスト版のデータを見て直してよい。
- 数は、今ある記録（操作の記録・投稿ストック・投稿済み・反応数）から作る。新しく記録を取り始める必要はない想定。
- 管理者が止まっている人に連絡する手段（メッセージなど）は作らない。

## Dependencies

- Constitution を、計画（`/speckit-plan`）の前に4.3.0へ改定した（2026-11-04）。
  - 原則IV：管理者のできることに「チームに入っているAccountの運用状況（数と日付だけ）を見る」を、編集者に「担当のAccountとそのオーナーの運用状況を見る」を足す。理由の「管理者がほかの人の事業の判断を代わりに行わない」は保つ（見るだけで、承認・設定・中身には触れない）。
  - 原則V：チーム運用の範囲に「運用状況（管理者と担当の編集者）」を足す。「見せてもらっているAccountでは、パフォーマンス…を見せず」は保ち、運用状況の数は「見せる設定に関わらず、管理者と担当の編集者にだけ、数と日付だけ」と書き分ける。
