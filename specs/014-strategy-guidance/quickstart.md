# Quickstart：課題の入力を手助けする

**日付**：2026-10-16 | **計画**：[plan.md](./plan.md)

本featureが動くことを確かめる手順。準備は001〜013と同じ（[README](../../README.md)、OrbStackで`orb start`と`docker compose up -d --wait`）。

## 1. 自動のテスト

```bash
pnpm --filter api db:migrate   # 0015_strategy_guidance（目的の6列・参考投稿の項目・文字数と割合）
pnpm lint && pnpm typecheck
pnpm test                      # 共通・Web・API
pnpm e2e                       # 001〜013の流れ（投稿をつくる・投稿ストックの分け方に合わせて直したもの）＋014
```

## 2. 手で確かめる

1. **課題（US1〜US5）**：新しいアカウントで課題を開く。
   - チップ・進み具合・次におすすめ
   - 考えるヒントの開閉
   - 入力で印と数がその場で変わる
   - 「AIと深掘りする」でChatGPTかClaudeに送り、完成版を貼って反映 → 保存
   - 活動の軸の「5問からAIと整理する」
   - 「全体をAIと整理する」
   - PCでスクロールしてもチップが見え、今の区分が変わる
2. **見せてもらっている人・読むだけ**：チームで見せてもらっているアカウントの課題で、ヒントは見え、AIのボタンが出ない。013の読むだけでも同じ。
3. **リサーチ（US6〜US9）**
   - 解説の読み物
   - 参考投稿を3件ためて登録する。投稿日と数字を変え、鮮度とカードの表示を確かめる
   - 「まとめてAIに解説してもらう」で実際にAIに送り、答えを貼って保存する。IDを書き換えた答えが弾かれる
   - 編集の画面で1件の解説
   - キーワードの案を実際のAIで出して登録し、「Threadsで検索」
4. **投稿をつくる（US10〜US15）**
   - サイドバーの「投稿をつくる」で開き、選ばれた見た目になる
   - 手順の案内の開閉（再読み込みで覚えている）
   - 情報の一覧の数と「編集」の移動
   - 文字数と割合の保存と、プロンプトの数字
   - 長いプロンプト（課題を長く書いたアカウント）で、2つに分けて送る。無料のChatGPTで1つ目に「受け取りました」が返り、2つ目で投稿が作られる
   - 答えを貼り付けて登録し、「投稿ストックで確かめる」で要確認が開く。答えがコードブロックで囲まれていても分かれる
5. **投稿ストック**：一覧だけで、上に「投稿をつくる」。空のアカウントで案内が出る。今の承認・却下・修正・まとめての承認が変わらない。
6. **ホーム**：「はじめに読んでほしいこと」の開閉（再読み込みで覚えている）。「投稿をつくりましょう」で投稿をつくるへ移る。
7. **スマートフォンの幅（375px）**：課題・リサーチ・投稿をつくる・投稿ストックが横にはみ出さない（SC-009）。
8. **生成の質（参考）**：同じアカウントで、014の前と後のプロンプトでそれぞれ10件作り、課題の話題・目的・宣伝の件数・リサーチの型が表れているかを見比べる（数字の基準は置かない）。
