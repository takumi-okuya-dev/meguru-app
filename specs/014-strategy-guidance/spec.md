# Feature Specification:課題の入力を手助けする

**Feature Branch**: `feature/014-strategy-guidance`

**Created**: 2026-10-16

**Status**: Draft

**Input**: 2026-10-16、Threadsの運用を代行している人の参考プロダクト（Threads Growth OS）の課題の画面を確かめ、「最初は何を入力すればいいかわからないので、考えるヒントがあるとよい」とユーザーが判断した。次の5つを作る。(1)課題の各項目に「考えるヒント」（コツ・良い例・悪い例）と3つの問い（もっとこんな内容も足してみたら？／こんな場合はどうだろう？／もっと良くするなら）、(2)項目ごとの自動チェック（未入力・短め）と、全体の進み具合（完了の数・要確認の数）と「次におすすめの項目」、(3)項目ごとの「AIと深掘りする」プロンプト（コピーして外部のAIに送り、返ってきた完成版を貼り戻して入力欄に入れる）と、全体をAIと整理するプロンプト、(4)新しい区分「活動の目的・在り方」の5問と「活動の軸」、(5)リサーチの画面に「伸びる投稿を見つけるリサーチ」のやり方の解説、ホームに「はじめに読んでほしいこと」。投稿カテゴリの配分・投稿スタイル・イメージする投稿の例・文体の複数選択は範囲外（別のfeature）。同じ日、モックを見たユーザーが次を足した。(6)区分の名前から「課題①〜③」を外し、区分へ移るチップをPCでも上に固定する、(7)リサーチの参考投稿を、本文を貼り付けて登録する形のまま、何件かためてまとめて登録する・1件ずつ登録する（AIに「なぜ伸びたか」を解説してもらえる）の2つを使えるようにする（参考プロダクトの「リサーチを追加する（テキスト）」を確かめた結果から。画面録画から登録する方法は、ユーザーの指示で今回は作らない）。

**Source**: [002のspec](../002-strategy-profile/spec.md)（課題の16項目・下書き4項目・入力済み項目数・リサーチの画面・ホーム）、[003のspec](../003-prompt-bulk-register/spec.md)（投稿のプロンプトに課題を反映する）、[008のspec](../008-team-operations/spec.md)・[011のspec](../011-team-revision/spec.md)（担当の人・見せてもらっている人）、[013のspec](../013-billing/spec.md)（読むだけ）、[Constitution](../../.specify/memory/constitution.md) 4.0.1原則I（課題を投稿のプロンプトに反映する）・III（外部のAIへはコピー＆ペーストだけ）・V（判定を1か所に集める）。

## 用語

- **課題**：アカウントごとの戦略設計（002）。今は、営業導線設計・アカウント設計・集客導線設計・人柄・その他の16項目と、プロフィール・固定投稿の下書き4項目からなる（002では「課題①〜③」の番号を付けていたが、本featureで外す。FR-019）。
- **活動の目的・在り方**：本featureで課題の先頭に足す区分。5つの問い（目的の5問）と「活動の軸」からなる。
- **目的の5問**：Q1：なぜ、この活動を始めようと思いましたか？／Q2：この活動を通して、自分自身はどうなりたいですか？／Q3：関わってくれた人に、どうなってほしいですか？／Q4：この活動を続けた先に、どんな未来を作りたいですか？／Q5：活動するうえで、どんな在り方を大切にしたいですか？
- **活動の軸**：目的の5問の答えを、短い言葉にまとめたもの（任意）。投稿・プロフィールの言葉を選ぶときの芯になる。
- **考えるヒント**：項目ごとに用意した、書き方のコツ・良い例・悪い例と、3つの問い（「もっとこんな内容も足してみたら？」の観点2〜3個、「こんな場合はどうだろう？」の問い1つ、「もっと良くするなら、ここを考えてみて」の問い1つ）。アプリに文言として持ち、利用者ごとには変わらない。
- **自動チェック**：入力の量だけを見た、項目ごとの判定。「未入力」「短め」「十分」の3つ。内容の良し悪しは判定しない。
- **AIと深掘りする**：項目ごとのプロンプトをコピーして外部のAI（ChatGPT・Claudeなど）に送り、AIとのやりとりで完成させた文章を、アプリの貼り付け欄に貼って入力欄に反映すること。アプリはAIを呼び出さない（Constitution原則III）。
- **全体をAIと整理する**：課題の全体をまとめたプロンプトをコピーして外部のAIに送り、重複・矛盾・抜けについての質問を出してもらうこと。返ってきた答えはアプリに取り込まない。
- **参考投稿**：リサーチで見つけた、ほかのアカウントの伸びている投稿（002）。今は本文・検索したキーワード・投稿のURL・なぜ良いかを持ち、投稿のプロンプト（003）に新しい順で入る。本featureで、媒体・元の投稿の投稿日・反応の数字・投稿者・メモを足す。
- **ためて登録する**：参考投稿を1件入れるたびに「この投稿をためて、次の投稿を入力する」を押してため、最後に「〇件を登録する」で、ためた分と入力中の分をまとめて登録すること。ためた投稿は、本文だけでなく、その投稿の欄の値（なぜ良いか・数字・投稿日など）をすべて持つ。
- **鮮度**：元の投稿の投稿日からの日数による区分。0〜30日は「最新」、31〜90日は「現役」、91日以上は「アーカイブ」、投稿日がわからなければ「投稿日不明」。
- **AIに解説してもらう**：参考投稿の本文から、解説のプロンプトを作ってコピーし、外部のAIが返した「なぜ伸びたか」の解説を貼り付けて「なぜ良いか」に入れること。
- **キーワードの案**：課題の内容から、Threadsで検索するとよい言葉の案を外部のAIに出してもらうこと。

## Clarifications

### Session 2026-10-16

- Q:新しく足す「活動の目的・在り方」の5問は、今の「16項目」の進み具合に足すか？ → A:足さない。参考プロダクトと同じく、課題の16項目（必須の扱い）とは別に「目的n/5問」として数える。今の「n/16入力済み」（ホーム・課題の画面・プロンプトの文言）は数え方を変えない（FR-020）。（specifyの中で決めた。参考プロダクトの「必須8/8項目・目的0/5問」の分け方に合わせ、002・003で決めた16の数と、それを使う画面・テストを変えずに済むため）
- Q:区分の名前に「課題①〜③」の番号を付けたままにするか？ → A:外す。画面の名前（課題）と重なって冗長なため。チップは「営業導線」「アカウント」「集客導線」にする（ユーザーの指示。FR-019）。
- Q:課題が長いので、PCでも区分へすぐ移れるようにするか？ → A:スマートフォンと同じく、区分のチップを上部バーの下に固定する。チップに区分ごとの進み具合を出し、今見ている区分を目立たせる（ユーザーの希望に、進み具合と今の区分の表示を足して決めた。FR-018）。
- Q:参考投稿はどう登録するか？ → A:今の「本文を貼り付けて登録する」形に、(1)何件かためてまとめて登録する、(2)AIに「なぜ伸びたか」を解説してもらい「なぜ良いか」に入れる、を足す（参考プロダクトの「リサーチを追加する（テキスト）」に合わせる。US7）。
- Q:画面録画をAIに分析してもらい、答えを貼り付けてまとめて登録する方法も作るか？ → A:今回は作らない（ユーザーの指示。範囲外）。
- Q:参考投稿の入力欄に何を足すか？ → A:反応の数字（いいね・コメント・閲覧数・保存数・リポスト・投稿者のフォロワー数）・投稿者・メモ、媒体、元の投稿の投稿日と鮮度の3つを足す（参考プロダクトの「リサーチを追加する（テキスト）」に合わせる。FR-095〜FR-099）。
- Q:ためてまとめて登録するとき、AIの解説はどうするか？ → A:投稿ごとに持てる。ためる前に解説を「なぜ良いか」に入れておけば、その投稿と一緒にたまる（参考プロダクトは、まとめて保存するときは解説を付けない）。
- Q:数字・媒体・投稿日などは、ためた投稿にどう付けるか？ → A:投稿ごとに持つ。ためるときに、その投稿の欄の値をすべて一緒にためて、欄を空にする（参考プロダクトは本文だけをためて、ほかの欄は全件に同じ値が付く）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 -項目ごとの考えるヒントを見て書ける(Priority: P1)

課題をはじめて開いた人が、各項目の下の「考えるヒント」を開くと、書き方のコツ、悪い例と良い例、3つの問いが読める。例えば「どんな人に投稿を届けたいか」なら、悪い例「20代会社員」と良い例「28歳前後の会社員。仕事は嫌いではないけれど、30歳が近づいてきて、このままでいいのかなと少し焦っている人」が並び、「もっとこんな内容も足してみたら？」で「休日の過ごし方」「よく見ているSNS」などの観点が出る。何を書けばよいか迷わずに、1項目ずつ埋められる。

**Why this priority**:ユーザーが一番に挙げた困りごと（最初は何を入力すればいいかわからない）に直接こたえる。ほかのどの手助けよりも単独で効き、ヒントの文言はほかのストーリー（AIと深掘りする）の材料にもなる。

**Independent Test**:課題の画面で、テキストの15項目と「近い人間性」、目的の5問のそれぞれに考えるヒントがあり、開くとコツ・良い例・悪い例・3つの問いが出ること、閉じた状態が初めの表示であることを確かめる。

**Acceptance Scenarios**:

1. **Given** 課題の画面を開いた人、**When** 項目の下の「💡考えるヒント」を押す、**Then** その項目のコツ、悪い例と良い例（それぞれ1つ以上）、「もっとこんな内容も足してみたら？」の観点2〜3個、「こんな場合はどうだろう？」の問い1つ、「もっと良くするなら、ここを考えてみて」の問い1つが出る。もう一度押すと閉じる。
2. **Given** 課題の画面を開いた直後、**When** 何も押さない、**Then** どの項目の考えるヒントも閉じている（画面が長くならない）。
3. **Given** 「発信テーマの掛け合わせ」の項目、**When** 画面を開く、**Then** 項目名の横に「★特に大事」の印があり、説明に「売りたいもの × ターゲットが共感するテーマ」の考え方と例（保険の営業の人なら「保険」×「子育て」など）が出る。
4. **Given** チームで見せてもらっている人・読むだけのオーナー（013）、**When** 課題の画面を開く、**Then** 考えるヒントは読めるが、入力欄は今のとおり直せない。
5. **Given** スマートフォンの幅（375px）、**When** 考えるヒントを開く、**Then** 横にはみ出さず、入力欄の下に縦に並ぶ。

### User Story 2 -自動チェックと進み具合で、次に書く項目がわかる(Priority: P1)

各項目に「未入力」「短め」「十分」の印が出て、入力すると、保存する前でもその場で変わる。画面の上には、完了の数（十分な項目の数）、要確認の数（短めの項目の数）、目的の5問の数と、「次におすすめ：〇〇」が出て、押すとその項目へ移る。どこから手をつければよいか、どこが薄いかがひと目でわかる。

**Why this priority**:ヒントだけでは「どこまで書けばよいか」「次はどれか」がわからない。進み具合が見えると、続けて埋める動機になる（参考プロダクトの「完了n/16・要確認n件・次におすすめ」）。

**Independent Test**:空の課題で全項目が「未入力」、短い文を入れると「短め」、十分な長さにすると「十分」に、保存しなくても変わること、上の数と「次におすすめ」がそれに合わせて変わり、押すとその項目へ移ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 空の課題、**When** 画面を開く、**Then** 数える項目はすべて「未入力」、上に「完了0/16」「目的0/5問」と「次におすすめ：（表示順で最初の項目）」が出る。
2. **Given** ある項目に、その項目の目安より短い文を入れた、**When** 入力した直後（保存する前）、**Then** その項目は「🟡短め」になり、「出来事・気持ち・具体的な場面を1つ足すと、ぐっと伝わりやすくなります」のような足し方の一言が出る。上の「要確認」の数が1つ増える。
3. **Given** ある項目に、目安以上の文を入れた、**When** 入力した直後、**Then** その項目は「🟢十分」になり、完了の数が1つ増える。
4. **Given** 「次におすすめ：〇〇」が出ている、**When** それを押す、**Then** その項目まで画面が動き、入力欄にカーソルが入る（直せる人のとき）。
5. **Given** 数える16項目と目的の5問がすべて「十分」、**When** 画面を開く、**Then** 「次におすすめ」の代わりに「すべての項目が十分に書けています」と、「全体をAIと整理する」（US4）への案内が出る。
6. **Given** 「近い人間性」（選ぶ項目）、**When** 選んだ・選んでいない、**Then** 選んでいれば「十分」、選んでいなければ「未入力」（「短め」はない）。
7. **Given** 下書きの4項目（プロフィール文・固定投稿①〜③）と「活動の軸」、**When** 画面を開く、**Then** 自動チェックの印は出さず、数にも入れない（任意の項目）。

### User Story 3 -項目ごとにAIと深掘りして完成させる(Priority: P2)

項目の「🤖この項目をAIと深掘りする」を押すと、その項目用のプロンプトがコピーされる。プロンプトには、その項目の問い・考えるヒント・今の入力・ほかの項目の入力（文脈）が入っていて、AIは利用者に質問を重ねたうえで完成版を出す。利用者は、返ってきた完成版を貼り付け欄に貼り、「この内容を反映する」を押すと、その項目の入力欄が置き換わる（保存は今のとおり上部の「保存」）。

**Why this priority**:ヒントを読んでも自分の言葉にできない人が、AIとの対話で言語化できる。参考プロダクトで、運用を代行している人が実際に使っている流れ。プロンプトの作り方はConstitution原則IIIの範囲（コピー＆ペーストだけ）。

**Independent Test**:ある項目で「AIと深掘りする」を押し、コピーされた文に、その項目の問いとヒントと今の入力が入っていることを確かめ、完成版の形の文を貼り付けて「この内容を反映する」を押すと入力欄が置き換わり、未保存の変更になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 直せる人が課題の画面を開いている、**When** 項目の「AIと深掘りする」を押す、**Then** 次の使い方（①コピー ②AIに送って質問に答える ③完成版を貼り付けて反映する）と「プロンプトをコピーする」と貼り付け欄が出る。
2. **Given** 1の状態、**When** 「プロンプトをコピーする」を押す、**Then** その項目のプロンプトがクリップボードに入り、「コピーしました」と出る。プロンプトには、その項目の名前・説明・考えるヒント（コツ・良い例・3つの問い）、今の入力（空なら「未入力」）、ほかの項目の入力済みの内容、AIへの頼み方（一度に1〜2問ずつ質問し、答えをもとに完成版を作る。完成版は決まった目印で囲んで出す）が入る。
3. **Given** AIが目印で囲んだ完成版を含む答えを返した、**When** 答えをまるごと貼り付け欄に貼る、**Then** 目印の内側だけが「反映する内容」として示される。目印がなければ、貼った文の全体を反映する内容として示す。
4. **Given** 3の状態、**When** 「この内容を反映する」を押す、**Then** その項目の入力欄が反映する内容に置き換わり、自動チェックと上の数が変わり、未保存の変更になる（保存するまでサーバーには残らない。「変更を破棄」で戻せる）。
5. **Given** 反映する内容がその項目の文字数の上限を超えている、**When** 貼り付けた、**Then** 「〇文字を超えています。反映した後に短くしてください」と出る。反映はでき、今のとおり上限を超えている間は保存できない。
6. **Given** 貼り付け欄が空か空白だけ、**When** 画面を見る、**Then** 「この内容を反映する」は押せない。
7. **Given** 入力欄にすでに文がある、**When** 「この内容を反映する」を押す、**Then** 確かめずに置き換える（「変更を破棄」と、上の未保存の印で戻せるため）。
8. **Given** 見せてもらっている人・読むだけの人、**When** 課題の画面を開く、**Then** 「AIと深掘りする」は出さない。

### User Story 4 -全体をAIと整理する(Priority: P2)

課題の上の「全体をAIと整理する」を押すと、課題の全項目（目的の5問・活動の軸を含む）をまとめたプロンプトがコピーされる。外部のAIに送ると、項目どうしの重複・矛盾・抜けと、それを埋めるための質問が返ってくる。利用者は、その質問を見て各項目を直す。

**Why this priority**:1項目ずつ書くと、全体として話がつながらない（ターゲットと来てほしくない人が重なる、など）。全体を見直す手段があると、課題の質が上がる。答えを取り込まないので、作るのは小さい。

**Independent Test**:「全体をAIと整理する」を押し、コピーされた文に全項目の名前と入力（空なら未入力）と、重複・矛盾・抜けを質問の形で出すように頼む文が入っていることを確かめる。

**Acceptance Scenarios**:

1. **Given** 課題の画面を開いた人、**When** 「全体をAIと整理する」を押す、**Then** プロンプトがクリップボードに入り、「コピーしました。ChatGPTやClaudeに貼り付けて送ってください」と出る。
2. **Given** 1でコピーした文、**When** 中を見る、**Then** 活動の目的・在り方（5問と活動の軸）、課題①〜③・人柄・その他の16項目の名前と入力（空なら「未入力」）が区分ごとに並び、AIへの頼み方（重複・矛盾・抜けを見つけ、直すための質問を項目ごとに出す。勝手に書き直さない）が入る。下書きの4項目は入れない。
3. **Given** 保存していない変更がある、**When** 「全体をAIと整理する」を押す、**Then** 画面の今の入力（未保存を含む）でプロンプトを作る。
4. **Given** 見せてもらっている人・読むだけの人、**When** 課題の画面を開く、**Then** 「全体をAIと整理する」は出さない。

### User Story 5 -活動の目的・在り方を書き、活動の軸をまとめる(Priority: P2)

課題の先頭に「活動の目的・在り方」の区分があり、目的の5問に答えられる。5問それぞれに考えるヒントと「AIと深掘りする」がある。5問のあとに「活動の軸」（任意）があり、「5問からAIと整理する」を押すと、5問の答えから活動の軸を一言にまとめてもらうプロンプトがコピーされる。返ってきた答えを貼り付けて反映できる。書いた目的と活動の軸は、投稿のプロンプトにも入る。

**Why this priority**:参考プロダクトでは課題の土台として最初に置かれている。何のために発信するかが決まると、ほかの項目（ターゲット・見られ方）が書きやすくなる。ただし、16項目への手助け（US1〜US3）より後でも価値は出る。

**Independent Test**:5問と活動の軸を書いて保存し、読み直して残っていること、「5問からAIと整理する」のプロンプトに5問の答えが入ること、投稿のプロンプトに目的と活動の軸が入ることを確かめる。

**Acceptance Scenarios**:

### User Story 7 -参考投稿を、ためてまとめて・1件ずつ登録する(Priority: P2)

リサーチの画面で「参考投稿を追加」を押すと、本文を貼り付ける欄（今の形）に加えて、媒体、元の投稿の投稿日、分かれば反応の数字・投稿者・メモを入れる欄が出る。見つけた投稿が何件もあるときは、1件入れるたびに「この投稿をためて、次の投稿を入力する」を押す。ためた投稿は欄の上に並び、最後に「〇件を登録する」で、ためた分と入力中の分をまとめて登録する。1件だけなら、そのまま「登録する」。

「なぜ良いか」は自分で書くか、「解説のプロンプトをコピーする」でAIに解説してもらい、返ってきた解説を貼り付けて入れる。ためる前に解説を入れておけば、ためた投稿にも解説が付く。

**Why this priority**:今のリサーチは、参考投稿を1件登録するたびに画面を開き直し、「なぜ良いか」も自分で考える必要があり、初めての人には重い。何件かまとめて登録でき、AIに「なぜ伸びたか」を解説してもらえると、分析つきの参考投稿がそろいやすく、投稿のプロンプト（003）の質が上がる。

**Independent Test**:数字や投稿日の違う本文を3件ためて「3件を登録する」を押すと、3件がそれぞれの値で参考投稿として登録されること、解説のプロンプトに本文・数字・課題が入り、貼り付けた解説が「なぜ良いか」に入ること、一覧に鮮度が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 直せる人がリサーチの画面を開いている、**When** 「参考投稿を追加」を押す、**Then** 本文（必須）・投稿のURL・検索したキーワード・なぜ良いか（今の形）、媒体（初めはThreads）・元の投稿の投稿日（初めは不明）、「投稿の数字・投稿者（分かる場合だけ）」の開閉の欄（いいね・コメント・閲覧数・保存数・リポスト・投稿者のフォロワー数・投稿者・メモ）、「AIに解説してもらう」、「この投稿をためて、次の投稿を入力する」、「登録する」が出る。
2. **Given** 本文を入れた、**When** 「この投稿をためて、次の投稿を入力する」を押す、**Then** その投稿（すべての欄の値）が欄の上の「ためた投稿」に加わり、欄が空になる。検索したキーワードと媒体は、次の投稿のために残す。投稿日は「不明」に戻る。本文が空なら押せない。
3. **Given** ためた投稿がある、**When** 画面を見る、**Then** ためた投稿が本文の書き出し・媒体・鮮度・解説の有無とともに並び、1件ずつ「外す」で取り除ける。登録のボタンは「〇件を登録する」（ためた分＋入力中の本文があれば1件）になる。
4. **Given** ためた投稿が2件、入力中の本文が1件、**When** 「3件を登録する」を押す、**Then** 3件が参考投稿として1回でまとめて登録され、「3件を登録しました」と出て、欄が閉じる。入力中の本文が空なら、ためた2件だけを登録する。
5. **Given** 登録すると参考投稿の上限（200件）を超える、**When** 登録を押す、**Then** 1件も登録せず、ためた投稿も消さずに、「参考投稿はあと〇件まで登録できます」と出る。ためる操作も、上限に届く数までしかできない。
6. **Given** 本文を入れた、**When** 「解説のプロンプトをコピーする」を押す、**Then** 本文・投稿のURL・検索したキーワード・媒体・投稿日・反応の数字・投稿者・メモ（空なら「不明」）、このアカウントの課題、解説の形（型の名前・なぜ伸びたか・誰が反応したか・このアカウントでの使い方・判定）が入った文がコピーされる。本文が空なら押せない。
7. **Given** 6の解説が返ってきた、**When** 解説を貼り付けて「なぜ良いかに入れる」を押す、**Then** なぜ良いかの欄が解説で置き換わる（登録はしない）。
8. **Given** ためた投稿や入力中の本文がある、**When** 欄を閉じる・画面を離れる、**Then** 「登録していない投稿があります。破棄しますか？」と確かめる。
9. **Given** 見せてもらっている人・読むだけの人、**When** リサーチの画面を開く、**Then** 「参考投稿を追加」は今のとおり出ない。
10. **Given** 参考投稿の一覧、**When** 画面を開く、**Then** 各参考投稿に媒体・鮮度（最新・現役・アーカイブ・投稿日不明）、分かっていれば閲覧数といいね、解説の有無（なぜ良いかが空か）が出る。
11. **Given** 鮮度の違う参考投稿がある、**When** 投稿のプロンプト（003）を作る、**Then** 参考投稿は、最新 → 現役 → 投稿日不明 → アーカイブの順に、同じ区分の中は新しく登録した順に入り、各参考投稿に媒体と分かっている数字が添えられる。

### User Story 8 -検索するキーワードの案をAIに出してもらう(Priority: P3)

リサーチの画面のキーワードのタブで「AIにキーワードの案を出してもらう」を押すと、課題の内容からThreadsで検索するとよい言葉を考えてもらうプロンプトがコピーされる。返ってきた案を貼り付けると、1行1つのキーワードとして一覧に出て、選んだものを登録できる。登録したキーワードには「Threadsで検索」があり、押すとThreadsの検索結果が新しいタブで開く。

**Why this priority**:何を検索すればよいかわからないと、リサーチの最初の一歩が出ない（参考プロダクトは課題の言葉からキーワードの候補を出している）。ただし、参考投稿の登録（US7）より後でよい。

**Independent Test**:プロンプトをコピーして課題の内容が入っていることを確かめ、1行1つの答えを貼り付けて選んだキーワードだけが登録されること、「Threadsで検索」がその言葉の検索結果を開くことを確かめる。

**Acceptance Scenarios**:

1. **Given** 直せる人がキーワードのタブを開いている、**When** 「AIにキーワードの案を出してもらう」を押す、**Then** 課題（届けたい人・本音の悩み・なりたい姿・発信テーマの掛け合わせ・投稿ジャンルのうち入力のあるもの）と、出してほしい形（Threadsの検索欄に入れる短い言葉を15〜20個。1行に1つ、「キーワード｜狙い」の形）が入った文がコピーされ、貼り付け欄が出る。
2. **Given** 1の答えを貼り付けた、**When** 貼り付けた直後、**Then** 1行ずつ「キーワード」と「狙い」に分かれ、チェック付きの一覧で出る。すでに登録してあるキーワードと同じものは「登録済み」と出て、チェックを付けられない。
3. **Given** 2の一覧、**When** 「〇件を登録する」を押す、**Then** チェックの付いたものがキーワード（狙い＝今の「狙いのメモ」）として登録される。キーワードの上限（100件）を超えるなら、1件も登録せずに残りの件数を出す。
4. **Given** 登録してあるキーワード、**When** 「Threadsで検索」を押す、**Then** そのキーワードのThreadsの検索結果が新しいタブで開く。
5. **Given** 見せてもらっている人・読むだけの人、**When** キーワードのタブを開く、**Then** 「AIにキーワードの案を出してもらう」は出さない。「Threadsで検索」は使える。

### Edge Cases

- **未保存のまま貼り付けて反映した後に、ほかの人が保存していた**：保存の衝突（008 FR-007）の扱いをそのまま使う。反映した内容は「入力を残して上書きする」で残せる。
- **AIの答えに目印が2組以上ある**：最初の1組の内側を反映する内容にする。
- **AIの答えに目印の始まりだけがある**：目印がないものとして扱い、貼った文の全体を示す（利用者が反映の前に見て、直せる）。
- **貼り付けた文の前後の空白・空行**：反映するときに取り除く。
- **クリップボードに書けない（ブラウザが許さない）**：プロンプトを選べる形で画面に出し、「コピーできませんでした。全体を選んでコピーしてください」と出す（003の投稿のプロンプトのコピーと同じ扱い）。
- **項目の目安の文字数ちょうど**：「十分」とする（目安以上なら十分）。
- **空白・改行だけの入力**：「未入力」とする（002の入力済みの数え方と同じ）。
- **見せてもらっている人がホームを開く**：見せてもらっているアカウントにはホームがない（011）ので、「はじめに読んでほしいこと」は自分のアカウントのホームでだけ出る。
- **目的の5問の答えに、投稿に出したくない個人的な事情が書かれる**：投稿のプロンプトに入るので、目的の区分の説明に「ここに書いた内容は、投稿づくりの材料になります」と出す（ほかの区分と同じ）。
- **ヒントの例文がNGワードに当たる**：ヒントの文はアプリの文言で、Threadsへ投稿されないのでNGワードのチェックはしない。反映した内容から作った投稿は、今のとおり配信の前にチェックされる（Constitution原則I）。
- **古い画面（本featureの前の版）から保存する**：新しい6項目を送らない保存では、新しい6項目の値を消さずに残す。
- **同じ本文を2回ためた・登録済みと同じ本文**：ためるときに「同じ本文の投稿があります」と示すが、ためること・登録することはできる（今の1件の登録も、重なりを止めていない）。
- **ためている途中で、別の画面・別の人が参考投稿を足して上限に近づいた**：登録のときに上限を確かめ直し、超えるなら1件も登録せずに、あと何件かを示す（ためた投稿は残る）。
- **キーワードの案に「#」や番号が付いている**：行頭の番号・記号（「1.」「・」「-」「#」など）と空白を除いて取り出す。

## Requirements *(mandatory)*

### Functional Requirements

**考えるヒント（US1）**

- **FR-001**: System MUST 課題の、数える16項目（テキスト15項目と「近い人間性」）と目的の5問のそれぞれに、考えるヒント（コツ、悪い例と良い例をそれぞれ1つ以上、「もっとこんな内容も足してみたら？」の観点2〜3個、「こんな場合はどうだろう？」の問い1つ、「もっと良くするなら、ここを考えてみて」の問い1つ）を持つ。
- **FR-002**: System MUST 考えるヒントを、項目の入力欄の下に閉じた状態で置き、押すと開閉する。開いたかどうかは保存しない。
- **FR-003**: System MUST 「発信テーマの掛け合わせ」に「★特に大事」の印と、「売りたいもの × ターゲットが共感するテーマ」の考え方を例とともに出す。
- **FR-004**: System MUST 考えるヒントを、直せる人・見せてもらっている人・読むだけの人のだれにも出す。
- **FR-005**: 考えるヒントの文言は、課題の項目の定義（項目名・説明・記入例）と同じ1か所に持ち、画面とプロンプト（US3）が同じものを使わなければならない。

**自動チェックと進み具合（US2）**

- **FR-010**: System MUST テキストの項目ごとに目安の文字数を持ち、入力が空（空白・改行だけを含む）なら「未入力」、目安より短ければ「短め」、目安以上なら「十分」と判定する。
- **FR-011**: System MUST 「近い人間性」は、選んでいれば「十分」、選んでいなければ「未入力」と判定する。
- **FR-012**: System MUST 自動チェックの印を、入力のたびに（保存する前に）変える。
- **FR-013**: System MUST 「短め」の項目に、足し方の一言（項目ごと。なければ共通の「出来事・気持ち・具体的な場面を1つ足すと、ぐっと伝わりやすくなります」）を出す。
- **FR-014**: System MUST 課題の画面の上に、完了の数（数える16項目のうち「十分」の数）/16、要確認の数（16項目と目的の5問のうち「短め」の数）、目的の5問のうち「十分」の数/5を出す。
- **FR-015**: System MUST 「次におすすめ」として、表示の順（活動の目的・在り方 → 課題① → … → その他）で最初の「未入力」の項目を、なければ最初の「短め」の項目を出し、押すとその項目へ移る。すべて「十分」なら、FR-014の数とともに「すべての項目が十分に書けています」と「全体をAIと整理する」への案内を出す。
- **FR-016**: System MUST 下書きの4項目と活動の軸には、自動チェックの印を出さず、数にも入れない。
- **FR-017**: スマートフォンの幅では、上部バーの下の区分のチップの並びに、完了の数と要確認の数を出さなければならない（今の「n/16」の置き換え）。
- **FR-018**: System MUST 区分へ移るチップの並びを、PCの幅でもスマートフォンの幅でも上部バーの下に固定し、画面をスクロールしても見えるようにする。チップには区分ごとの「十分」の数（例：営業導線2/5。すべて十分なら完了の印。下書きは数を出さない）を出し、今見ている区分のチップを目立たせる。押すとその区分の見出しへ移る（見出しが固定の並びに隠れない位置）。
- **FR-019**: System MUST 区分の名前から「課題①〜③」の番号を外す。区分の見出しは「活動の目的・在り方」「営業導線設計」「アカウント設計」「集客導線設計」「人柄（トンマナ）」「その他」「プロフィール・固定投稿（下書き）」、チップは「目的」「営業導線」「アカウント」「集客導線」「人柄」「その他」「下書き」とする（2026-10-16、ユーザーの指示。「課題」が画面の名前と重なって冗長なため）。

**今の数え方との関係**

- **FR-020**: System MUST 002の「入力済み項目数（n/16）」の数え方（空でなければ入力済み）を変えない。ホームのカードの「n/16入力済み」、ホームの「次にやること」の判定、投稿のプロンプト（003）の文言は今のままとする。自動チェックの「完了」は課題の画面の中だけの目安とする。

**AIと深掘りする（US3・US5）**

- **FR-030**: System MUST 直せる人に、数える16項目のうちテキストの15項目と目的の5問のそれぞれに「この項目をAIと深掘りする」を出す。「近い人間性」・下書きの4項目には出さない。
- **FR-031**: System MUST 「AIと深掘りする」を押すと、使い方（3つの手順）、「プロンプトをコピーする」、貼り付け欄、「この内容を反映する」を、その項目の下に出す。同時に開くのは1項目までとする。
- **FR-032**: System MUST 項目のプロンプトに、(1)その項目の名前・説明・考えるヒント、(2)今の入力（未保存を含む。空なら「未入力」）、(3)ほかの数える項目と目的の5問・活動の軸のうち入力のある内容（文脈）、(4)AIへの頼み方（利用者に一度に1〜2問ずつ質問し、答えをもとに、その項目に入れる完成版を作る。完成版は決まった始まりと終わりの目印の行で囲んで出す。事実を作らない）を入れる。
- **FR-033**: System MUST 貼り付けた文に目印の組があれば、最初の組の内側を、なければ貼った文の全体を、前後の空白を除いて「反映する内容」として示す。
- **FR-034**: System MUST 「この内容を反映する」を押すと、その項目の入力欄を反映する内容に置き換え、貼り付け欄を閉じる。保存はしない（未保存の変更になる）。反映する内容が空なら押せない。
- **FR-035**: System MUST 反映する内容がその項目の文字数の上限（002の上限）を超えるとき、超えていることを反映の前に示す。反映はでき、上限を超えている間は今のとおり保存できない。

## Assumptions

- 考えるヒントの文言（21項目分）は、参考プロダクトの考え方（ターゲットの悪い例・良い例など）を参考に、このアプリの言葉で書き起こす。参考プロダクトの文をそのまま写さない（2026-10-02のユーザーの方針「簡単にして取り込む。そのまま写さない」）。文言は計画（plan）で一覧にし、ユーザーが確かめる。
- 目安の文字数は項目ごとに決める（初めの値はおよそ20〜40文字。「成功の指標」など短く書ける項目は小さく）。値は計画で一覧にする。
- AIの答えの目印は、AIのチャット画面でMarkdownの装飾にならない文字の並びにする（003の区切り「@@@」と同じ考え方）。具体の文字は計画で決める。
- 「はじめに読んでほしいこと」を閉じたことは、その端末のブラウザに覚える（サーバーに持たない）。読み物の表示の好みで、なくなっても困らないため。
- 本featureは、Constitution原則Vの「決済をMVPの最後のfeatureとする」の後に、公開の前に足す手助けの機能である。決済の仕組みや料金には触れない。原則Vの文言の扱い（公開前に足す機能の書き方）は、計画のConstitution Checkで確かめる。
- 範囲外（別のfeature）：投稿カテゴリの配分、投稿スタイル（得意な型）、イメージする投稿の例、文体（近い人間性）の複数選択、プロフィール・固定投稿のプロンプト（参考プロダクトの「プロフィール」の画面）、課題の「矛盾」の自動判定（参考プロダクトの「未入力・矛盾n件」。自動チェックは量だけを見る）。リサーチでは、画面録画をAIに分析してもらい答えを貼り付けて登録する方法（2026-10-16、ユーザーの指示で今回は作らない）、参考投稿の判定（○△×）と型への分解・型ライブラリ、ほかのアカウントとの参考投稿の共有（参考プロダクトの「このアカウント専用にする」）、Instagramのフォロワー数と投稿頻度の欄、画像の参考投稿、未分析の参考投稿のまとめての分析、課題の言葉から自動で拾うキーワードの候補（参考プロダクトにはある）。
- アプリはAIを呼び出さず、プロンプトの生成と貼り付けの取り込みだけを行う（Constitution原則III）。
