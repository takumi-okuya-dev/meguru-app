# プロンプトの契約：課題の入力を手助けする

**Feature**：[spec.md](../spec.md) | **調べ**：[research.md](../research.md) R4・R8・R10〜R12・R16 | **元の契約**：[003 prompt-template.md](../../003-prompt-bulk-register/contracts/prompt-template.md)

`{…}`は差し込む値。`［…］`は条件で入る行。文面は日本語で、前置き・Markdownの装飾を避ける（コピーで崩れないように）。どのプロンプトも、アプリはAIを呼び出さない（Constitution原則III）。

## 1. 投稿のプロンプト（`buildPrompt`。003を直す）

### 件数（1か所で求め、全体で同じ値を使う。FR-118）

| 値 | 求め方 |
|---|---|
| `promoCount` | 宣伝内容が1件以上で割合が1%以上なら`max(1, round(count×割合/100))`、それ以外は0 |
| `normalCount` | `count − promoCount` |
| `patternCount` | 入った参考投稿が1件以上なら`min(count, max(3, ceil(入った件数×1.2)))`、0件なら0 |
| `profileInviteCount` | 下書き（プロフィール文・固定投稿①〜③）のどれかに入力があれば`max(1, round(count/10))`、なければ0 |
| `[short, medium, long]` | `splitLengthMix(count, [shortRatio, mediumRatio, longRatio])`（R11） |

### 節の順と、足す・変える文

1. 冒頭：`以下の情報をもとに、Threadsに投稿する文章を{count}件作ってください。`（今のまま）
2. **最初に確認すること**（新規。FR-110）

```text
【最初に確認すること(最重要)】
① 投稿は、ちょうど{count}件［（うち宣伝投稿{promoCount}件・通常投稿{normalCount}件）］。② 投稿と投稿の間は「@@@」だけの行で区切る。③ 1件は{target}文字以内(500文字は絶対に超えない)。
【ルールがぶつかったときの優先順位】出力のルール ＞ 宣伝投稿の件数 ＞ CORE RULES・NGワード・事実を作らない ＞ 戦略設計(人柄・文体・話題) ＞ 参考情報(リサーチ・投稿ストックの下書き)
```

3. 話者・CORE RULES：今のまま。
4. **アカウントの戦略設計**：見出しの次に指示を足す（FR-111）。項目の並びと見出しは今のまま（16項目）。

```text
ここに書かれているのは、本人が決めた方針です。要約したり一部だけ使ったりせず、言葉づかい・禁止事項・例文・箇条書きのニュアンスまで忠実に反映すること。「来てほしくない人」やCORE RULESと食い違う内容は書かないこと。文体・人柄の指定が、下の共通ルール(語尾・改行など)と食い違うときは、文体・人柄を優先する(ただし、文字数・区切り「@@@」・NGワード・CORE RULESは必ず守る)。
```

   ［発信テーマの掛け合わせ・投稿ジャンル・本音の悩み・なりたい姿のどれかがあるとき］節の最後に（FR-112）：

```text
【話題の配分(必ず守る)】
上の「発信テーマの掛け合わせ」「投稿ジャンル」「ターゲットの本音の悩み」「ターゲットのなりたい姿」に出てくる主な話題を、{count}件の中に、すべて最低1件ずつ入れること。1つの話題が、全体の4割を超えないようにすること。投稿ジャンルに割合や件数が書かれている場合は、その配分どおりにすること。
```

5. **活動の目的・在り方**（新規。入力があるとき。FR-053）

```text
■活動の目的・在り方(本人の言葉。投稿の方向性・判断基準として踏まえ、これと矛盾する内容は書かないこと)
- 活動を始めたきっかけ: {purposeOrigin}
- 活動を通して自分がなりたい姿: {purposeSelf}
- 関わった人にどうなってほしいか: {purposeOthers}
- 活動の先に作りたい未来: {purposeFuture}
- 大切にしたい在り方・判断基準: {purposeStance}
- 活動の軸: {activityAxis}
```

   入力のない行は入れない。

6. **現在のプロフィールと固定投稿**（新規。下書きに入力があるとき。FR-113）

```text
■現在のプロフィールと固定投稿(このアカウントの軸。すべての投稿の方向性の基準)
- プロフィール文:
{profileBioDraft}
- 固定投稿①:
{pinnedPostDraft1}
【使い方】
・プロフィールが示す「誰に・何を・どんな価値を届けるか」を軸にして、各投稿を書く。プロフィールの約束と関係ない話題、トーンが食い違う話題は作らない。文章そのものはコピーしない。
・{count}件のうち{profileInviteCount}件は、文末で、プロフィールや固定投稿へ自然に誘う一言を添える(毎回違う言い方にする。URLは書かない。宣伝投稿とは別の投稿にする)。
```

7. **今回組み込む宣伝内容**：見出しを件数の明示に変え、各行にタイトルと期限を足し、書き方を足す（FR-114・FR-119b）。

```text
■今回組み込む宣伝内容({count}件のうち、宣伝投稿はちょうど{promoCount}件。残りの{normalCount}件は宣伝の行動喚起を入れない通常投稿にすること)
［今の並びと偏りの指示］
同じ宣伝内容を続けて扱わないこと。
1. 【{title}】(掲載期限: {validUntil}・残り{n}日 ／ 期限なし) {content}(届けたい相手: …) / 行動喚起: {cta} / 専用URL: {linkedUrl}
…
【宣伝投稿の書き方(宣伝内容を扱う{promoCount}件に必ず適用する)】
・構成: ①思わず目が止まる1行目(いきなり告知から始めない) → ②読者が自分ごとになる一言 → ③中身(日時・場所・料金・内容は、上の宣伝内容に書かれている事実だけを使う) → ④読者が次にすることを伝える誘導の一言。
・1〜2文ごとに改行し、長い文を作らない。「ぜひご参加ください」「お待ちしております」のような広告の定型文は使わない。
・行動喚起は、そのまま写さず本人の言葉に言い換え、投稿ごとに違う言い回しにする。行動喚起が空の宣伝内容は、コメント・保存などのどれか1つだけを軽く促す。
・同じ宣伝内容でも、切り口を変えて別の投稿にする。
```

   残り日数は今日（日本時間）から期限の日までの日数（当日は0日）。

8. 却下・反応が低かった投稿：今のまま。
9. **リサーチ**：参考投稿の並びと書き方、型の件数を変える（FR-115）。

```text
■リサーチで見つけた「伸びている投稿」とその分析(型・構成の最重要参考資料)
［手順1〜3は今のまま］
手順4: {count}件のうち、最低でも{patternCount}件はこの手順で明確に「型」を踏襲した投稿にすること。同じ参考投稿から何度も型を借りず、なるべく異なる投稿から1件ずつ借りること。新しい参考投稿を優先すること。

1. 元の投稿(参考: 内容はコピーしない) [{鮮度}・{媒体(Threads以外)}・閲覧 {views}・いいね {likes}・コメント {replies}・フォロワー {followers}]
   > {本文の1行目}
   > {本文の2行目}
   なぜ良いか: {whyGood ／ (分析メモなし。フック・構成・感情の動かし方を自分で読み取ること)}
［検索語があれば今のまま [検索語:…] を角かっこの中に足す］
```

   鮮度は「最新」「現役」「アーカイブ」「投稿日不明」。わからない数字は書かない。メモは入れない。

10. 重複防止：今のまま。
11. **短文・中文・長文**（FR-119a）：

```text
■短文・中文・長文は「長さ」だけでなく「役割」も変える(必ず守ること)
{count}件の内訳: 短文{short}件・中文{medium}件・長文{long}件(割合は{shortRatio}:{mediumRatio}:{longRatio})。同じ役割の投稿を3件以上連続させないこと。
- 短文(だいたい{shortLength}文字({shortLength×0.8}〜{min(target, shortLength×1.2)}文字)): ［今の役割の説明］
- 中文(だいたい{mediumLength}文字(…)): ［今の役割の説明］
- 長文(だいたい{longLength}文字(…)): ［今の役割の説明］
［今のフックの指示］
```

   件数が0件の種類の行は入れない。

12. **文字数について**：`150`の固定をやめ、`{target}`から作る（目標×0.85前後をめざす、超えても`min(500, target×1.35)`まで、500文字は絶対に超えない、絵文字の数え方の説明は今のまま）。
13. **出力形式**：先頭に足す（FR-119）。

```text
- 出力全体(全{count}件と「@@@」の行)を、1つのコードブロック(バッククォート3つ「```」で始まり「```」で終わる枠)の中に入れること。コードブロックの外には、何も書かない。理由: コピーしたときに、改行と「@@@」の行が崩れずに残るため。コードブロックは出力全体で1つだけにし、投稿ごとに分けないこと。
```

   最後の「貼り付け欄に1回で貼り付けてください」の案内は、「投稿をつくる」の画面の名前に合わせる。

14. **出力する前の最終チェック**（新規。FR-116）：材料のある行だけ。

```text
■出力する前の最終チェック(次を1つずつ確認して、足りないところは直してから出力すること)
□ 投稿は、ちょうど{count}件になっている(区切り「@@@」は{count−1}個)。短文{short}件・中文{medium}件・長文{long}件。
□ 1件ずつ、{target}文字以内(500文字は絶対に超えない)。
［課題］□ 上の「戦略設計」［と「活動の目的・在り方」］の内容が、投稿に表れている。
［話題の配分］□ 「発信テーマ」「投稿ジャンル」などに書かれた話題が、すべて最低1件ずつ入っている。
［宣伝］□ 宣伝投稿がちょうど{promoCount}件あり、そのすべてに、投稿ごとに違う言い回しの誘導の一言がある。
［リサーチ］□ リサーチの「型」を使った投稿が、少なくとも{patternCount}件ある。
［下書き］□ プロフィールや固定投稿へ誘う投稿が{profileInviteCount}件ある(宣伝投稿とは別)。
□ 同じ内容・同じ書き出しの投稿がない。ネガティブなまま終わる投稿がない。
```

### 2つに分けるとき（`parts`。FR-152）

- 1つ目：`これから、Threadsに投稿する文章を{count}件作ってもらうための情報を、2つのメッセージに分けて送ります(長いため)。`、`【1/2つ目】このメッセージは、全部で2つのうちの1つ目です。まだ投稿は作らないでください。内容を読んで覚えたら、「1つ目、受け取りました。続きをどうぞ」とだけ返信して、次のメッセージを待ってください。`、最初に確認すること、節2〜6、最後に`(ここまでが1つ目です。続きを送るまで、投稿は作らず待っていてください)`。
- 2つ目：`【2/2つ目(最後)】これで全部です。1つ目に送った内容と、この内容を、すべて合わせて読んで、Threadsに投稿する文章を{count}件作ってください。`、最初に確認すること、節7〜14。

## 2. AIと深掘りする（`buildDeepenPrompt(key, values)`。FR-032・FR-037）

```text
あなたは、SNS発信の設計を手伝う聞き役です。これから、私のThreadsアカウントの設計の1つの項目「{label}」を、一緒に深掘りして完成させてください。

■この項目で考えること
{description}

■考えるヒント
コツ: {tip}
悪い例: {bad}
良い例: {good}
足してみたい観点: {moreを「・」でつなぐ}
こんな場合はどうだろう？: {whatIf}
もっと良くするなら: {better}

■今の私の答え
{今の入力 ／ 未入力}

■ほかの項目に書いたこと(参考。この項目と食い違わないように)
- {ほかの項目名}: {入力}
…

■進め方
1. 私の今の答えとヒントをもとに、足りないところを、一度に1〜2問ずつ質問してください。質問は、答えやすい具体的な問いにしてください。
2. 私が答えたら、必要なら次の質問をしてください(3〜5往復を目安に)。
3. 十分に材料がそろったら、この項目に入れる完成版を、私の言葉づかいを生かして書いてください。私が言っていない事実・数字・エピソードは作らないでください。
4. 完成版は、次の2行のあいだに書いてください。目印の行は、そのまま書き写してください。
【完成版ここから】
(完成版)
【完成版ここまで】
```

- 「発信テーマの掛け合わせ」では、進め方の3を「掛け合わせの候補を3つ以上出し、それぞれの『集まりそうな人』を添えて、私と相談して1つに決めてから、完成版を書いてください」に替える。
- ほかの項目は、入力のある数える項目・目的の5問・活動の軸（下書きを除く）。

```text
あなたは、SNS発信の設計を見直す相談相手です。下は、私のThreadsアカウントの設計です。項目どうしの重複・矛盾・抜けを見つけて、直すための質問をしてください。

■活動の目的・在り方
- {問い}: {答え ／ 未入力}
…
■営業導線設計
- {項目名}: {入力 ／ 未入力}
…(アカウント設計・集客導線設計・人柄・その他も同じ)

■お願い
1. 重複している・食い違っている・足りないと思う所を、項目の名前を挙げて、項目ごとに質問の形で出してください(例: 「ターゲット」と「来てほしくない人」が重なっていませんか？)。
2. 項目を勝手に書き直さないでください。私が答えを考えるための質問だけにしてください。
3. 大事な順に、多くても10問にしてください。
```

## 5. 参考投稿の解説（`buildExplainPrompt`。FR-086・FR-101）

```text
あなたは、Threads運用・コピーライティング・消費者心理に詳しい、SNSマーケティングの専門家です。
ほかのアカウントで反応が良かったThreadsの投稿［を{n}件］分析し、「なぜ伸びたのか」を、読んだ人がすぐ理解できる形で説明してください。最終目的は、投稿者だから伸びた要素を取り除いて、別のテーマ・別のアカウントでも使える「再現できる型」にすることです。

■分析する投稿
［まとめてのとき］【ID:{shortId}】
本文:
{本文}
媒体: {媒体} ／ 元の投稿の投稿日: {日付・〇以内・不明} ／ 投稿者: {投稿者 ／ 不明} ／ 投稿者のフォロワー数: {n ／ 不明}
閲覧数: {n ／ 不明} ／ いいね: … ／ コメント: … ／ リポスト: … ／ 保存: … ／ 検索したキーワード: … ／ 登録者のメモ: …
［まとめてのとき］@@@
［次の投稿…］

■私たちのアカウント(このアカウントで使えるかを判断する材料)
［活動の目的・最終的に取ってほしい行動・届けたい人・本音の悩み・発信テーマの掛け合わせ・来てほしくない人のうち、入力のあるもの］

■判断の軸
・一番バズった投稿が、一番参考になる投稿とは考えない。集めたい人に届くか × 再現できるか × 反応の質で判断する。
・愚痴・批判・炎上・あおりなど、ネガティブな気持ちだけで伸びた投稿は、数字が大きくても型の対象にしない(最後に前向きに変わる投稿は参考にしてよい)。

■出力の形(前置きなしで、この見出しのまま書く。1件{まとめて: 400〜600字 ／ 1件: 800字程度})
［まとめてのとき］【ID:{shortId}】(上と同じIDをそのまま書き写す)
【型の名前】「○○ × ○○型」の1行
【なぜ伸びたか】重要な順に3つ。「何が(フック・言葉・構成) → 誰に → どう作用して → どんな反応になったか」を1〜2文で。
【誰が反応したか】年代・状況・そのとき感じていたことを2文以内(根拠がなければ「不明」)。
【このアカウントでの使い方】この型を、私たちのアカウントでどう使うかを1〜2文。
【判定】○ 真似してOK ／ △ 条件付きでOK ／ × 真似しない のどれか1つと、理由を1文。
［まとめてのとき］投稿と投稿のあいだは、「@@@」だけの行で区切る。

■ルール
・数字・実績・事実を作らない。分からないことは「不明」と書く。
・投稿の文章をコピーした言い換えで終わらせず、反応が生まれた構造を書く。
```

- まとめての取り出し（`parseExplanations`）は、`@@@`の行で分け、各ブロックの`【ID:〜】`の行を除いた残りを解説にする（R8）。1件のときは貼った文の全体（前後の空白を除く）を「なぜ良いか」に入れる。

## 6. キーワードの案（`buildKeywordIdeaPrompt`。FR-090）

```text
あなたは、Threadsのリサーチを手伝う相談相手です。下の私のアカウントの設計をもとに、Threadsの検索欄に入れると「集めたい人に届いて伸びている投稿」が見つかりそうな言葉の案を出してください。

■私のアカウント
［届けたい人・本音の悩み・なりたい姿・発信テーマの掛け合わせ・投稿ジャンルのうち、入力のあるもの］

■お願い
・短い言葉(1〜3語)を15〜20個。集めたい人が使いそうな言葉・その人の気持ちに近い言葉を中心にする。
・1行に1つ、「キーワード｜狙い」の形で書く(例: 20代後半 友達｜社会人になって友達が増えない人の本音を探す)。
・前置き・番号・見出しは書かない。
```
