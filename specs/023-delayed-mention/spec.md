# Feature Specification：時間差のメンション

**Feature Branch**: `feature/023-delayed-mention`

**Created**: 2026-11-05

**Status**: Draft

**Input**: 2026-11-05に、ユーザーが「拡散してほしい投稿に、メンション（@ほかのユーザー）できる機能がほしい」「時間差でメンションしたい」と挙げた（[docs/next-features.md](../../docs/next-features.md) §K）。投稿してから時間をおいて、自分の投稿への返信で @ユーザー名 を付ける。

**Source**: [docs/next-features.md](../../docs/next-features.md) §K、[004のspec](../004-review-approval/spec.md)（承認・NGワード）、[005のspec](../005-auto-post/spec.md)（自動投稿・投稿の時刻）、[010のspec](../010-token-connect/spec.md)（トークンを貼ってつなぐ・権限の警告）、[019のspec](../019-feature-switches/spec.md)（機能のまとまり「自動投稿」）、[Constitution](../../.specify/memory/constitution.md) 4.3.0 原則I（NGワード）・II（人間承認ゲート）・V（判定の1か所）。

## Clarifications

### Session 2026-11-05

- Q: メンションする人はどう決めるか？ → A: アカウントごとに「メンションする人」の一覧を登録しておき、投稿ごとにその中から選ぶ。
- Q: 時間差のメンションを付ける投稿は、いつ・どう決めるか？ → A: 投稿ストックで、承認するときに投稿ごとに付ける。返信の文も一緒に確かめて承認する。
- Q: 時間差はどう決めるか？ → A: アカウントで1つ決める（例：投稿の30分後）。投稿ごとには変えない。
- Q: 返信の文はどうするか？ → A: アカウントで決めた「ひとこと」の後ろに @ユーザー名 を付ける。投稿ごとに直せる。
- Q: 画面の移り変わりを減らせるか？（モックを見て） → A: ワンクリックで付けられるようにする。メンションする人に「いつも付ける」の印を付けておき、下書きのカードの「メンションを付ける」を1回押すと、その人たちで付く。人の入れ替えはカードの中の丸いボタンを押すだけ、文はカードの中で直す（ポップアップは開かない）。選んだ下書きにまとめて付けることもできる。
- Q: 投稿済みの投稿にも付けられるか？ → A: 付けられる。投稿済みの一覧のカードで「メンションを付ける」を押し、人と文を確かめて「返信する」を押すと、次の処理の回（数分以内）に返信を出す（もう時間がたっているので、時間差は待たない）。「返信する」を押すことを、返信の文の承認とする（原則II）。

## 用語

- **メンションする人**：アカウントごとに登録する、Threadsのユーザー名と呼び名（例：@minato_place・港の運営）。拡散に協力してくれる人を想定する。
- **時間差のメンション**：投稿が公開されてから、決めた時間がたったあとに、その投稿への自分の返信として出す文。文は「ひとこと」と、選んだ人の @ユーザー名 でできている。
- **ひとこと**：返信の文の初めに置く、アカウントで決める文（例：「よければシェアお願いします🙏」）。
- **時間差**：投稿が公開されてから、返信を出すまでの時間。アカウントで1つ決める。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 承認するときに、時間差のメンションを付ける (Priority: P1)

オーナー（または承認できる担当の人）が投稿ストックの下書きのカードで「メンションを付ける」を1回押すと、「いつも付ける」の人で時間差のメンションが付く。カードの中で、人の入れ替え（丸いボタンを押す）と返信の文（ひとこと＋@ユーザー名）を確かめ、必要なら直して、下書きと一緒に承認する。投稿が公開されてから決めた時間がたつと、その投稿への返信として文が出る。

**Why this priority**: ユーザーが求めている中心。拡散に協力してくれる人へ、投稿の直後ではなく少し時間をおいて知らせる。

**Independent Test**: メンションする人を2人登録して「いつも付ける」にし、時間差を30分にしたアカウントで、下書きのカードの「メンションを付ける」を1回押して承認する。下書きが投稿されて30分たったあと（自動投稿の次の処理の回）、その投稿への返信として「ひとこと @a @b」が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** メンションする人が登録してあるアカウントの「要確認」の下書き、**When** カードの「メンションを付ける」を押す、**Then** 画面を移らずに、カードの中に「投稿の30分後にメンション」と、一覧の人の丸いボタン（「いつも付ける」の人は選ばれた状態）と、返信の文の案（ひとこと＋選んだ人の @ユーザー名）が出る。丸いボタンを押すと、その人が入る・外れ、文も変わる。
1a. **Given** 「要確認」の下書きを複数選んだ、**When** 選んだときに出る操作の「メンションを付ける」を押す、**Then** 選んだ下書きのすべてに、「いつも付ける」の人で付く（24時間に1回までの人は外れる）。
2. **Given** 選んだ状態、**When** 下書きを承認する、**Then** 下書きと返信の文が一緒に承認される。返信の文にNGワードがあれば承認できない（下書きと同じ扱い）。
3. **Given** 承認した下書きが投稿された、**When** 時間差がたった最初の処理の回、**Then** その投稿への返信として文が出る。投稿ストックの投稿済みの一覧に「メンション済み」と、返信を出した日時が出る。
4. **Given** まだ返信を出していない投稿、**When** 「メンションをやめる」を押す、**Then** 返信は出ない。
5. **Given** 承認したあと・投稿の前に、返信の文を直したい、**When** 承認済みの下書きを開く、**Then** 下書きの本文と同じく直せる（直すと承認し直しになる今の決まりに従う）。

### User Story 2 - メンションする人・ひとこと・時間差を決める (Priority: P1)

オーナーが「このアカウントの設定」で、メンションする人（ユーザー名と呼び名）を登録し、ひとことと時間差を決める。

**Why this priority**: US1の前提。一覧から選ぶので打ち間違いが減り、同じ人へのメンションの回数も数えられる。

**Independent Test**: 設定で、メンションする人を3人足し、1人を消し、1人を「いつも付ける」にし、ひとことを「よければシェアお願いします」、時間差を1時間にして保存する。投稿ストックで「メンションを付ける」を押すと、2人の丸いボタンが並んで「いつも付ける」の1人が選ばれ、予定が「投稿の1時間後」になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 設定の「時間差のメンション」、**When** ユーザー名（@の後ろ）と呼び名を入れて足す、**Then** 一覧に並ぶ。ユーザー名の形が違う（使えない文字・長すぎる）・同じ人がもういる・自分のアカウントのときは足せない。
2. **Given** 一覧、**When** 消す、**Then** 一覧から消える。その人を選んで承認済みで、まだ返信を出していない投稿があるときは、消す前に件数を出して確かめる。消すと、その投稿の返信からその人が外れる（ほかの人が残っていれば、残りの人で返信する）。
3. **Given** ひとことと時間差、**When** 保存する、**Then** 次に「時間差でメンション」を付ける投稿から使われる。もう承認した投稿の返信の文・予定は変わらない。
4. **Given** ひとこと、**When** NGワードを含む、**Then** 保存できない。

### User Story 3 - 出せなかったときに分かる (Priority: P2)

返信を出せなかったとき（投稿が消えた・つなぎ直しが要る・返信の権限がない・Threadsが受け付けない）、投稿ストックの投稿済みの一覧に、その理由が出る。

**Why this priority**: 自動で出るものなので、出なかったことが分からないと、協力してくれる人に知らせられない。

**Independent Test**: 返信の権限のないトークンでつないだアカウントで、時間差のメンションを付けた投稿が投稿されたあと、返信の時刻を過ぎても返信が出ず、投稿済みの一覧に「出せませんでした（返信の権限がありません）」と出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 返信を出す時刻に、投稿がThreadsで消えている、**When** 処理の回、**Then** 返信は出さず、「出せませんでした（投稿が見つかりません）」と出る。
2. **Given** アカウントのつなぎ直しが要る、**When** 処理の回、**Then** 返信は出さずに待ち、つなぎ直したあとの処理の回で出す。ただし投稿から24時間を過ぎたら出さず、「出せませんでした（時間が過ぎました）」と出る。
3. **Given** トークンに返信の権限がない、**When** つなぐとき・トークンを確かめるとき、**Then** 今の「反応数の権限がない」と同じ形の警告が出て、「時間差でメンション」は選べず、案内（トークンを作り直すとき返信の権限を付ける）が出る。
4. **Given** 一時的な失敗（通信・Threadsの一時的な不調）、**When** 処理の回、**Then** 次の回にやり直す。3回失敗したら「出せませんでした」と出す。

### User Story 4 - 投稿済みの投稿にあとからメンションする (Priority: P2)

オーナー（または承認できる担当の人）が投稿ストックの投稿済みの一覧で、メンションを付けていない投稿のカードの「メンションを付ける」を押す。カードの中に、「いつも付ける」の人が選ばれた状態の丸いボタンと返信の文が出る。確かめて「返信する」を押すと、数分以内にその投稿への返信が出る。

**Why this priority**: 承認のときに付け忘れた投稿や、あとから伸びてきた投稿にも、協力してくれる人へ知らせたい。

**Independent Test**: メンションを付けずに投稿した投稿のカードで「メンションを付ける」→「返信する」を押し、次の処理の回にその投稿への返信が出て、カードが「返信済み」になることを確かめる。

**Acceptance Scenarios**:

1. **Given** アプリから投稿した、メンションを付けていない投稿（投稿から7日以内。`[ASSUMPTION]`）、**When** 「メンションを付ける」を押す、**Then** 画面を移らずに、カードの中に「今からメンションする」と、人の丸いボタン・返信の文・「返信する」が出る。
2. **Given** 人と文を確かめた、**When** 「返信する」を押す、**Then** 返信の文にNGワードがなければ、次の処理の回に返信が出る。NGワードがあれば押せない。
3. **Given** 時間差のメンションがもう付いている投稿（予定・済み）、**When** 見る、**Then** 「メンションを付ける」は出ない（1つの投稿に1つまで）。

---

### Edge Cases

- 下書きを却下・削除した：時間差のメンションも一緒になくなる。
- 投稿に失敗した（005の投稿の失敗）：返信は出さない。
- 自動投稿のまとまりがOFFになった（019）：まだ出していない返信は出さない。ONに戻したとき、投稿から24時間以内なら出す。
- 同じ人へのメンションが多すぎる：同じ人は、そのアカウントから24時間に1回まで（`[ASSUMPTION]`）。承認のときに、24時間以内に返信の予定・済みがある人は選べず、理由が出る。
- 1つの返信で選べる人は5人まで（`[ASSUMPTION]`）。返信の文は500文字まで（Threadsの上限）。
- 相手がメンションを受けない設定：返信は出るが、相手に通知されないことがある（Threadsの決まり。画面の説明に書く）。
- 自分の返信で、その投稿の返信の数が1増える：パフォーマンス（006）・解析（022）の返信の数に入る。解析の返信率では、時間差のメンションの返信は数えない（`[ASSUMPTION]`。取り込んだ返信の数から1を引く）。パフォーマンスの数はThreadsの値のまま。
- 投稿の時刻と返信の時刻：自動投稿の処理の回（今は5分ごと）で出すので、返信は決めた時間差から最大で処理の間隔ぶん遅れる。
- 見せてもらっている人（チーム）：時間差のメンションの設定も、付けることもできない。

## Requirements *(mandatory)*

### Functional Requirements

#### メンションする人・ひとこと・時間差（US2）

- **FR-001**: Users MUST be able to アカウントごとに、メンションする人（Threadsのユーザー名と呼び名）を20人まで（`[ASSUMPTION]`）登録・削除し、人ごとに「いつも付ける」を切り替える。ユーザー名はThreadsのユーザー名の形（英数字・ピリオド・アンダースコア、30文字まで）で、@は付けても付けなくてもよい（保存は@なし）。同じユーザー名・自分のアカウントのユーザー名は足せない。
- **FR-002**: Users MUST be able to ひとこと（100文字まで。空でもよい）と時間差（10分・30分・1時間・3時間・6時間・12時間・24時間から選ぶ。初めは30分）をアカウントごとに決める。
- **FR-003**: System MUST ひとことにNGワードがあれば保存させない（原則I）。
- **FR-004**: System MUST 一覧の人を消すとき、その人を含み、まだ出していない返信があれば件数を出して確かめ、消したらその返信から外す（ほかの人が残っていなければ、その返信は出さない）。
- **FR-005**: System MUST 設定を変えても、もう承認した返信の文と予定を変えない。

#### 承認のときに付ける（US1）

- **FR-010**: Users MUST be able to 投稿ストックの「要確認」の下書きのカードで、「メンションを付ける」を1回押して、「いつも付ける」の人（5人まで。24時間に1回までの人は除く）で時間差のメンションを付ける。画面を移らず、カードの中に、一覧の人の丸いボタン・返信の文の案（ひとこと、改行、選んだ人の @ユーザー名 を半角スペースでつないだもの）・予定（「投稿の30分後」）が出る。丸いボタンを押して、1〜5人の範囲で入れ替える。「いつも付ける」の人がいなければ、だれも選ばれていない状態で出る。
- **FR-010a**: Users MUST be able to 選んだ複数の下書きに、まとめて「メンションを付ける」（「いつも付ける」の人で）。
- **FR-011**: Users MUST be able to 返信の文を、承認する前にカードの中で直す（500文字まで。ポップアップは開かない）。選んだ人の @ユーザー名 を消したら、その人は外れたものとして扱う（文の中の @ユーザー名 が一覧にない人でも、そのまま出す）。
- **FR-012**: System MUST 返信の文を、下書きと一緒に承認する。返信の文にNGワードがあれば、下書きと同じく承認できない（原則I・II）。一括承認では、時間差のメンションを付けた下書きも、付けていない下書きと同じく承認できる。
- **FR-013**: System MUST 承認したあとに返信の文を直したら、下書きの本文を直したときと同じく、承認し直しにする（004の決まり）。
- **FR-014**: System MUST 同じ人を、そのアカウントから24時間に1回までしか選べないようにする（返信の予定・済みの時刻で数える）。選べない人には理由を出す。
- **FR-015**: Users MUST be able to まだ出していない時間差のメンションを、投稿の前・後に「やめる」。
- **FR-016**: Users MUST be able to 投稿済みの一覧で、アプリから投稿し、時間差のメンションの付いていない投稿（投稿から7日以内。`[ASSUMPTION]`）に、「メンションを付ける」を押して、FR-010・FR-011と同じくカードの中で人と文を決め、「返信する」で返信を頼む。返信は次の処理の回に出す（時間差は待たない）。「返信する」を押すことを返信の文の承認とし、NGワードがあれば押せない（原則I・II）。1つの投稿に時間差のメンションは1つまで。

#### 返信を出す（US1・US3）

- **FR-020**: System MUST 投稿が公開されてから時間差がたったあとの、最初の自動投稿の処理の回に、その投稿への返信として文を出す（投稿済みの投稿に付けたとき（FR-016）は、「返信する」を押したあとの最初の処理の回）。返信の時刻は、承認したときの時間差で決める（あとから設定を変えても変わらない）。
- **FR-021**: System MUST 出す直前に、もう一度NGワードを確かめる（原則I。005の投稿の直前の確かめと同じ）。NGワードがあれば出さず、「出せませんでした（NGワード）」とする。
- **FR-022**: System MUST 二重に出さない（同じ投稿に同じ返信を2回出さない。005の二重投稿の防ぎ方と同じ考え方）。
- **FR-023**: System MUST 次のときは返信を出さず、理由を残す：投稿が見つからない・投稿に失敗した・下書きを消した・返信の権限がない・投稿から24時間を過ぎた・NGワード・一時的な失敗が3回続いた。つなぎ直しが要る・自動投稿のまとまりがOFFのときは、24時間までは待つ。
- **FR-024**: System MUST 投稿ストックの投稿済みの一覧で、時間差のメンションの状態（予定の時刻・済み（日時）・やめた・出せなかった（理由））を見せる。

#### 権限と範囲

- **FR-030**: System MUST トークンに返信の権限があるかを、つなぐとき・トークンを確かめるときに調べ、ないときは今の権限の警告と同じ形で知らせ、「時間差でメンション」を選べないようにする（010）。
- **FR-031**: System MUST メンションする人・ひとこと・時間差の設定は「設定」の権限（オーナー）、付ける・直す・やめるは「承認」の権限（004・011）で行えるようにする。判定は今の判定の1か所を通す（原則V）。見せてもらっている人には出さない。
- **FR-032**: System MUST 機能のまとまり「自動投稿」の中に置く（019）。自動投稿が使えない人には出さない。
- **FR-033**: System MUST 解析（022）の返信率・傾向で、時間差のメンションの返信を数えない（`[ASSUMPTION]`）。パフォーマンス（006）の返信の数は、Threadsの画面と同じ値のまま変えない（plan research.md R7）。
- **FR-034**: System MUST 画面の文は短くし、説明（相手がメンションを受けない設定だと通知されないこと・同じ人は24時間に1回まで・返信は処理の回で出すので数分遅れること）は閉じたトグルに箇条書きで置く（docs/ui-design.md）。
- **FR-035**: System MUST スマートフォンの幅でも、横にスクロールせずに選べて確かめられるようにする。

### Key Entities *(include if feature involves data)*

- **メンションする人**：アカウントごと。ユーザー名・呼び名・「いつも付ける」・登録した日時。
- **時間差のメンションの設定**：アカウントごと。ひとこと・時間差。
- **時間差のメンション**：下書きごとに0か1つ。返信の文・選んだ人・承認したときの時間差・状態（予定・済み・やめた・出せなかった）・予定の時刻・出した日時・Threadsの返信の識別子・出せなかった理由・やり直しの回数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 時間差のメンションを付けて承認した投稿の返信が、投稿から時間差＋処理の間隔（今は5分）以内に出る。
- **SC-002**: 承認していない返信の文、NGワードを含む返信の文が、1つもThreadsに出ない。
- **SC-003**: 同じ投稿に、時間差のメンションの返信が2回出ることがない。
- **SC-004**: 同じ人が、1つのアカウントから24時間に2回以上メンションされない。
- **SC-005**: 返信を出せなかったとき、投稿ストックの投稿済みの一覧で、その理由が分かる。
- **SC-007**: 「いつも付ける」の人を決めてあれば、下書き1件に時間差のメンションを付けるのが1回の操作で済み、画面を移らない。
- **SC-006**: 承認の権限のない人・関わりのない人・自動投稿が使えない人が、時間差のメンションを付けたり、設定を変えたりできない。

## Assumptions

- Threadsでは、自分の投稿への返信を、投稿と同じ手順（返信先の投稿を指定して出す）で出せる。要る権限（返信の権限）は、計画のときにMetaの公式の説明と、トークンを貼る方法で確かめる（2026-11-05の調べでは、Metaの説明のページによって書き方が違う）。利用者が自分のMetaアプリでトークンを作るので、返信の権限を付けて作り直してもらう案内を出す。
- 返信の文に @ユーザー名 を書けばメンションになり、相手に通知が届く。相手の設定によっては「@」が付かない・通知されないことがある（外部の投稿サービスの説明）。
- 人数（5人・20人）・回数（24時間に1回）・24時間で出さない決まりは、迷惑な投稿と見られないための仮の値。テスト版で直してよい。
- 返信は自動投稿の処理の回（005、今は5分ごと）で出す。新しい処理の仕組みは足さない。
- 返信の文は、外のAIでは作らない（決まったひとことと @ユーザー名 を組み合わせるだけ。原則III）。
- 手でThreadsに投稿した投稿（アプリから出していない投稿）には付けられない。

## Dependencies

- 004（承認・NGワード）、005（自動投稿の処理の回・二重投稿の防ぎ方）、006（反応数の取り込み・返信の数）、010（トークンの権限の警告）、011（権限）、019（機能のまとまり「自動投稿」）、022（解析の返信率）。
- Constitution：原則I（返信の文もNGワードを確かめる）・II（返信の文も承認してから出す）。改定は要らない見込み（返信もThreadsへ出る内容として、今の原則がそのまま当てはまる）。
