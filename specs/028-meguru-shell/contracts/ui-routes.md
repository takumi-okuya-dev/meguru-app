# 画面の契約（UI Routes）：めぐるの外枠とWebの分割

**日付**：2026-11-12 | **計画**：[../plan.md](../plan.md)

見た目は[docs/ui-design.md](../../../docs/ui-design.md)の今の約束と、[めぐる 外枠モック](https://claude.ai/artifact/9ZdabDgbgJbVVny89hFasu)に従う。

## 1. ルート

### 1-1. ログインのいらないルート（関所の外。URLは変えない）

| URL | 画面 | 持ち主 |
|---|---|---|
| `/sign-in/*` | ログイン | 外枠 |
| `/terms`・`/legal/commerce` | 利用規約・特定商取引法の表記（環境の帯つき） | 外枠 |
| `/test-invite/:token` | テスト用のグループの招待 | 外枠 |
| `/r/:code` | 紹介リンク | 外枠 |
| `/invite/:token` | チームの招待 | Threads |
| `/guide/threads-token` | トークンの作り方（環境の帯つき） | Threads |
| `/data-deletion/:code` | データ削除の確認 | Threads |
| `/accounts/*`・`/teams/*` | 前のURLの転送（2） | Threads（`legacyRedirects`） |

### 1-2. ログインの要るルート（関所の中）

| URL | 画面 | 持ち主 | 変える前 |
|---|---|---|---|
| `/` | 入口の振り分け（3） | 外枠 | Threadsの振り分け |
| `/apps` | すべてのアプリ（4） | 外枠 | （新規） |
| `/settings`・`/settings/<slug>` | 共通の設定 | 外枠（運営の「テスター招待」「アカウント一覧」はThreadsが渡す） | 同じ |
| `/threads` | Threadsのホームの振り分け（最後に使ったアカウント → なければ「アカウントを作る」。`?error=`のトースト） | Threads | `/` |
| `/threads/complete` | 接続から戻る画面（サイドバーなし） | Threads | 同じ |
| `/threads/accounts/new` | アカウントを作る | Threads | `/accounts/new` |
| `/threads/accounts/:accountId/*` | アカウントの画面（ホーム・設定・戦略・宣伝・外部媒体・リサーチ・投稿をつくる・投稿ストック・パフォーマンス・分析・操作の記録） | Threads | `/accounts/:accountId/*` |
| `/threads/teams/:teamId/*` | チーム（チーム・担当・運用状況） | Threads | `/teams/:teamId/*` |
| `/threads/teams/:teamId/accounts/:accountId` | 見せてもらっているアカウント | Threads | `/teams/:teamId/accounts/:accountId` |
| `*` | 見つかりません | 外枠 | 同じ |

- 出せないアプリ（`released`でない）のパスは、ルートがないので「見つかりません」。
- 機能のまとまりのOFF（`RequireFeature`）・契約前の画面・テスト版に入れない人の画面・退会の途中の画面は、今と同じ場所・同じ条件で出す。契約前でも開ける画面（`/settings/billing`・`/settings/account`）も今と同じ。

## 2. 前のURLの転送

- `/accounts/…` → `/threads/accounts/…`、`/teams/…` → `/threads/teams/…`。パスの残り・クエリ・`#…`をそのまま付ける。
- 履歴を置き換える（戻るボタンで前のURLに戻らない）。
- 関所の外で移すので、ログインしていない人は、新しいURL → ログインの画面 → 新しいURL の順になる。
- 少なくとも、次の外枠のfeature（ドメインの移行など）までは残す。

## 3. 入口の振り分け（`/`）

| 条件 | 行き先 |
|---|---|
| `me.apps.landing`がある | そのアプリの`basePath`（今は`/threads`）。クエリはそのまま渡す |
| `me.apps.landing`が`null` | `/apps` |
| `/api/me`を読めない | 今と同じエラーの画面（もう一度読む） |

- 読みこみ中は今と同じ骨組みを出す。開くたびに`/api/me`を読み直す（今と同じ）。

### Threadsから入る道（`/threads`へ向ける）

| 場所 | 変える前 | 変えた後 |
|---|---|---|
| 紹介リンク：ログインしている人 | `/` | `/threads` |
| 紹介リンク：ログインしていない人のログインの戻り先 | `/` | `/threads` |
| テスト用のグループの招待：「アプリを開く」 | `/` | `/threads` |
| チームの招待：「アプリを開く」 | `/` | `/threads` |
| ログインの画面が許す戻り先 | 招待の2つ | 招待の2つと`/threads` |

変えないもの：チームの招待の「参加しない」、テスト用のグループの招待の「トップへ」、見つかりませんの「戻る」、設定の画面の「戻る」（どれも`/`）。

## 4. すべてのアプリ（`/apps`）

- サイドバーなしの1カラム（設定の画面と同じく、左上に「戻る」。押すと`/`）。
- 見出し「すべてのアプリ」。
- 「使っているアプリ」：`me.apps.using`のアプリ。名前（`APP_CATALOG.name`）・アイコン・1行の説明・「開く」（そのアプリの`basePath`へ）。0本なら区分ごと出さない。
- 「足せるアプリ」：`available`のうち`using`でないアプリ。名前・アイコン・1行の説明・料金の文言・「詳しく見る」・「使い始める」。0本なら区分ごと出さない。
  - 「詳しく見る」：その場で説明（`details`）を開く（ダイアログか、カードを広げる。モックに合わせる）。開いても使い始めたことにはならない。
  - 「使い始める」：Threadsは`/threads/accounts/new`へ。そこから先（契約前の画面・接続）は今と同じ。
- 入るところ：ユーザーメニューの「すべてのアプリ」、アプリの切り替えの「すべてのアプリ」、入口の振り分け（使っているアプリが0本）。
- 開いても`PUT /api/me/last-app`は呼ばない（アプリではないため）。

## 5. サイドバー

### 5-1. 使っているアプリが1本以下（今の利用者は全員これ）

今とまったく同じ並び：いちばん上の行にアカウントの切り替えと畳むボタン → 担当の案内 → 機能の一覧 → チーム → 区切り線 → このアカウントの設定 → ユーザーメニュー。

- ユーザーメニューに「すべてのアプリ」を足す（「設定」の下）。ほかは変えない。

### 5-2. 使っているアプリが2本以上

- いちばん上の行：アプリの切り替え（開いているアプリのアイコンと名前、下向きの印）と畳むボタン。
- その下に、開いているアプリのサイドバーの頭（Threadsならアカウントの切り替え）・中身・下の項目、最後にユーザーメニュー。
- アプリの切り替えを押すと：使っているアプリの一覧（開いているアプリに印）、区切り線、「すべてのアプリ」。アプリを選ぶと、そのアプリの`basePath`へ移る。
- 画面の幅が狭いとき（引き出しのサイドバー）も同じ並び。

## 6. 最後に使ったアプリを覚える

- 画面のURLが、あるアプリの`basePath`の下になったとき、`me.apps.last`がそのアプリでなければ、`PUT /api/me/last-app`を1回呼び、成功したら`me`を読み直す。
- 失敗しても、画面には何も出さない（次の入口で`using`の最初になるだけ）。
- `/apps`・`/settings`・ログインのいらないページでは呼ばない。

## 7. 表示名（spec FR-017）

- 「めぐる Threads」と出すのは、すべてのアプリの画面とアプリの切り替えだけ。
- ブラウザのタブ・ログイン・招待や紹介のページ・トークンの作り方・利用規約などの「ThreadsGrower」は変えない。
