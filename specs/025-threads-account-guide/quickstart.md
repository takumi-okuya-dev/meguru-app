# 動かして確かめる手順：Threadsで許可するときのアカウントの取り違えを減らす案内

**日付**：2026-11-08 | **計画**：[plan.md](./plan.md)

画面の形は[contracts/ui-routes.md](./contracts/ui-routes.md)、APIは[contracts/api.md](./contracts/api.md)を見る。

## 0. 準備

- `pnpm --filter api db:migrate`で`0023_connection_notice`まで当てる。
- `pnpm -r test`・`pnpm -r typecheck`・`pnpm lint`がすべて通ること。

## 1. 押す前の案内（US1）

1. つながっているアカウントで「接続し直す」を開く。
   - 期待：「Threadsで許可する」の下に「… @{今の名前} でログインしているか確かめてください。」が出る。
   - 期待：トグルを開くと、3つの手順と「threads.comを開く」が出る。
2. 招待済みの、つなぐ前のアカウントを開く。
   - 期待：申し込んだ名前で、同じ案内が出る。
3. 「トークンを貼り付ける」を開く。
   - 期待：案内は出ない。

## 2. 違うアカウントで戻ったとき（US2）

1. threads.comで別のアカウントにログインした状態で、「接続し直す」→「Threadsで許可する」→ 許可する。
   - 期待：「Threadsとの接続」に、エラーの文、3つの手順、「threads.comを開く」が出る。
2. 「threads.comを開く」を押す。
   - 期待：新しいタブで開く。アプリの画面は残る。
3. threads.comで正しいアカウントに切り替え、「接続し直す」からやり直す。
   - 期待：つなぎ直せる（SC-002：2分以内）。

## 3. 違うアカウントでつながった知らせ（US3）

1. 招待済みの申し込み（@shop_tokyo）のアカウントを、別のアカウントでつなぐ。
   - 期待：「Threadsとの接続」に「@{つながった名前} でつながりました。申し込んだ @shop_tokyo とは違うアカウントです。」が出る。
2. 「閉じる」を押し、再読み込みする。
   - 期待：もう出ない。
