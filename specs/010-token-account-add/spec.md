# Feature Specification: 自分のMetaアプリのトークンでアカウントを追加

**Feature Branch**: `feature/010-token-account-add`

**Created**: 2026-10-10

**Status**: Draft

**Input**: 2026-10-10 のユーザーの決定。Meta App Review を待たずに利用者を増やせるよう、利用者が自分で作ったMetaアプリ（例：ユーザー自身の「ThreadsAutomation」）のユーザートークン生成ツールで作ったアクセストークンを貼り付けて、Threadsアカウントを追加できるようにする（Threads Growth OS や以前のGAS版と同じ方式）。2026-10-03 に決めた Meta への接続の方針（B：テスター招待で始め、A：App Review の通過で公開。C：利用者自身のMetaアプリは別のfeature）の「C」にあたる（[Metaアプリの設定](../../docs/external-services-setup.md)）。

**Source**: [001のspec](../001-login-account-setup/spec.md)（FR-008・FR-012・FR-013・FR-018〜FR-021・FR-023）、[002のspec](../002-strategy-profile/spec.md) FR-028（検証期間中の案内）、[005のspec](../005-auto-post/spec.md)（投稿の権限の確認）、[006のspec](../006-performance-feedback/spec.md)（反応数を読む権限）、[008のspec](../008-team-operations/spec.md)（オーナーだけの操作・要再接続の示し方）、[Constitution](../../.specify/memory/constitution.md) 3.0.0 原則IV・V、[011 決済のメモ](../011-billing/notes.md)（番号の変更）。

## Clarifications

### Session 2026-10-10

- Q: アカウント追加画面で、トークンの貼り付けをどう位置づけるか？ → A: 今の「Threadsアカウントを接続」（このアプリのMetaアプリでの許可。検証期間中は招待されたテスターだけ）を主の方法にし、「自分のMetaアプリのトークンで追加する」を2つ目の方法として並べる。App Review の通過後（検証期間の案内を出さなくなった後）も残す。
- Q: 同じThreadsアカウントを、2つの方法の両方で登録しようとしたら？ → A: ThreadsのユーザーIDはMetaアプリごとに違うことがあるため、IDに加えて@ユーザー名でも照合し、登録済みなら止める（自分のAccountなら接続し直しの案内、他の人のAccountなら001と同じ「すでに登録されています」）。
- Q: 登録した後、接続の方法を切り替えられるか？ → A: 「接続し直す」で、どちらの方法も選べる。同じThreadsアカウント（ユーザー名が同じ）なら、戦略・投稿ストック・設定・記録はそのまま引き継ぐ。
- Q: トークンの取り方の案内はどこまで用意するか？ → A: 追加の画面に短い手順（5ステップまで）を出し、Metaアプリの作り方を含む詳しい手順はドキュメントのページに書いてリンクする。
- Q: 貼り付けたトークンが短期（1時間）か長期（60日）かを、追加の時点で見分けられないときは？ → A: 長期として追加し、追加の約2時間後にもう一度Threadsに問い合わせて確かめ直す。使えなければ要再接続にし、「短期トークンだった可能性があります。長期トークンを貼り付けてください」と案内する（FR-012）。
- Q: トークンの扱いを書く利用規約のページは？ → A: 本featureで最小限の利用規約のページを作る。トークンの扱い（利用者の代わりに処理するサービスで、運用のためだけに使う）・禁止事項など最小限を書き、トップページと追加の画面からリンクする。料金・解約・特定商取引法の表示などは011（決済）で足す（FR-052）。
- Q: トークンの確認に続けて失敗した利用者には、どれくらい待ってもらうか？ → A: 10分の間に5回失敗したら、その後10分は確かめない。画面に「しばらく待ってから、もう一度お試しください（あと○分）」と出す（FR-015）。

## 用語

- **このアプリの接続**：001の方法。このアプリのMetaアプリで、Threadsの許可の画面から許可する。検証期間中は、招待されたテスターだけが使える。
- **トークンでの接続**：本featureの方法。利用者が自分のMetaアプリで作ったアクセストークン（長期トークン）を貼り付ける。
- **接続の方法**：Accountごとに、今どちらの方法で接続しているか。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自分のMetaアプリのトークンを貼ってアカウントを追加する (Priority: P1)

検証期間中でテスターに招待されていない人や、自分のMetaアプリを使いたい人が、「Threadsアカウントを追加」の画面で「自分のMetaアプリのトークンで追加する」を選ぶ。画面の短い手順に沿って、自分のMetaアプリのユーザートークン生成ツールでトークンを作り、貼り付けて「追加する」を押す。トークンが確かめられると、Threadsのユーザー名・表示名・プロフィール画像の入ったAccountができ、そのAccountの画面に移る。以降は001〜009と同じ機能（戦略・投稿ストック・承認・自動投稿・分析・チーム）が使える。

**Why this priority**: Meta App Review の通過を待たずに、テスター招待なしで利用者を増やすための中心の流れ。

**Independent Test**: 有効な長期トークンを貼り付け、Accountが作られ、プロフィールが表示され、投稿の権限の確認が「投稿できます」になることを確かめる。

**Acceptance Scenarios**:

1. **Given** ログイン済みでAccountの登録の上限に達していない利用者、**When** 「Threadsアカウントを追加」を開く、**Then** 主の方法「Threadsアカウントを接続」と、2つ目の方法「自分のMetaアプリのトークンで追加する」が出る。2つ目は開くまで手順と入力欄を出さない。
2. **Given** 2つ目の方法を開いた、**When** 画面を見る、**Then** トークンの作り方の短い手順（5ステップまで）、詳しい手順へのリンク、トークンの入力欄（入力した文字は隠す）、「追加する」、トークンの扱いの説明（暗号化して保存し、画面に二度と出さない。このアプリはあなたのアカウントの運用のためだけに使う）が出る。
3. **Given** 有効な長期トークン、**When** 貼り付けて「追加する」を押す、**Then** Accountが作られ、利用者がそのAccountのオーナーになり、そのAccountのホームに移る。プロフィール（ユーザー名・表示名・画像）が表示される。
4. **Given** 投稿の権限を含まないトークン、**When** 追加する、**Then** Accountは作られるが、「このトークンには投稿の権限がありません。自動投稿を使うには、権限を付けて作り直したトークンで接続し直してください」と出る。自動投稿は005と同じく投稿できない状態として扱う。
5. **Given** 反応数を読む権限を含まないトークン、**When** 追加する、**Then** Accountは作られ、006と同じく反応数を読めない状態として案内が出る。
6. **Given** 無効・期限切れ・取り消されたトークン、または形が明らかに違う文字列、**When** 追加する、**Then** Accountは作られず、「トークンを確かめられませんでした。トークンを作り直して貼り付けてください」と、詳しい手順へのリンクが出る。入力欄の内容は残す。
7. **Given** 登録の上限に達した利用者、**When** 追加の画面を開く、**Then** 001と同じく上限の案内が出て、2つ目の方法でも追加できない。

### User Story 2 - 同じアカウントの二重登録を防ぐ (Priority: P1)

同じThreadsアカウントが、このアプリの接続とトークンでの接続の両方で別々のAccountとして登録されると、自動投稿が2重になる。トークンのMetaアプリが違うとThreadsのユーザーIDも違うことがあるため、ユーザー名でも照合して止める。

**Why this priority**: 二重の自動投稿は、運用者が最も恐れる事故（Constitution 原則II の理由と同じ）に近い。

**Independent Test**: このアプリの接続で登録済みのThreadsアカウントのトークン（別のMetaアプリ）を貼り付け、Accountが作られないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 自分がすでにAccountとして登録している@cafe_b（どちらの方法でも）、**When** @cafe_b のトークンで追加しようとする、**Then** 新しいAccountは作らず、「このアカウントはすでに登録されています。接続を更新するときは、そのアカウントの設定の『接続し直す』を使ってください」と、そのAccountの設定へのリンクが出る。
2. **Given** 他の利用者が登録している@cafe_b、**When** @cafe_b のトークンで追加しようとする、**Then** 001 FR-012 と同じく「このThreadsアカウントは、すでに別のユーザーが登録しています」と出て、Accountは作られない。登録している人の名前は出さない。
3. **Given** トークンで登録した@cafe_b、**When** 同じ利用者がこのアプリの接続（許可の画面）で@cafe_bを追加しようとする、**Then** 同じく新しいAccountを作らない（001 FR-013 と同じく、既存のAccountの接続を更新する）。

### User Story 3 - 接続し直すときに方法を選ぶ (Priority: P2)

オーナーが、Accountの設定の「接続し直す」（要再接続のときはバナーの操作）から、このアプリの接続とトークンでの接続のどちらかを選んで接続し直す。トークンの期限切れや取り消しのときに新しいトークンを貼り付けたり、App Review の通過後にこのアプリの接続へ移ったりできる。

**Why this priority**: トークンでの接続は、利用者がMetaアプリ側でトークンを取り消したり、更新が止まったりしたときに、貼り付け直す以外に戻す方法がない。

**Independent Test**: トークンで接続したAccountを、このアプリの接続で接続し直し、戦略・投稿ストックが残っていることを確かめる。逆も同じ。

**Acceptance Scenarios**:

1. **Given** オーナーのAccount（どちらの方法でも）、**When** 「接続し直す」を押す、**Then** 「Threadsで許可する」と「トークンを貼り付ける」の2つが選べる。今の接続の方法が分かる（例：「今の接続：自分のMetaアプリのトークン」）。
2. **Given** トークンで接続した要再接続のAccount、**When** 新しいトークンを貼り付けて接続し直す、**Then** 同じAccountが接続中に戻り、戦略・投稿ストック・設定・操作の記録・チームはそのまま残る。登録の上限に達していても使える（001 FR-020 と同じ）。
3. **Given** トークンで接続したAccount、**When** このアプリの接続で接続し直す、**Then** 接続の方法が「このアプリの接続」に変わり、データはそのまま残る。逆（このアプリの接続 → トークン）も同じ。
4. **Given** @cafe_b のAccount、**When** 別のThreadsアカウント（@shop_c）のトークンで接続し直そうとする、**Then** 001 FR-020 と同じく拒否し、「別のThreadsアカウントのトークンです。@cafe_b のトークンを貼り付けてください」と出す。
5. **Given** パートナー・編集者、**When** 要再接続のAccountを開く、**Then** 008と同じく「オーナーの再接続待ち」と出て、接続し直す操作は出ない。トークンの貼り付けも出さない。

---

### User Story 4 - トークンでの接続を自動で保つ (Priority: P2)

トークンで接続したAccountも、このアプリの接続と同じく、期限が切れる前に自動で延長され、利用者の操作なしで接続中のままになる。延長できなくなったら要再接続になり、トークンの貼り直しを案内する。

**Why this priority**: 長期トークンは60日で切れる。自動で延長しないと、2か月ごとに自動投稿が止まる。

**Independent Test**: 期限まで7日を切ったトークンでの接続が、日次の処理で延長されることを確かめる。延長に失敗したら要再接続になることを確かめる。

**Acceptance Scenarios**:

1. **Given** トークンで接続し、期限が近いAccount、**When** 日次の処理が動く、**Then** このアプリの接続と同じ条件で延長され、接続中のまま。
2. **Given** 利用者がMetaアプリ側でトークンを取り消した・アプリを消した、**When** 次にThreadsに問い合わせる（画面を開いたとき・自動投稿・日次の処理）、**Then** 認証のエラーで要再接続になり、オーナーに「トークンが使えなくなりました。新しいトークンを貼り付けて接続し直してください」と出る。
3. **Given** トークンで接続したAccount、**When** 自動投稿の時刻になる、**Then** このアプリの接続と同じく、NGワードの確認・承認済みの案だけ・投稿の順（Constitution 原則I・II、005）で投稿される。

---

### User Story 5 - トークンの作り方の詳しい手順を読む (Priority: P3)

Metaアプリをまだ持っていない人が、追加の画面のリンクから、Metaの開発者アカウントの登録、アプリの作成、Threadsの使い方の追加、権限の選び方、テスターの追加、ユーザートークン生成ツールでの長期トークンの作成までの手順を読める。

**Why this priority**: 手順の多くはMetaの画面での作業で、初めての人には分かりにくい。画面の短い手順だけでは足りない人のため。

**Independent Test**: ドキュメントの手順だけで、Metaアプリを持っていない人がトークンを作り、追加できることを手で確かめる。

**Acceptance Scenarios**:

1. **Given** 追加の画面、**When** 「詳しい手順」を開く、**Then** Metaアプリの作り方からトークンの作成・貼り付けまでの手順と、必要な権限（プロフィール・投稿・反応数）、トークンの扱い（このアプリが何に使うか、取り消し方）が読める。
2. **Given** 詳しい手順、**When** 読む、**Then** Metaの画面の名前が変わることがあるため、手順ごとに「何をする手順か」が分かる書き方になっている（画面の写真に頼らない）。

---

### Edge Cases

- **短期トークン（1時間で切れる）を貼った**：確かめた時点では有効でも、すぐに切れる。追加の時点で見分けられれば止め、見分けられなければ追加の約2時間後の確かめ直しで要再接続にして案内する（FR-012）。その間に自動投稿の時刻が来ても、トークンが有効な間は投稿される。
- **前後に空白・改行・引用符が付いた**：取り除いてから確かめる。
- **トークンでない文字列（URL・パスワードなど）を貼った**：Threadsに問い合わせる前に形で弾ける場合は弾き、エラーの文言はUS1-6と同じにする。貼った文字列は画面・記録・エラーに出さない。
- **非公開のプロフィールのThreadsアカウント**：Metaの仕様で、許可の有効期間が短い（90日）ことがある。期限が来たら他と同じく要再接続になる。
- **ユーザー名を変えたThreadsアカウント**：日次の処理でプロフィールを取り直すので、照合に使うユーザー名は新しい名前に変わる。変えた直後に別の方法で追加すると、IDもユーザー名も違えば別のAccountとして登録できてしまう。この場合は前提として受け入れる（Assumptions）。
- **ユーザー名が他の人に移った**：Threadsでは、手放されたユーザー名を別の人が取ることがある。照合で「すでに登録されています」と出て追加できないときは、登録済みのAccountのプロフィールを取り直して、まだ同じユーザー名かを確かめ直す。違えば追加を続ける。
- **同じトークンを2つのブラウザで同時に貼った**：Accountは1つだけ作られる（001の同時操作と同じ）。
- **貼り付けを何度も失敗する**：10分の間に5回失敗したら、10分待つよう案内する（FR-015。総当たりやThreadsへの問い合わせすぎを防ぐ）。
- **トークンで接続したAccountの削除**：001 FR-022と同じく、Account・接続情報（トークン）・データを消す。利用者のMetaアプリ側のトークンは消せないため、「Metaアプリ側のトークンは、必要なら自分で取り消してください」と添える。
- **Metaアプリからのアンインストール・データ削除の通知**：利用者のMetaアプリに届き、このアプリには届かない。このアプリでは、次の問い合わせの認証のエラーで要再接続にする。データ削除の依頼は、Accountの削除で受ける。
- **検証期間が終わった後**：検証期間中の案内（002 FR-028）は出さなくなるが、2つ目の方法は残す。

## Requirements *(mandatory)*

### Functional Requirements

#### 追加の画面

- **FR-001**: System MUST 「Threadsアカウントを追加」の画面に、主の方法（このアプリの接続）と、2つ目の方法「自分のMetaアプリのトークンで追加する」を出す。2つ目の方法は、開くまで手順と入力欄を出さない。検証期間かどうかにかかわらず出す。
- **FR-002**: System MUST 2つ目の方法を開くと、トークンの作り方の短い手順（5ステップまで）、詳しい手順（FR-030）へのリンク、トークンの入力欄、「追加する」、トークンの扱いの説明を出す。
- **FR-003**: System MUST トークンの入力欄の文字を隠し、入力した文字を画面・ブラウザの保存・記録・エラーに出さない。前後の空白・改行・引用符は取り除く。
- **FR-004**: System MUST 001 FR-008 の「認証情報を手で貼り付ける方式は提供しない」を、本featureの方法に限って改める。001 FR-008 の文言に、本featureへの例外を書き足す。

#### 確かめて追加する

- **FR-010**: System MUST 貼り付けたトークンでThreadsに問い合わせ、プロフィール（ユーザーID・ユーザー名・表示名・画像）を読めることを確かめてから、Accountを作る。読めなければAccountを作らず、US1-6の文言を出す。
- **FR-011**: System MUST 追加のときに、投稿の権限（005と同じ確かめ方）と反応数を読む権限（006と同じ）を確かめ、ないものを案内する（US1-4・US1-5）。プロフィールが読めれば、投稿・反応数の権限がなくてもAccountは作る。
- **FR-012**: System MUST 長期トークンかどうかを追加の時点で確かめられる場合は、短期トークンを拒み、「長期トークンを作って貼り付けてください」と出す。確かめられない場合は長期として追加し、追加（またはトークンでの接続し直し）の約2時間後にもう一度Threadsに問い合わせる。使えなければ要再接続にし、オーナーに「短期トークンだった可能性があります。ユーザートークン生成ツールで作った長期トークンを貼り付けてください」と出す。
- **FR-013**: System MUST 追加で作るAccount・オーナーのMembership・初期の設定を、001のAccount作成と同じにする（001 FR-009・FR-011・FR-014、008までの初期値）。登録の上限（001 FR-015〜FR-017）も同じく判定する。
- **FR-014**: System MUST 同じ利用者が同じトークンを同時に送っても、Accountを1つだけ作る。
- **FR-015**: System MUST 利用者ごとに、トークンの確認（追加と接続し直しの両方）の失敗が10分の間に5回に達したら、その後10分はThreadsに問い合わせず、「しばらく待ってから、もう一度お試しください（あと○分）」と出す。形で弾いた文字列（FR-003のあと、Threadsに問い合わせる前に弾いたもの）も失敗に数える。成功しても、それまでの失敗の数は消さない。

#### 二重登録の防止

- **FR-020**: System MUST 新しいAccountを作る前に、ThreadsのユーザーIDに加えて、ユーザー名（大文字・小文字を区別しない）でも、登録済みのAccountと照合する。どちらかが一致したら新しいAccountを作らない。この照合は、このアプリの接続での追加（001）にも同じく使う。
- **FR-021**: System MUST 一致したAccountが自分のものなら、新しいAccountを作らず、そのAccountの「接続し直す」へ案内する（US2-1）。このアプリの接続での追加では、001 FR-013 と同じく既存のAccountの接続を更新する（US2-3）。
- **FR-022**: System MUST 一致したAccountが他の利用者のものなら、001 FR-012 と同じ文言で拒否し、登録している人を明かさない。
- **FR-023**: System MUST ユーザー名だけが一致したときは、登録済みのAccountのプロフィールをThreadsから取り直し、まだ同じユーザー名かを確かめる。違えば登録済みのAccountのユーザー名を更新し、追加を続ける。取り直せない（要再接続など）ときは、一致したものとして扱う。

#### 接続し直す・方法の切り替え

- **FR-030**: System MUST トークンの作り方の詳しい手順を、ドキュメントのページとして用意する。Metaの開発者アカウントの登録、アプリの作成、Threadsの使い方と権限（プロフィール・投稿・反応数）の追加、自分をテスターに加える、ユーザートークン生成ツールでの長期トークンの作成、貼り付け、トークンの取り消し方を含める。手順ごとに目的を書き、画面の写真に頼らない。
- **FR-031**: Users MUST be able to オーナーとして、Accountの設定の「接続し直す」（要再接続のときはバナーの操作）から、このアプリの接続とトークンの貼り付けのどちらかを選んで接続し直せる。登録の上限に達していても使える。今の接続の方法を示す。
- **FR-032**: System MUST 接続し直すトークンが別のThreadsアカウントのものなら拒否する（001 FR-020）。同じThreadsアカウントかは、ユーザーIDまたはユーザー名で判定する（ユーザーIDはMetaアプリごとに違うことがあるため）。
- **FR-033**: System MUST 接続し直しで方法が変わっても、Accountのデータ（戦略・投稿ストック・設定・NGワード・パフォーマンス・改善メモ・操作の記録・チーム）をそのまま残す。ThreadsのユーザーIDが変わったときは、新しいIDに更新する。
- **FR-034**: System MUST パートナー・編集者には、接続し直す操作もトークンの貼り付けも出さない（008 FR-044）。トークンの追加・接続し直しのAPIはオーナーだけが使える（008の判定を通す）。
- **FR-035**: System MUST チームがあるAccountでは、トークンでの接続し直しを、このアプリの接続での接続し直しと同じく操作の記録に残す。トークンの中身は記録に書かない。

#### 接続を保つ

- **FR-040**: System MUST トークンでの接続も、001 FR-021 と同じ条件で、期限が切れる前に自動で延長する。
- **FR-041**: System MUST トークンでの接続で、Threadsが認証のエラーを返したら、001 FR-018 と同じく要再接続にする。オーナーへの案内は「トークンが使えなくなりました。新しいトークンを貼り付けて接続し直してください」とし、このアプリの接続も選べるようにする（FR-031）。
- **FR-042**: System MUST トークンでの接続のAccountも、自動投稿・パフォーマンスの取得・NGワードの確認・承認の要否を、このアプリの接続のAccountと同じに扱う（Constitution 原則I・II）。
- **FR-043**: System MUST トークンを001 FR-010 と同じく暗号化して保存し、画面・記録・エラー・書き出しに平文で出さない。保存した後に、画面でトークンを再表示する操作は作らない。

#### 削除と規約

- **FR-050**: System MUST トークンで接続したAccountの削除で、保存しているトークンも消す（001 FR-022）。削除の確認に「Metaアプリ側のトークンは、必要なら自分で取り消してください」と添える。
- **FR-051**: System MUST 2つ目の方法の説明に、このアプリがトークンを利用者のThreadsアカウントの運用（投稿・プロフィールと反応数の取得）のためだけに使うこと、利用者の代わりに処理するサービスであることを書き、利用規約（FR-052）へのリンクを置く。
- **FR-052**: System MUST ログインしなくても読める利用規約のページを用意する。本featureでは最小限とし、サービスの内容、トークンでの接続のときの扱い（利用者の代わりに、その利用者のThreadsアカウントの運用のためだけに処理する。第三者に渡さない。Accountの削除で消す。利用者はMetaアプリ側でいつでも取り消せる）、禁止事項、データの削除のページへの案内、変更の扱いを書く。トップページと追加の画面からリンクする。料金・解約・特定商取引法に基づく表示は011（決済）で足す。

#### 文書の番号の変更

- **FR-060**: System MUST 番号の変更（009＝このアカウントのチーム、010＝本feature、011＝決済）に合わせ、Constitution（原則V「決済（feature 009）」）、008の spec FR-080・research.md R15・contracts/permissions.md、PRD §6.1 に残る「009（決済）」を「011（決済）」に直す。Constitution はPATCHの改定として版を上げる。

### Key Entities *(include if feature involves data)*

- **Account**：001のまま。今の接続の方法（このアプリの接続／トークン）を持つ。照合に使うユーザー名は、日次の処理でプロフィールを取り直すたびに新しくなる。
- **Threadsの接続**：001のまま（暗号化したトークン・期限・権限）。トークンでの接続も同じところに持つ。どのMetaアプリのトークンかは持たない（利用者のアプリの情報は受け取らない）。
- **トークンの確認の失敗の回数**：FR-015 の待ちの判定のため、利用者ごとに失敗の時刻を10分の間だけ持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Metaアプリとトークンを持っている利用者が、追加の画面を開いてから2分以内に、トークンを貼り付けてAccountを作れる。
- **SC-002**: Metaアプリを持っていない利用者が、詳しい手順のページだけを見て、30分以内にトークンを作り、Accountを追加できる（手で確かめる）。
- **SC-003**: 同じThreadsアカウントを、2つの方法のどの組み合わせで追加しようとしても、Accountは1つしかできない（自動テストで、このアプリの接続→トークン、トークン→このアプリの接続、トークン→別のMetaアプリのトークン、の3通り）。
- **SC-004**: トークンが画面・記録・エラー・書き出しのどこにも平文で出ない（自動テストで確かめる）。
- **SC-005**: 接続の方法を切り替えても、Accountのデータが1件も失われない（切り替えの前後で、投稿ストック・戦略・設定・記録の件数が同じ）。
- **SC-006**: トークンで接続したAccountが、利用者の操作なしで60日を超えて接続中のままになる（日次の延長の自動テスト）。
- **SC-007**: 個人運用のオーナーが「Threadsアカウントを接続」で追加する流れの手数は変わらない（2つ目の方法を開かなければ、今までと同じ画面）。

## Assumptions

- 利用者のMetaアプリのユーザートークン生成ツールは、長期トークン（60日）を出す。長期トークンの延長には、アプリのシークレットは要らない（Meta の Threads API の文書、2026-10-10 に確認）。
- ThreadsのユーザーIDは、Metaアプリごとに違うことがある（Meta の文書は「アプリごとのユーザー」と書くが、違うかどうかの明言はない）。違っても同じでも動くように、ユーザーIDとユーザー名の両方で照合する。
- Threadsのユーザー名は、ある時点では1つのアカウントだけが持つ。手放されたユーザー名が他の人に移ることはある（FR-023 で扱う）。ユーザー名を変えた直後の別の方法での追加で二重になることは、まれなので受け入れる。
- Meta の Platform Terms では、このアプリは、トークンでの接続の利用者（Metaアプリの持ち主）のサービスプロバイダーとして、その利用者のためだけにデータを処理する形になる。利用規約にこのことを書く。法的な確認は本featureの外で行う。
- 利用規約の文面は、運営者が公開の前に確かめる（本featureでは下書きとして用意する。法的な確認は本featureの外）。
- 検証期間中の案内（002 FR-028）は、主の方法の下に今までどおり出す。2つ目の方法を勧める文言は出さない（どちらを使うかは利用者が選ぶ）。
- トークンでの接続のAccountの料金・無料体験は、このアプリの接続のAccountと同じに扱う（011で決める）。
- 削除・アンインストールの通知はこのアプリに届かないため、トークンの取り消しを知るのは次の問い合わせのときになる（最大で日次の処理の間隔の遅れ）。
