# 画面の契約：自分のMetaアプリのトークンでアカウントを追加

**日付**：2026-10-10 | **計画**：[../plan.md](../plan.md) | **UI全体設計**：[docs/ui-design.md](../../../docs/ui-design.md)

## 「Threadsアカウントを追加」（`/accounts/new`、001）

上から：

1. 見出し「Threadsアカウントを追加」、「登録済みn / max件」（今のまま）
2. 上限・エラーの`Alert`（今のまま。トークンのエラーは4の中に出す）
3. 主のボタン「Threadsアカウントを接続」（今のまま）
4. 検証期間中の案内（今のまま。`threadsAccessMode === "testers"`のときだけ）
5. **新規**：折りたたみの行「自分のMetaアプリのトークンで追加する」（文字のボタン、`aria-expanded`、右に下向きの矢印）。初めは閉じる。開くと`TokenConnectForm`：
   - 短い手順（番号つき、5つ）：
     1. Metaの開発者サイトで、自分のアプリを作る（Threadsの使い方を選ぶ）
     2. 権限に「threads_basic」「threads_content_publish」「threads_manage_insights」を加える
     3. 自分のThreadsアカウントをテスターに加え、Threadsのアプリで招待を承認する
     4. 「ユーザートークン生成ツール」で、長期トークンを作ってコピーする
     5. 下の欄に貼り付けて「追加する」を押す
   - リンク「詳しい手順を見る」（`/guide/threads-token`、新しいタブ）
   - 入力欄（ラベル「アクセストークン」、入力欄は`type="text"`で、隠している間は欄に「•」だけを出し、本当の値は部品の状態だけで持つ（貼り付けは中身を置き換え、1文字でも消すと全部を消す）。パスワード欄やCSSの`-webkit-text-security`は使わない（パスワード管理ツールの保存・Firefoxで隠れない。PR #12 のCodexレビュー）、右に「表示」の切り替え）。形が違えば欄の下に「トークンの形ではないようです」（送信しない）
   - 説明（小さい文字）：「トークンは暗号化して保存し、画面に二度と表示しません。このアプリは、あなたの代わりに、このThreadsアカウントの投稿と、プロフィール・反応数の取得のためだけに使います。」＋「利用規約」へのリンク
   - 「追加する」（黒の丸いボタン、送信中は無効）
   - エラーは欄の下の`Alert`。`TOKEN_CHECK_LOCKED`は残りの分を出し、ボタンを残りの時間だけ無効にする。`ACCOUNT_ALREADY_REGISTERED`は「そのアカウントの設定を開く」のリンクを添える
   - 上限に達していれば、行は出すが開いても入力欄の代わりに上限の案内（2と同じ）
6. 成功：`/accounts/:id?connected=new`へ移る（001と同じトースト）。`warnings`があれば`&warn=publish,insights`を付け、ホームの上部に`Alert`を1回出す：
   - 投稿：「このトークンには投稿の権限がありません。自動投稿を使うには、権限を付けて作り直したトークンで接続し直してください。」
   - 反応数：「このトークンには反応数を読む権限がありません。パフォーマンスを見るには、権限を付けて作り直したトークンで接続し直してください。」

- 個人運用のオーナーが5を開かなければ、画面の項目と手数は今と同じ（SC-007）。

## 「接続し直す」のダイアログ（新規、`ReconnectDialog`）

- 開くところ：設定の「Threadsとの接続」のボタン、要再接続のバナー・投稿の知らせ・反応数の知らせの「再接続」（`ReconnectButton`）。オーナーだけに出す（今のまま）。
- PCは中央のダイアログ、スマートフォンは下からのシート（008の招待のダイアログと同じ）。
- 見出し「Threadsとの接続し直し」、本文「@{username}の接続を更新します。投稿ストックや設定はそのまま残ります。」
- 2つの選択（大きめの行）：
  - 「Threadsで許可する」（説明：このアプリのMetaアプリで許可します）→ 001の流れ（認可の画面へ）
  - 「トークンを貼り付ける」（説明：自分のMetaアプリで作ったトークンを使います）→ 同じダイアログの中で`TokenConnectForm`（`mode: "reconnect"`、ボタンは「接続し直す」）
- 今の方法の行に「今の接続」のラベル。
- 成功：ダイアログを閉じ、トースト「接続し直しました」。`warnings`は設定の画面の上部に同じ`Alert`。

## 「このアカウントの設定」の「Threadsとの接続」（001）

- 説明を「今の接続：このアプリで許可」または「今の接続：自分のMetaアプリのトークン」と、今の文（同じThreadsアカウントで…）に変える。
- `reconnectHint === "short_lived_token"`なら、要再接続の文に「短期トークンだった可能性があります。ユーザートークン生成ツールで作った長期トークンを貼り付けてください。」を添える。
- ボタンは今の文言（「再接続」／「Threadsとの接続を認可し直す」→「接続し直す」）で、ダイアログを開く。

## 要再接続のバナー（001 FR-019）

- トークンの接続のときの文：「トークンが使えなくなりました。新しいトークンを貼り付けて接続し直してください。」（オーナー）。パートナー・編集者は008の「オーナーの再接続待ち」のまま。

## Accountの削除の確認（001）

- 接続の方法が`token`なら、本文の後に「Metaアプリ側のトークンは、必要なら自分で取り消してください。」を足す。

## 利用規約（`/terms`、新規、ログイン不要）

- 1カラムの読み物（`CenteredLayout`の幅、見出しと本文）。項目：サービスの内容／アカウントとログイン／トークンでの接続の扱い（利用者の代わりに、そのThreadsアカウントの運用のためだけに処理する。第三者に渡さない。Accountの削除で消す。Metaアプリ側でいつでも取り消せる）／禁止事項／データの削除（`/data-deletion`の案内）／変更／最終更新日。
- ログイン画面（ログインしていない人の最初の画面）の足元に「利用規約」のリンク。

## トークンの作り方（`/guide/threads-token`、新規、ログイン不要）

- 1カラムの読み物。節：はじめに（何をするか・かかる時間の目安30分）／1. Metaの開発者アカウント／2.アプリを作る（Threadsの使い方）／3.権限を加える（3つ。それぞれ何に使うか）／4.自分をテスターに加える（Threadsのアプリでの承認）／5.長期トークンを作る（ユーザートークン生成ツール）／6.貼り付ける／トークンを取り消すには／うまくいかないとき（短期トークン・別のアカウント・待ち）。
- 手順ごとに「この手順の目的」を1行で書き、画面の写真は使わない（FR-030）。最後に「この手順は2026-10-10に確かめました」。

## 操作の記録（`/accounts/:id/activity`、008）

- `threads_reconnected`：「Threadsとの接続し直しをしました（このアプリで許可）」／「（自分のMetaアプリのトークン）」。
