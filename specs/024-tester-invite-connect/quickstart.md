# 動かして確かめる手順：テスター招待での接続、アカウント数・投稿数の上限、無料体験の廃止

**日付**：2026-11-08 | **計画**：[plan.md](./plan.md)

APIの形は[contracts/api.md](./contracts/api.md)、画面は[contracts/ui-routes.md](./contracts/ui-routes.md)、データは[data-model.md](./data-model.md)を見る。ここには、確かめる順と期待する結果だけを書く。

## 0. 準備

- **自動のテスト**：
  - `pnpm install`、ローカルのPostgresを起動し、`pnpm --filter api db:migrate`で`0022_tester_invites`まで当てる。
  - `pnpm -r test`、`pnpm -r typecheck`、`pnpm -r lint`がすべて通ること。
- **手元で画面を見る**：
  - `apps/api/.dev.vars`に次を入れる。
    - `BILLING_ENABLED="true"`（Stripeのテスト用環境の鍵と、1件1,000円の`STRIPE_PRICE_ID`）
    - `OPERATOR_CLERK_USER_IDS=<自分>`
    - `THREADS_ACCESS_MODE="testers"`
    - `THREADS_CONNECT_METHODS`は未設定
  - 運営者でないGoogleのアカウントを1つ用意する。

## 1. 契約前（US6）

1. 運営者でないアカウントで、はじめてログインする。
   - 期待：契約前の画面（「アカウント1件につき 月1,000円」「契約する」）だけが出る。
2. 開発者ツールなどで`POST /api/accounts`を直接呼ぶ。
   - 期待：`403 SUBSCRIPTION_REQUIRED`。
3. 「契約する」からテスト用のカード（4242…）で払う。
   - 期待：その場で1,000円の請求があり、「契約中」になって、アカウントを作れる。
4. マイグレーションの前からいた利用者でログインする。
   - 期待：無料体験のまま（終わる日の表示も今のまま）。
5. 運営者・料金なしの印の人。
   - 期待：契約しなくても使える。

## 2. 招待の申し込みから接続まで（US1・US2）

1. 契約した利用者で、つなぐ前のアカウントを開く。
   - 期待：ユーザー名の欄と「招待を申し込む」が出る。
2. `@Shop_Tokyo`と入れて申し込む。
   - 期待：「申し込み中」と`@shop_tokyo`（小文字）が出る。
3. 運営者で「運営 › テスター招待」を開く。
   - 期待：「申し込み中 1」に出る。
4. Metaの開発者の画面で、そのユーザー名をThreadsテスターに加える。アプリに戻って「招待した」を押す。
   - 期待：枠の使用数が1増え、利用者の画面が「招待済み」と承認の手順になる。
5. （実際のThreadsアカウントで）招待を承認する前に「Threadsで許可する」を押す。
   - 期待：戻ったときに「招待を承認してから」の案内が出る。
6. Threadsで招待を承認して、「Threadsで許可する」を押す。
   - 期待：つながり、運営者の一覧で「接続済み」になる。
7. 別の申し込みを「招待済み」にしてから、利用者が取り消す。
   - 期待：運営者の一覧の「外してよい」に「申し込みが取り下げられました」と出る。
8. 接続済みのアカウントを消す。
   - 期待：運営者の一覧の「外してよい」に「アカウントが消されました」と出る。「外した」を押すと、枠の使用数が1減る。
9. 別の申し込みで「見送る」（理由つき）を押す。
   - 期待：利用者に理由が出て、申し込み直せる。
10. 申し込みと取り消しを短い間に6回繰り返す。
   - 期待：6回目は`429 RATE_LIMITED`。

## 3. 上限（US3・US4）

1. 運営者で、既定値をアカウント2件・投稿3件にする。
2. 利用者で3件目のアカウントを作ろうとする。
   - 期待：「作れるアカウントは2件までです」と出て作れない。
3. 投稿のスケジュールで4つ目の時刻を足そうとする。
   - 期待：足せず、「1日に投稿できるのは3件までです」と出る。
4. 運営者で、その利用者だけアカウント3件・投稿5件にする。
   - 期待：3件目を作れ、5つまで足せる。画面に「この人だけ」と出る。
5. その利用者の投稿の上限を2件に下げる。
   - 期待：設定の画面に「◯つ目からの時刻には投稿しません」と出る。自動投稿の時刻の処理（テスト）で、早い2つだけ投稿される。
6. 運営者の自分のアカウントで、既定値より多く作る・足す。
   - 期待：どちらもできる。

## 4. 料金

1. 契約中で、アカウントを3件にする。
   - 期待：「契約と支払い」の次の請求の見込みが3,000円。
2. 古い料金（段階制）の契約がある利用者で、数の合わせ直しを走らせる（アカウントを足す、または日次）。
   - 期待：Stripeの契約の項目が新しい料金に替わる（日割りなし）。

## 5. 招待の管理のOFF（US5）

1. `THREADS_ACCESS_MODE="public"`にして起動し直す。
   - 期待：つなぐ画面に申し込みの欄が出ず、「Threadsで許可する」がすぐ出る。
   - 期待：運営者の画面に「この環境では招待の管理を使っていません」と出て、記録は読める。

## 6. テスト版で確かめる（マージのあと）

- ThreadsAutomationに3つのコールバックのURLを登録し、`THREADS_APP_SECRET`を入れる（手順はdocs/external-services-setup.md 3-3・9-8）。
- 2の手順を、テスト版の実際のThreadsアカウントで行う。利用者が承認からつなぐまでの時間（SC-002：10分以内）と、運営者が1件を招待するまでの時間（SC-004：3分以内）を測る。
- テスト版は招待制がONなので、グループの招待リンクから入った人は料金なしで使える（016）。リンクを使わずに入った人は、今のとおり「テスト版は招待された方だけが使えます」が先に出る（契約前の画面より先に判定する）。
