# 画面の契約：Threadsのアルゴリズムの解析

**日付**：2026-11-05 | **計画**：[../plan.md](../plan.md) | **モック**：https://claude.ai/artifact/5GK8yF32kwsAqPVU1SaT8A

色・角丸・ボタンは今の画面（パフォーマンス・外部媒体展開）と同じものを使う。新しい強調の色は足さない（docs/ui-design.md）。

## サイドバー

「自動投稿」の「パフォーマンス」の次に「解析」（`ChartLineIcon`、`path: "analysis"`）。自動投稿のまとまりがOFFなら、まとまりごと出ない（今のまま）。

## /accounts/:accountId/analysis（`pages/analysis.tsx`）

上から次の順（モック「解析（パソコン）」）。

1. **見出し**：「解析」。右に「直近90日・確定した投稿 {n}件」と、範囲の切り替え（「すべて」「ふだんの投稿」。`?scope=`）。
2. **この画面の見方**（閉じたトグル。`HelpToggle` を使う）。箇条書き：
   - 確定した投稿（投稿から約7日）だけで見ています
   - 中央値（真ん中の値）で比べています
   - 表示の順位はThreadsから取れないので、フォロワー数と閲覧から推し量っています（FR-022）
   - 傾向は相関で、原因とは限りません。件数が少ないうちは偶然の差が出ます（FR-031）
   - 宣伝の投稿は、本文に宣伝内容のタイトルかURLがある投稿です
3. **件数が足りないとき**：表の代わりに「あと{needMore}件たまると見られます」（点線の枠。パフォーマンスの空の状態と同じ）。
4. **伸びた傾向**：傾向を灰色の行で並べる（文と、件数・中央値）。右上に「プロンプトに入れる」の切り替え（`Switch`。`canEdit` がなければ出さない）。下に短い説明「次の投稿のプロンプトに入ります（最大5つ）。人柄・CORE RULESを優先します。」。時間帯・曜日の傾向には「時刻の参考」の小さい印を付ける（プロンプトには入らない）。傾向がなければ「まだはっきりした傾向はありません」。
5. **おすすめに乗った目安の投稿**：表（投稿の書き出しと日時・閲覧・広がり・初速・後からの伸び・返信率）。初めは3件、「残りの{n}件を見る」で全部。その下に「ほかの投稿とのちがい（中央値）」の2行の表。`available` が false なら「フォロワー数の記録がある投稿が10件たまると見られます」。
6. **時間帯**：表（件数・閲覧の中央値の棒・反応率・返信率）。件数10件未満の棒は薄い灰色、「件数が少ない」「試していない」の印。下に「自動投稿の時刻の見直しの参考に」（今の時刻と、時間帯の傾向。「投稿の時刻を開く」で投稿の設定へ）。
7. **曜日**・**文字数**（パソコンでは2つ並べる）。
8. **本文の特徴**：あり・なしの件数と閲覧、差（×1.9）。
9. **内容（書き出しの型・テーマ）**：「分類が付いた投稿 {classified}件 / {confirmed}件」、「内容を分類する」ボタン（`canEdit` のとき）、「書き出しの型」「テーマ」の切り替え、表。

スマートフォンの幅（モック「解析（スマートフォン）」）：表は縦の並び（1行＝名前と値の並び）にして、横にスクロールしない（FR-063）。

## 内容を分類する（`components/analysis/ClassifyDialog.tsx`）

モック「内容を分類する」。018の `ExplainBatchPanel`・021の `PolishDialog` と同じ流れ。

- 上に「まだの投稿」「分類済み」の切り替え。
- **まだの投稿**：
  1. **テーマの一覧**：タグで並べ、「テーマを直す」で名前の入力（10個まで）。保存は `PATCH /analysis/settings`。
  2. **① プロンプトをコピー**：`classifyPrompt` の文をコピー。
  3. **② AIの答えを貼る**：入力欄と「読み取る」。
  4. **③ 候補を確かめる**：投稿の書き出し・型・テーマ（選び直せる）。読み取れなかった投稿は理由を出す。
  5. 「{n}件を反映する」で `PUT /analysis/classifications`（`source: "ai"`）。
- **分類済み**：投稿ごとに型とテーマを選び直し、変えたらその場で保存（`source: "manual"`。FR-053）。
- 投稿が0件なら「分類する投稿はありません」。
