# Quickstart：Threadsのアルゴリズムの解析

**Feature**：[spec.md](./spec.md) | **計画**：[plan.md](./plan.md)

## 1. 自動のテスト

```bash
pnpm --filter ./packages/shared test -- analysis prompt
pnpm --filter ./apps/api test -- analysis migration-0020 prompt
pnpm --filter ./apps/web test -- analysis
pnpm --filter ./packages/shared test && pnpm --filter ./apps/api test && pnpm --filter ./apps/web test && pnpm lint && pnpm -r exec tsc --noEmit
```

確かめること：
- **shared**：
  - 祝日：元日・成人の日（1月の第2月曜）・春分の日・振替休日・国民の休日（2026-09-22）が休日、ふつうの平日は平日
  - 投稿ごとの値：反応率・返信率・広がり・初速・後からの伸び、区切り（時間帯は日本時間）、本文の特徴（contracts/analysis.md）
  - 文字数の区切りが、Accountの文字数の設定から決まる（初めの値で 〜77字・78〜117字・118字〜）
  - 夜の投稿の閲覧を高めにした60件で、夜の傾向が出る。10件未満の区切りから傾向が出ない（SC-002）。区切りの種類ごとに1つまで、5つまで
  - 確定した投稿が20件未満なら `needMore` が出て、表が空
  - おすすめに乗った目安：広がりの上位20%かつ1を超える投稿。フォロワー数のない投稿は外れる
  - プロンプトに入れる傾向：時間帯・曜日は入らない。CORE RULESに「絵文字」があると絵文字の傾向が入らない。NGワードを含むテーマの傾向が入らない（SC-003）
  - プロンプト：傾向があると「■伸びた傾向」が低調の節の後に入る。傾向が空なら、本featureの前と同じ文（SC-004）
  - 分類のプロンプトと答えの読み取り（目印あり・前後に文・知らない型・知らないテーマ・番号の抜け）
- **API**：
  - 解析：期間の確定した投稿だけ（遅れて確定・計測できない・91日前は入らない）、範囲 `regular` で宣伝の投稿が外れる
  - 設定：初めの値、保存、衝突（STALE_UPDATE）、テーマを消すと分類のテーマが外れる
  - 分類：保存・入れ替え・ほかのAccountの投稿は `skipped`
  - プロンプト：切り替えOFFで節がない、`trendCount`
  - 守り：自動投稿がOFFは FEATURE_DISABLED、見せてもらっている人・関わりのない人に結果が返らない（SC-005）、`view` だけの人は書けない
  - マイグレーション（足すだけ・投稿の削除で分類が消える）
- **Web**：サイドバーの「解析」、件数不足の表示、傾向と切り替え、おすすめに乗った目安（3件と残り）、時間帯の印、範囲の切り替え、内容を分類する（コピー → 貼る → 候補 → 反映、分類済みを直す）

## 2. 手元で試す

1. 確定した投稿が20件以上あるAccountで、サイドバーの「自動投稿 › 解析」を開く。時間帯・曜日・文字数・おすすめに乗った目安が1画面で見られる（SC-001）。
2. 「この画面の見方」を開き、推し量りであることと、相関であることの説明があることを確かめる。
3. 傾向が出ていれば、「投稿をつくる」でプロンプトを作り、「■伸びた傾向」があることを確かめる。「プロンプトに入れる」を外すと、節がなくなる。
4. 「内容を分類する」でプロンプトをコピーし、ChatGPTの答えを貼って反映する。内容の表に件数が出る。
5. 「分類済み」で1件の型を変え、内容の表の件数が変わることを確かめる。
6. スマートフォンの幅（390px）で、横にスクロールせずに全部の表と傾向に届くことを確かめる（FR-063）。

## 3. テスト版で確かめる（マージのあと）

確定した投稿の多いテスト用のAccountで、出た傾向と、おすすめに乗った目安の投稿が、利用者の感覚と合うかを見る。しきい値（10件・1.5倍・上位20%・90日）を直すかを決める（spec Assumptions）。
