# Feature Specification:AIと壁打ちして課題を埋める

**Feature Branch**: `feature/018-strategy-ai-sparring`

**Created**: 2026-11-02

**Status**: Draft

**Input**: 2026-11-02に、ユーザーが追加機能のアイデアとして「AIと壁打ちして戦略を考える機能」を挙げた（[docs/next-features.md](../../docs/next-features.md) §F）。課題は「戦略（課題の画面）を埋めるのが大変」。今の「AIと深掘り」（014）は1項目ずつ外のAIと往復するので、テキストの20項目を埋めるには20往復かかる。解決として、外のチャットAI（ChatGPT・Claude）と1つの会話でまとめて相談し、AIが出した項目ごとの完成版を、アプリに一括で反映できるようにする。次の2つを決めた：①外のAIを使う（アプリの中でAIを呼ばない。費用をかけない）②項目ごとの「AIと深掘り」はそのまま残す。

**Source**: [docs/next-features.md](../../docs/next-features.md) §F、[014のspec](../014-strategy-guidance/spec.md)（考えるヒント・AIと深掘り・全体をAIと整理する・自動チェック）、[002のspec](../002-strategy-profile/spec.md)（課題の項目と保存）、[Constitution](../../.specify/memory/constitution.md)原則III（外部LLM前提・API依存ゼロ）・原則V（個人運用起点のシンプルさ）。

## 用語

- **壁打ち**：外のチャットAIに、課題のいくつかの項目をまとめて相談すること。AIが質問し、利用者が答え、最後にAIが項目ごとの完成版を出す。
- **壁打ちのプロンプト**：壁打ちを始めるために、アプリがコピーする文。対象の項目の問い・考えるヒント・今の入力と、AIへの頼み方が入る。
- **範囲**：壁打ちで扱う項目の集まり。利用者がプロンプトをコピーする前に選ぶ。
- **項目ごとの完成版**：AIの答えのうち、項目の名前の目印で区切られた、その項目に入れる文。
- **反映の候補**：貼り付けた答えから読み取れた、項目ごとの「今の入力 → 新しい案」の組。
- **対象の項目**：壁打ちで扱える項目。この仕様では、課題の数える16項目のうちテキストの15項目、目的の5問、活動の軸の21項目とする（014の「AIと深掘り」が出る20項目に、活動の軸を足したもの）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 -まとめて壁打ちし、答えを一括で反映する（Priority: P1）

課題がほとんど空の利用者が、課題の画面の「AIと壁打ちして埋める」を押す。範囲を選んで「プロンプトをコピーする」を押し、ChatGPTやClaudeに貼って送る。AIが1〜2問ずつ質問してくるので答えていくと、最後にAIが項目ごとの完成版を出す。利用者はその答えをまるごとアプリに貼る。項目ごとに「今の入力 → 新しい案」が並ぶので、内容を見て、反映したい項目を選んで「選んだ項目を反映する」を押す。入力欄が置き換わり、利用者が「保存」を押すと残る。

**Why this priority**：この機能の中心。1つの会話と1回の貼り付けで、多くの項目を埋められる。

**Independent Test**：空の課題で範囲に「全部」を選び、プロンプトをコピーする。対象の項目すべての完成版を目印つきで含む答えを貼り、すべて選んで反映する。21項目の入力欄が置き換わり、未保存の変更になり、「保存」で残ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 直せる人が課題の画面を開いている、**When** 「AIと壁打ちして埋める」を押す、**Then** 使い方（①範囲を選んでプロンプトをコピーする ②ChatGPTやClaudeに貼って送り、質問に答える ③最後に出た答えをまるごと貼る ④反映する項目を選んで反映し、保存する）、範囲の選び方、「プロンプトをコピーする」、貼り付け欄が出る。
2. **Given** 1の状態、**When** 範囲を選んで「プロンプトをコピーする」を押す、**Then** 壁打ちのプロンプトがクリップボードに入り、「コピーしました」と出る。
3. **Given** 2でコピーした文、**When** 中を見る、**Then** 範囲の項目ごとに、名前・説明・考えるヒント・今の入力（未保存を含む。空なら「未入力」）が並ぶ。範囲の外の項目は、入力のあるものだけが文脈として入る。AIへの頼み方として、次が入る：一度に1〜2問ずつ質問する／利用者の答えにないことを作らない／範囲の項目をすべて聞き終えたら、項目ごとの完成版を決まった形で出す／途中で利用者が「完成版を出して」と送ったら、その時点までの内容で出す／項目どうしで重複・矛盾がないようにする。
4. **Given** AIが項目ごとの完成版を決まった形で出した、**When** 答えをまるごと貼り付け欄に貼る、**Then** 読み取れた項目ごとに、項目の名前・今の入力・新しい案が、表示の順（014の課題の画面の順）に並ぶ。
5. **Given** 4の状態、**When** 反映する項目を選んで「選んだ項目を反映する」を押す、**Then** 選んだ項目の入力欄だけが新しい案に置き換わり、自動チェックと上の数が変わり、未保存の変更になる。貼り付け欄と候補は閉じる。保存するまでサーバーには残らず、「変更を破棄」で戻せる。
6. **Given** 反映する項目を1つも選んでいない、**When** 画面を見る、**Then** 「選んだ項目を反映する」は押せない。
7. **Given** 見せてもらっている人・読むだけの人、**When** 課題の画面を開く、**Then** 「AIと壁打ちして埋める」は出さない。

### User Story 2 -範囲を絞って壁打ちする（Priority: P2）

すでに半分ほど書いた利用者が、まだ書けていない項目だけをAIと相談したい。範囲で「未入力と短めの項目だけ」を選んでコピーすると、プロンプトにはその項目だけが質問の対象として入り、書き終えた項目は文脈として入る。区分（営業導線・アカウントなど）ごとに少しずつ進めたい人は、区分を選んで壁打ちする。

**Why this priority**：1回で全部を相談すると会話が長くなり、AIが形を崩しやすい。書き終えた項目を聞き直されないようにすると、利用者の手間が減る。ただし、まず一括で埋められること（US1）が先。

**Independent Test**：16項目のうち10項目が「十分」の課題で、「未入力と短めの項目だけ」を選んでコピーし、質問の対象に残りの項目だけが入り、十分な項目は文脈に入ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 壁打ちの欄を開いている、**When** 範囲を見る、**Then** 区分（目的・営業導線・アカウント・集客導線・人柄・その他）を選ぶ欄と、「未入力と短めの項目だけにする」の選択が出る。はじめはすべての区分が選ばれ、「未入力と短めの項目だけにする」がオンになっている。
2. **Given** 一部の項目が「十分」、**When** 「未入力と短めの項目だけにする」をオンにしてコピーする、**Then** 質問の対象は、選んだ区分のうち自動チェック（014）が「未入力」か「短め」の項目だけになる。活動の軸は自動チェックがないので、空のときだけ対象に入る。
3. **Given** 区分を1つだけ選んだ、**When** コピーする、**Then** 質問の対象は、その区分の対象の項目だけになる。
4. **Given** 選んだ範囲に対象の項目が1つもない（例：区分を選んでいない、またはすべて「十分」）、**When** 画面を見る、**Then** 「プロンプトをコピーする」は押せず、「この範囲には、相談する項目がありません」と出る。
5. **Given** 範囲を選んだ、**When** 画面を見る、**Then** 質問の対象になる項目の数（例：「8項目を相談します」）が出る。

### User Story 3 -反映する前に、案を見比べて選ぶ（Priority: P2）

すでに書いてある項目にAIが新しい案を出したとき、利用者は今の入力と見比べて、良いほうを選ぶ。今の入力を残したい項目は選ばずに反映する。

**Why this priority**：AIの案がいつも良いとは限らない。自分で書いた文を、気づかないうちに置き換えないようにする。

**Independent Test**：入力のある項目と空の項目の両方を含む答えを貼り、候補の選択のはじめの状態と、選ばなかった項目が変わらないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 候補が並んでいる、**When** はじめの状態を見る、**Then** 今の入力が空の項目は選ばれた状態、今の入力がある項目は選ばれていない状態で並ぶ。
2. **Given** 候補が並んでいる、**When** 「すべて選ぶ」「すべて外す」を押す、**Then** すべての候補の選択がそろって変わる。
3. **Given** 今の入力と新しい案が同じ、**When** 候補を見る、**Then** その項目に「今と同じ」と出し、はじめは選ばない。
4. **Given** 新しい案がその項目の文字数の上限（002の上限）を超えている、**When** 候補を見る、**Then** その項目に「〇文字を超えています。反映した後に短くしてください」と出る。反映はでき、上限を超えている間は今のとおり保存できない。
5. **Given** 候補が並んでいる、**When** 選んで反映する、**Then** 選ばなかった項目の入力欄は変わらない。

---

### User Story 4 -答えの形が崩れていても、読めた分だけ使う（Priority: P3）

会話が長くなって、AIが決まった形を一部崩した。利用者が答えを貼ると、読み取れた項目は候補として並び、読み取れなかった部分はそうとわかる。必要なら、AIに「決まった形で出し直して」と頼む。

**Why this priority**：外のAIは指示どおりに出さないことがある。読めた分を無駄にせず、読めない部分を見落とさないようにする。

**Independent Test**：目印のない答え、知らない項目名を含む答え、同じ項目が2回ある答えを貼り、それぞれの表示を確かめる。

**Acceptance Scenarios**:

1. **Given** 貼った答えに、項目の目印が1つもない、**When** 貼る、**Then** 候補は出さず、「項目ごとの完成版が見つかりませんでした。AIに『決まった形で完成版を出してください』と送り、出た答えを貼ってください」と出る。
2. **Given** 貼った答えに、対象の項目ではない名前の目印がある、**When** 貼る、**Then** 読み取れた項目だけが候補に並び、「読み取れなかった項目：〇〇」と出る。
3. **Given** 貼った答えに、同じ項目が2回以上ある、**When** 貼る、**Then** 最後に出てきたものを候補にする（会話の中で直した版が後に出るため）。
4. **Given** 貼った答えに、範囲の外の対象の項目がある、**When** 貼る、**Then** その項目も候補に並ぶ（AIが関連して直した案も使えるようにする）。
5. **Given** 項目の目印のあとの中身が空、**When** 貼る、**Then** その項目は候補に出さない。

---

### Edge Cases

- **未保存の変更があるままコピーする**：画面の今の入力（未保存を含む）でプロンプトを作る（014 FR-041と同じ）。
- **プロンプトをコピーしてから、貼るまでの間に入力を直した**：候補の「今の入力」は、貼った時点の画面の入力を出す。
- **未保存のまま反映した後に、ほかの人が保存していた**：保存の衝突（008 FR-007）の扱いをそのまま使う。
- **項目の名前の書き方がわずかに違う**（全角・半角、前後の空白、括弧の種類）：同じ項目として読み取る。
- **目印のあとの文の前後の空白・空行**：取り除く。
- **答えの中で、目印の前後にAIの説明文がある**：目印で区切られた中身だけを候補にし、ほかの文は使わない。
- **クリップボードに書けない（ブラウザが許さない）**：プロンプトを選べる形で画面に出し、「コピーできませんでした。全体を選んでコピーしてください」と出す（014・003と同じ扱い）。
- **プロンプトが長い**（全部を選び、すでに長い入力がある）：そのままコピーする。長さを削らない（AIの会話の上限は利用者の使うAIによるため）。
- **項目ごとの「AIと深掘り」の欄と、壁打ちの欄を同時に開く**：どちらも開ける。反映はそれぞれの操作で、後に反映したものが入力欄に残る。
- **近い人間性・下書きの4項目の目印が答えにある**：対象の項目ではないので、「読み取れなかった項目」として示す。

## Requirements *(mandatory)*

### Functional Requirements

**壁打ちの欄とプロンプト（US1・US2）**

- **FR-001**: System MUST 直せる人に、課題の画面の上（「全体をAIと整理する」と同じ場所）に「AIと壁打ちして埋める」を出す。見せてもらっている人・読むだけの人には出さない。
- **FR-002**: System MUST 「AIと壁打ちして埋める」を押すと、使い方（4つの手順）、範囲の選び方、質問の対象の項目の数、「プロンプトをコピーする」、貼り付け欄を出す。もう一度押すと閉じる。開いたかどうかは保存しない。
- **FR-003**: System MUST 範囲として、区分（目的・営業導線・アカウント・集客導線・人柄・その他）を複数選べるようにし、「未入力と短めの項目だけにする」を選べるようにする。はじめはすべての区分を選び、「未入力と短めの項目だけにする」をオンにする。選んだ範囲は保存しない。
- **FR-004**: 質問の対象は、選んだ区分にある対象の項目でなければならない。「未入力と短めの項目だけにする」がオンなら、そのうち自動チェック（014 FR-010）が「未入力」か「短め」の項目に絞る。活動の軸は、空のときだけ絞り込みに残す。
- **FR-005**: System MUST 質問の対象が0のとき、「プロンプトをコピーする」を押せなくし、「この範囲には、相談する項目がありません」と出す。
- **FR-006**: System MUST 壁打ちのプロンプトに、(1)質問の対象の項目ごとの名前・説明・考えるヒント（014 FR-001）・今の入力（未保存を含む。空なら「未入力」）、(2)質問の対象ではない数える項目・目的の5問・活動の軸のうち、入力のある内容（文脈）、(3)AIへの頼み方（US1の受け入れシナリオ3の5点）、(4)完成版の決まった形（項目ごとに、項目の名前を入れた始まりの目印の行・中身・終わりの目印の行。目印の行はそのまま書き写すこと）を入れる。下書きの4項目と「近い人間性」は、質問の対象に入れない。
- **FR-007**: 壁打ちのプロンプトの考えるヒント・項目の名前・説明は、014の項目の定義と同じ1か所のものを使わなければならない（014 FR-005）。

**貼り付けと反映の候補（US1・US3・US4）**

- **FR-010**: System MUST 貼った答えから、FR-006の目印で区切られた項目ごとの完成版を読み取り、対象の項目ごとに1つの反映の候補にする。項目の名前は、全角・半角・前後の空白・括弧の種類の違いを同じものとして扱う。
- **FR-011**: System MUST 同じ項目が2回以上あれば、最後のものを候補にする。中身が空（空白・改行だけ）の項目は候補にしない。
- **FR-012**: System MUST 範囲の外にある対象の項目も、答えにあれば候補にする。
- **FR-013**: System MUST 対象の項目ではない名前の目印があれば、その名前を「読み取れなかった項目」として出す。
- **FR-014**: System MUST 目印が1つも読み取れなければ、候補を出さず、AIに決まった形で出し直してもらう案内（US4の受け入れシナリオ1の文）を出す。
- **FR-015**: System MUST 候補を表示の順（課題の画面の順）に並べ、項目ごとに項目の名前・今の入力（貼った時点の画面の入力。空なら「未入力」）・新しい案・選ぶ印を出す。
- **FR-016**: System MUST 候補の選ぶ印のはじめの状態を、今の入力が空なら選ぶ、入力があれば選ばない、新しい案が今の入力と同じなら選ばない（「今と同じ」と出す）にする。
- **FR-017**: System MUST 「すべて選ぶ」「すべて外す」を出す。
- **FR-018**: System MUST 新しい案が項目の文字数の上限（002）を超えていれば、その候補に超えていることを出す。反映はできる。
- **FR-019**: System MUST 「選んだ項目を反映する」を押すと、選んだ項目の入力欄を新しい案に置き換え、貼り付け欄と候補を閉じる。保存はしない（未保存の変更になる）。選んだ項目が0なら押せない。
- **FR-020**: System MUST 反映した後、自動チェック・上の数・区分のチップの数（014 FR-012・FR-014・FR-018）を、ほかの入力と同じく保存の前に変える。

**今の機能との関係**

- **FR-030**: System MUST 項目ごとの「AIと深掘り」（014 FR-030〜FR-037）を今のまま残す。
- **FR-031**: System MUST 「全体をAIと整理する」（014 FR-040〜FR-042）を今のまま残す。
- **FR-032**: System MUST 課題の保存のしかた（まとめて保存・版による衝突の検知・操作の記録）を変えない。壁打ちのために新しく保存するものはない。

### Key Entities *(include if feature involves data)*

新しく保存するものはない。反映は、今の課題の項目（002・014）の入力欄を、未保存の変更として置き換えるだけ。

- **反映の候補**（画面の中だけ）：項目・今の入力・新しい案・選んだか。貼り付け欄を閉じるか画面を離れると消える。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 課題が空の利用者が、プロンプトのコピー1回と答えの貼り付け1回で、対象の21項目すべてを入力欄に反映できる（今の「AIと深掘り」では20回の往復が要る）。
- **SC-002**: 決まった形どおりに出た答えでは、含まれる項目の100%が反映の候補になる。
- **SC-003**: 反映しても、利用者が「保存」を押すまで、課題の保存された内容は1文字も変わらない。
- **SC-004**: 利用者が選ばなかった項目の入力は、反映の前後で1文字も変わらない。
- **SC-005**: 答えの形が崩れていても、読み取れなかった項目の名前か出し直しの案内が必ず出て、利用者が何も表示されないまま終わることがない。

## 未決定（`/speckit-clarify` で決める）

ユーザーの指示で、次の4点は clarify で決める。この仕様では、仮に次のとおり書いている。

1. **範囲の選び方**：仮に「区分を複数選べる＋『未入力と短めの項目だけにする』」にしている（FR-003・FR-004）。ほかの案：「全部」だけ／区分を1つずつ／「未入力と短めだけ」だけ。
2. **すでに書いてある項目の扱い**：仮に「AIに改善案も出してもらい、反映の候補では選ばない状態で並べる」にしている（FR-016）。ほかの案：すでに書いてある項目には案を出させない（空の項目だけ）。
3. **対象にする項目**：仮に「テキストの15項目＋目的の5問＋活動の軸」の21項目にし、下書きの4項目と近い人間性は入れない（用語「対象の項目」・FR-006）。
4. **「全体をAIと整理する」の答えも取り込めるようにするか**：仮に「取り込まない（今のまま）」にしている（FR-031）。ほかの案：「全体をAIと整理する」のプロンプトにも完成版の形を頼み、同じ貼り付け欄で取り込めるようにする。

## Assumptions

- 外のチャットAI（ChatGPT・Claudeなど）は、プロンプトの指示に従って質問を重ね、最後に決まった形で項目ごとの完成版を出せる。崩れたときは、利用者が出し直しを頼める（US4）。
- AIとの会話の長さの上限は、利用者が使うAIとプランによる。アプリはプロンプトを削らない。範囲を絞る（US2）ことで、会話を短くできる。
- 自動チェックの「未入力」「短め」の判定は、014のものをそのまま使う。
- スマートフォンでも使う。候補は、今の入力と新しい案を縦に並べて読めるようにする。
- 反映の候補は画面の中だけで持ち、閉じると消える。答えを貼り直せば、また出せる。
- 押したときにボタンの位置を変えない（[docs/ui-design.md](../../docs/ui-design.md) §6）。コピーの結果の文は、ボタンの行の外に出す。

## Out of Scope

- アプリの中でAIを呼ぶこと（会話・自動での書き込み）。Constitution原則IIIの範囲の外。アイデア「このアプリ専用のThreadsコンサルAIエージェント」（docs/next-features.md §F）で扱う。
- 宣伝内容・リサーチ（参考投稿）の壁打ち。
- 壁打ちの会話の記録をアプリに残すこと。
- 反映した内容の、項目ごとの元に戻す操作（今の「変更を破棄」で、保存の前の状態に戻せる）。
