# Feature Specification:外部媒体展開

**Feature Branch**: `feature/021-external-media`

**Created**: 2026-11-04

**Status**: Draft

**Input**: 2026-11-04に、ユーザーが「外部媒体展開」を作ると決めた（[docs/next-features.md](../../docs/next-features.md) §F-2「外部媒体のイベント募集を補助する機能」）。宣伝内容（イベント）を、外部のイベント募集サイト（こくちーずプロ・Peatix・つなげーと・ジモティー・YOUTRUST）に載せるときの手間を減らす。媒体の登録画面と同じ順で掲載内容を作り、欄ごとにコピーして貼れるようにする。

**Source**: ユーザーの運営する「港」の管理画面「外部媒体展開」（2026-11-04に読んだ内容。ログインが要るため、URLは載せない）、[002のspec](../002-strategy-profile/spec.md)（宣伝内容）、[019のspec](../019-feature-switches/spec.md)（機能のまとまり）、[Constitution](../../.specify/memory/constitution.md) 4.3.0 原則III（アプリの中でAIを呼ばない）・IV・V。

## Clarifications

### Session 2026-11-04

- Q: イベントの情報（開催日時・会場・住所・定員・参加費・キャンセルの決まりなど）を、どこに持つか？ → A: 宣伝内容に、任意の「イベントの情報」として足す。一度入れれば、Threadsの宣伝投稿にも外部媒体にも使える。宣伝内容の画面では閉じた区分にする。
- Q: 掲載内容のタイトルと本文は、どう作るか？ → A: 媒体の決まりで組み立てたものをすぐ出す。言い回しも整えたいときだけ、外のAIに頼むプロンプトをコピーし、答えを貼って反映する（「AIと考える」と同じ形。原則III）。

- Q: モック（https://claude.ai/artifact/78VBSVeE19t3EqqvjckMRZ ）の画面でよいか？ → A: よい（ルールのチェックの赤の印・一覧→入力→作業の3段も、このまま）。画面は少し複雑なので、まずモックのとおりに作り、テスト版で使いながらシンプルにしていく。

## 用語

- **媒体**：外部のイベント募集サイト。本featureでは、こくちーずプロ・Peatix・つなげーと・ジモティー・YOUTRUSTの5つ。
- **イベントの情報**：宣伝内容のうち、イベントとして載せるための情報（開催日時・会場・定員・参加費など。FR-001）。
- **掲載内容**：宣伝内容（イベント）から、媒体ごとに作る欄の値の集まり。宣伝内容とは別に保存し、直しても宣伝内容は変わらない。
- **入力の画面**：掲載内容を作って直す画面。宣伝内容の元の情報と見比べながら、媒体の欄ごとに直す。
- **作業の画面**：媒体の画面の横に置いて使う画面。媒体の画面の順のSTEPで、上から順にコピーして貼る。
- **ルールのチェック**：媒体の掲載のルールに合わないところを、赤（掲載できない）・黄（確かめる）・参考（知っておくとよいこと）で示すもの。
- **自動の直し**：媒体のルールに合わない行・言葉を、掲載内容から外したり直したりすること。直した内容と理由を残す。
- **状況**：媒体ごとの掲載の進み（未着手・作成中・掲載済み・掲載停止）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 媒体の登録画面の順に、コピーして貼るだけで載せられる (Priority: P1)

オーナーが、宣伝内容（イベント）を選び、媒体（例：Peatix）の「掲載内容を作る」を押す。媒体の登録画面と同じ順・同じ欄の名前で、値が並ぶ。選ぶ欄には、媒体の実際の選択肢と「このイベントでは〇〇を選びます」が出る。「作業を始める」で作業の画面にすると、媒体の画面の順のSTEPが並び、上からコピーして媒体に貼れば、掲載が終わる。

**Why this priority**: 機能の中心。媒体ごとに違う登録画面に、毎回同じイベントを手で打ち直す手間をなくす。

**Independent Test**: 開催日時・会場・定員・参加費のある宣伝内容で、Peatixの掲載内容を作る。Peatixの5ステップの順に欄が並び、イベント名・日時・会場・チケットの値が入っていること、作業の画面のSTEPの「コピー」で値がコピーされることを確かめる。

**Acceptance Scenarios**:

1. **Given** イベントの情報のある宣伝内容、**When** 媒体の「掲載内容を作る」を押す、**Then** 媒体の登録画面と同じ順・同じ区切りで、欄が並ぶ。欄ごとに、媒体の画面での欄の名前・必須の印・「登録後は変更できない」の印（あるもの）・文字数（上限のあるもの）・「コピー」が出る。
2. **Given** 選ぶ欄、**When** 掲載内容を見る、**Then** 媒体の実際の選択肢がすべて並び、「このイベントでは『〇〇』を選びます」と、選んだ理由（例：参加費があるので「有料」）が出る。
3. **Given** 掲載内容、**When** 「作業を始める」を押す、**Then** 作業の画面になり、「上から順番にコピーして、〇〇に貼り付けてください」と、媒体の画面の順のSTEPが並ぶ。STEPごとに、媒体の画面で何をするかの1行と、入れる値と「コピー」が出る。「入力の画面に戻る」で戻れる。
4. **Given** 作業の画面の最後のSTEP、**When** 見る、**Then** 公開したら掲載URLを保存して状況を「掲載済み」にするよう案内があり、媒体ごとの決まり（例：こくちーずは1日3件まで、YOUTRUSTは公開すると下書きに戻せない）が出る。
5. **Given** 掲載内容の欄、**When** 直して保存する、**Then** 掲載内容は保存され、宣伝内容は変わらない。宣伝内容の元の情報は、入力の画面の横に読むだけで出る。

---

### User Story 2 - 媒体のルールに合わないところを、先に直してくれる (Priority: P1)

掲載内容を作ると、媒体ごとのルールのチェックが出る。ルールに合わない行（外部のURL・連絡先・紹介割引・男女差・参加が限られて見える表現など）は、自動で外され、何を外したかと理由が残る。

**Why this priority**: 媒体の審査で消される・止められることを防ぐ。港の運用でも、媒体ごとに禁止がかなり違う。

**Independent Test**: 本文に地図のURL・LINEの案内・紹介割引を書いた宣伝内容で、つなげーとの掲載内容を作る。3つの行が本文から外れ、「自動で直した内容」に理由つきで残ること、ルールのチェックに件数が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 掲載内容、**When** 作る、**Then** 媒体ごとに、赤・黄・参考の件数と、項目ごとの説明（例：【確認】住所が空です）が出る。
2. **Given** 媒体のルールに合わない行、**When** 掲載内容を作る、**Then** その行は掲載内容から外れ（または直され）、「自動で直した内容」に、外した行の書き出しと理由が残る。宣伝内容の文は変わらない。
3. **Given** 赤の項目がある掲載内容、**When** 作業の画面を開く、**Then** 最初のSTEP「ルールの確認」で、赤の項目を直すよう案内される。
4. **Given** 掲載内容の欄を直した、**When** 保存する、**Then** ルールのチェックを、直した内容で出し直す。

---

### User Story 3 - 媒体ごとの画像を、外のAIで作れる (Priority: P2)

媒体ごとに、画像を作るためのプロンプトをコピーできる。媒体の大きさ・一覧での切れ方・画像に入れてはいけないものに合わせてある。

**Why this priority**: 画像は多くの媒体で必須で、媒体ごとに大きさと禁止が違う。アプリの中では画像を作らない（原則III）。

**Independent Test**: Peatixの「画像のプロンプトをコピー」を押し、コピーした文に、イベント名・日時・会場・1840×900の大きさ・入れてはいけないもの（URL・QRコード・口座）が入っていることを確かめる。

**Acceptance Scenarios**:

1. **Given** 掲載内容、**When** 「画像のプロンプトをコピー」を押す、**Then** イベントの情報と、その媒体の画像の大きさ・入れてはいけないもの・目立つ画像の傾向を含むプロンプトがコピーされる。
2. **Given** 画像の種類（イラスト型・写真を使う型）、**When** 選ぶ、**Then** プロンプトが、その種類に合わせて変わる。

---

### User Story 4 - どの媒体に載せたかを残す (Priority: P2)

媒体ごとに、状況（未着手・作成中・掲載済み・掲載停止）と掲載URLを残す。宣伝内容を選ぶ一覧に、掲載済みの媒体が出る。

**Why this priority**: 同じイベントを同じ媒体に2回載せる（多くの媒体で禁止）ことと、載せ忘れを防ぐ。

**Independent Test**: Peatixの状況を「掲載済み」にし、掲載URLを入れて保存する。宣伝内容を選ぶ一覧に「掲載済み：Peatix」が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 媒体のカード、**When** 状況と掲載URLを入れて保存する、**Then** 保存され、次に開いたときもそのまま出る。
2. **Given** 掲載済みの媒体がある宣伝内容、**When** 宣伝内容を選ぶ一覧を見る、**Then** 「掲載済み：〇〇」が出る。
3. **Given** 掲載内容を作ったことがある媒体、**When** もう一度「掲載内容を作る」を押す、**Then** 直したところが消えることを確かめてから作り直す。

---

### Edge Cases

- イベントの情報が足りない（開催日時・会場がない）：その欄は空にし、「〇〇がありません。入れてください」と黄で出す。作ることは止めない。
- 終了日時がない：終了の欄は空にし、決めて入れるよう出す（港と同じ）。
- 無料のイベント：媒体ごとの無料の扱いにする（例：つなげーとはチケットを作らない、こくちーずは「無料」を選ぶ）。
- 参加費の金額がない（参加費の説明だけ）：金額の欄は空にし、黄で入れるよう出す。
- 住所の欄が空（会場で開くのに、都道府県・市区町村がない）：その欄は空にし、住所が必須の媒体（こくちーずプロ・YOUTRUST）では黄で出す。
- 宣伝内容を消した：掲載内容と状況も消える。
- 宣伝内容を直した：掲載内容は変わらない。宣伝内容が掲載内容を作った後に変わったことを示し、作り直せるようにする。
- 掲載URLの形がURLでない：保存しない。
- スマートフォン：作業の画面も入力の画面も、横にスクロールせずに使える。

## Requirements *(mandatory)*

### Functional Requirements

#### イベントの情報

- **FR-001**: Users MUST be able to 宣伝内容に、任意の「イベントの情報」を入れる：開催日時（開始・終了）・会場か オンラインか・会場名・住所（都道府県・市区町村・番地・建物）・最寄り駅・定員・参加費（金額と、割引などの説明）・キャンセルの決まり・主催者名・対象者。申込先のURLは、今の「専用URL」を使う（二重に入れない）。宣伝内容の画面では、閉じた区分「イベントの情報」に置き、入れなくても今までどおり保存できる。
- **FR-001a**: System MUST イベントの情報を、Threadsの宣伝投稿のプロンプトにも入れる（宣伝内容の材料の1つとして。入っていなければ今と同じ文）。
- **FR-001b**: System MUST 外部媒体展開で選べる宣伝内容を、イベントの情報に開催日時があるものだけにする。選べるものが1つもなければ、「宣伝内容に、イベントの情報を入れると使えます」と宣伝内容への案内を出す。
- **FR-002**: System MUST 媒体ごとに毎回同じ値（事務局名・連絡先の電話番号とメールアドレス・主催グループ・主催サークル・運営者名など）を、Accountごとの「媒体の既定値」として保存し、掲載内容に最初から入れる。

#### 掲載内容（入力の画面）

- **FR-010**: System MUST 媒体ごとに、その媒体の登録画面と同じ順・同じ区切り（ステップ）で欄を並べる。欄ごとに、媒体の画面での欄の名前・必須・登録後に変更できない・文字数と上限・「コピー」を出す。
- **FR-011**: System MUST 選ぶ欄には、媒体の実際の選択肢をすべて出し、宣伝内容から選んだ値と理由を出す。決められないときは、選ばずに理由を出す。
- **FR-012**: System MUST 掲載内容のタイトル・本文を、媒体ごとの決まり（文字数の上限、冒頭に置くもの、上位に出やすい形）に合わせて組み立てる。タイトルは候補を2〜3案出す。
- **FR-012a**: Users MUST be able to 媒体ごとに「AIと整える」で、タイトルと本文の言い回しを外のAIに頼むプロンプトをコピーし、返ってきた答えを貼って、タイトルと本文に反映する。プロンプトには、媒体の決まり（文字数・冒頭に置くもの・禁止の表現）と、宣伝内容とイベントの情報を入れる。反映した後も、ルールのチェックと自動の直しを通す。アプリの中ではAIを呼ばない（原則III）。
- **FR-013**: System MUST 掲載内容を、宣伝内容とは別に、宣伝内容と媒体ごとに保存する。保存しても、宣伝内容は変わらない。
- **FR-014**: System MUST 入力の画面に、宣伝内容の元の情報（イベントの情報を含む）を読むだけで出す。
- **FR-015**: System MUST 「まとめてコピー」で、その媒体の掲載内容をすべて、欄の名前つきで1つの文にしてコピーできる。

#### ルールのチェックと自動の直し

- **FR-020**: System MUST 媒体ごとに、ルールのチェックを赤・黄・参考で出す。チェックの内容は媒体ごとに決め、少なくとも次を含む：必須の欄が空、文字数の上限を超える、媒体で禁止の表現（外部への誘導・連絡先・紹介の特典・男女差・参加が限られて見える表現・ビジネスの勧誘など）、媒体の手数料と支払いの決まり、画像の大きさ。
- **FR-021**: System MUST 媒体のルールに合わない行・言葉を、掲載内容から外す（または直す）。外した行の書き出しと理由を「自動で直した内容」に残す。どの行を外すかは媒体ごとに決める（こくちーずプロは外さない）。
- **FR-022**: System MUST 掲載内容を直して保存したら、ルールのチェックを出し直す。

#### 作業の画面

- **FR-030**: System MUST 媒体ごとに、作業の画面を出す。媒体の画面の順のSTEPに、媒体の画面で何をするかの1行・入れる値・「コピー」を並べる。最初のSTEPは「ルールの確認」、最後のSTEPは「公開する」とする（こくちーずプロだけは、登録の最初の画面で選ぶ2つを先にし、ルールの確認は公開の前に置く。港と同じ。contracts/media.md）。どの媒体も、公開後に掲載URLを保存して状況を「掲載済み」にするよう案内する。
- **FR-031**: System MUST 作業の画面と入力の画面を、同じ媒体の中で切り替えられるようにする。作業の画面を開いても、保存も状況の変更もしない。
- **FR-032**: System MUST 最後のSTEPに、媒体ごとの決まり（登録の数の上限・二重の掲載の禁止・公開後に戻せない・通知の時刻など）を出す。

#### 画像のプロンプト

- **FR-040**: System MUST 媒体ごとに、画像を作るためのプロンプトをコピーできるようにする。プロンプトには、イベントの情報と、媒体の画像の大きさ・縦横の比・一覧での切れ方・入れてはいけないもの（URL・QRコード・連絡先・他のサイトの名前など）を入れる。
- **FR-041**: System MUST 画像の種類（イラスト型・写真を使う型）を選べるようにし、プロンプトを変える。アプリの中では画像を作らない。

#### 状況

- **FR-050**: System MUST 宣伝内容と媒体ごとに、状況（未着手・作成中・掲載済み・掲載停止）と掲載URLを保存する。初めは未着手。掲載内容を作ったら作成中にする。
- **FR-051**: System MUST 宣伝内容を選ぶ一覧に、掲載済みの媒体を出す。
- **FR-052**: System MUST 掲載内容を作り直す前に、直したところが消えることを確かめる。

#### 範囲と画面

- **FR-060**: System MUST 本featureを、機能のまとまり「戦略」に入れる（019）。戦略が使えない人には出さない。
- **FR-061**: System MUST 外部媒体展開（掲載内容・状況・媒体の既定値）を、オーナーと担当の人にだけ見せ、作る・直すを許す。見せてもらっている人と関わりのない人には出さない（媒体の既定値に連絡先が入るため。research.md R7）。宣伝内容のイベントの情報は、宣伝内容と同じく見せてもらっている人も読める。判定は今の判定の1か所を通す（原則V）。
- **FR-062**: System MUST 本featureの画面を、サイドバーの「戦略」の中に置く（宣伝内容の近く）。チームの画面には足さない。個人運用の画面に足すのは、サイドバーの1行と、宣伝内容の閉じた区分「イベントの情報（任意）」だけにする。
- **FR-063**: System MUST スマートフォンの幅でも、横にスクロールせずに、すべての欄とコピーに届くようにする。
- **FR-064**: System MUST 掲載内容の保存は、別のタブ・端末での変更とぶつかったら知らせる（002 FR-020と同じ）。

### Key Entities *(include if feature involves data)*

- **イベントの情報**：宣伝内容に任意で足す。開催日時（開始・終了）・会場かオンラインか・会場名・住所・最寄り駅・定員・参加費（金額と説明）・キャンセルの決まり・主催者名・対象者（FR-001）。申込先は「専用URL」。
- **媒体の既定値**：Accountごと・媒体ごとの、毎回同じ値（事務局名・連絡先・主催グループなど）。
- **掲載内容**：宣伝内容×媒体ごと。欄の値・自動で直した内容・作った日時・宣伝内容のその時点の版。
- **掲載の状況**：宣伝内容×媒体ごと。状況・掲載URL・最後に変えた日時と人。
- **媒体の決まり**：媒体ごとの欄の並び・選択肢・文字数・ルール・画像の大きさ・作業のSTEP。アプリが持つ定数で、利用者は変えない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: イベントの情報のある宣伝内容から、1つの媒体の掲載内容が、1回の操作で出る。
- **SC-002**: 利用者が、作業の画面だけを見ながら、媒体の登録を終えられる（媒体の欄の名前と並びが一致し、迷う欄がない）。5つの媒体それぞれで、テスト版で通しで確かめる。
- **SC-003**: 媒体のルールで禁止の行（外部のURL・連絡先・紹介の特典）が、その媒体の掲載内容に1つも残らない（こくちーずプロを除く）。
- **SC-004**: 掲載内容を直しても、宣伝内容が1文字も変わらない。
- **SC-005**: 戦略が使えない人・関わりのない人・見せてもらっている人に、掲載内容と状況が1つも返らない。

## Assumptions

- 媒体へ自動で投稿はしない。コピーして、利用者が媒体の画面に貼る。
- 媒体の登録画面・ルール・選択肢は、2026-11-04 時点の港の管理画面の内容に合わせる。媒体が画面を変えたら、アプリの定数を直す。
- 画像はアプリの中で作らない（原則III）。
- 口座・PayPayの情報は、掲載内容に入れない（港と同じ）。
- 媒体ごとの既定値（電話番号・メールアドレス）は、Accountのオーナーと担当の人だけが見られる。見せてもらっている人には出さない。
- 「掲載作業を開始」は見た目を切り替えるだけで、保存しない（港と同じ）。

## Dependencies
