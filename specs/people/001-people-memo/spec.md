# Feature Specification：人物メモ（アンケートから人を覚え、次の会に誘う）

**Feature Branch**: `feature/people-001-people-memo`

**Created**: 2026-11-13

**Status**: Draft

**Input**: めぐるの新しいアプリ「人物メモ」（アプリのID `people`、表示名「めぐる 人物メモ」）の最初のfeature。作り手が港で月に1回開くIT交流会で、会った人を後から思い出せず、次の会に誰を誘えばよいか分からない。毎回取っているGoogleフォームのアンケートの回答から人の一覧を作り、人ごとにイベントをまたいで「アンケートの答え」「自分のメモ（任意）」「声かけの記録」をつなげる。次の会が決まったら、声をかけてよい人のうち「前に来た」「次回も来られそうと答えた」「ITやAIに興味がある」人が並び、作り手はLINEで声をかける。参加者に新しい手間はかけない。

**Source**: [プロダクトブリーフ](../../../_bmad-output/initiative-threads-grower-app/brief-people-memo/brief-people-memo.md)・[補足](../../../_bmad-output/initiative-threads-grower-app/brief-people-memo/addendum.md)（2026-10-11のアンケートの9つの質問・画面の形・モック）、[競合調査](../../../_bmad-output/initiative-threads-grower-app/research-people-memo-competitors/)、[docs/app-separation.md](../../../docs/app-separation.md)（パターン①）、[docs/product-structure.md](../../../docs/product-structure.md)（スイートの形・スマートフォンのメニュー）、[specs/collect/001-event-day-collection](../../collect/001-event-day-collection/spec.md)（既定でOFFのアプリの出し方）、[specs/meguru/029-threads-pattern1](../../meguru/029-threads-pattern1/spec.md)（出来事の仕組み）、[Constitution](../../../.specify/memory/constitution.md)（原則III・技術スタック制約「アプリのデータの分け方」）。

## Clarifications

### Session 2026-11-13（仕様を書く前にユーザーと決めたこと）

- Q：Googleフォームの回答を、最初の版ではどう取り込むか？ → A：**回答のCSVを書き出して画面に上げる**。Googleのログインや許可は求めない。会の後に1回行う作業とする。
- Q：イベントごとにフォームの質問が少しずつ違うとき、列と項目の対応はどうするか？ → A：**取り込むときに画面で選び、覚えておく**。同じ質問文の列は、次から自動で当てる。質問が変わっても取り込める。
- Q：同じ人かどうかは、どうつなぐか？ → A：**候補を出して、作り手が手で確定する**。取り込むとき、LINE名や本名が同じ人を「同じ人かも」と出し、作り手が「つなぐ」「別の人」を選ぶ。勝手にはつながない。
- Q：最初の版は、だれが使えるか？ → A：集金管理と同じく**既定でOFF**。運営者がONにした人だけが使える。**料金はかけない**。ほかの主催者へ広げるときに料金を決める。
- Q：「リピーター」はどう数えるか？ → A：**作り手のイベントに2回以上来た人の数**。作り手が決めた目標の人数と比べる。
- Q：声をかけてよい人の絞り方は？ → A：**目的ごとに絞る**。交流会への誘いは、アンケートの「個別に案内してよいか」で「交流会・勉強会の案内」を選んだ人だけ。仕事の相談先へのつなぎは「転職・求人情報」か「副業・業務委託案件」を選んだ人だけ。「個別の案内は希望しない」を選んだ人は、どちらの候補にも出さない。手で足した人は、作り手が同意を選ぶ。
- Q：人物メモの「イベント」はどう持つか？ → A：**人物メモの中で作る**。取り込むときに、どのイベントの回答かを選ぶか作る。集金管理・めぐる Threadsのイベントとは、あとで出来事でつなぐ（このfeatureでは作らない）。
- Q：参加者から「自分の記録を消してほしい」と言われたら？ → A：**その人を全部消せる**。人のページから消すと、アンケートの答え・メモ・声かけの記録をすべて消す。会ごとの参加者数だけは数として残す。

## 用語

- **作り手**：このアプリの利用者。イベントを開く主催者で、ほかの会にも参加者として出る。めぐるにログインする。
- **参加者**：作り手のイベントに来た人や、作り手がほかの会で会った人。このアプリは使わない（ログインしない）。アンケートに答えるだけ。
- **イベント**：人物メモの中のイベント。名前と開催日を持つ。作り手が開いた会か、参加者として出た会か（自分の会かどうか）を持つ。
- **アンケート**：イベントごとのGoogleフォーム。作り手が作って、参加者が答える。人物メモはフォームを作らない。
- **回答**：アンケートの1人分の答え。取り込むと、その人が「そのイベントに来た」記録になる。
- **取り込み**：アンケートの回答のCSVを上げて、人と回答をアプリに入れること。
- **列の対応**：CSVの列（質問）が、人物メモのどの項目（LINE名・本名・次回参加・欲しいつながり・キャリアの興味・個別の案内の同意など）にあたるか。質問文ごとに覚える。
- **人**：人物メモの中の1人。本名・LINE名（別名を複数持てる）・来たイベント・回答・メモ・声かけの記録を持つ。
- **別名**：その人のLINE名。LINE名は変えられるので、取り込むたびに新しいLINE名は別名として足す。
- **同じ人の候補**：取り込んだ回答のLINE名や本名が、すでにいる人と同じとき、「同じ人かも」と出す組。
- **メモ**：作り手が人に足す、見た目の特徴・話したこと。任意。
- **声かけ**：作り手が人に、ある目的で声をかけること。目的は「交流会への誘い」と「仕事の相談先へのつなぎ」の2つ。
- **進み具合**：声かけがどこまで進んだか。交流会への誘いは「興味を聞いた → リンクを送った → 来た」、仕事の相談先へのつなぎは「本人に聞いた → OKをもらった → つないだ」。
- **同意**：その人が、どの目的の個別の案内を受けてよいか。アンケートの「個別に案内してよいか」の答えから決める（手で足した人は作り手が選ぶ）。
- **誘う候補**：ある目的で、同意があり、絞り込みに合う人の一覧。
- **リピーター**：作り手の会（自分の会）に2回以上来た人。
- **リピーターの目標**：作り手が決める、リピーターの人数の目標。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - アンケートのCSVを取り込み、人の一覧を作る (Priority: P1)

作り手は会の後、Googleフォームの回答のスプレッドシートからCSVを書き出し、人物メモに上げる。どのイベントの回答かを選び（なければ作り）、初めての質問には「この列は何か」を選ぶ。取り込むと、回答した人が人の一覧に入り、そのイベントに来た記録と、アンケートの答えが人ごとに残る。

**Why this priority**：人の一覧も誘う候補も、すべてアンケートの回答が土台になる。これがないと何もできない。

**Independent Test**：2026-10-11の形のアンケートのCSV（9つの質問・20行）を上げ、イベント「IT交流会 10/11」を作って取り込むと、20人が人の一覧に出て、それぞれにLINE名・次回参加の答え・欲しいつながり・キャリアの興味・同意が残る。

**Acceptance Scenarios**：

1. **Given** 作り手がまだ何も取り込んでいない、**When** CSVを上げてイベントを作り、列の対応を選んで取り込む、**Then** 回答した人が人の一覧に入り、それぞれにそのイベントに来た記録とアンケートの答えが残る。
2. **Given** 前に同じ質問文の列を取り込んだ、**When** 次のイベントのCSVを上げる、**Then** 同じ質問文の列は、前と同じ項目に自動で当たる。作り手は、新しい質問の列だけを選べばよい。
3. **Given** 列の対応を選ぶ画面、**When** 作り手がLINE名の列を選ばずに取り込もうとする、**Then** 取り込めず、「LINE名の列を選んでください」と出る（LINE名は人を見分けるのに要る）。
4. **Given** 人物メモの項目にあたらない質問（満足度・もっとこうだったら嬉しいことなど）、**When** 取り込む、**Then** その答えも、回答の一部としてその人のページで読める（項目にあたらない答えも捨てない）。
5. **Given** 同じCSVをうっかりもう一度上げた、**When** 取り込もうとする、**Then** すでに取り込んだ回答は二重に入らない（同じイベントで、回答の時刻とLINE名が同じ回答は1つとして扱う）。
6. **Given** 取り込みの前、**When** 作り手が画面を見る、**Then** 何人が新しく入り、何人が同じ人の候補になり、何行が取り込めないか（LINE名が空など）が、取り込む前に分かる。

### User Story 2 - 同じ人をつなぎ、手で人を足す (Priority: P1)

取り込むとき、LINE名や本名がすでにいる人と同じ回答は「同じ人かも」と出る。作り手は1組ずつ「つなぐ」か「別の人」を選ぶ。つなぐと、その回答は前からいる人のものになり、来たイベントが増える。アンケートのない会で会った人は、作り手が手で足せる。

**Why this priority**：同じ人がイベントごとに別の人として増えると、「前に来た人」も「リピーター」も正しく出ない。人の一覧が正しいことが、誘う候補の土台になる。

**Independent Test**：10/11の回答を取り込んだあと、11/25のCSV（10/11と同じLINE名の人が5人いる）を上げると、5組が同じ人の候補に出る。4組を「つなぐ」、1組を「別の人」にすると、4人は来たイベントが2つになり、1人は新しい人として入る。

**Acceptance Scenarios**：

1. **Given** 取り込む回答のLINE名か本名が、すでにいる人と同じ、**When** 取り込みの画面を開く、**Then** その回答と前からいる人が「同じ人かも」として並び、作り手は「つなぐ」「別の人」を選べる。選ぶまで、勝手にはつながない。
2. **Given** 「つなぐ」を選んだ、**When** 取り込む、**Then** その回答は前からいる人のものになり、来たイベントに今回のイベントが足される。回答のLINE名が前と違えば、別名として足される。
3. **Given** LINE名も本名も違うが、作り手が同じ人だと分かっている、**When** 人のページで「この人と同じ人」として別の人を選ぶ、**Then** 2人が1人にまとまり、来たイベント・回答・メモ・声かけの記録がすべて1人に集まる。
4. **Given** 間違ってつないでしまった、**When** 人のページで、ある回答を「別の人に分ける」、**Then** その回答と、その回答で来た記録が、新しい人に分かれる。
5. **Given** アンケートのない会で会った人、**When** 作り手が人を手で足し、名前・LINE名・会ったイベント・同意（どの目的の声かけをしてよいか）を入れる、**Then** その人が人の一覧に入り、誘う候補にも同意に沿って出る。

---

### User Story 3 - 次の会の誘う候補を見て、声をかけ、記録する (Priority: P1)

次の会が決まったら、作り手は「交流会への誘い」の候補を開く。同意がある人のうち、前に来た人・次回も来られそうと答えた人・ITやAIに興味がある人・最後に会ったのがいつかで絞って並べられる。作り手は相手を選び、誘いの文をコピーしてLINEで送り、進み具合（興味を聞いた → リンクを送った → 来た）を残す。

**Why this priority**：これが作り手のいちばんの困りごと（次の会に誰を誘えばよいか分からない）を解く。US1・US2で作った人の一覧を、実際の声かけに使う。

**Independent Test**：10/11と11/25の回答を取り込んだ状態で、12月の会への誘いの候補を開き、「前に来た」「次回も来られそうと答えた」で絞ると、該当する人だけが並ぶ。「個別の案内は希望しない」と答えた人は出ない。1人を選んで文をコピーし、「興味を聞いた」にすると、その人のページと候補の一覧に進み具合が出る。

**Acceptance Scenarios**：

1. **Given** 人の一覧がある、**When** 作り手が「交流会への誘い」の候補を開く、**Then** 「交流会・勉強会の案内」に同意した人（手で足した人は作り手が同意を選んだ人）だけが並ぶ。「個別の案内は希望しない」と答えた人は出ない。
2. **Given** 候補の一覧、**When** 作り手が「前に来た（自分の会に1回以上）」「次回も来られそうと答えた」「欲しいつながり」「キャリアの興味」「最後に会った日」で絞る、**Then** 条件に合う人だけが、最後に会った日の新しい順に並ぶ。
3. **Given** 誘う会（人物メモのイベント）を選んだ、**When** 候補の1人の「文をコピー」を押す、**Then** 相手の名前と誘う会の名前・日にちが入った誘いの文がコピーされ、LINEに貼れる。作り手は文の型を自分で変えられる。
4. **Given** 声をかけた、**When** 作り手が進み具合を「興味を聞いた」「リンクを送った」にする、**Then** その人のページと候補の一覧に、誘う会ごとの進み具合が出る。同じ会に、同じ人へ二重に声をかけた記録は作らない（進み具合を進める）。
5. **Given** 誘った人が、誘った会のアンケートに答えた（その会に来た）、**When** その会の回答を取り込み、同じ人としてつながった、**Then** 進み具合が自動で「来た」になる。
6. **Given** スマートフォン、**When** 作り手が候補の一覧を開く、**Then** 下のバー（誘う候補・人・取り込み・イベント）から開け、1人を選んで文をコピーするまでが片手で済む。

### User Story 4 - 人のページで、その人を思い出す (Priority: P2)

作り手は人の一覧から名前やLINE名で探し、人のページを開く。本名・LINE名の別名・来たイベント・イベントごとのアンケートの答え・メモ（見た目の特徴・話したこと）・声かけの記録が1ページで読める。会場で「お久しぶりです」と声をかけられたときや、申し込み一覧を見たときにも使う。

**Why this priority**：誘う候補（US3）がなくても、人を思い出す道具として役に立つ。ただし、まず候補を出すことを優先する。

**Independent Test**：2回来た人のページを開くと、来た2つのイベント・それぞれの回答・LINE名の別名が出る。メモに「メガネ、Pythonの話」と足すと、次に開いたときも残っている。人の一覧で別名のLINE名を入れて探すと、その人が出る。

**Acceptance Scenarios**：

1. **Given** 人の一覧、**When** 作り手が名前（本名）かLINE名（今のものでも別名でも）の一部を入れる、**Then** 合う人が出る。
2. **Given** 人のページ、**When** 開く、**Then** 本名・LINE名の別名・来たイベント（新しい順）・イベントごとのアンケートの答え・メモ・声かけの記録が出る。
3. **Given** 人のページ、**When** 作り手がメモ（見た目の特徴・話したこと）を書く、**Then** 保存され、人の一覧の検索でもメモの言葉で探せる。
4. **Given** 人の一覧、**When** 作り手が来たイベント・次回参加の答え・欲しいつながり・キャリアの興味・最後に会った日で絞る、**Then** 合う人だけが出る（誘う候補と同じ絞り込みを、同意に関わらず使える）。
5. **Given** 人のページ、**When** 作り手が本名を直す、**Then** 以降の検索・誘いの文に新しい本名が使われる。

---

### User Story 5 - リピーターの目標と今の数を比べる (Priority: P2)

作り手はリピーターの目標（例：10人）を決める。人物メモは、自分の会に2回以上来た人の数を数え、目標と並べて出す。会ごとに、初めて来た人と前にも来た人の数も出る。

**Why this priority**：「リピーターを増やす」という作り手の目的が、どこまで来たかを示す。誘う候補（US3）の効き目を確かめるのにも使う。

**Independent Test**：目標を10人にする。10/11と11/25の回答を取り込み、両方に来た人が4人なら、「リピーター 4人／目標 10人」と出る。11/25の会には「初めて 6人・前にも来た 4人」と出る。

**Acceptance Scenarios**：

1. **Given** 作り手が目標を決めていない、**When** ホーム（誘う候補の画面の上）を開く、**Then** 今のリピーターの数と、「目標を決める」が出る。
2. **Given** 目標を10人に決めた、**When** 開く、**Then** 「リピーター 4人／目標 10人」のように、今の数と目標が並ぶ。
3. **Given** 自分の会ではない（参加者として出た）イベントで会った人、**When** 数える、**Then** そのイベントはリピーターの回数に数えない（自分の会だけを数える）。
4. **Given** イベントの一覧、**When** 自分の会を開く、**Then** その会の参加者数・初めて来た人の数・前にも来た人の数が出る。

---

### User Story 6 - 仕事の相談先へつなぐ記録を残す (Priority: P2)

作り手は、イベントの一環として、仕事の相談先へ人をつなぐことがある。「仕事の相談先へのつなぎ」の候補を開くと、「転職・求人情報」か「副業・業務委託案件」に同意した人だけが並ぶ。作り手はつなぐ前に必ず本人に聞き、OKをもらってからつなぐ。アプリは「本人に聞いた → OKをもらった → つないだ」を記録するだけで、相手の情報を外へ渡さない。

**Why this priority**：作り手の第二の使い道。交流会への誘い（US3）と同じ仕組みで作れるが、まず誘いを優先する。

**Independent Test**：「副業・業務委託案件」に同意した人が3人いるとき、つなぎの候補を開くと3人だけが並ぶ。1人を「本人に聞いた → OKをもらった → つないだ」まで進めると、その人のページに、いつ・どこへつないだか（作り手が書く相談先の名前）が残る。

**Acceptance Scenarios**：

1. **Given** 人の一覧、**When** 「仕事の相談先へのつなぎ」の候補を開く、**Then** 「転職・求人情報」か「副業・業務委託案件」に同意した人だけが並ぶ。「個別の案内は希望しない」と答えた人は出ない。
2. **Given** つなぎの候補、**When** 作り手が相談先の名前（例：〇〇社の採用）を書いて声かけを始める、**Then** 進み具合は「本人に聞いた」から始まる。
3. **Given** 「本人に聞いた」、**When** 作り手が「OKをもらった」にせずに「つないだ」にしようとする、**Then** できない（本人のOKを先に記録する）。
4. **Given** つないだ、**When** その人のページを開く、**Then** いつ・どの相談先へ・だれの判断でつないだか（作り手）が残っている。アプリは相手の情報を外へ送らない。

---

### User Story 7 - 参加者の求めで、その人の記録を消す (Priority: P3)

参加者から「自分の記録を消してほしい」と言われたら、作り手は人のページから「この人を消す」を選ぶ。その人のアンケートの答え・メモ・声かけの記録がすべて消える。会ごとの参加者数だけは、数として残る。

**Why this priority**：めったに起きないが、他人の個人の情報を預かる道具として、必ず持つべき操作。

**Independent Test**：10/11に来た人を消すと、その人は人の一覧・誘う候補・検索に出なくなり、回答・メモ・声かけの記録も残らない。10/11の会の参加者数は変わらない。

**Acceptance Scenarios**：

1. **Given** 人のページ、**When** 作り手が「この人を消す」を選ぶ、**Then** 確かめの画面（名前を入れて確かめる）を経て、その人の回答・メモ・声かけの記録・別名がすべて消える。元に戻せない。
2. **Given** 人を消した、**When** その人が来たイベントの参加者数を見る、**Then** 数は変わらない（人は特定できないが、数としては残る）。
3. **Given** 人を消した、**When** その人が次の会のアンケートにまた答え、取り込む、**Then** 新しい人として入る（消した人の記録は戻らない）。

### Edge Cases

- **CSVの文字化け**：Googleのスプレッドシートから書き出したCSV（UTF-8。先頭に印が付くことがある）を、文字化けせずに読む。読めない形式なら、「Googleフォームの回答のスプレッドシートから『CSV形式でダウンロード』したファイルを上げてください」と出す。
- **1つのCSVの中で同じ人が2回答えた**：同じLINE名の行が2つあれば、取り込む前に知らせ、作り手が1つを選ぶか、2つとも別の人として入れるかを選ぶ。
- **LINE名が空の行**：取り込めない行として数え、取り込む前に何行あるかを出す（LINE名は必須の質問だが、列の対応を間違えると空になる）。
- **同意の列がない・答えが空**：その回答では、どの目的の同意もないものとして扱う（候補に出さない）。作り手は、人のページで同意を直せる（例：口頭でOKをもらった）。
- **同意が後の回答で変わった**：同じ人の、新しいイベントの回答の同意を使う（新しい答えを優先する）。
- **複数選択の答え**：Googleフォームの複数選択の答え（「、」区切り）を、選んだ項目ごとに分けて持つ。フォームにない「その他」の自由記述も、そのまま残す。
- **質問文がイベントごとに少し違う**：質問文が違えば、新しい列として作り手に対応を選んでもらう（似ている質問文を推し量って勝手に当てない）。
- **イベントを間違えて取り込んだ**：取り込みは、イベントごとに取り消せる（その取り込みで入った回答と、その回答だけで作られた人を消す。メモや声かけを書いた人は、確かめてから消す）。
- **同じ名前の別人**：LINE名が同じでも、作り手が「別の人」を選べば別の人として持つ。同じLINE名の人が複数いる候補は、来たイベントと答えを並べて見分けられるようにする。
- **作り手が人物メモをOFFにされた**：運営者がOFFにすると、作り手は人物メモを開けなくなる。記録は消えず、ONに戻すと前のまま使える。
- **作り手がめぐるを退会した**：その作り手の人物メモの記録（人・回答・メモ・声かけ）をすべて消す。
- **スマートフォンでの取り込み**：取り込み（列の対応・同じ人のつなぎ）はパソコンでの作業を想定するが、スマートフォンでもできる（狭い画面でも、1列・1組ずつ選べる）。

## Requirements *(mandatory)*

### Functional Requirements

**取り込み**

- **FR-001**：作り手は、Googleフォームの回答のCSVを上げて取り込めなければならない。Googleのログインや許可は求めない。
- **FR-002**：取り込むとき、作り手はどのイベントの回答かを、既存のイベントから選ぶか、新しく作らなければならない（名前・開催日・自分の会かどうか）。
- **FR-003**：アプリは、CSVの列（質問文）ごとに、人物メモの項目（LINE名・本名・次回参加・友達を誘えるか・欲しいつながり・キャリアの興味・個別の案内の同意・回答の時刻、またはどれにもあたらない）を作り手に選ばせなければならない。LINE名の列は必須とする。
- **FR-004**：アプリは、作り手ごとに、質問文と項目の対応を覚え、同じ質問文の列には次から自動で当てなければならない。作り手は当てた対応を直せる。
- **FR-005**：アプリは、項目にあたらない答えも、回答の一部として残さなければならない。
- **FR-006**：アプリは、取り込む前に、新しく入る人数・同じ人の候補の組数・取り込めない行数を示さなければならない。
- **FR-007**：同じイベントで、回答の時刻とLINE名が同じ回答は、二重に取り込んではならない。
- **FR-008**：作り手は、イベントごとに取り込みを取り消せなければならない（その取り込みで入った回答と、それだけで作られた人を消す。メモや声かけのある人は確かめてから）。
- **FR-009**：アプリは、「個別に案内してよいか」の答えから、人ごとに目的ごとの同意を決めなければならない：「交流会・勉強会の案内」→ 交流会への誘いの同意、「転職・求人情報」または「副業・業務委託案件」→ 仕事の相談先へのつなぎの同意、「個別の案内は希望しない」→ どちらの同意もない。答えがない・列がないときは、どちらの同意もないものとする。同じ人の回答が複数あれば、いちばん新しいイベントの回答で決める。

**同じ人と人の一覧**

- **FR-010**：取り込む回答のLINE名（今のものか別名）または本名が、すでにいる人と同じとき、アプリは「同じ人の候補」として示し、作り手が「つなぐ」「別の人」を選ぶまで、つないではならない。
- **FR-011**：「つなぐ」を選んだ回答は前からいる人のものになり、回答のLINE名が今のLINE名と違えば別名として足さなければならない。
- **FR-012**：作り手は、人のページで2人を1人にまとめられなければならない（来たイベント・回答・メモ・声かけ・別名がすべて1人に集まる）。
- **FR-013**：作り手は、人のページで、ある回答を別の人に分けられなければならない（その回答と、その回答による来た記録が新しい人に移る）。
- **FR-014**：作り手は、人を手で足せなければならない（本名・LINE名・会ったイベント・目的ごとの同意）。手で足した人の同意は、作り手が選ぶ。
- **FR-015**：作り手は、人の本名・メモ（見た目の特徴・話したこと）・目的ごとの同意を、人のページで直せなければならない。同意を直したときは、いつ・どう直したかを残す。
- **FR-016**：作り手は、人の一覧を、本名・LINE名（別名を含む）・メモの言葉で探せなければならない。
- **FR-017**：作り手は、人の一覧を、来たイベント・次回参加の答え・欲しいつながり・キャリアの興味・最後に会った日で絞れなければならない。

**誘う候補と声かけ**

- **FR-018**：アプリは、目的（交流会への誘い・仕事の相談先へのつなぎ）ごとに、その目的の同意がある人だけを誘う候補として示さなければならない。同意のない人は、どの絞り込みでも候補に出してはならない。
- **FR-019**：誘う候補は、FR-017の絞り込みと「前に来た（自分の会に1回以上）」で絞れ、最後に会った日の新しい順に並ばなければならない。
- **FR-020**：交流会への誘いでは、作り手は誘う会（人物メモのイベント）を選び、相手の本名（なければLINE名）と誘う会の名前・日にちを入れた誘いの文をコピーできなければならない。作り手は、誘いの文の型を変えられる。
- **FR-021**：作り手は、声かけの進み具合を記録できなければならない：交流会への誘いは「興味を聞いた → リンクを送った → 来た」、仕事の相談先へのつなぎは「本人に聞いた → OKをもらった → つないだ」。同じ目的・同じ相手・同じ誘う会（つなぎは同じ相談先）の声かけは1つとし、進み具合を進める。
- **FR-022**：誘った会の回答を取り込み、誘った人とつながったとき、アプリはその声かけの進み具合を「来た」にしなければならない。
- **FR-023**：仕事の相談先へのつなぎでは、「OKをもらった」を記録しないと「つないだ」にできてはならない。アプリは、相手の情報を外へ送ってはならない。
- **FR-024**：アプリは、LINEへの送信・LINEとの連携をしてはならない（作り手がコピーした文を自分で送る）。

**人のページ・リピーター・イベント**

- **FR-025**：人のページは、本名・LINE名と別名・来たイベント（新しい順）・イベントごとの回答・メモ・目的ごとの同意・声かけの記録を示さなければならない。
- **FR-026**：作り手は、リピーターの目標（人数）を決め、変えられなければならない。アプリは、自分の会に2回以上来た人の数を、目標と並べて示さなければならない。
- **FR-027**：作り手は、イベントを作り・直し・消せなければならない（名前・開催日・自分の会かどうか）。回答のあるイベントを消すときは、取り込みの取り消し（FR-008）と同じ扱いにする。
- **FR-028**：自分の会のページは、参加者数・初めて来た人の数・前にも来た人の数を示さなければならない。

**消すこと・使える人・置き場所**

- **FR-029**：作り手は、人のページから人を消せなければならない（名前を入れて確かめる）。その人の回答・メモ・声かけ・別名をすべて消し、元に戻せない。イベントの参加者数は数として残す。
- **FR-030**：作り手がめぐるを退会したら、その作り手の人物メモの記録をすべて消さなければならない。
- **FR-031**：人物メモは既定でOFFとし、運営者がONにした人だけが使えなければならない。料金はかけない。運営者がOFFにしても記録は消さず、ONに戻すと前のまま使える。
- **FR-032**：作り手の記録（人・回答・メモ・声かけ・イベント）は、その作り手だけが読めなければならない（ほかの作り手やチームとは共有しない）。
- **FR-033**：画面は、パソコン・タブレットでは左のサイドバー、スマートフォンでは下のバー（誘う候補・人・取り込み・イベント）で開けなければならない。

### Key Entities *(include if feature involves data)*

- **イベント**：作り手ごと。名前・開催日・自分の会かどうか・参加者数（人を消しても残る数）。回答と声かけ（誘う会）につながる。
- **取り込み**：1回のCSVの取り込み。どのイベントか・いつ・何行入ったか。取り消しの単位になる。
- **列の対応**：作り手ごとの、質問文と人物メモの項目の組。次の取り込みで同じ質問文に自動で当てる。
- **人**：作り手ごと。本名・今のLINE名・別名（複数）・メモ（見た目の特徴・話したこと）・目的ごとの同意（交流会への誘い・仕事の相談先へのつなぎ。どこから決まったか：回答・作り手）・最後に会った日。
- **回答**：1人の、1つのイベントのアンケートの答え。回答の時刻・LINE名・項目ごとの答え（次回参加・友達を誘えるか・欲しいつながり（複数）・キャリアの興味（複数）・個別の案内の同意（複数））・項目にあたらない答え。人とイベントにつながる。回答があることが「そのイベントに来た」記録になる（手で足した人の「会ったイベント」も来た記録として持つ）。
- **声かけ**：人ごと。目的・誘う会（交流会への誘い）または相談先の名前（つなぎ）・進み具合と、それぞれの日時。
- **誘いの文の型**：作り手ごと。相手の名前・会の名前・日にちを差し込む文。
- **リピーターの目標**：作り手ごとの人数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：作り手は、20人分のアンケートのCSVを、初めての質問の列の対応を選ぶところまで含めて5分以内に取り込める。2回目以降（同じ質問のフォーム）は2分以内に取り込める。
- **SC-002**：2回分の回答（10/11・11/25）を取り込んだあと、12月の会に誘う候補（前に来た・次回も来られそうと答えた・同意あり）を、LINEを見返さずに1分以内に出せる。
- **SC-003**：「個別の案内は希望しない」と答えた人、または目的の同意がない人は、誘う候補に1人も出ない（取り込んだすべての回答で確かめる）。
- **SC-004**：同じLINE名の回答は、作り手が選ぶまで1件も勝手につながらない。作り手は、同じ人の候補を1組あたり10秒以内に見分けて選べる（来たイベントと答えが並んでいる）。
- **SC-005**：スマートフォンで、誘う候補を開いてから1人の誘いの文をコピーするまでが、3回のタップ以内で済む。
- **SC-006**：人を消すと、その人の名前・LINE名・回答・メモ・声かけは、人の一覧・候補・検索・人のページのどこにも出ない。イベントの参加者数は変わらない。
- **SC-007**：アプリを実際の会で使い、「アンケートを毎回取り込める」「誘う相手をアプリから選べる」「リピーターの目標に対して今どこまで来たかが分かる」の3つを、作り手が満たしたと判断できる（ブリーフの「うまくいった基準」3）。

## Assumptions

- **最初の利用者は作り手1人**。ほかの主催者への展開・チームでの共有・課金はこのfeatureでは作らない。運営者がONにした人は、それぞれ自分だけの人物メモを持つ。
- **取り込むのはGoogleフォームの回答のCSV**。2026-10-11のIT交流会のフォーム（9つの質問）を基準にする。複数選択の答えは「、」区切り（Googleの書き出しの形）を前提にする。回答の時刻の列（Googleが付ける「タイムスタンプ」）を、二重の取り込みの判定に使う。
- **同意の目的と選択肢の対応**は、2026-10-11のフォームの「個別に案内してよいか」の4つの選択肢に合わせる。選択肢の文が違うフォームでは、作り手が列の対応と同じように、選択肢と目的の対応を選ぶ（取り込むときに、知らない選択肢があれば聞く）。
- **「最後に会った日」**は、その人が来たイベント（回答・手で足した会ったイベント）の開催日のうち、いちばん新しい日とする。
- **「前に来た」**は、自分の会に1回以上来たこととする（参加者として出た会で会った人は含めない）。
- **誘いの文の型の初めの文**は、ブリーフの使い方（「興味ありますか？」と聞く）に合わせ、「〇〇さん、〇月〇日の△△、もしご興味あれば一緒にいかがですか？」のような短い文を用意する。作り手が変えられる。
- **港の参加リンク**は、作り手が誘いの文の型に自分で書き入れる（このfeatureではリンクを管理しない）。
- **イベントのつなぎ**：集金管理・めぐる Threadsのイベントや参加者とは、このfeatureではつながない。将来、出来事でつなぐ（パターン①）。そのときに備え、人物メモのイベントは名前・開催日を持つ。
- **パターン①で作る**：人物メモは、ほかのアプリや共通の表を直接さわらない。ログインと「使えるか（既定でOFF・運営者がONにした人）」は共通の入口の関数で確かめる。API は `/api/people/…`、画面は `/people/…`。実装はThreadsをパターン①にそろえる作業（029）の後に始める。
- **既定でOFFの仕組み**は、集金管理（specs/collect/001）の前提の段（PR0：既定でOFFの機能のON/OFF・人ごとに使えるか）と同じものを使う。どちらが先に作るかは、計画で決める。
- **作らないもの**：写真・顔認識・名刺の読み取り、LINEとの連携や自動送信、仕事の相談先への相手の情報の自動の受け渡し、めぐる独自のアンケートフォーム、参加者のログインと会場のQRでのその場登録、ほかの主催者との共有・チームでの利用・課金。
- **個人の情報の扱い**：参加者の名前・LINE名・アンケートの答えは、作り手が参加者から集めたもので、作り手だけが読める。参加者の求めがあれば作り手が消す（FR-029）。仕事の相談先へつなぐときの本人の同意の残し方と、つないだことにお礼がある場合の扱いは、展開の前に専門家に確かめる（ブリーフの「分からないこと」）。このfeatureでは、同意の記録（いつ・だれが・どう）を残すことまでを行う。
