# Quickstart：チームの見直し

**日付**：2026-10-13 | **計画**：[plan.md](./plan.md)

本featureが動くことを確かめる手順。準備は001〜010と同じ（[README](../../README.md)、OrbStackで`docker compose up -d`）。

## 1. 自動のテスト

```bash
pnpm --filter api db:migrate   # 0012_team_revision（008のチームのデータを消す）
pnpm lint && pnpm typecheck
pnpm test                      # 共通・Web・API（API はローカルのPostgresの表を空にする）
pnpm e2e -- team               # 3人のブラウザでの流れ（SC-007）
pnpm e2e -- token              # 010の流れが変わらないこと
```

確かめること（対応するテストはtasks.md）：

| 確かめること | 出どころ |
|---|---|
| 関わり4種×権限の表で、許されない要求が拒まれる。チームのAPIは管理者・チームの人の判定を通る | SC-002、contracts/permissions.md |
| 見せるをオフにすると、担当の人を除くチームの人（管理者を含む）は次の要求で開けない。別のチームの人は見せていても開けない | SC-003 |
| 引き継ぎ・抜ける・外す・アカウントの削除のどの順番でも、管理者がいないチームができない | SC-004、research.md R7 |
| チームに入っていないオーナーの画面が008の前と同じ（チームの区分の1行「チームに入っていません」「チームを作る」を除く。Constitution 4.0.1原則V） | SC-005 |
| マイグレーションの前後で、アカウント・投稿の案・戦略・操作の記録の件数が同じ | SC-006、research.md R2 |
| 招待リンクで参加するには自分のアカウントが1つ以上要る。ほかのチームのアカウントは選べない | FR-013・FR-014 |
| 見せてもらっているアカウントでは、投稿ストックと戦略のGETだけが通り、パフォーマンス・設定・書き込みは拒まれる | FR-031、research.md R3 |
| 承認・設定は、担当の人・管理者でも拒まれる（任せる範囲がない） | FR-060 |

## 2. 手で確かめる（3人のブラウザ）

```bash
pnpm team:demo   # DB・偽のThreads・api・webを起動し、チームを用意して3人のブラウザを開く
```

`team:demo`の用意（`e2e/scripts/team-open.ts --setup`）は、011の形に作り直す：

- 管理者（田中役）が自分のアカウント（`@partner_co`）で「飲食チーム」を作る。
- オーナー（鈴木役）が招待リンクから、自分のアカウント（`@e2e_user`）を入れて参加する。
- 編集者（佐藤役）が自分のアカウント（`@cafe_b`）を入れて参加し、管理者が編集者に切り替えて、`@e2e_user`の担当にする。

その上で：

1. 3人とも、サイドバーの「チーム」の見出しの下に「飲食チーム」が出る。押すとメンバー一覧が開く（「あなた」の印）。
2. オーナーがチームの画面で`@e2e_user`の「チームに見せる」をオンにする → 管理者の一覧で「見る」が付き、開くと投稿ストックと戦略だけが読める（ボタンが出ない）。
3. 編集者が`@e2e_user`で投稿の案を登録できる。承認のボタンは出ない（「オーナーの確認待ち」）。
4. 管理者が「チームを抜ける」→ 引き継ぎ先を選ぶまで押せない → オーナーを選んで抜ける → オーナーの画面で管理者になっている。
5. チームに入っていないアカウントに切り替えると、サイドバーにチーム名は出るが、そのアカウントの設定のチームの区分は「チームに入っていません」と「チームを作る」の1行だけ。
6. スマートフォン幅（375px）で、引き出しの中にチーム名が出る。
7. 管理者の招待リンクを、自分のアカウントを1つ持つ別の利用者のブラウザで開き、開いてから参加が終わるまでの時間を測る（1分以内。SC-001）。
