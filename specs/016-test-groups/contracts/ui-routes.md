# 画面の契約：テスト用のグループ

**日付**：2026-10-31 | **計画**：[../plan.md](../plan.md)

## ルート

| パス | ログイン | 画面 |
|---|---|---|
| `/test-invite/:token` | 任意 | グループの招待の確認と「参加する」 |
| `/settings/test-groups` | 必須・運営者 | テスト用のグループの一覧と「グループを作る」 |
| `/settings/test-groups/:groupId` | 必須・運営者 | グループの詳しい画面（人・上限・リンク・閉じる・記録） |

## 1. グループの招待（`/test-invite/:token`）

- 読み込み中は骨組みだけ。
- 使えないリンク（`TEST_INVITE_INVALID`）：「このリンクは使えません」「招待してくれた方に、新しいリンクをもらってください」と「トップへ」。
- 中身（どの場合も上に出す）：グループ名、「テスト版に招待されています」、注意の3行（「料金はかかりません」「投稿は、つないだThreadsアカウントに実際に投稿されます」「テスト版のデータは本番版へは引き継がれません」）。
- ログインしていない：「Googleで始める」（`/sign-in?next=/test-invite/:token`）。定員なら、代わりに定員の文。
- ログインしている（`viewer.state`）：
  - `can_join`：「参加する」。押したら`POST …/join`、成功したら`/`へ置き換え遷移（ホームでアカウントを作る案内が出る）。失敗は文言を出し、確認を読み直す。
  - `full`：「このグループは定員に達しています。招待してくれた方に連絡してください」。
  - `already_member`：「すでに〇〇に入っています」と「アプリを開く」（`/`）。
- 下に「ログアウト」（別のGoogleアカウントで入り直したい人のため）。
- 環境の帯（015）を出す（`CenteredLayout`）。

## 2. 入れない人の画面

ONの環境で、`/api/me`の`testGroups.admitted`がfalse、またはAPIが`TEST_ACCESS_REQUIRED`を返したら、認証のガードの中のすべての画面の代わりに出す。

- 見出し「テスト版は招待された方だけが使えます」
- 本文「招待のリンクを受け取った方は、そのリンクをもう一度開いてください。別のGoogleアカウントでログインしている場合は、ログアウトしてから入り直してください。」
- 「ログアウト」
- `/test-invite/:token`はこの画面にならない（ガードの外）。

## 3. 運営者の管理の画面（設定の「運営」の区分）

設定の左の一覧に「運営」の区分を作り、「テスト用のグループ」を置く。運営者（`testGroups.operator`）にだけ出す。運営者でない人が直接開いたら「この画面は運営者だけが使えます」。

### 一覧（`/settings/test-groups`）

- 「グループを作る」：名前（1〜50文字）と上限（1〜1000人。既定10）を入れるダイアログ。作ったら詳しい画面へ。
- グループごとの行：名前、「入っている人／上限」（定員なら「定員」の印）、閉じていれば「閉じています」。押すと詳しい画面。
- グループがなければ「まだグループはありません。組織やコミュニティごとにグループを作り、招待リンクを送ってください」。

### 詳しい画面（`/settings/test-groups/:groupId`）

- 名前・人数／上限。「名前と上限を変える」（ダイアログ。上限を今の人数より少なくすると「入っている人は外れません。人数が上限より少なくなるまで、新しい人は入れません」と出す）。
- 招待リンク：URL・「コピー」・「リンクを作り直す」（確認：「前のリンクは使えなくなります。入っている人はそのままです」）。閉じていれば出さない。
- 入っている人：名前・メールアドレス・入った日・「外す」（確認：「〇〇さんをグループから外しますか？この人はテスト版を使えなくなり、自動投稿も止まります。データは消えません」）。
- 「グループを閉じる」（確認：「入っている〇人は全員テスト版を使えなくなり、自動投稿も止まります。招待リンクも使えなくなります。閉じたグループは開き直せません」）。
- 記録：新しい順に50件（「〇月〇日 〇〇さんが入りました」など）。
- スマートフォンの幅でも、表は縦に並べて読める。
