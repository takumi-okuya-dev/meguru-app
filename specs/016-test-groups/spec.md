# Feature Specification:テスト用のグループ

**Feature Branch**: `feature/016-test-groups`

**Created**: 2026-10-31

**Status**: Draft

**Input**: 2026-10-31、テスト環境（ステージング、015）の公開のあと、ユーザーが「テストユーザーの制限」を作ると決めた。テスト環境を、使ってもらう組織やコミュニティの単位で提供し、グループごとに人数の上限を設ける（例：この組織には10人まで）。グループの招待リンクから登録した人だけがテスト環境を使え、上限に達したらそれ以上は登録できない。テストユーザーには料金を求めない（013の「料金なしの印」`billing_exempt`を使う）。今はClerkのAllowlistを使っておらず、テスト環境は誰でも登録できる状態（015で、テストユーザーの段階では不具合を見つけてもらうことを優先し、Allowlistを置かないと決めた）。同じ日に挙がった「紹介リンク（他の人にアプリを勧めてもらう）」は、別のfeature（017）にする。

**Source**: [015のspec](../015-deploy-environments/spec.md)（テスト環境・「料金なしの印」で料金を求めない）、[013のspec](../013-billing/spec.md)（FR-062の料金なしの印と、退会）、[011のspec](../011-team-revision/spec.md)（チームの招待リンクの見た目と流れ）、[Constitution](../../.specify/memory/constitution.md)原則V（個人運用起点のシンプルさ）、開発ワークフロー（環境の違いは設定に置く）。

## Clarifications

### Session 2026-10-31

- Q:紹介リンク（他の人にアプリを勧めてもらう）と一緒に作るか？ → A:別のfeatureにする。テスト用のグループを016、紹介リンクを017にする。
- Q:運営者がグループを作る・見る・変える方法は？ → A:アプリの中に、運営者だけが開ける管理の画面を作る（コマンドだけにはしない）。
- Q:グループの招待リンクからログインした人は、自動でグループに入れるか？ → A:自動では入れない。ログインのあと、グループ名・料金なし・「投稿は本物のThreadsに出ます」を確かめて「参加する」を押してもらう（チームの招待と同じ流れ）。
- Q:グループから外された人・閉じたグループの人の自動投稿は？ → A:止める。反応の取り込みも止める。またテスト環境に入れる人に戻れば、再開する。
- Q:この仕組みを環境ごとにON/OFFできるようにするか？ → A:する。環境の設定で切り替え、テスト環境はON、本番はOFFにする。OFFの環境では、グループの招待リンク・運営者の管理の画面・入れる人の判定のどれも働かない。

## 用語

- **テスト用のグループ**：テスト環境を提供する組織やコミュニティの単位。名前、人数の上限、グループの招待リンク1本を持つ。テスト環境だけにある。
- **グループの招待リンク**：テスト用のグループに入るためのリンク。テスト環境では、このリンクから入った人だけがアプリを使える。チームの招待リンク（011）とは別物で、チームには入らない。
- **テスト環境に入れる人**：テスト用のグループのどれかに入っている人と、この機能の前からテスト環境を使っていた人（開発者を含む）。
- **運営者**：テスト環境を運営する人。今は開発者1人。
- **テスト用のグループの設定（ON/OFF）**：この仕組みを使うかどうかを、環境ごとに決める設定。テスト環境はON、本番はOFF。

## User Scenarios & Testing *(mandatory)*

### User Story 1 -運営者が、組織ごとに人数を決めてテスト環境を渡す（Priority: P1）

運営者は、テスト環境を使ってもらう組織やコミュニティごとに「テスト用のグループ」を作り、名前と人数の上限（例：10人）を決める。グループの招待リンクを、その組織の窓口の人に送る。リンクから登録した人は、そのグループに入り、料金なしでテスト環境のすべての機能を使える。上限に達したグループのリンクからは、それ以上登録できない。

**Why this priority**：テスト環境は今、誰でも登録できる。テストユーザーは本物のThreadsアカウントをつなぎ、自動投稿も本物に出るので、知らない人が入れる状態のまま広く配れない。組織ごとに人数を決めて渡せることが、テストユーザーを増やす前提になる。

**Independent Test**：テスト環境で、上限2人のグループを作る。グループの招待リンクから2人が登録して使えること、3人目は登録できないこと、リンクを使わずに登録した人はアプリを使えないこと、入った2人に料金が求められないことを確かめる。

**Acceptance Scenarios**:

1. **Given** テスト環境の運営者、**When** グループの名前と人数の上限を決めて作る、**Then** グループと、グループの招待リンクができる。
2. **Given** 上限に空きがあるグループの招待リンク、**When** まだテスト環境に入れる人ではない人が開く、**Then** ログインしていなくても、グループ名・「テスト版に招待されています」・「料金はかかりません」・「投稿は本物のThreadsに出ます」と「Googleで始める」が出る。
3. **Given** 上の画面、**When** その人がGoogleでログインする、**Then** グループ名・料金なし・「投稿は本物のThreadsに出ます」と「参加する」が出る。まだグループには入っていない。
4. **Given** 上の画面、**When** その人が「参加する」を押す、**Then** その人はグループに入り、料金なしの印が付き、アプリをすべて使えるようになる。グループの人数が1人増える。
5. **Given** 上限に達したグループの招待リンク、**When** まだテスト環境に入れる人ではない人が開く、**Then** 「このグループは定員に達しています。招待してくれた方に連絡してください」と出て、グループには入れない。
6. **Given** テスト環境、**When** どのグループの招待リンクも使わずにログインした人（テスト環境に入れる人ではない）がアプリを開く、**Then** 「テスト版は招待された方だけが使えます」と出て、アカウントの作成など、アプリのほかの画面と操作は使えない。
7. **Given** すでにグループに入っている人、**When** 別のグループの招待リンクを開く、**Then** 「すでに〇〇（グループ名）に入っています」と出て、グループは変わらず、どちらの人数も変わらない。
8. **Given** この機能の前からテスト環境を使っていた人、**When** この機能が出たあとにアプリを開く、**Then** これまでどおり使える（グループに入っていなくても締め出されない）。

### User Story 2 -運営者が、グループの人数と人を管理する（Priority: P2）

運営者は、グループの一覧で、グループごとの人数と上限、入っている人を確かめる。組織から「もう少し人を増やしたい」と言われたら上限を上げ、使わなくなった人を外し、テストが終わった組織のグループを閉じる。

**Why this priority**：渡したあとの調整ができないと、上限を間違えたときや、組織の担当が替わったときに困る。ただし、まずはグループを作って渡せること（US1）が先。

**Independent Test**：上限2人で2人入っているグループの上限を3に上げ、3人目が入れること、1人を外すとその人が使えなくなり料金なしの印が外れること、グループを閉じると全員が使えなくなることを確かめる。

**Acceptance Scenarios**:

1. **Given** 運営者、**When** グループの一覧を見る、**Then** グループごとの名前・人数／上限・招待リンク・閉じたかどうかがわかる。
2. **Given** 運営者、**When** 1つのグループを開く、**Then** 入っている人の名前・メールアドレス・入った日がわかる。
3. **Given** 定員のグループ、**When** 運営者が上限を上げる、**Then** そのグループの招待リンクから、また新しい人が入れる。
4. **Given** グループに入っている人、**When** 運営者がその人を外す、**Then** その人はテスト環境に入れる人ではなくなり、次にアプリを開くと「テスト版は招待された方だけが使えます」と出る。その人のアカウントの自動投稿と反応の取り込みは止まる。グループで付いた料金なしの印が外れる。データは消さない。グループの人数が1減る。
5. **Given** グループ、**When** 運営者がグループを閉じる、**Then** 入っていた人は全員テスト環境に入れる人ではなくなり、招待リンクは使えなくなる。データは消さない。
6. **Given** グループの招待リンク、**When** 運営者がリンクを作り直す、**Then** 前のリンクは「このリンクは使えなくなりました」と出て使えない。入っている人はそのまま。

### Edge Cases

- 上限ちょうどのとき、2人が同時に「参加する」を押した → 上限を超えて入らない。先に押した人だけが入り、もう1人には「定員に達しています」と出る。
- ログインしたあと「参加する」を押さずに画面を閉じた → グループには入っていない。同じリンクを開き直せば、続きから参加できる（そのとき定員なら入れない）。
- 運営者がグループの上限を、今の人数より少なくした → 入っている人は外さない。人数が上限より少なくなるまで、新しい人は入れない。
- 外された人・閉じたグループの人が、別のグループの招待リンクを開いた → そのグループに空きがあれば入れる（もうグループに入っていないため）。
- グループに入った人が退会した（013）→ グループの人数が1減る。
- 外された人のアカウントを、チームの人が担当していた → 担当の人がいても、そのアカウントの自動投稿は止まる（持ち主がテスト環境に入れる人でないため）。
- グループで料金なしの印が付いた人に、運営者が手でも印を付けていた（013のコマンド）→ グループから外れても、手で付けた印は残す。
- この機能の前からテスト環境を使っていた人がグループの招待リンクを開いた → そのグループに入れる（空きがあれば）。入らなくても使えるのは変わらない。
- OFFの環境（本番）でグループの招待リンクのURLを開いた → 「このリンクは使えません」と出し、ふつうのログインへ案内する。
- テスト環境でいったんOFFにした → その間は誰でも使える。ONに戻したときは、OFFの間に登録した人も含め、その時点で使っていた人を締め出さない（FR-016）。
- テスト環境に入れない人が、ログイン済みでAPIを直接呼んだ → 画面と同じく拒まれる（画面の出し分けだけに頼らない）。
- テスト環境に入れない人が、チームの招待リンク（011）を開いた → 先にテスト環境に入れる人にならないと使えない（「テスト版は招待された方だけが使えます」）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：この仕組みがONの環境（テスト環境）では、運営者がテスト用のグループを作れなければならない。グループは名前と人数の上限（1人以上）を持つ。
- **FR-002**：グループを作ると、グループの招待リンクが1本できなければならない。運営者は、リンクを作り直せる（前のリンクは使えなくなる）。リンクは推測できないものにする。
- **FR-003**：グループの招待リンクを開いた人には、ログインしていなくても、グループ名、テスト版に招待されていること、料金がかからないこと、投稿が本物のThreadsに出ることと、「Googleで始める」を見せなければならない。
- **FR-004**：まだグループに入っていない人がグループの招待リンクからログインしたら、グループ名・料金がかからないこと・投稿が本物のThreadsに出ることと「参加する」を見せ、押したときにそのグループに入れなければならない。押すまではグループに入れない。ただし、グループの人数が上限より少なく、グループが閉じていないときに限る。入った人には料金なしの印（013）を付ける。
- **FR-005**：上限に達したグループには、誰も新しく入れてはならない。同時に「参加する」を押しても上限を超えてはならない。
- **FR-006**：テスト環境に入れる人ではない人には、テスト環境のアプリの画面と操作（アカウントを作る・Threadsにつなぐ・チームに入るなど）を使わせてはならない。画面には「テスト版は招待された方だけが使えます」と、ログアウトを出す。この判定は画面の出し分けだけでなく、すべてのAPIで行う。
- **FR-007**：この機能が出る時点（またはONに切り替えた時点）ですでにテスト環境を使っていた人は、グループに入っていなくてもテスト環境に入れる人として扱わなければならない。
- **FR-008**：1人が入れるグループは1つまでとする。すでにグループに入っている人が別のグループの招待リンクを開いても、グループを変えてはならない。
- **FR-009**：運営者は、グループの一覧（名前・人数／上限・招待リンク・閉じたかどうか）と、グループごとに入っている人（名前・メールアドレス・入った日）を見られなければならない。
- **FR-010**：運営者は、グループの上限を変えられ、グループから人を外せ、グループを閉じられなければならない。外された人・閉じたグループの人は、テスト環境に入れる人ではなくなり、グループで付いた料金なしの印も外れる。データは消さない。
- **FR-011**：運営者は、アプリの中の運営者だけが開ける管理の画面で、グループを作る・一覧を見る・上限を変える・人を外す・リンクを作り直す・閉じることができなければならない。誰が運営者かは環境の設定で決め、運営者でない人には、管理の画面への入口を出さず、開いても使わせない（APIでも拒む）。スマートフォンの幅でも使えるようにする。
- **FR-012**：テスト用のグループの仕組みは、環境ごとの設定でON/OFFを切り替えられなければならない。テスト環境はON、本番はOFFにする。切り替えはコードの分岐ではなく環境の設定で行う（015）。
- **FR-013**：グループに入った・外された・グループを閉じた・上限を変えたことは、いつ・誰が・何をしたかを記録に残さなければならない（運営者があとから確かめるため）。
- **FR-014**：ONの環境で、テスト環境に入れる人ではなくなった人のアカウントでは、自動投稿と反応の取り込みをしてはならない（承認済みの案は承認済みのまま残す）。またテスト環境に入れる人に戻ったら、再開する。時刻を過ぎた案の扱いは、自動投稿（005）の決まりに従う。
- **FR-015**：OFFの環境では、誰でもこれまでどおり登録して使えなければならない。グループの招待リンクを開いた場合は「このリンクは使えません」と出し、ふつうのログインへ案内する。運営者の管理の画面への入口は出さず、開いても使わせない（APIでも拒む）。グループと入っている人の記録は消さない。
- **FR-016**：OFFからONに切り替えたときは、その時点でその環境を使っていた人を、テスト環境に入れる人として扱わなければならない（FR-007と同じ扱い。切り替えで誰も締め出さない）。

### Key Entities *(include if feature involves data)*

- **テスト用のグループ**：名前、人数の上限、招待リンク（作り直すと変わる）、閉じたかどうか、作った日。テスト環境だけにある。
- **グループの人**：どのグループに、誰が、いつ入ったか。1人1グループまで。グループで料金なしの印が付いたかどうか。
- **テスト環境に前からいた人**：この機能が出る時点でテスト環境を使っていた人の印。グループに入っていなくても使える。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：テスト環境で、グループの招待リンクを使わずに登録した人が、アプリの画面と操作を1つも使えない（すべての画面とAPIで拒まれる）。
- **SC-002**：どのグループも、入っている人が上限を超えない（同時に10人が「参加する」を押しても超えない）。
- **SC-003**：運営者が新しい組織にテスト環境を渡すのに、グループを作ってリンクを送るまで5分以内でできる。
- **SC-004**：グループの招待リンクから入った人が、料金の画面を一度も通らずに、すべての機能を使い始められる。
- **SC-005**：この機能が出たあとも、すでにテスト環境を使っていた人が1人も締め出されない。
- **SC-006**：OFFの環境（本番）の登録の流れが、この機能の前と変わらない（誰も締め出されず、グループの画面やリンクも働かない）。
- **SC-007**：設定を変えるだけで、コードを変えずに、環境ごとにこの仕組みをON/OFFできる。

## Assumptions

- 運営者は今のところ開発者1人。テスト用のグループを作る・変えるのは運営者だけで、グループの窓口の人（組織の担当者）には管理の権限を渡さない。運営者は、テスト環境の設定にログインのIDを書いて決める（画面から運営者を足す仕組みは作らない）。
- グループの招待リンクを窓口の人に渡し、窓口の人が組織の中で配る。誰にリンクを渡すかはアプリの外で決める。
- テスト環境に入れない人も、Google（Clerk）のログインまではできてしまう。アプリの側で使わせないことで制限する（ClerkのAllowlistは使わない。015の決定のまま）。
- グループの招待リンクを開いてから、別のブラウザや端末でログインした場合は、グループに入らない（同じブラウザでログインしてもらう）。
- テスト用のグループとチーム（011）は別物。グループに入っても、チームには入らない。
- 料金なしの印は、この機能で付けたものも、運営者が手で付けたもの（013のコマンド）と同じ働きをする。グループから外れたときに外すのは、グループで付いた印だけ。

## Out of Scope

- 紹介リンク（他の人にアプリを勧めてもらう）。別のfeature（017）で作る。
- 本番でONにして使うこと（本番はOFFで始める。必要になったら設定でONにできるが、本番向けの文言や画面の調整はしない）。
- グループの窓口の人が、自分でグループを管理する画面。
- グループごとの期限（いつまでテスト環境を使えるか）。
- テスト環境のデータを本番へ移すこと。
