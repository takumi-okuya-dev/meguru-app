# 確かめの手順（quickstart）：名簿なしで受付する

**前提**：001〜003 の quickstart が通ること。手元は `pnpm dev`、テスト版はステージング（API `threads-grower-api-staging`・画面 `develop.threads-grower-web`）。取り決めは [contracts/api.md](./contracts/api.md)。

## 手元のテスト

```bash
pnpm --filter @meguru/shared test -- collect          # 形・上限・仮の区分の決め方
pnpm --filter api test -- collect/rosterless          # 名簿なしの入口・区分を確かめる・外す・締め
pnpm --filter api test -- collect                     # 001〜003 が壊れていない
VITE_API_BASE_URL=http://localhost:8787 pnpm --filter web test -- collect
pnpm e2e                                              # 名簿なしのセルフ受付（参加者と主催者の2つのブラウザ・390px）
```

## 1. 名簿なしでイベントを作る（User Story 3）

1. 「イベントを作る」を開く → 受付のしかたが「名簿なし」になっている。区分を「通常 3,000円・早割 2,500円」にして作る。
2. セルフ受付の画面が開く → 「セルフ受付のQRを出す」。名簿は0人のまま。

## 2. 参加者が名前と媒体を入れる（User Story 1）

1. 別のスマートフォン（ログインなし）でQRを開く → 名前・ふりがな・「どこで申し込みましたか」・紹介してくれた人の入力が出る（名前を探す欄は出ない）。
2. 「松本 れい」・媒体「Peatix」・紹介してくれた人「井上」で送る → 「No.1 松本 れい さん」と、区分ごとの金額（通常 3,000円・早割 2,500円）が出る。区分を選ぶ欄は出ない。
3. 主催者の名簿の画面に、5秒以内に松本 れい（Peatix・区分を確かめる・紹介した人 井上）が出る。
4. 「現金」を選ぶ → 「受付で払ってください（受付の人が区分を確かめます）」。
5. 同じスマートフォンで開き直す → 入力の画面ではなく、受付番号と「確かめ待ち」が出る。

## 3. 受付をする人が区分を決めて受け取る（User Story 2）

1. 主催者の受付の画面の確かめ待ちに「No.1 松本 れい・現金・区分を確かめる」が出る。
2. 「受け取った」→ 区分を選ぶ段 →「早割」→ 支払い済み・2,500円。現金の合計が2,500円増える。参加者の画面が「受付が済みました」になる。名簿の区分も早割になる。
3. 別の参加者が「振込（後日）」を選ぶ → 振込待ちの「入金を確かめた」で区分を選ぶ段が出る。
4. 区分が1つのイベントでは、「受け取った」の1回で済む（区分を選ぶ段は出ない）。

## 4. 同じ名前と外す（User Story 4）

1. 別のスマートフォンで「まつもと れい」を入れる → No.2 として入り、受付の画面のNo.1とNo.2に「同じ名前の人がいます」が出る。参加者の画面には、No.1 がいることは出ない。
2. 受付の画面で、No.2 の「名簿から外す」（記録があれば先に取り消す）→ No.2 が消え、知らせも消える。
3. 主催者が名簿に「井上 そら」を先に入れておき、参加者が「いのうえ そら」を入れる → 新しい人は増えず、井上 そらとして受付する。

## 5. 締めと受付のしかたを変える

1. 名簿なしのイベントの締めの画面 → 来なかった人の段は出ず、「受付の記録がない人 N人」が出る。CSV の区分の列で、未定の人は「未定」。
2. イベントを直す画面で「名簿あり」に変える → 参加者の画面が名前を探す形（002）になる。名簿と記録は変わらない。
3. 前からあるイベントは、名簿ありのまま今と同じに動く。

## 6. 守り

1. 1つの端末から11人目を入れる → 「受付が混んでいます。受付の人に声をかけてください」。
2. 主催者がセルフ受付を止める → 参加者の画面が5秒以内に止まり、入れられない。
3. 名簿ありのイベントで名簿なしの入口を呼ぶ → 409 `CHECK_IN_MODE_MISMATCH`。
