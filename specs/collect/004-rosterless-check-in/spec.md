# Feature Specification：名簿なしで受付する（セルフ受付で名簿を作る）

**Feature Branch**: `feature/collect-004-rosterless-check-in`

**Created**: 2026-11-15

**Status**: Draft

**Input**: 2026-11-15に、集金管理（アプリのID `collect`）の4つめのfeatureとして決めた。参加者にセルフ受付をしてもらえば、主催者が事前に名簿を作る必要がなくなり、参加者が「名簿の中から自分を探す」照らし合わせもなくせる。イベントごとに「名簿なし」と「名簿あり（今の形）」を選べるようにし、名簿なしでは、参加者がセルフ受付で入れた名前と申し込んだ媒体で、そのまま名簿を作る。

**Source**: ユーザーの考えと答え（2026-11-15。ステージングでセルフ受付の流れを聞いたあと）、[001 の spec](../001-event-day-collection/spec.md)（名簿・受付・受付の手伝い・締め・振込待ち・飛び入り）、[002 の spec](../002-self-check-in/spec.md)（セルフ受付・本人の申告・確かめ待ち・飛び入りの申し出・守り）、[003 の spec](../003-revenue-sharing/spec.md)（紹介した人・分配）、[docs/app-separation.md](../../../docs/app-separation.md)（パターン①）、[Constitution](../../../.specify/memory/constitution.md)（原則III・技術スタック制約「モバイル化を見込んだ技術の選び方」）。

## Clarifications

### Session 2026-11-15（仕様を書く前にユーザーと決めたこと）

- Q：名簿をなくすか？ → A：なくさず、**イベントごとに「名簿なし」「名簿あり」を選べる**ようにする。名簿ありは、事前に払ってもらう会や、来なかった人を数えたい会のために残す。
- Q：新しく作るイベントの既定は？ → A：**名簿なし**。
- Q：参加者に、どこで申し込んだかを聞くか？ → A：**聞く**（媒体ごとの名簿・来場・売上を出し続けるため）。
- Q：料金の区分が2つ以上あるとき、だれが区分を決めるか？ → A：**受付の人が「受け取った」を押すときに決める**。参加者は区分を選ばない。

## 用語

001・002・003 の用語（主催者・手伝う人・受付をする人・参加者・名簿・受付番号・媒体・料金の区分・払い方・受付の記録・会場の共有・締め・振込待ち・セルフ受付のリンク・本人の申告・確かめ待ち・飛び入りの申し出・紹介した人）はそのまま使う。

- **受付のしかた**：イベントごとの設定。「名簿なし」か「名簿あり」。
- **名簿なし**：事前に名簿を作らない受付のしかた。参加者がセルフ受付で名前と媒体を入れると、名簿に入る（主催者・受付をする人の確かめはいらない）。お金の受け取りは、今と同じく受付をする人が確かめる。
- **名簿あり**：001・002 の受付のしかた。主催者が事前に名簿を入れ、参加者はセルフ受付で名簿の中から自分を探す。
- **区分を決める**：料金の区分が2つ以上あるイベントで、参加者が名簿なしで入ったときは区分が決まっていない。受付をする人が「受け取った」（振込は「入金を確かめた」）を押すときに区分を選ぶ。
- **同じ名前の知らせ**：名簿なしで、別の端末から名簿の人と同じ名前が入ったときに、受付をする人に出す知らせ。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 参加者が名前と媒体を入れるだけで受付し、払い方を選ぶ（Priority: P1）

名簿なしのイベントで、参加者は会場のQRを読み、名前（任意でふりがな）と「どこで申し込みましたか」（媒体）を入れる。紹介してくれた人がいれば入れられる（空けてもよい）。入れるとそのまま名簿に入り、受付番号が出る。続けて払い方（現金・PayPay・振込）を選ぶと、002 と同じ案内が出る。区分が1つなら金額を出し、2つ以上なら区分ごとの金額を並べて「受付で区分を確かめます」と出す。参加者には、ほかの参加者の名前は見えない。

**Why this priority**: このfeatureの中心。これだけで、主催者は名簿を作らずに会を開け、参加者は自分を探さずに受付できる。

**Independent Test**: 区分が1つ（通常 3,000円）で名簿が空の名簿なしのイベントでセルフ受付のリンクを出し、別のスマートフォン（ログインなし）でQRを開く。名前「松本 れい」・媒体「Peatix」を入れると受付番号 1 で名簿に入り、PayPayを選ぶと「PayPayで3,000円」と確かめ待ちになること、名簿の画面に松本 れい（Peatix）が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 名簿なしのイベント（区分は通常 3,000円だけ・名簿は空）でセルフ受付のリンクが使える、**When** 参加者がQRを開く、**Then** イベントの名前・日時・会場と、名前・ふりがな（任意）・「どこで申し込みましたか」（媒体）・紹介してくれた人（任意）の入力が出る。名前を探す欄は出ない。
2. **Given** 1の画面、**When** 名前「松本 れい」・媒体「Peatix」を入れて送る、**Then** 「No.1 松本 れい さん・通常 3,000円」が出て、払い方のボタン（イベントで使う払い方だけ）が出る。名簿に松本 れい（媒体 Peatix・区分 通常）が入る。
3. **Given** 2の画面、**When** 「PayPay」を選ぶ、**Then** 主催者のPayPayの受け取り用QRと「3,000円」が出て、受付の記録が「本人の申告・PayPay・確かめ待ち」で残る（002 と同じ）。
4. **Given** 区分が「通常 3,000円・早割 2,500円」の名簿なしのイベント、**When** 参加者が名前と媒体を入れて「現金」を選ぶ、**Then** 「受付で払ってください（通常 3,000円・早割 2,500円。受付の人が区分を確かめます）」と受付番号が出る。区分を選ぶ欄は出ない。
5. **Given** 4のイベント、**When** 「振込（後日）」を選ぶ、**Then** 振込先と「名義の前に受付番号を付けてください」の案内と、区分ごとの金額が出て、振込待ちに入る（区分はまだ決まっていない）。
6. **Given** 名簿なしで受付を済ませた端末、**When** 同じQRを開き直す、**Then** 入力の画面ではなく、自分の受付番号と状態（確かめ待ち・受付が済みました など）が出る。

### User Story 2 - 受付をする人が、区分を決めて「受け取った」で確定する（Priority: P1）

名簿なしで入った参加者の確かめ待ちは、002 と同じく受付の画面の上に出る。区分が2つ以上あるイベントでは、受付をする人が「受け取った」を押すときに、参加者に聞いた区分を選ぶ。区分が1つなら選ばない。振込は、振込待ちで「入金を確かめた」を押すときに区分を選ぶ。

**Why this priority**: 参加者に区分を選ばせない以上、受け取るときに区分を決める手段がないと、金額と締めが合わない。User Story 1 と組で最小の形になる。

**Independent Test**: 区分が2つの名簿なしのイベントで、参加者が現金で確かめ待ちになったあと、受付の画面で「受け取った」を押すと区分を選ぶ欄が出て、「早割」を選ぶと支払い済み・2,500円・区分 早割になり、現金の合計が2,500円増えることを確かめる。

**Acceptance Scenarios**:

1. **Given** 区分が2つの名簿なしのイベントで、参加者が現金を選んで確かめ待ちになった、**When** 受付の画面を見ている、**Then** 5秒以内に、確かめ待ちに「No.3 田中 ゆう・現金・区分を確かめる」が出る（金額は区分を決めるまで出さない）。
2. **Given** 1の確かめ待ち、**When** 受付をする人が「受け取った」を押す、**Then** 区分（通常 3,000円・早割 2,500円）を選ぶ欄が出て、選ぶまで支払い済みにしない。「早割」を選ぶと、支払い済み・区分 早割・2,500円になり、名簿の区分も早割になる。
3. **Given** 区分が1つの名簿なしのイベントの確かめ待ち、**When** 「受け取った」を押す、**Then** 区分を選ばずに、001・002 と同じ1回の操作で支払い済みになる。
4. **Given** 区分が2つの名簿なしのイベントで振込（後日）を選んだ人、**When** 主催者が振込待ちで「入金を確かめた」を押す、**Then** 区分を選ぶ欄が出て、選んだ区分の金額で入金を確かめたことになる。
5. **Given** 区分がまだ決まっていない確かめ待ち・振込待ち、**When** 主催者が締めの画面を開く、**Then** 002 の確かめ待ちと同じく件数と人を出し、締める前に知らせる。

### User Story 3 - 主催者が受付のしかたを選び、名簿を作らずに会を開く（Priority: P1）

主催者は、イベントを作るときに受付のしかた（名簿なし・名簿あり）を選ぶ。新しく作るイベントの既定は名簿なし。名簿なしのイベントを作ると、すぐセルフ受付のQRを出せる。あとから受付のしかたを変えられる。名簿の画面には、参加者が入れた人が増えていく（主催者が直す・消す・先に入れることもできる）。

**Why this priority**: 受付のしかたを選べないと、名簿なしを使い始められない。既定を名簿なしにすることで、主催者の手間が最初から減る。

**Independent Test**: 主催者がイベントを作る画面で受付のしかたの既定が「名簿なし」になっていること、作るとセルフ受付の画面が開きQRを出せること、イベントを直す画面で「名簿あり」に変えられることを確かめる。

**Acceptance Scenarios**:

1. **Given** 主催者がイベントを作る画面を開いた、**When** 受付のしかたを見る、**Then** 「名簿なし（参加者がセルフ受付で入れる）」が選ばれていて、「名簿あり（先に名簿を入れる）」も選べる。Threads のイベントから選んで作るときも同じ。
2. **Given** 名簿なしでイベントを作った、**When** 作り終える、**Then** そのイベントのセルフ受付の画面が開き、「セルフ受付のQRを出す」をすぐ押せる（名簿ありで作ったときは、今と同じく名簿の画面が開く）。
3. **Given** 名簿なしのイベント、**When** 主催者が名簿の画面を開く、**Then** 参加者がセルフ受付で入れた人が、媒体・区分（決まっていなければ「区分を確かめる」）・紹介した人と一緒に出て、直す・消すができる。主催者が先に人を入れることもできる。
4. **Given** 前からあるイベント（このfeatureの前に作ったもの）、**When** 主催者が開く、**Then** 受付のしかたは名簿ありのままで、今と同じように動く。
5. **Given** 名簿ありのイベント、**When** 主催者がイベントを直す画面で名簿なしに変える、**Then** それまでの名簿と受付の記録はそのまま残り、セルフ受付の参加者の画面が名前と媒体の入力に変わる（名簿なしから名簿ありに変えたときは、参加者の画面が名簿を探す形に戻る）。

---

### User Story 4 - 受付をする人が、同じ名前の知らせで二重の受付に気づく（Priority: P2）

名簿なしでは、主催者が名簿を確かめないので、同じ人が別の端末からもう一度入れたり、他人の名前で入れられたりしうる。同じ端末からの二重の受付は防ぎ、別の端末から名簿の人と同じ名前が入ったときは、受付の画面に「同じ名前の人がいます」と知らせる。受付をする人は、二重だった人を取り消して名簿から外せる。

**Why this priority**: お金は受付をする人が確かめるので、二重の受付があっても締めの合計はずれない。ただ、名簿と媒体ごとの数字を正しく保つために要る。

**Independent Test**: 名簿なしのイベントで、端末Aから「松本 れい」で受付したあと、端末Bから「まつもと れい」で入れると、名簿に2人目が入り、受付の画面の両方の行に「同じ名前の人がいます」が出ること、受付をする人が2人目を取り消して名簿から外せることを確かめる。

**Acceptance Scenarios**:

1. **Given** 端末Aで「松本 れい」が受付を済ませた、**When** 端末Aで同じQRを開き直す、**Then** 新しく入れる画面は出さず、自分の受付番号と状態が出る（User Story 1 の6）。「ほかの人の受付をする」を選んだときだけ、別の人を入れられる。
2. **Given** 名簿に「松本 れい（No.1・受付済み）」がいる、**When** 端末Bから「まつもと れい」が入る、**Then** No.2 として名簿に入り、受付の画面のNo.1とNo.2の行に「同じ名前の人がいます」が出る。参加者の画面には、No.1 がいることを出さない。
3. **Given** 2の状態、**When** 受付をする人がNo.2の記録を取り消し、「名簿から外す」を押す、**Then** No.2 は名簿から消え、知らせも消える（受付番号は詰めない）。
4. **Given** 主催者が先に名簿に入れた「井上 そら（未受付）」、**When** 参加者が名簿なしのセルフ受付で「いのうえ そら」と入れる、**Then** 新しい人は増やさず、井上 そらとして受付する（媒体・紹介した人が空なら、参加者が入れたもので埋める）。

### Edge Cases

- **区分が決まっていない記録の金額**：支払い済みになるまで、受付の画面・締めの現金とPayPayの合計には入れない（002 の確かめ待ちと同じ）。振込待ちの見込み（003）には、区分が決まるまで0円を除いた最も安い区分の金額で入れ、「区分を確かめる」と分かるようにする。
- **区分が0円の区分を含む**：参加者の画面に並べる区分ごとの金額には、0円の区分を出さない。招待の人が来たら、受付をする人が「受け取った」で0円の区分を選ぶか、受付の画面で直す。区分が「1つ」かどうかも、0円の区分を除かずに数える（0円の区分があれば、受付をする人が区分を決める）。
- **媒体の選択肢**：001 の媒体（港・こくちーずプロ・つなげーと・ジモティー・Peatix・YOUTRUST・当日・その他）を出す。Threads のイベントから作ったときは、掲載済みの媒体を先に並べる（名簿の画面と同じ）。
- **紹介してくれた人**：参加者には前に使った名前の候補を出さない（ほかの人の名前が見えるため）。入れた名前はそのまま紹介した人になり、主催者が名簿の画面で直せる。
- **名前の書き方**：名前は必須（001 の名前の長さの上限）、ふりがなは任意。名簿の人と同じかどうかは、001 の決まり（ひらがなとカタカナ・全角と半角・空白を区別しない）で比べる。
- **主催者が先に入れた人と一致**：未受付の名簿の人と名前が完全に一致したら、その人として受付する（User Story 4 の4）。一致する人が2人以上いるとき、または一致した人がすでに受付済みのときは、新しい人として入れ、同じ名前の知らせを出す。
- **いたずらで大量に入れられる**：1つの端末・1つのリンクから入れられる人数に上限を設け（具体的な値は plan で決める）、超えたら「受付が混んでいます。受付の人に声をかけてください」を出す。受付をする人は、記録を取り消して名簿から外せる。主催者はリンクを止められる。
- **リンクを止めた・期限が過ぎた・出し直した**：002 と同じく、入れることも払い方を選ぶこともできない。それまでに入った人は残る。
- **名簿なしで締める**：来なかった人（名簿にいて受付の記録がない人）は出さない。主催者が先に入れた人や取り消した人で受付の記録がない人は、締めの画面で「受付の記録がない人」として件数だけ出す。
- **書き出し（CSV）**：名簿ありと同じ列で出す。区分が決まっていない人は区分を「未定」とする。
- **受付のしかたを途中で変える**：名簿と受付の記録は変えない。名簿なしから名簿ありに変えると、参加者の画面は名簿を探す形（002）になる。名簿ありから名簿なしに変えると、名前と媒体を入れる形になる。変えたことは、開いている参加者の画面にも次に読み直したときに反映する。
- **締めたあと**：名簿なしで入った人の記録も、001 と同じく「締めのあとで変わった」と出す。
- **通信が切れた**：入れた内容が届いたかどうか分からないときは、送り直しても名簿に2人入らない（002 の送り直しと同じ）。

## Requirements *(mandatory)*

### Functional Requirements

**受付のしかた（主催者）**

- **FR-001**: Users（主催者） MUST be able to イベントを作るとき・直すときに、受付のしかた（名簿なし・名簿あり）を選ぶ。新しく作るイベントの既定は名簿なし（Threads のイベントから選んで作るときも同じ）。
- **FR-002**: System MUST このfeatureの前からあるイベントを、名簿ありとして扱う。
- **FR-003**: System MUST 名簿なしでイベントを作ったら、そのイベントのセルフ受付の画面を開く（名簿ありは、今と同じく名簿の画面）。
- **FR-004**: System MUST 受付のしかたを変えても、名簿・受付の記録・セルフ受付のリンクを変えない。

**参加者の画面（名簿なし・ログインなし）**

- **FR-010**: System MUST 名簿なしのイベントのセルフ受付の画面で、名前を探す欄の代わりに、名前（必須）・ふりがな（任意）・「どこで申し込みましたか」（必須。001 の媒体の並び。Threads で掲載済みの媒体を先に並べる）・紹介してくれた人（任意）の入力を出す。
- **FR-011**: System MUST 参加者が入れたら、主催者・受付をする人の確かめなしで、その人を名簿に入れ、次の受付番号を振る。区分は、イベントの区分が1つならその区分、2つ以上なら「区分を確かめる」（未定）にする。
- **FR-012**: System MUST 名簿に入れたら、参加者に受付番号・名前と、区分が1つなら区分と金額、2つ以上なら区分ごとの金額（0円の区分を除く）を出し、払い方（イベントで使う現金・PayPay・振込（当日）・振込（後日））を選ばせる。区分を選ぶ欄は出さない。
- **FR-013**: System MUST 払い方を選んだあとの案内と受付の記録を、002 と同じにする（現金・PayPayは確かめ待ち、振込は振込待ち、本人の申告の印）。区分が決まっていないときは、金額の代わりに区分ごとの金額と「受付の人が区分を確かめます」を出す。
- **FR-014**: System MUST 同じ端末からは、同じリンクで名簿なしの受付を済ませたあとに開き直すと、自分の受付番号と状態を出し、新しく入れる画面は出さない。参加者が「ほかの人の受付をする」を選んだときだけ、別の人を入れられる。
- **FR-015**: System MUST 入れた名前が、名簿の未受付の人1人と完全に一致したら（001 の名前の比べ方）、新しい人を増やさずにその人として受付する。一致した人の媒体・紹介した人が空なら、参加者が入れたもので埋める。
- **FR-016**: System MUST 参加者の画面に、ほかの参加者の名前・人数・名簿にいるかどうかを出さない（同じ名前の人がいることも出さない）。
- **FR-017**: System MUST 名簿なしのセルフ受付から、名簿の一覧・メモ・ほかの人の記録・紹介した人の候補・締め・設定にたどれないようにする（002 の FR-051 と同じ）。

**受付をする人の画面**

- **FR-020**: System MUST 区分が決まっていない確かめ待ちを、受付の画面の確かめ待ちに「区分を確かめる」と一緒に出す（金額は出さない）。会場の共有で、5秒以内にほかの受付の画面にも出す（002 と同じ）。
- **FR-021**: Users（受付をする人） MUST be able to 区分が決まっていない確かめ待ちを、区分を選んでから「受け取った」で支払い済みにする。区分を選ぶまで支払い済みにしない。選んだ区分を名簿の人の区分にもする。区分が1つのイベントでは選ばない。
- **FR-022**: Users（主催者） MUST be able to 区分が決まっていない振込待ちを、振込待ちの画面で区分を選んでから「入金を確かめた」にする。
- **FR-023**: System MUST 名簿なしで、別の端末から名簿の人と同じ名前（001 の名前の比べ方）が入ったら、受付の画面の該当するすべての行に「同じ名前の人がいます」を出す。
- **FR-024**: Users（受付をする人） MUST be able to 名簿なしで入った人の記録を取り消し、受付の記録のない人を名簿から外す（手伝う人も、本人の申告で入った人は外せる。002 の FR-032 と同じ考え）。
- **FR-025**: Users（受付をする人） MUST be able to 名簿なしのイベントでも、受付の画面から名前だけで人を足してそのまま記録する（001 の飛び入りと同じ）。

**締め・記録・数字**

- **FR-030**: System MUST 名簿なしのイベントの締めの画面で、来なかった人を出さない。受付の記録のない名簿の人は、件数だけ出す。
- **FR-031**: System MUST 名簿なしで入った人も、媒体ごとの名簿・来場・売上、紹介した人ごとの売上（003）、分配（003）、まとめ、書き出し（CSV）に、名簿ありの人と同じく数える。区分が決まっていない人は、区分を「未定」として出す。
- **FR-032**: System MUST 区分が決まっていない記録の金額を、支払い済みになるまで現金・PayPayの合計に入れない。振込待ちの見込みには、0円を除いた最も安い区分の金額で入れ、未定と分かるようにする。

**守り**

- **FR-040**: System MUST 名簿なしのセルフ受付で、1つの端末・1つのリンクから名簿に入れられる人数に上限を設け、超えたら入れさせず「受付が混んでいます。受付の人に声をかけてください」を出す（具体的な値は plan で決める）。
- **FR-041**: System MUST リンクの期限・止める・出し直す・送り直しで二重にしない、を002 と同じにする。
- **FR-042**: System MUST 参加者の連絡先・端末の情報を名簿に残さない（002 の FR-052 と同じ）。参加者が入れた名前・ふりがな・媒体・紹介した人は名簿として持ち、イベントを消すと一緒に消える（001 と同じ）。

### Key Entities *(include if feature involves data)*

- **イベント（001 に足すもの）**：受付のしかた（名簿なし・名簿あり）。新しく作るときの既定は名簿なし、前からあるイベントは名簿あり。
- **名簿の人（001 に足すもの）**：区分が決まっていないこと（名簿なしで、区分が2つ以上のときに入った人）。名簿なしのセルフ受付で入ったこと（どの端末から入ったかの印。同じ端末の判定と上限のため。名前や連絡先は持たない）。
- **受付の記録（002 のまま）**：本人の申告・確かめ待ち・確かめた人。区分を決めて受け取ったときは、その区分の金額になる。
- **参加者の端末の印（002 のまま）**：名簿なしでは、この端末から入れた人数（上限のため）にも使う。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 名簿なしのイベントで、主催者が事前に入れる名簿は0人で会を開ける（イベントを作ってからセルフ受付のQRを出すまで1分以内）。
- **SC-002**: 参加者が、会場のQRを読んでから払い方を選び終えるまで、45秒以内（名前・媒体を入れる・払い方を選ぶ）。
- **SC-003**: 受付をする人の操作は、確かめ待ちの人1人につき、区分が1つなら「受け取った」の1回、2つ以上なら区分を選ぶのを入れて2回まで。
- **SC-004**: 名簿なしで入った人は、5秒以内にすべての受付の画面と名簿の画面に出る。
- **SC-005**: 同じ端末からの二重の受付は0件。別の端末からの同じ名前は、受付の画面で100%知らせる。
- **SC-006**: 名簿なしの参加者の画面から、自分以外の参加者の名前・人数は、どの操作でも見えない。
- **SC-007**: 区分が決まっていない金額は、締めの現金・PayPayの合計に入らない（締めの合計と、受け取った人が実際に持つお金がずれない）。
- **SC-008**: テスト版の主催者が、名簿なしで会を開き、名簿を作る手間がなくなったと答える。

## Assumptions

- **前提**：001・002・003 が develop に入っていること（済み）。名簿なしは、002 のセルフ受付のリンク・本人の申告・確かめ待ち・会場の共有・振込待ちをそのまま使い、新しい払い方は足さない。
- **お金**：001 と同じく、アプリはお金を預からない。名簿なしで入っても、お金の受け取りは受付をする人が確かめる。
- **使える人**：001 と同じく、運営者が開いた主催者（テスト版・料金なし）。参加者は集金管理の利用者ではない。
- **区分を決める時**：ユーザーの答えのとおり、受付をする人が「受け取った」を押すとき。振込は「受け取った」がないので、振込待ちの「入金を確かめた」のときにする。
- **見込みの金額**：区分が決まっていない振込待ちは、003 の見込みに0円を除いた最も安い区分の金額で入れる（多く見積もらないため）。
- **上限の値**：名簿なしで1つの端末・1つのリンクから入れられる人数の具体的な値は plan で決める（イベントの名簿の上限（001）を超えない）。
- **言語・画面**：日本語、スマートフォンで使える（390px幅で横にはみ出さない・押すところは44px以上。001 と同じ）。
- **作らないもの**：参加者が区分を選ぶこと・参加者ごとのQR（チケット）・参加者のログイン・参加者の連絡先を聞くこと・同じ名前の人の自動のまとめ（受付をする人が取り消して外す）・事前のオンラインの申し込み（申し込みは外部の媒体に任せる。[集金管理の中心の課題](../001-event-day-collection/spec.md) と同じ）。
- **作り方**：パターン①（集金管理専用の置き場所。共通は入口の関数と出来事だけ）。業務の判断はAPIと共通のパッケージに置き、将来のモバイルの画面からも同じものを使えるようにする。共通のファイルを変える必要が出たら、docs/parallel-development.md 11章に従って小さな共通のPRに分ける。
- **依存**：001・002・003 が develop に入っていること（済み）。
