# 決めたことと理由（research）：名簿なしで受付する

**対象**：[spec.md](./spec.md) | **計画**：[plan.md](./plan.md) | **002 の research**：[002 research.md](../002-self-check-in/research.md)

## R1. 受付のしかたの持ち方と既定

- **Decision**：`collect.events` に `check_in_mode`（`roster`・`rosterless`。NOT NULL・既定 `roster`）を足す。前からあるイベントは `roster` になる（FR-002）。API の作る（POST）・直す（PUT）は `checkInMode` を任意で受け、作るときに省いたら `roster`。新しいイベントの既定を名簿なしにするのは画面（作る画面の初めの値）で、共通のパッケージの `NEW_EVENT_CHECK_IN_MODE = "rosterless"` を使う（将来のモバイルの画面も同じ値を使う）。
- **Rationale**：API の既定を `rosterless` にすると、001〜003 の結合テストと E2E（名簿を作ってセルフ受付で探す）がすべて名簿なしになって壊れる。画面の初めの値で既定を決めれば、ユーザーの答え（新しく作るイベントは名簿なし）を満たし、古い呼び方も変わらない。
- **Alternatives**：API の既定を `rosterless` にしてテストをすべて直す（変更が大きく、API の呼び方の意味が変わる）。主催者ごとの設定にする（ユーザーはイベントごとと答えた）。

## R2. 名簿なしの入口は、飛び入りの申し出の表を使い回す

- **Decision**：新しい道筋 `POST /api/collect/s/:token/entries` で、名簿の人を作り、`self_check_in_requests` に `status = accepted`（主催者が先に入れた人に当てたときは `matched`）の行を同じトランザクションで作る。参加者の画面は、002 の `GET …/me` の `request.person` から払い方の選択に進む（002 で「名簿に入れた」あとと同じ流れ）。送り直しで二重にしないよう、申し出の表に `client_request_id`（uuid・一意）を足す。
- **Rationale**：002 の申し出は、端末の印・自分の状態の読み直し・「名簿に入りました」→ 払い方の選択、まで揃っている。名簿なしは「申し出をすぐ名簿に入れる」ことなので、表と画面の流れをそのまま使える。同じ端末の二重の受付を防ぐこと（FR-014）も、002 の `me` が最後の申告・申し出を返すことで満たせる。
- **Alternatives**：名簿の人に端末の印を持たせ、新しい表を作る（`me` の作り直しが要る）。002 の申し出（pending）を作り、受付をする人の確かめを省く仕組みを足す（状態が増えて分かりにくい）。

## R3. 区分を確かめる（区分が2つ以上のとき）

- **Decision**：`roster_people` に `tier_undecided`（boolean・既定 false）を足す。`price_tier_id` は NOT NULL のままにし、名簿なしで入った人には**0円を除いた最も安い区分**を仮に入れる（0円の区分しかなければ最初の区分）。本人の申告の記録も、その区分と金額で作る。
  - 区分が「1つ」かは、0円の区分も数える（イベントの区分が1つなら `tier_undecided = false`）。
  - 受付をする人の確かめ（`POST …/reception/:personId/confirm`。主催者・手伝う人とも）と、振込待ちの「入金を確かめた」（`POST /transfers/:personId/confirm`）は、`tier_undecided` の人で、イベントの区分が2つ以上なら `priceTierId` が要る。なければ 400 `TIER_REQUIRED`。選んだら、記録の区分と金額を変え、名簿の人の区分も変えて `tier_undecided = false` にする。
  - 主催者が名簿の画面で区分を直したとき・受付の記録を直したときも `tier_undecided = false` にする。
- **Rationale**：仮の区分を入れておけば、締め・CSV・分配・見込み（003）の計算をほぼ変えずに済む。支払い済みにならないと合計に入らないので（002 の確かめ待ち）、仮の金額が締めの合計に紛れない（SC-007）。振込待ちの見込みは、仮の金額（0円を除いた最も安い区分）で入るので、多く見積もらない（spec の Assumptions）。
- **Alternatives**：`price_tier_id` を NULL にできるようにする（001〜003 の集計・CSV・分配の多くが区分のあることを前提にしていて、直す所が多い）。

## R4. 同じ名前の知らせ

- **Decision**：受付の画面の人（`ReceptionPerson`）に `sameName`（boolean）を足す。名簿なしのイベントで、同じ `name_key` の名簿の人が2人以上いれば、その全員を true にする（名簿ありでは常に false）。
- **Rationale**：名簿の画面で人を足すとき（001）にはすでに同じ名前を知らせている。受付の画面では、名簿なしで別の端末から入った二重の受付に気づければよい（FR-023）。名簿ありでは主催者が自分で入れた名前なので出さない。

## R5. 主催者が先に入れた人と一致したとき

- **Decision**：入れた名前の `name_key` が、名簿の人のうち「名簿なしで入っていない（`self_entered_at IS NULL`）・受付の記録がない」人1人と一致したら、その人として受付する（申し出は `matched`）。その人の紹介した人が空なら、参加者が入れたもので埋める（媒体は変えない）。2人以上と一致したとき・一致した人が受付済みのときは、新しい人として入れる（同じ名前の知らせが出る）。
- **Rationale**：名簿ありから名簿なしに変えたイベントや、主催者が招待の人を先に入れたイベントで、二重にしない（FR-015）。名簿なしで入った人どうし（別の端末）は当てない（他人の名前で入れて、ほかの人の受付に割り込めないようにする）。
- **ほかの人の名前が見えないこと**：当てたときも、参加者に返すのは002と同じ本人の情報（名前・受付番号・区分と金額）だけ。

## R6. 上限

- **Decision**：共通のパッケージの `SELF_CHECK_IN_LIMITS` に足す。
  - `entriesPerDevicePerLink: 10`（1つの端末から名簿なしで入れられる人数。友だちの分も入れられるように10）
  - `entriesPerLinkPerMinute: 60`（リンク全体で1分に入れられる人数）
  - `entriesPerLink: 1000`（リンク全体で入れられる人数。出し直すと数え直す）
  - 超えたら 429 `RATE_LIMITED`。数えるのは申し出の表（`status IN ('accepted', 'matched')` で `client_request_id` のある行＝名簿なしの入口から作った行）。
- **Rationale**：主催者の確かめなしで名簿に入るので、いたずらで大量に入れられないようにする（FR-040）。受付をする人は取り消して外せ、主催者はリンクを止められる。

## R7. 名簿なしで入った人を外す

- **Decision**：`roster_people` に `self_entered_at`（timestamptz null）を足し、名簿なしの入口で作った人に入れる。受付をする人（主催者・手伝う人）は、`self_entered_at` のある人で受付の記録がない人を外せる（`DELETE …/reception/:personId/entry`。主催者・手伝う人の両方の道筋）。記録があれば 409 `ALREADY_RECORDED`（先に記録を取り消す）。主催者は、これまでどおり名簿の画面からも消せる。
- **Rationale**：手伝う人は名簿を編集できない（001）が、名簿なしの二重の受付は受付の場で片付けたい（FR-024）。外せる人を名簿なしで入った人に限れば、手伝う人が主催者の名簿を壊せない。

## R8. 締め・CSV・まとめ・分配

- **Decision**：
  - 締めの画面（`ClosingSnapshot`）に `checkInMode` と `unrecordedCount`（受付の記録がない名簿の人の数）を足す。名簿なしでは `absent`（来なかった人）を空で返し、画面は来なかった人の段の代わりに「受付の記録がない人 N人」を出す（FR-030）。
  - CSV の区分の列は、`tier_undecided` の人を「未定」にする。
  - まとめ・分配・紹介ごとの売上は、記録の金額で数えるので変えない（仮の金額は支払い済みになるまで入らない）。
- **Rationale**：名簿なしでは、名簿にいて記録がない人は「来なかった人」ではない（取り消した人・主催者が先に入れた人）。

## R9. 会場の共有の知らせ

- **Decision**：名簿なしの入口で人ができたら、002 で申し出を名簿に入れたときと同じ知らせ（名簿の人が増えた）を会場の共有に送り、5秒以内に受付の画面に出す（SC-004）。外したときは、名簿の人を消したときと同じ知らせを送る。

## R10. 画面

- 参加者（`SelfCheckInPublicPage`）：`GET /s/:token` の `checkInMode` が `rosterless` なら、探す欄の代わりに入れる欄（名前・ふりがな・媒体・紹介してくれた人）。媒体は `media`（掲載済みを先に並べたもの）を並べる。入れたあとは 002 の「名簿に入りました」→ 払い方の選択。区分が決まっていなければ、払い方の選択と案内に区分ごとの金額（`tiers`）を並べる。
- 受付（主催者・手伝う人）：確かめ待ちの「受け取った」で、`tierUndecided` の人には区分を選ぶ段を出す。`sameName` の行に「同じ名前の人がいます」。名簿なしで入った人で記録のない行に「名簿から外す」。
- 振込待ち：`tierUndecided` の人の「入金を確かめた」で区分を選ぶ。
- イベントを作る・直す：受付のしかた（名簿なし・名簿あり）。作る画面の初めの値は `NEW_EVENT_CHECK_IN_MODE`。名簿なしで作ったら、セルフ受付の画面へ移る。
- 名簿：区分が決まっていない人に「区分を確かめる」。名簿なしのイベントでは、上に「参加者がセルフ受付で入れると、ここに増えます」。
- 締め：名簿なしでは来なかった人の段の代わりに「受付の記録がない人」。

## R11. PR の分け方

- **Decision**：PR1（共通の形・API・マイグレーション 0043・結合テスト。CI を流す）→ PR2（画面・Web のテスト・E2E・使い方の文書）。
- **Rationale**：002・003 と同じ分け方。マイグレーションのある PR1 だけ CI を流す（ユーザーの決まり）。
