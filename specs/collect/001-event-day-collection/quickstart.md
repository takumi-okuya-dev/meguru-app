## 1. 名簿を速く入れる（User Story 1）

1. `/collect/events/new`で、料金の区分「通常3,000円・早割2,500円・紹介割2,000円」のイベントを作る → 名簿の画面になる。
2. 媒体「Peatix」で、5人を名前＋Enterで続けて入れる → 受付番号1〜5、媒体はすべてPeatix。
3. 過去のイベントにいた人の名前の頭（例：「もり」）を入れる → 候補に「森 はるか（11/8 朝活もくもく会）」が出て、選ぶと名前とふりがなが入る。
4. 媒体「こくちーずプロ」で「まとめて貼る」に次を貼り、「読み込む」：
   ```text
   1. 松本 れい 様 matsumoto@example.com
   2. 井上 そら 様 090-1234-5678
   3. 木村 ゆうき さん
   申込日 11/20
   ```
   → 3人の名前だけになり、「申込日 11/20」は外れた状態で出る。足すと受付番号6〜8。
5. もう一度「松本 れい」を足す → 「同じ名前の人がいます（こくちーずプロ）」と出るが、足せる。

## 2. 受付と会場の共有（User Story 2・3）

1. 主催者がPCとスマートフォンの両方で`/collect/events/:id/reception`を開き、スマートフォンで1人記録する → PCに5秒以内に出る（User Story 2だけで確かめられる形）。
2. 「受付の手伝い」でリンクを出し、スマートフォン（または別のブラウザ）でQRのURLを開く → 名前「大野」を入れる → 受付の画面だけが出る（サイドバー・名簿の編集・締めはない）。
3. 大野の画面で「やま」で絞り、山田さんの「現金」を押す → 大野の画面で「受付済み・現金・3,000円・受け取り：大野」。**主催者の画面にも5秒以内に**同じ記録が出て、上の数字が変わる（SC-006）。
4. 主催者と大野が、同じ人の「現金」をほぼ同時に押す → 記録は1件だけ。後の人には「受付済み（受け取り：〇〇）」が出る（SC-005）。
5. 大野の画面で、主催者が記録した行の「取り消す」が出ないことを確かめる。
6. 大野のブラウザを閉じて同じURLを開き直す → 名前を入れずに続きから。別のブラウザで「大野」と入れる → 「すでに大野さんがいます。同じ人ですか？」→「同じ人」で、受け取った現金が1人にまとまる。
7. 「PayPay」を押す → QRが大きく出る →「受け取った」で記録。
8. 主催者がリンクを止める → 大野の画面が「このリンクは止められました」になり、記録は残る。
9. 開発者ツールで通信を切って「現金」を押す → 「保存できませんでした・もう一度送る」が出て、受付済みに見えない。つないで「もう一度送る」→ 1件だけ記録される。

## 3. 締め（User Story 4）

1. 大野が現金2人（6,000円）、主催者が現金1人とPayPay2人を記録した状態で`/collect/events/:id/closing`を開く。
2. 現金が「大野 6,000円・主催者 3,000円」と分かれて出る。大野に5,000と入れる → 「1,000円足りません」。6,000にして「精算した」。
3. PayPayの件数と合計が出る →「履歴と合った」。
4. 媒体ごとの名簿・来場・売上と、来なかった人が出る。
5. 「締める」→ 締めた時刻が出る。そのあと受付を1件取り消す → 「締めのあとで変わりました」。
6. 「書き出す」→ CSVをExcelで開き、文字化けせず、受け取った人の列があることを確かめる。

## 4. 振込（User Story 5）

1. 受付で2人を「振込（後日）」にする → `/collect/transfers`に2人が出る。
2. 1人の「入金を確かめた」→ 振込待ちが1人になり、締めの振込の受け取った額が増える。「戻す」で戻る。
3. 「連絡文をコピー」→ 名前・イベント名・金額・受付番号・振込先（設定に入れた文）が入った文がコピーされる。

## 5. 消すとき・退会

1. イベントを消す → 確かめの画面のあと消え、`/collect/summaries`に数字だけのまとめが残る。前回の参加者の候補に、そのイベントの人が出なくなる。
2. テストユーザーで退会する → 10分以内に、その人のイベント・まとめ・設定が消える（029の出来事）。

## 6. Threadsのイベントから選ぶ（User Story 6。PR4のあと）

1. めぐる Threadsの宣伝内容に、開催日時・会場・参加費3,000円のイベントの情報を入れて保存し、Peatixを掲載済みにする。
2. 10分以内に、集金管理の「Threadsのイベントから選ぶ」に出る → 選ぶと名前・日時・会場と、料金の区分の下書き3,000円が入る。
3. 名簿の媒体でPeatixが先に並ぶ。Threadsで宣伝内容を直すと、集金管理のイベントに「元が変わりました」が出る（中身は変わらない）。

## 7. 自動のテスト

```bash
pnpm --filter @meguru/shared test     # 名前の正規化・貼り付けの整え方・連絡文
pnpm --filter api test                # 結合テスト（作業場所をまたいで1つずつ流れる）
pnpm --filter web test
pnpm e2e                              # 受付と手伝う人の流れ
pnpm lint                             # 境界の規則（apps/collect がほかのアプリ・共通の表を読まない）
```

主に確かめること：二重の記録が1件になる（同時の2つの呼び出し）、同じ`clientRequestId`の送り直し、手伝う人の権限（取り消し・道筋）、止めたリンクの410、版の番号が上がること、まとめに名前が入らないこと、退会の出来事を2回受け取っても同じ結果。
