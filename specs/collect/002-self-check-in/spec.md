# Feature Specification：参加者が自分で受付する（セルフ受付）

**Feature Branch**: `feature/collect-002-self-check-in`

**Created**: 2026-11-13

**Status**: Draft

**Input**: 2026-11-13に、集金管理（アプリのID `collect`）の2つめのfeatureとして決めた。混む会で受付の手が足りないときに、参加者が会場のQRを読んで、自分で来場を記録し、払い方を選べるようにする。お金を受け取ったかどうかは参加者の申告なので、受付をする人（主催者・手伝う人）が確かめてから確定する。[001](../001-event-day-collection/spec.md) の「次のfeatureで考える」にあった「参加者が自分で受付する形（受付のQRを読んで自分で名前を入れる）」を作る。

**Source**: ユーザーの要望（2026-11-13。001 を作り終えたあと、次に作るものとして B「参加者が自分で受付」を選んだ）、[001 の spec](../001-event-day-collection/spec.md)（名簿・受付・受付の手伝い・会場の共有・締め・振込待ち）、[docs/app-separation.md](../../../docs/app-separation.md)（パターン①）、[Constitution](../../../.specify/memory/constitution.md)（原則III・技術スタック制約「モバイル化を見込んだ技術の選び方」）。

## Clarifications

### Session 2026-11-13（仕様を書く前にユーザーと決めたこと）

- Q：何を楽にするか？ → A：混む会で、受付をする人が足りないときの待ち時間。参加者が会場のQRを読み、自分で来場を記録して払い方を選べるようにする。
- Q：参加者はめぐるにログインするか？ → A：**しない**。主催者がイベントごとに出すセルフ受付のリンク（QR）から入る。
- Q：参加者が「払った」と言えば、それで支払い済みにするか？ → A：**しない**。本人の申告は「確かめ待ち」とし、受付をする人が「受け取った」で確定する。現金は受付で払ってもらう。
- Q：名簿にいない人は？ → A：名前を入れて**飛び入りとして申し出る**。受付をする人が確かめて名簿に入れる（または断る）。

## 用語

001 の用語（主催者・手伝う人・受付をする人・参加者・名簿・受付番号・払い方・受付の記録・会場の共有・締め・振込待ち）はそのまま使う。

- **セルフ受付のリンク**：主催者がイベントごとに出す、参加者のためのリンク（とQR）。会場に貼るか、画面に出して読んでもらう。期限があり、主催者がいつでも止められる。手伝う人の受付用リンク（001）とは別のリンク。
- **本人の申告**：参加者がセルフ受付で来場を記録し、払い方を選んだこと。受付の記録として残すが、お金を受け取ったことにはまだしない。
- **確かめ待ち**：本人の申告のうち、受付をする人がまだ確かめていない現金・PayPayの記録。受付の画面の上に出る。
- **飛び入りの申し出**：名簿にいない参加者が、セルフ受付で名前を入れて「来ました」と申し出たもの。受付をする人が名簿に入れるか断る。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 参加者が会場のQRを読み、自分で来場を記録して払い方を選ぶ（Priority: P1）

参加者は会場に貼られたQRをスマートフォンで読み、自分の名前か受付番号を入れて自分を探す。見つかると、自分の料金の区分と金額が出るので、払い方（現金・PayPay・振込）を選ぶ。PayPayなら主催者のQRと金額、振込なら振込先と「名義の前に受付番号」の案内、現金なら「受付で〇円を払ってください」が出る。参加者には、ほかの参加者の名前は見えない。

**Why this priority**: 受付の待ち時間を減らすという、このfeatureの中心。これだけで、受付をする人の「探して・押す」の手間が参加者の側に移る。

**Independent Test**: 名簿に3人いるイベントでセルフ受付のリンクを出し、別のスマートフォン（ログインなし）でQRを開く。名前を入れて自分が見つかること、払い方を選ぶと案内が出て「確かめ待ち」として記録されること、ほかの2人の名前がどこにも出ないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 名簿に「松本 れい（No.12・通常 3,000円）」がいてセルフ受付のリンクが使える、**When** 参加者がQRを開き「まつもと れい」と入れる、**Then** 「No.12 松本 れい さん・通常 3,000円」が出て、払い方のボタン（イベントで使う払い方だけ）が出る。
2. **Given** 1の画面、**When** 「PayPay」を選ぶ、**Then** 主催者のPayPayの受け取り用QRと「3,000円」が大きく出て、受付の記録が「本人の申告・PayPay・確かめ待ち」で残る。
3. **Given** 1の画面、**When** 「振込（後日）」を選ぶ、**Then** 振込先の案内と「名義の前に受付番号 12 を付けてください」が出て、受付の記録が「本人の申告・振込（後日）」で残り、振込待ちに入る。
4. **Given** 1の画面、**When** 「現金」を選ぶ、**Then** 「受付で3,000円を払ってください。受付番号は12です」が出て、受付の記録が「本人の申告・現金・確かめ待ち」で残る。
5. **Given** 名簿に「松本 れい」が2人いる、**When** 「松本 れい」と入れる、**Then** 人を選ぶ一覧は出さず、「同じ名前の人がいます。受付番号を入れてください」と聞く。
6. **Given** 名簿にない名前を入れた、**When** 探す、**Then** 「見つかりませんでした」と、受付番号で探す・飛び入りとして申し出る・受付の人に声をかける、の案内が出る（似た名前の候補は出さない）。

### User Story 2 - 受付をする人が、確かめ待ちを見て「受け取った」で確定する（Priority: P1）

主催者と手伝う人の受付の画面（001）の上に、確かめ待ちの人が出る。参加者が受付に来たら、現金を受け取るかPayPayの受け取りを確かめて「受け取った」を押す。受け取った人はそのとき押した人になる。違っていたら払い方・区分・金額を直すか、申告を取り消す。

**Why this priority**: 本人の申告だけでは、お金を受け取ったことにならない。確かめる手段がないと、締めの現金・PayPayが合わなくなる。User Story 1 と組で最小の形になる。

**Independent Test**: User Story 1 で確かめ待ちを1件作り、主催者と手伝う人の2つの受付の画面に5秒以内に出ること、手伝う人が「受け取った」を押すと支払い済み・受け取った人＝その手伝う人になり、両方の画面と数字が直ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 参加者がPayPayで本人の申告をした、**When** 受付の画面を見ている、**Then** 5秒以内に、一覧の上の「確かめ待ち」に「No.12 松本 れい・PayPay 3,000円」が出て、件数が増える。
2. **Given** 1の確かめ待ち、**When** 手伝う人が「受け取った」を押す、**Then** 支払い済みになり、受け取った人＝その手伝う人、記録に「本人の申告」の印が残る。PayPayの合計が3,000円増える。
3. **Given** 確かめ待ちの人が別の払い方で払いたいと言った、**When** 受付をする人が払い方を変えて「受け取った」を押す、**Then** 変えた払い方で支払い済みになる。
4. **Given** 他人がいたずらで申告した、**When** 受付をする人が「申告を取り消す」を押す、**Then** その人は未受付に戻る。
5. **Given** 確かめ待ちが残っている、**When** 主催者が締めの画面を開く、**Then** 確かめ待ちの件数と人が出て、締める前に知らせる（締めることは止めない）。

---

### User Story 3 - 主催者がセルフ受付のリンクを出し、止める（Priority: P2）

主催者は、イベントごとにセルフ受付のリンクを出し、QRを印刷するか画面に出して会場に置く。期限を変える・止める・出し直す（前のQRを使えなくする）ができる。セルフ受付で何件の申告・申し出があったかが分かる。

**Why this priority**: User Story 1 の入口。手伝う人の受付用リンク（001）と同じ操作で済むので、作りは小さい。

**Independent Test**: 主催者がセルフ受付のリンクを出し、QRと期限が出ること、止めると参加者の画面が「受付は終わりました（受付の人に声をかけてください）」になること、出し直すと前のQRで開けなくなることを確かめる。

**Acceptance Scenarios**:

1. **Given** イベントにセルフ受付のリンクがない、**When** 主催者が「セルフ受付のQRを出す」を押す、**Then** QR・リンク・期限（既定は開催日の日本時間23:59と、終わりの時刻の1時間後の遅い方）が出る。
2. **Given** リンクが使える、**When** 主催者が「止める」を押す、**Then** 参加者の画面は5秒以内に「セルフ受付は止められました。受付の人に声をかけてください」になり、それまでの申告は残る。
3. **Given** リンクが使える、**When** 主催者が「出し直す」を押す、**Then** 新しいQRになり、前のQRでは開けない。
4. **Given** セルフ受付が使われた、**When** 主催者がセルフ受付の画面を見る、**Then** 本人の申告・確かめ待ち・飛び入りの申し出の件数が出る。

---

### User Story 4 - 名簿にいない人が、飛び入りとして申し出る（Priority: P2）

名簿にいない人（当日来た人・名前のつづりが違って見つからない人）は、名前を入れて「来ました」と申し出る。受付の画面に「申し出」として出て、受付をする人が名簿に入れる（001の飛び入りと同じ：媒体「当日」・最初の区分・次の受付番号）か、名簿の人に当てる（つづり違い）か、断る。名簿に入れると、参加者の画面に受付番号と払い方の選択が出る。

**Why this priority**: 見つからない参加者が受付に並び直すと、セルフ受付の意味が薄れる。ただし、名簿の中の人で済む会も多い。

**Independent Test**: 名簿にない名前で申し出て、受付の画面に5秒以内に「申し出」が出ること、「名簿に入れる」で受付番号が振られ、参加者の画面が払い方の選択に進むことを確かめる。

**Acceptance Scenarios**:

1. **Given** 名簿にない「田中 ゆう」、**When** 参加者が「飛び入りとして申し出る」で名前を送る、**Then** 受付の画面に「申し出：田中 ゆう」が出て、参加者の画面は「受付の人が確かめています」になる。
2. **Given** 1の申し出、**When** 受付をする人が「名簿に入れる」を押す、**Then** 媒体「当日」・最初の区分・次の受付番号で名簿に入り、参加者の画面に受付番号と払い方の選択が出る。
3. **Given** 名簿の「田中 優」と同じ人の申し出（つづり違い）、**When** 受付をする人が「名簿の人に当てる」で田中 優を選ぶ、**Then** 新しい人は増えず、参加者の画面は田中 優（No.5）の払い方の選択に進む。
4. **Given** いたずらの申し出、**When** 受付をする人が「断る」を押す、**Then** 申し出は消え、参加者の画面は「受付の人に声をかけてください」になる。

---

### Edge Cases

- **二重の受付**：受付済み（確かめ待ち・本人の申告を含む）の人がもう一度セルフ受付すると「もう受付済みです（No.12）。違っていたら受付の人に声をかけてください」と出し、新しい記録は作らない。受付をする人とほぼ同時に記録しても、記録は1件だけ（001 の決まり）。
- **選び直し**：本人の申告のあと、確かめられる前なら、同じ端末から払い方を選び直せる。確かめられたあとは選び直せない。
- **なりすまし**：他人の名前で申告されても、現金・PayPayは確かめ待ちなので、本人が受付に来たときに気づける。受付をする人は申告を取り消せる。振込（後日）の本人の申告はそのまま振込待ちに入るが、入金は001の振込待ちで確かめる。
- **確かめ待ちのまま会が終わる**：締めの画面で、確かめ待ちを件数と人で出し、締める前に知らせる。確かめ待ちの金額は現金・PayPayの合計に入れない。
- **リンクを止めたあと**：開いたままの参加者の画面は止まり、探す・申告・申し出はできない。それまでの申告と申し出は残る。
- **期限が過ぎた・出し直した**：前のリンクでは「このQRは使えません。受付の人に声をかけてください」。
- **締めたあと**：セルフ受付で記録すると、001 と同じく「締めのあとで変わった」と出る。
- **つづり違い・旧姓**：名前が完全に一致しなければ見つからないので、受付番号で探すか、飛び入りとして申し出てもらい、受付をする人が名簿の人に当てる。
- **通信が切れた**：申告が届いたかどうか分からないときは、送り直しても二重にならない（001 と同じ）。届いていなければ「送れませんでした。もう一度送る」を出す。
- **名簿を推測しようとする**：名前を何度も入れて名簿にいるかを試せないよう、1つの端末から探せる回数に上限を設け、上限を超えたら少し待ってもらう。
- **0円の区分の人**（招待など）：払い方は選ばず「来場を記録しました」で終わる（確かめ待ちにしない）。

## Requirements *(mandatory)*

### Functional Requirements

**セルフ受付のリンク（主催者）**

- **FR-001**: Users（主催者） MUST be able to イベントごとにセルフ受付のリンク（とQR）を出し、期限を変え、止め、出し直す。使えるリンクはイベントに1つ。期限の既定は、開催日の日本時間23:59と、終わりの時刻（なければ開始の時刻）の1時間後の遅い方。出し直すと前のリンクは使えない。手伝う人の受付用リンク（001）とは別に持つ。
- **FR-002**: System MUST 主催者に、セルフ受付の本人の申告の件数・確かめ待ちの件数・飛び入りの申し出の件数を出す。
- **FR-003**: System MUST セルフ受付のリンクを、手伝う人には出させない（出す・止めるのは主催者だけ）。

**参加者の画面（ログインなし）**

- **FR-010**: Users（参加者） MUST be able to セルフ受付のリンクをログインなしで開く。開いた画面には、イベントの名前・開催日時・会場だけを出す。
- **FR-011**: Users（参加者） MUST be able to 自分の名前（フルネーム）か受付番号を入れて自分を探す。名前はひらがなとカタカナ・全角と半角・空白を区別しない（001 の決まりと同じ）。ふりがなでも探せる。
- **FR-012**: System MUST 探した結果として、入れた名前・ふりがな・受付番号に**完全に一致した人だけ**を出す。部分一致の候補や、名簿の一覧は出さない。同じ名前の人が2人以上いれば、人を選ばせず受付番号を聞く。
- **FR-013**: System MUST 見つかった人について、名前・受付番号・料金の区分と金額だけを出す（メモ・媒体・ほかの人の記録は出さない）。
- **FR-014**: Users（参加者） MUST be able to 見つかったら、イベントで使う払い方（現金・PayPay・振込（当日）・振込（後日））から1つを選ぶ。「来場のみ」は選べない（0円の区分の人は、払い方を選ばずに来場だけを記録する）。
- **FR-015**: System MUST 払い方を選んだら、その場で次を出す。現金：「受付で〇円を払ってください」と受付番号。PayPay：主催者の受け取り用QRと金額。振込：振込先の案内と「名義の前に受付番号を付ける」案内（001 の連絡文と同じ言い方）。
- **FR-016**: System MUST 本人の申告を受付の記録として残す。記録には「本人の申告」の印を付ける。現金・PayPayは**確かめ待ち**（支払い済みにしない）、振込（当日・後日）は001と同じく**振込待ち**、0円の区分は来場だけ。
- **FR-017**: Users（参加者） MUST be able to 確かめられる前なら、同じ端末から払い方を選び直す。
- **FR-018**: System MUST 受付済み（本人の申告・確かめ待ちを含む）の人には新しい記録を作らず、「もう受付済みです（受付番号）」を出す。受付をする人の記録と重なっても、記録は1人1件（001 の決まり）。送り直しで二重にしない。
- **FR-019**: System MUST リンクが止められた・期限が過ぎた・出し直されたときは、探す・申告・申し出をさせず、「受付の人に声をかけてください」を出す。開いている画面も5秒以内に止める。

**飛び入りの申し出**

- **FR-020**: Users（参加者） MUST be able to 名簿で見つからないとき、名前（任意でふりがな）を入れて飛び入りとして申し出る。
- **FR-021**: Users（受付をする人） MUST be able to 申し出を、名簿に入れる（001 の飛び入りと同じく、媒体「当日」・最初の区分・次の受付番号）・名簿の人に当てる（つづり違い）・断る、のどれかで片付ける。
- **FR-022**: System MUST 申し出を片付けたら、参加者の画面を進める（名簿に入れた・当てた：受付番号と払い方の選択へ。断った：「受付の人に声をかけてください」）。
- **FR-023**: System MUST 1つの端末からの申し出の数に上限を設ける（同時に待てる申し出は1件）。

**受付をする人の画面（001 の受付・手伝う人の受付）**

- **FR-030**: System MUST 確かめ待ちと飛び入りの申し出を、受付の画面の一覧の上に、件数と一緒に出す。会場の共有で、5秒以内にほかの受付の画面にも出す。
- **FR-031**: Users（受付をする人） MUST be able to 確かめ待ちの人を「受け取った」で支払い済みにする。受け取った人は押した人にする。払い方・料金の区分・金額を直してから受け取れる。
- **FR-032**: Users（受付をする人） MUST be able to 本人の申告を取り消して未受付に戻す（手伝う人も、本人の申告は取り消せる。001 の「手伝う人は自分が受け取った記録だけ取り消せる」の例外）。
- **FR-033**: System MUST 受付の画面の数字で、確かめ待ちの金額を現金・PayPayの合計に入れず、「確かめ待ち」の件数と合計として別に出す。

**締めと記録**

- **FR-040**: System MUST 締めの画面で、確かめ待ちが残っていれば件数と人を出し、締める前に知らせる（締めることは止めない）。確かめ待ちの金額は、受け取った人ごとの現金・PayPayの合計に入れない。
- **FR-041**: System MUST 書き出し（CSV）と記録で、本人の申告で記録されたこと、だれが確かめたかが分かるようにする。

**守り**

- **FR-050**: System MUST 1つの端末・1つのリンクあたりの探す回数に上限を設け（目安：1分に10回）、超えたら少し待ってもらう。結果は「見つかった・見つからない・受付番号を入れて」だけにし、名簿にいるかどうか以外は分からないようにする。
- **FR-051**: System MUST セルフ受付の画面から、名簿の一覧・メモ・ほかの人の記録・締め・設定に一切たどれないようにする。
- **FR-052**: System MUST 参加者の連絡先・端末の情報を名簿に残さない（同じ端末の判定に使う印だけを持ち、イベントを消すと一緒に消える）。

### Key Entities *(include if feature involves data)*

- **セルフ受付のリンク**：イベント・期限・止めた時刻・作った時刻。イベントに使えるものは1つ。手伝う人の受付用リンクとは別。
- **受付の記録（001 に足すもの）**：本人の申告かどうか、確かめた人と時刻。現金・PayPayの本人の申告は、確かめるまで「確かめ待ち」。
- **飛び入りの申し出**：イベント・名前・ふりがな・申し出た時刻・状態（待ち・名簿に入れた・当てた・断った）・当てた名簿の人。
- **参加者の端末の印**：同じ端末からの選び直し・回数の上限・申し出の上限のための印。名前や連絡先は持たない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 参加者が、会場のQRを読んでから払い方を選び終えるまで、30秒以内（名前を入れる・払い方を選ぶ・PayPayなら受け取ったと伝える）。
- **SC-002**: 受付をする人の操作は、確かめ待ちの人1人につき「受け取った」の1回（払い方を変えないとき）。
- **SC-003**: 本人の申告・飛び入りの申し出は、5秒以内にすべての受付の画面に出る。
- **SC-004**: セルフ受付の画面から、完全に一致した本人の名前以外の参加者の名前は、どの操作でも見えない。
- **SC-005**: セルフ受付と受付をする人の記録を合わせても、1人に受付の記録は1件だけ（二重の記録0件）。
- **SC-006**: 確かめ待ちの金額は、締めの現金・PayPayの合計に入らない（締めの合計と、受け取った人が実際に持つお金がずれない）。
- **SC-007**: テスト版の主催者が、混む会（参加者30人以上）でセルフ受付を使い、受付の待ちが減ったと答える。

## Assumptions

- **前提**：001（名簿・受付・受付の手伝い・会場の共有・締め・振込待ち）が使えること。セルフ受付は 001 の受付の記録・会場の共有・振込待ちをそのまま使い、新しい払い方は足さない。
- **お金**：001 と同じく、アプリはお金を預からない。本人の申告は「払うと言った」記録で、受け取りは受付をする人が確かめる。
- **使える人**：001 と同じく、運営者が開いた主催者（テスト版・料金なし）。参加者は集金管理の利用者ではない。
- **名前で探す決まり**：完全に一致した人だけを出す（似た名前の候補を出すと、ほかの参加者の名前が見えてしまうため）。つづり違いは、受付番号か飛び入りの申し出で受付をする人が当てる。
- **回数の上限**：探す回数・申し出の数の具体的な値は plan で決める（目安は FR-050・FR-023）。
- **言語・画面**：日本語、スマートフォンで使える（390px幅で横にはみ出さない・押すところは44px以上。001 と同じ）。
- **作らないもの**：参加者ごとのQR（チケット）・事前のチェックイン（会場に来る前）・参加者のログイン・PayPayの自動の照らし合わせ・参加者への連絡（メール・LINE）・顔写真。
- **作り方**：パターン①（集金管理専用の置き場所。共通は入口の関数と出来事だけ）。業務の判断はAPIと共通のパッケージに置き、将来のモバイルの画面からも同じものを使えるようにする。共通のファイルを変える必要が出たら、docs/parallel-development.md 11章に従って小さな共通のPRに分ける。
- **依存**：001 が develop に入っていること（済み）。
