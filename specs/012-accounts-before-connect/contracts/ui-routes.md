## アカウントの示し方（すべての画面で共通。research.md R2）

`accountLabel(account)`で決める。

| 状態 | 画像 | 主の名前 | 添える名前 | 印 |
|---|---|---|---|---|
| 未接続 | 名前の頭文字 | アカウントの名前 | なし | 「未接続」（`ConnectionBadge`、灰色） |
| 接続中 | Threadsのプロフィール画像（読めなければ名前の頭文字） | アカウントの名前 | @ユーザー名（小さく、薄い色） | なし |

## アカウントを作る（`/accounts/new`）

```text
┌──────────────────────────────────┐
│ アカウントを作る                     │
│ 運用するThreadsアカウントごとに1つ作ります。 │
│                                  │
│ アカウントの名前                      │
│ [ 例：カフェの公式            ] 0/50 │
│                                  │
│ [          作る          ]        │
│                                  │
│ Threadsには、あとで「このアカウントの    │
│ 設定」からつなげます。                 │
│ 登録済み 1 / 5 件（2つ目から）          │
└──────────────────────────────────┘
```

- 名前の入力欄は1つだけ（`FieldWithCounter`、50文字）。空・空白だけでは「作る」を押せない。50文字を超えた分は入らない。
- 送信中はボタンを止める。成功したら`/accounts/:id`へ（`?next=`があれば覚えておき、つないだ後に戻す。R7）。
- 上限に達していれば、入力欄の代わりに001 FR-017の案内（今の`ACCOUNT_LIMIT_REACHED`の文言と次の操作）。
- 1つ目のアカウントのときは「登録済み n/m件」を出さない（はじめての人に数を見せない）。
- 検証期間の案内（`TESTER_NOTICE`）とトークンの方法は、この画面から消す（「Threadsとの接続」へ移す）。

## 「このアカウントの設定」

区分の並び（上から）：**アカウントの名前**（新規）→ **Threadsとの接続** → 投稿の時刻（自動投稿）→ （今の区分）→ チーム → 削除。

### アカウントの名前（新規。オーナーだけ）

- 名前の入力欄と「保存」。保存したら切り替えメニューなどの表示がすぐ変わる（`/api/me`と`/api/accounts/:id`を取り直す）。
- オーナー以外には区分を出さない（今の設定の区分と同じ出し分け）。

### Threadsとの接続（`id="threads"`）

未接続のとき：

```text
Threadsとの接続                         [未接続]
Threadsにつなぐと、承認した案を自動で投稿し、反応を分析できます。
戦略・投稿ストック・設定は、つないでもそのまま残ります。

[ Threadsで許可する ]
（検証期間中の案内：TESTER_NOTICE）

▸ 自分のMetaアプリのトークンでつなぐ        （開くと010の手順と入力欄）
```

- 「Threadsで許可する」：`POST /api/threads/connect { mode: "connect", accountId }`の`authorizeUrl`へ移る。
- トークン：010の`TokenConnectForm`を`mode="connect"`で使う。成功したら同じ画面で「つながりました」に変える。
- エラー（`?error=CODE`、またはトークンの応答）：区分の中に`Alert`で出す。`ACCOUNT_ALREADY_REGISTERED`は、重なったアカウントの名前とそのアカウントへのリンク（`details`）を出す。
- オーナー以外：区分に「未接続」と「オーナーがThreadsにつなぐと使えます」だけを出す（つなぐ操作は出さない。spec FR-015）。

つないだ直後（`?connected=connect`、またはトークンの成功）：

```text
✓ {name}をThreadsにつなぎました（@cafe_b）
  自動投稿はオフのままです。投稿の時刻を決めてオンにすると、承認した案の投稿が始まります。
  [ 自動投稿を始める ]   ← 下の「投稿の時刻」の区分へ移り、設定のダイアログを開く
```

- 権限の案内（010の`warn`）は今のまま、この下に出す。
- 招待のリンクを覚えていれば（R7）、この案内の代わりに招待の画面へ戻す。

接続中・要再接続のとき：今のまま（今の接続の方法、「接続し直す」のダイアログ）。

### 投稿の時刻（自動投稿）

- 未接続なら、区分の上に`NotConnectedNotice`（「Threadsにつなぐと使えます」と「Threadsとの接続」へのリンク）。時刻の設定のダイアログは開けるが、オンのスイッチは使えない（`disabled`、理由を`aria-describedby`で示す）。
- 未接続のとき、`ReconnectButton`・要再接続の文言は出さない。

### 削除

- 確認の入力：「確認のため、{name} と入力してください」。プレースホルダーも`{name}`。
- 未接続なら、トークンの注意（010 FR-050）を出さない。

## ホーム（`/accounts/:id`）

- 未接続なら、一番上に`NotConnectedBanner`（控えめな帯。灰色の背景、1行）：「未接続：Threadsにつなぐと、承認した案を自動で投稿し、反応を分析できます」と「Threadsにつなぐ」（`/accounts/:id/settings#threads`。オーナーだけ）。
- 「次にやること」（`nextStep`）：未接続で承認済みの案が1件以上（`GET /post-drafts/counts`の`approved`）なら、ほかより先に「Threadsにつないで自動投稿を始めましょう」（`/accounts/:id/settings#threads`）。それ以外は今のまま。
- 要再接続のバナー（`account-layout.tsx`）は、`needs_reconnect`のときだけ（今のまま）。

## パフォーマンス（`/accounts/:id/performance`）

- 未接続なら、見出しの下に`NotConnectedNotice`だけを出す。数字・グラフ・一覧・書き出しのメニューは出さない。

## 投稿ストック（`/accounts/:id/stock`）

- `AutoPostNotices`：`kind: "not_connected"`の知らせを「承認した案は、Threadsにつないで自動投稿をオンにすると投稿されます」と「Threadsとの接続」へのリンクで出す。
- `NextPostCard`：オフなので出ない（今のまま）。

## 切り替えメニュー

- 一覧の各行：上の「アカウントの示し方」。未接続の行に「未接続」の印。
- 一番下の「Threadsアカウントを追加」を「アカウントを作る」（`/accounts/new`）にする。上限に達していても出し、押した先で案内する（今のまま）。

## 招待の確認（`/invite/:token`）とチームを作る

- `needs_account`（アカウントが0件）：「先に、自分のアカウントを作り、Threadsにつないでください」と「アカウントを作る」（`/accounts/new?next=/invite/:token`）。
- `needs_connection`（アカウントはあるが未接続だけ）：「先に、自分のアカウントをThreadsにつないでください」と、最初の未接続のアカウントの「Threadsとの接続」へのリンク。リンクを押す前に招待のURLを覚える（`rememberInviteReturn`）。
- `ready`：アカウントの選択で、未接続のアカウントは選べない形（`disabled`）で「Threadsにつなぐと入れられます」を添える。
- 「チームを作る」のダイアログも同じ（選べない形と添え書き。つないだアカウントがなければ「先にThreadsにつないでください」と作るボタンを止める）。

## 個人運用の画面（Constitution原則V）

- 接続中のアカウントだけを持つ人の画面は、アカウントの名前の区分（設定）と、切り替えメニューの「アカウントを作る」の文言を除いて変わらない（spec SC-007）。今の`solo-owner-unchanged.test.tsx`を、この2つを除いて同じであることを確かめる形に直す。
