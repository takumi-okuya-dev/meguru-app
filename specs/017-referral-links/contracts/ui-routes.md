# 画面の契約：紹介リンク

**日付**：2026-11-01 | **計画**：[../plan.md](../plan.md) | **UI全体設計**：[docs/ui-design.md](../../../docs/ui-design.md)

## 1. 紹介リンクの画面 `/r/:code`（認証のガードの外）

016の招待の画面（`/test-invite/:token`）と同じ骨格（中央のカード、上に「ThreadsGrower」）。

**ログインしていない人**

- 開いたら、`:code`を`localStorage`の`tg.referral`に`{ code, at: 今 }`で書く（形に合わないものも書かない）。
- 見出し：「ThreadsGrowerに招待されています」
- アプリの紹介（3行）：
  - 「Threadsの投稿案を、戦略に沿って作れます」
  - 「承認した投稿だけを、決めた時刻に自動で投稿します」
  - 「投稿の反応を取り込み、次の案に生かせます」
- テスト用のグループがONの環境（`GET /api/referral-page`の`testGroups`）では、注意を1行足す：「テスト版は、招待された方だけが使えます。招待のリンクを受け取った方は、そちらから始めてください。」
- ボタン：「Googleで始める」→`/sign-in`（戻り先は付けない）
- 紹介した人の名前は出さない。`GET /api/referral-page`が失敗しても、注意を出さずに画面は出す。

**ログインしている人**

- `localStorage`には書かず、`/`へ置き換えで移る（すでに登録している人。FR-005）。

## 2. 設定 › 個人設定 › 紹介 `/settings/referral`

- 項目の一覧（`sections.ts`）の「個人設定」の最後に「紹介」を足す。検索語：「紹介」「招待」「友だち」「共有」「リンク」。
- 見出し：「紹介」。説明：「このリンクから登録した人の数がわかります。紹介した人・された人への特典はありません。」
- 紹介リンク：読み取り専用の入力欄と「コピー」（016の運営者の画面の招待リンクと同じ見た目。コピーできたら「コピーしました」）。
- 人数：「あなたの紹介で登録した人：N人」。
- 読み込み中・エラーは、ほかの設定の項目と同じ出し方。

## 3. APIクライアント

- `localStorage`の`tg.referral`を読み、`at`から30日以内なら、すべてのAPIの呼び出しに`X-Referral-Code`を付ける。30日を過ぎていれば消す。読み書きできない環境（プライベートブラウズなど）では何もしない。
- `api.me`が成功したら、`tg.referral`を消す。
- ログアウトでは消さない（ログアウトしてから別のアカウントで新しく登録する人の紹介を残すため）。

## 4. ホームの「アプリを紹介する」（2026-11-02に追加）

- ホーム（`/accounts/:id`）の、「課題」「宣伝内容」「リサーチ」の3枚のカードの下に置く。
- 見出し：「アプリを紹介する」。説明：「リンクを送って、ThreadsGrowerを勧められます。」
- 「共有する」：端末の共有の画面（`navigator.share`）で紹介リンクを渡す。共有の画面がない端末では出さない。
- 「リンクをコピー」：紹介リンクをコピーし、「コピーしました」に変える。コピーできなければ、紹介リンクを読み取り専用の入力欄で出して選んだ状態にし、手でコピーしてもらう。
- 「紹介した人数を見る」：設定 › 紹介 へ移る。人数はホームには出さない。
- `GET /api/me/referral`を読めるまで・読めなければ、カードを出さない（ホームの残りはそのまま出す）。リンクは変わらないので、ホームを開くたびには読み直さない。
