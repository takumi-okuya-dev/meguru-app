# Feature Specification:紹介リンク

**Feature Branch**: `feature/017-referral-links`

**Created**: 2026-11-01

**Status**: Draft

**Input**: 2026-10-31に、ユーザーが「他の人にアプリを勧めてもらう機能（リンクを共有して、アカウントを作ってもらいたい）」を挙げ、テスト用のグループ（016）とは別のfeatureにすると決めた。2026-11-01、016をテスト環境に出したあとに作ると決め、次の3つを決めた：①紹介した人・紹介された人に特典は付けない（誰の紹介で登録したかを記録するだけ）②テスト用のグループがONの環境（テスト環境）では、紹介リンクではテスト環境に入れない（入れるのは今までどおりグループの招待リンクだけ。紹介の記録は残す）③紹介した人に見せるのは、自分の紹介で登録した人数だけ（名前やメールアドレスは見せない）。

## Clarifications

### Session 2026-11-01

- Q:紹介した人・紹介された人に特典を付けるか？ → A:付けない。誰の紹介で登録したかを記録するだけにする。料金の処理には触れない。
- Q:テスト環境で、紹介リンクから来た人をどう扱うか？ → A:紹介リンクではテスト環境に入れない。テスト環境に入れるのは、今までどおりグループの招待リンクから入った人だけ。紹介の記録は残す。
- Q:紹介した人に何を見せるか？ → A:自分の紹介で登録した人数だけ。紹介された人の名前やメールアドレスは見せない。

## 用語

- **紹介リンク**：利用者1人に1本ずつある、アプリを人に勧めるためのリンク。開いた人がそのあと登録すると、「この人の紹介で登録した」と記録される。チームの招待リンク（011）やグループの招待リンク（016）とは別物で、チームやグループには入らない。
- **紹介した人**：紹介リンクの持ち主。
- **紹介された人**：紹介リンクを開いたあとに、新しく登録した人。
- **紹介の記録**：紹介された人ごとに、誰の紹介で登録したかを1つだけ持つ記録。

## User Scenarios & Testing *(mandatory)*

### User Story 1 -利用者が、自分の紹介リンクを人に送る（Priority: P1）

アプリを気に入った利用者が、設定の画面で自分の紹介リンクをコピーし、知り合いにメッセージやSNSで送る。リンクを開いた人は、アプリの紹介と「Googleで始める」を見て、そのまま登録する。登録すると、誰の紹介で登録したかが記録される。

**Why this priority**：アプリを広める入口になる。紹介リンクがないと、利用者がアプリを勧めても、どれだけ紹介から人が来ているかがわからない。

**Independent Test**：利用者Aが設定で紹介リンクをコピーする。まだ登録していない人Bが、そのリンクを開いてGoogleで登録する。BがAの紹介で登録したと記録されていることを確かめる。

**Acceptance Scenarios**:

1. **Given** ログインしている利用者、**When** 設定の「紹介」を開く、**Then** その人の紹介リンクと「コピー」が出る。リンクは、何度開いても同じ。
2. **Given** 紹介リンク、**When** まだ登録していない人が開く、**Then** ログインしていなくても、アプリの紹介（何ができるか）と「Googleで始める」が出る。紹介した人の名前は出さない。
3. **Given** 上の画面、**When** その人が「Googleで始める」から登録する、**Then** その人は、紹介リンクの持ち主の紹介で登録したと記録される。登録のあとは、紹介リンクを使わずに登録した人と同じ画面に進む。
4. **Given** 紹介リンクを開いたあと、その場では登録しなかった人、**When** 30日以内に、同じブラウザでアプリに戻って登録する、**Then** 紹介の記録が残る。
5. **Given** すでに登録している人、**When** 誰かの紹介リンクを開く、**Then** ふつうにアプリを開くのと同じになり、紹介の記録はできない（紹介した人も変わらない）。
6. **Given** 紹介リンクの持ち主、**When** 自分の紹介リンクを開く、**Then** 紹介の記録はできない。

---

### User Story 2 -紹介した人が、自分の紹介で何人が登録したかを確かめる（Priority: P2）

紹介リンクを送った利用者は、設定の「紹介」で、自分の紹介で何人が登録したかを確かめる。名前やメールアドレスは見えないので、紹介された人のことは伝わらない。

**Why this priority**：紹介した人にとって「送った効果があったか」がわかる。ただし、まずリンクを送れて記録できること（US1）が先。

**Independent Test**：利用者Aの紹介リンクから2人が登録したあと、Aの「紹介」に「2人」と出ることを確かめる。そのうち1人が退会すると「1人」になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 自分の紹介で2人が登録した利用者、**When** 設定の「紹介」を開く、**Then** 「あなたの紹介で登録した人：2人」と出る。名前・メールアドレスなど、誰が登録したかがわかるものは出ない。
2. **Given** 自分の紹介でまだ誰も登録していない利用者、**When** 設定の「紹介」を開く、**Then** 「0人」と出る。
3. **Given** 紹介された人が退会した、**When** 紹介した人が「紹介」を開く、**Then** その人は数えない。

---

### User Story 3 -テスト環境では、紹介リンクで入れる人を増やさない（Priority: P3）

テスト環境（テスト用のグループがONの環境）では、テスト環境に入れるのはグループの招待リンクから入った人だけ（016）。紹介リンクを開いた人が登録しても、テスト環境に入れるようにはならない。ただし、紹介の記録は残す。

**Why this priority**：016で決めた「テスト環境は招待された人だけ」を、紹介リンクが崩さないようにする。テスト環境では紹介の利用は少ないので、P3。

**Independent Test**：テスト環境で、利用者Aの紹介リンクを開いた人Bが登録する。Bは「テスト版は招待された方だけが使えます」になり、Aの紹介で登録した記録は残ることを確かめる。

**Acceptance Scenarios**:

1. **Given** テスト用のグループがONの環境の紹介リンク、**When** まだ登録していない人が開く、**Then** アプリの紹介と「Googleで始める」に加えて、「テスト版は、招待された方だけが使えます」と出る。
2. **Given** 上の画面、**When** その人が登録する、**Then** 紹介の記録は残る。その人は、グループの招待リンクから入るまで、テスト環境に入れない人のまま（016のUS1と同じ）。
3. **Given** テスト用のグループがOFFの環境（本番）、**When** 紹介リンクから登録する、**Then** 登録した人は、ふつうに登録した人と同じくアプリを使える。

---

### Edge Cases

- 紹介リンクの文字が壊れている・存在しない：アプリの紹介と「Googleで始める」は出すが、紹介の記録はしない（登録はふつうにできる）。
- 紹介リンクの持ち主が退会した：そのリンクは使えなくなる（開いても紹介の記録はしない）。その人の紹介で登録した人の記録からは、紹介した人が消える（紹介された人のアカウントはそのまま）。
- 紹介リンクを開いたあと、チームの招待リンク（011）やグループの招待リンク（016）から登録した：紹介の記録は残る。チームやグループにも、それぞれの招待のとおりに入る。
- 2人の紹介リンクを続けて開いてから登録した：あとから開いた方の紹介として記録する。
- 紹介リンクを開いた端末とは別のブラウザや端末で登録した：紹介の記録はしない（同じブラウザで登録してもらう）。
- 紹介リンクを開いてから30日を過ぎて登録した：紹介の記録はしない。
- 紹介の記録は、あとから変えたり消したりしない（紹介された人が、紹介した人を選び直すことはできない）。
- 紹介された人が退会した：紹介の記録もいっしょに消える（013の退会でデータを消すのと同じ）。
- 紹介リンクの持ち主が退会の途中（受け付けたが、データを消し終えていない）：そのリンクから登録すると記録はいったんできるが、退会が終わると紹介した人が消える（退会が終わったあとと同じ結果になる）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：システムは、利用者1人につき1本の紹介リンクを持たなければならない。リンクは、ほかの人が推測できない文字列を使う。
- **FR-002**：利用者は、設定の「紹介」で、自分の紹介リンクを見てコピーできなければならない。
- **FR-003**：紹介リンクは、ログインしていなくても開けなければならない。開くと、アプリの紹介と「Googleで始める」を出す。紹介した人の名前やメールアドレスは出さない。
- **FR-004**：紹介リンクを開いた人が、同じブラウザで30日以内に新しく登録したとき、システムはその人を紹介リンクの持ち主の紹介で登録したと記録しなければならない。
- **FR-005**：システムは、次のときは紹介の記録をしてはならない。すでに登録している人が開いたとき、紹介リンクの持ち主が自分のリンクを開いたとき、リンクが存在しない・持ち主が退会しているとき、開いてから30日を過ぎたとき。
- **FR-006**：紹介された人1人につき、紹介した人は1人まで。2つ以上の紹介リンクを開いてから登録したときは、あとから開いた方を記録する。一度できた紹介の記録は、あとから変えない。
- **FR-007**：利用者は、設定の「紹介」で、自分の紹介で登録した人数を見られなければならない。人数には、退会した人を数えない。紹介された人の名前・メールアドレスなど、誰かがわかるものは出してはならない。
- **FR-008**：紹介した人・紹介された人のどちらにも、特典（無料体験の延長・割引など）を付けない。紹介の記録は、料金・使える状態・権限の判定に使わない。
- **FR-009**：テスト用のグループがONの環境では、紹介リンクの画面に「テスト版は、招待された方だけが使えます」と出さなければならない。紹介リンクから登録しても、テスト環境に入れる人にはならない（016のとおり、グループの招待リンクから入った人だけが入れる）。紹介の記録は残す。
- **FR-010**：紹介リンクを開いたあとに、チームの招待リンクやグループの招待リンクから登録したときも、紹介の記録をする。チームやグループには、それぞれの招待のとおりに入る（紹介の記録はそれを変えない）。
- **FR-011**：紹介した人が退会したら、その人の紹介リンクは使えなくなり、その人の紹介で登録した人の記録から、紹介した人を消さなければならない。紹介された人が退会したら、その人の紹介の記録も消す。

### Key Entities *(include if feature involves data)*

- **紹介リンク**：利用者1人に1本。持ち主と、リンクの文字列を持つ。
- **紹介の記録**：紹介された人1人に1つまで。紹介した人（退会したら空になる）と、記録した日時を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：利用者は、設定を開いてから10秒以内に、自分の紹介リンクをコピーできる。
- **SC-002**：紹介リンクを開いて同じブラウザで登録した人は、100%、紹介の記録が残る（30日以内）。
- **SC-003**：すでに登録している人・自分のリンクを開いた人・30日を過ぎた人について、紹介の記録が誤ってできることが0件。
- **SC-004**：紹介した人の画面に、紹介された人が誰かわかる情報が出ることが0件。
- **SC-005**：テスト環境で、紹介リンクだけで（グループの招待リンクを使わずに）テスト環境に入れた人が0人。
- **SC-006**：紹介リンクの有無で、料金・無料体験の長さ・使える機能が変わる人が0人。

## Assumptions

- 紹介リンクを開いたことは、そのブラウザの中に30日だけ覚えておく。別のブラウザや端末で登録した場合は、紹介を記録しない（グループの招待リンク（016）と同じく、同じブラウザで登録してもらう）。
- 紹介リンクの画面に紹介した人の名前を出さないのは、リンクが転送されたときに、持ち主の名前が知らない人に伝わらないようにするため。
- 紹介リンクの作り直し（前のリンクを使えなくする）は作らない。特典がないので、リンクが広まりすぎても困ることがない。
- 紹介された人の数は、紹介した人が自分で見るだけ。運営者が全体を見る画面は作らない（必要になったら、データベースの記録から数える）。
- この機能の前から登録している人には、紹介の記録はない。
- 紹介リンクは、本番とテスト環境のどちらにもある。環境ごとのON/OFFは設けない（テスト環境での扱いはFR-009）。

## Out of Scope

- 紹介の特典（無料体験の延長、割引、紹介した人へのお礼）。
- 紹介した人に、紹介された人の名前や一覧を見せること。
- 運営者が、紹介の記録を見る・集計する画面。
- 紹介リンクの作り直し、使えなくすること（退会のほか）。
- 紹介の記録を、あとから付ける・変える・消すこと（退会のほか）。
- 紹介リンクの画面を、利用者ごとに変えること（ひとことメッセージなど）。
