# 動作の確かめ方（Quickstart）：紹介リンク

**日付**：2026-11-01 | **計画**：[plan.md](./plan.md)

## 1. 自動テスト

```bash
pnpm --filter ./apps/api test     # 紹介の記録・人数・退会・テスト用のグループON、マイグレーション0017
pnpm --filter ./apps/web test     # 紹介リンクの画面・設定の「紹介」・APIクライアントの見出し
pnpm lint && pnpm -r exec tsc --noEmit
```

確かめること（[contracts/api.md](./contracts/api.md)・[contracts/ui-routes.md](./contracts/ui-routes.md)）：

| 場面 | 結果 |
|---|---|
| 新しく登録する人が、持ち主のいる紹介の文字列を付けてAPIを呼ぶ | 行が作られ、`referred_by_user_id`が持ち主になる |
| すでに行がある人が、紹介の文字列を付けて呼ぶ | 記録されない・変わらない |
| 形に合わない・持ち主のいない文字列 | 紹介なしで行が作られる（エラーにならない） |
| `GET /api/me/referral`を2回呼ぶ | 同じURL。人数は紹介された人の数 |
| 紹介された人が退会 | 人数から外れる |
| 紹介した人が退会 | 紹介された人の`referred_by_user_id`がNULL。その文字列では記録されない |
| テスト用のグループがONで紹介から登録 | 記録は残り、`TEST_ACCESS_REQUIRED`のまま |
| 紹介リンクの画面をログインしていない人が開く | `tg.referral`に書かれる。名前は出ない |
| ログインしている人が開く | 書かれずに`/`へ移る |
| 30日を過ぎた`tg.referral` | 見出しを付けずに消す |

## 2. テスト版で手で確かめる（マージのあと）

1. ログインして、設定 › 紹介 で紹介リンクをコピーする（人数は0人）。
2. スマートフォンのプライベートでない窓で、紹介リンクを開く。「テスト版は、招待された方だけが使えます」が出ること、紹介した人の名前が出ないことを確かめる。
3. そのまま、まだ使っていないGoogleアカウントで登録する（テスト版なので「招待された方だけ」の画面になる）。
4. 1の画面を開き直し、人数が1人になっていることを確かめる。
5. 3のアカウントを退会し、人数が0人に戻ることを確かめる。
