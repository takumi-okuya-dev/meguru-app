# 画面契約：戦略プロファイル

**対象feature**：[spec.md](../spec.md) ／ **API**：[api.md](./api.md) ／ **UI全体設計**：[docs/ui-design.md](../../../docs/ui-design.md) ／ **001の画面契約**：[001 contracts/ui-routes.md](../../001-login-account-setup/contracts/ui-routes.md)

画面の骨格・型・見た目・スマートフォン対応はdocs/ui-design.mdに従う。ここには本featureで足す画面・遷移の規則・文言を書く。001の遷移の規則（ガード、Accountを開いたときの記録など）はそのまま使う。

## アカウント追加画面の案内（FR-028、research.md R15）

001の`/accounts/new`の「現在は検証期間中のため、招待されたThreadsアカウントのみ接続できます。…」という案内は、`GET /api/me`の`threadsAccessMode`が`testers`のときだけ出す。`public`のときは出さない。

## サイドバー（docs/ui-design.md「2. 画面の骨格」）

本featureの時点で出す項目は次のとおり。

- Accountの切り替え（ドロップダウン）とサイドバーを畳むボタン
- 「ホーム」
- 見出し「戦略」：「課題」「宣伝内容」「リサーチ」
- 下部：「このアカウントの設定」（001の`/accounts/:id/settings`）とユーザーメニュー

「投稿をつくる」「投稿ストック」「パフォーマンス」と見出し「分析」は、それぞれの画面ができるfeatureで足す。

## 遷移と操作の規則

1. **画面の読み込み**：各画面は、開いたときに対応する`GET`を呼ぶ。読み込み中は骨組み（スケルトン）を出す。`404 ACCOUNT_NOT_FOUND`なら、001の規則4と同じく404画面にする。
2. **保存**（FR-018）：
   - 課題は上部バーの「保存」で、全項目をまとめて保存する。未保存の変更がないときは「保存」を無効にする。
   - 保存に成功したら、トーストで「保存しました」と出し、上部バーの「最終更新：{日時}」を更新する。
   - 失敗したら、入力内容を残したまま、エラー文言（下の表）と「もう一度保存」をトーストで出す。
3. **未保存の変更の警告**（FR-019、research.md R10）：
   - 課題の画面、または追加・編集のダイアログに未保存の変更があるとき、アプリ内の移動（サイドバー、Accountの切り替え、ブラウザの戻る）を止めて、確認のダイアログを出す。
     - 見出し：「保存していない変更があります」
     - 説明：「このまま移動すると、変更は失われます。」
     - ボタン：「編集に戻る」（既定）／「変更を破棄して移動」
   - タブを閉じる・再読み込みでは、ブラウザ標準の確認を出す。
   - 追加・編集のダイアログでは、閉じる操作（✕・キャンセル・Esc・背景のクリック）でも同じ確認を出す。
4. **変更の破棄**（FR-011の課題版、US1）：課題の画面の上部バーの「⋯」メニューに「変更を破棄」を置き、最後に保存した内容に戻す。
5. **他の場所での更新**（FR-020、research.md R3）：保存で`409 STALE_UPDATE`を受けたら、次のダイアログを出す。
   - 見出し：「他の場所で更新されています」
   - 説明：「この内容は、別のタブや端末で先に保存されています（{最新の更新日時}）。」
   - ボタン：「最新の内容を読み込み直す」（既定）／「自分の内容で上書きする」
   - 「読み込み直す」は、自分の入力内容を捨てて最新の値を出す。「上書き」は、最新の`version`で保存し直す。
6. **削除された行の保存**：編集の保存で`404 ITEM_NOT_FOUND`を受けたら、ダイアログを閉じずに「この{宣伝内容／参考投稿／キーワード}は、別のタブや端末で削除されています。」と出す。入力内容はコピーできるように残し、「閉じる」で一覧を読み込み直す。
7. **削除**（FR-011、US3）：カードの「⋯」メニューの「削除」から、確認のダイアログ（「{管理用タイトル}を削除しますか？ 元に戻せません。」、「キャンセル」／「削除する」）を出す。削除したらトーストで「削除しました」と出す。
8. **件数の上限**（FR-022）：一覧の件数が上限に達したら「＋ 追加」を無効にし、一覧の上に「登録できる上限（{上限}件）に達しています。不要なものを削除してから追加してください。」と出す（宣伝内容を「終了」にしても件数には数えるので、終了は案内しない。2026-10-03に実装時に修正）。APIの`409 ITEM_LIMIT_REACHED`を受けた場合も同じ表示にする。
9. **入力欄の検証**（FR-021、research.md R8）：
   - 文字数を入力欄の右下に「{いまの文字数}/{上限}」で出す。上限を超えたら、文字数と入力欄の枠を注意の色にし、入力欄の下に「{上限}文字以内で入力してください」と出して、保存を無効にする。入力済みの内容は消さない。
   - 必須の項目が空のまま保存しようとしたら、その入力欄の下に「入力してください」と出す。
   - URLの形が違えば「https:// から始まるURLを入力してください」と出す。
   - 文字数の数え方は`packages/shared`の関数を使う（research.md R2）。
10. **grower機能を使えないAccount**（FR-024、FR-024a。`canEdit: false`）：
    - 課題・宣伝内容・リサーチの画面は、保存済みの内容を読むだけの表示にする（入力欄は読み取り専用、保存・追加・「⋯」の編集系の操作は出さない）。
    - 画面の上部（上部バーの下）に、「課題・宣伝内容・リサーチの編集は、プラン2以上で使えます。保存済みの内容はそのまま残っています。」という案内を出す。課金featureができるまでは、続けて「プランの変更は運営者にお問い合わせください。」と出す。
    - 保存で`403 GROWER_FEATURE_REQUIRED`を受けたら（画面を開いた後に無料体験が終わった場合）、入力内容を残したまま同じ案内をダイアログで出し、画面を読むだけの表示に切り替える。
11. **ホームの入力状況の更新**：課題・宣伝内容・リサーチを保存・削除したら、ホームの入力状況（`profile-status`）を取り直す対象にする（research.md R11）。

## 課題の画面（型A）

- **上部バー**：画面名「課題」、「{入力済み}/16 入力済み」、「最終更新：{日時}」（PCのみ）、「⋯」（変更を破棄）、「保存」。スマートフォンでは「{入力済み}/16」を区分のチップの列の先頭に出す。
- **案内**：「ここに書いた内容が、投稿づくりの材料になります。空欄があっても保存できます。」
- **区分のチップ**：「課題① 営業導線」「課題② アカウント」「課題③ 集客導線」「人柄」「その他」「プロフィール・固定投稿」。押すとその区分の見出しへスクロールする。
- **未入力の項目**：ラベルの右に「未入力」の小さなラベルを出す（FR-005）。
- **プロフィール・固定投稿の区分**：見出しの下に「Threadsには自動で反映されない下書きです。投稿づくりの材料には使いません。」と出す（FR-003b）。

### 項目の文言（`packages/shared`の`STRATEGY_FIELDS`に置く）

記入例は、空の入力欄の中に薄く表示する（保存しない。FR-003）。

| 区分 | キー | ラベル | 説明 | 記入例 |
|---|---|---|---|---|
| 課題① 営業導線設計 | `finalAction` | 最終的に読者に取ってほしい行動 | 投稿を見た人に、最終的に何をしてほしいか | 例: 公式LINEに登録してもらう。主催しているイベントに参加してもらう |
| | `targetPersona` | どんな人に投稿を届けたいか | 年齢や職業だけでなく、今どんな状況にいる人か。実在しそうな1人を思い浮かべるのがコツです | 例: 28歳前後の会社員。仕事は嫌いではないけれど、30歳が近づいて「このままでいいのかな」と少し焦っている人 |
| | `realWorries` | ターゲットの本音の悩み | 表向きの悩みではなく、本当は何にモヤモヤしているか | 例: 会社と家の往復で新しい出会いが減った。SNSで同世代と比べて焦る |

| | `benchmarkAccounts` | ベンチマークにしたい他アカウント | 参考にしたい3アカウント程度と、良いと思う点 | 例: @account_a（共感投稿の言葉選びが上手い） |

## 宣伝内容の画面（型B）

- **上部バー**：画面名「宣伝内容」、「＋ 追加」。
- **案内**：「登録した宣伝内容は、投稿づくりの材料になります。宣伝内容がなくても投稿は作れます。」
- **宣伝投稿の割合**（FR-010）：一覧の上の設定の行。ラベル「宣伝投稿の割合」、説明「投稿全体のうち、宣伝内容を扱う投稿の割合」、0〜100の数値の入力欄と「%」。値を変えると、その行に「保存」ボタンが出る。
- **一覧**（FR-009）：見出し「宣伝の対象（{件数}）」と「対象外（{件数}）」に分けて出す。
  - 宣伝の対象のカード：状態のラベル（「有効」）、「優先度 {n}」、掲載期限（あれば「{M/D}まで」）、管理用タイトル、宣伝したい内容（3行まで。続きは「もっと見る」）、届けたい属性のチップ、「CTA：{CTA}」、専用URL（あればリンク）、「⋯」。
  - 対象外のカード：1行で、状態のラベル（「一時停止」「終了」「期限切れ」）、管理用タイトル、「優先度 {n}」または「掲載期限 {M/D}」、「⋯」。期限切れは、状態が「有効」でも「期限切れ」のラベルにする（FR-008）。
  - 「⋯」メニュー：「編集」「一時停止」または「有効に戻す」「終了」「削除」。状態の変更は、その場で保存する（`PUT`）。
- **空の状態**：「まだ宣伝内容がありません。イベントやサービスを登録すると、投稿の材料になります。」と「＋ 追加」。
- **追加・編集のダイアログ**（PCは中央のダイアログ、スマートフォンは全画面のシート）：
  - 見出し：「宣伝内容を追加」／「宣伝内容を編集」
  - 項目：管理用タイトル（必須。「投稿には出ません」と添える）、宣伝したい内容（必須）、届けたい属性（場所・どんな人・年齢）、読者に取ってほしい行動（CTA）、専用URL、優先度（既定0）、状態（既定「有効」）、掲載期限
  - 掲載期限に過去の日付を入れたら、入力欄の下に「この日付はすでに過ぎているため、期限切れとして扱われます。」と出す（保存はできる）。
  - ボタン：「キャンセル」／「追加」または「保存」

## リサーチの画面（型B）

- **上部バー**：画面名「リサーチ」、選択中のタブに応じて「＋ 参考投稿を追加」または「＋ キーワードを追加」。
- **案内**（FR-015）：「Threadsで検索して、反応の良い投稿を見つけたら保存しましょう。「なぜ良いか」を書いておくと、投稿の材料になります。」と、折りたたみの「リサーチの手順」（1. キーワードでThreadsを検索する 2. 反応の良い投稿の本文をコピーして保存する 3. なぜ良いかを書き残す。ChatGPTやClaudeに分析してもらった結果を貼り付けてもよい）。
- **タブ「参考投稿」**（FR-012、FR-013）：
  - カード：本文（改行を保って6行まで。続きは「もっと見る」）、キーワード・保存日時、URL（あればリンク）、「なぜ良いか」。未入力なら「なぜ良いか：未入力」と出し、そこから編集を開ける。「⋯」（編集・削除）。
  - 追加・編集のダイアログ：本文（必須。「Threadsで見つけた投稿の本文をそのまま貼り付け」）、検索したキーワード、投稿のURL、なぜ良いか。
  - 空の状態：「まだ参考投稿がありません。Threadsで見つけた反応の良い投稿を保存しましょう。」
- **タブ「キーワード」**（FR-014）：
  - 行：キーワード、狙いのメモ、「⋯」（編集・削除）。
  - 追加・編集のダイアログ：キーワード（必須）、狙いのメモ。同じキーワードがすでにあれば、入力欄の下に「同じキーワードがすでに登録されています」と出す（Webでも`packages/shared`の正規化で事前に判定し、APIの`409 KEYWORD_DUPLICATE`でも同じ表示にする）。
  - 空の状態：「まだキーワードがありません。リサーチで検索する言葉を登録しておきましょう。」

## ホーム（FR-017、research.md R11）

001の表示（アイコン・表示名・@ユーザー名・接続状態）の下に、次を出す。

- **次にやること**（大見出しと1文の説明）：

  | 条件（上から順に判定） | 大見出し | 説明 |
  |---|---|---|
  | 課題の入力済みが0項目 | まずは「課題」から埋めましょう | 誰に何を届けるかを決めておくと、投稿の方向性が定まります。 |
  | 宣伝内容が0件 | 次は「宣伝内容」を登録しましょう | 案内したいイベントやサービスがあれば登録します（なくても投稿は作れます）。 |
  | 参考投稿が0件 | 次は「リサーチ」がおすすめです | Threadsで伸びている投稿を保存しておくと、投稿の精度が上がります。 |
  | 上のどれでもない | 投稿の材料がそろっています | 課題・宣伝内容・リサーチは、いつでも見直せます。 |

- **3枚のカード**（押すとその画面へ）：
  - 課題：「{入力済み}/16 入力済み」
  - 宣伝内容：「宣伝の対象 {宣伝の対象の件数}件（任意）」
  - リサーチ：「参考投稿 {件数}件（任意）」
- 「次にやること」で案内している画面のカードは、枠線を濃くする。
- **無料体験中**（FR-024b）：Accountの表示の下に「無料体験中：{終了日（日本時間、YYYY年M月D日）}まで、すべての機能を使えます」と小さく出す。
- **grower機能を使えないAccount**：「次にやること」の代わりに、大見出し「課題・宣伝内容・リサーチの編集は、プラン2以上で使えます」と規則10の案内を出す。3枚のカードは出し、保存済みの内容を見に行けるようにする。

## エラー文言（`packages/shared`に足す）

| code | 文言 | 次に取れる操作 |
|---|---|---|
| `STALE_UPDATE` | 別のタブや端末で先に保存されています。 | 規則5のダイアログ |
| `ITEM_NOT_FOUND` | この項目は、別のタブや端末で削除されています。 | 一覧を読み込み直す |
| `ITEM_LIMIT_REACHED` | 登録できる上限に達しています。不要なものを削除してから追加してください。 | 一覧で削除する |
| `KEYWORD_DUPLICATE` | 同じキーワードがすでに登録されています。 | 入力し直す |
| `GROWER_FEATURE_REQUIRED` | この機能はプラン2以上で使えます。保存済みの内容はそのまま残っています。 | 規則10の案内 |
| `VALIDATION_FAILED`（本featureの画面） | 入力内容を確認してください。 | 該当する入力欄の案内（規則9）を見て直す |

保存の失敗で通信そのものが失敗した場合（`API_UNREACHABLE`）や`INTERNAL_ERROR`は、「保存できませんでした。通信状況を確認して、もう一度お試しください。」とし、入力内容は残す。
