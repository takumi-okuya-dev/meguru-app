# 動作確認ガイド（Quickstart）：戦略プロファイル

**対象feature**：[spec.md](./spec.md) ／ **契約**：[contracts/api.md](./contracts/api.md)、[contracts/ui-routes.md](./contracts/ui-routes.md) ／ **UI全体設計**：[docs/ui-design.md](../../docs/ui-design.md)

本featureが端から端まで動くことを確かめる手順。実装コードは含めない。

## 前提

- 001のセットアップ（[001 quickstart.md](../001-login-account-setup/quickstart.md)の「前提」「セットアップ」）が済んでいる。
- 本featureはThreads APIを呼ばないので、本物のMetaアプリやCloudflare Tunnelがなくても確認できる。偽のThreadsサーバーで動かす`pnpm dev:fake`を使う。

## セットアップ

```bash
pnpm install
docker compose up -d
pnpm --filter api db:migrate        # 本featureのマイグレーション（テーブル4つと accounts の列1つ）を当てる
pnpm dev:fake                       # 偽のThreadsサーバー + API + Web
```

ブラウザで`http://localhost:5173`を開き、ログインしてAccountを1件接続する（偽のThreadsサーバーが認可画面の代わりになる）。Accountを2件使う確認では、`pnpm --filter api admin:set-plan <accountId> multi-account`でプランを上げてから2件目を接続する。

## 自動テスト

```bash
pnpm --filter @threads-grower/shared test   # 文字数・空欄・キーワードの正規化・日本時間の日付と宣伝の対象
pnpm --filter api test      # Workersランタイム上、ローカルDB
pnpm --filter web test      # 画面の振る舞い
pnpm e2e                    # Clerkのテスト用ログインが使える環境のみ
```

**期待する結果**：すべて成功する。とくに次のテストがあり、成功していること。

| テスト | 確かめること | 対応 |
|---|---|---|
| 課題の復元 | `PUT /strategy`で保存した全20項目と近い人間性が、`GET /strategy`で同じ値で返る。保存前の`GET`は全項目`""`・`version: 0` | FR-006、SC-003 |
| 空欄の扱い | 空白・改行だけの項目は`""`で返り、入力済み項目数に数えられない。プロフィール・固定投稿の下書きは入力済み項目数に数えない | FR-004、FR-005 |
| 文字数の上限 | 2,000文字ちょうどは保存でき、2,001文字は`400 VALIDATION_FAILED`（`details`に項目名）。絵文字1つは1文字に数える | FR-021、research.md R2 |
| 課題の競合 | 同じ`expectedVersion`で2回保存すると、2回目は`409 STALE_UPDATE`で`latest`に1回目の値が入る。`latest.version`で保存し直すと成功する。行がない状態で2つのタブが`expectedVersion: 0`で同時に保存しても、成功は1つだけ | FR-020、SC-005 |
| 他人のAccount | 別ユーザーのAccountの`strategy`・`promotions`などへの`GET`・`PUT`・`POST`・`DELETE`は、すべて`404 ACCOUNT_NOT_FOUND`で、相手のデータは変わらない | FR-023、SC-006 |
| 別のAccountの行 | 自分の別のAccountの宣伝内容のIDを使った`PUT`は`404 ITEM_NOT_FOUND` | FR-023 |
| 宣伝内容の並び順 | 有効・一時停止・終了・期限切れ・優先度違いを混ぜて登録すると、`GET /promotions`がFR-009の順で、`isTargetable`・`isExpired`が正しい | FR-008、FR-009、SC-007 |
| 掲載期限の境目 | 日本時間の今日が掲載期限の日は宣伝の対象で、翌日の0時（日本時間）からは期限切れになる | FR-008、research.md R6 |
| 件数の上限の同時実行 | 宣伝内容が49件のAccountに2つの`POST`を同時に送っても、50件を超えない（1つは`409 ITEM_LIMIT_REACHED`） | FR-022、research.md R4 |
| 削除済みの行の更新 | 削除した宣伝内容への`PUT`は`404 ITEM_NOT_FOUND`。同じ行への2回目の`DELETE`も`204` | spec エッジケース |
| キーワードの重複 | 「AI」がある状態で「ＡＩ」「 ai 」を追加すると`409 KEYWORD_DUPLICATE` | FR-014、research.md R5 |
| キーワードの削除 | キーワードを削除しても、そのキーワードを記録した参考投稿は残る | US3 シナリオ6 |
| URLの検証 | `javascript:alert(1)`の専用URL・投稿のURLは`400 VALIDATION_FAILED` | spec エッジケース |
| Accountの削除 | Accountを削除すると、課題・宣伝内容・参考投稿・キーワードの行がすべて消える | FR-026 |
| 要再接続のAccount | `needs_reconnect`のAccountでも、すべてのエンドポイントが使える | FR-025 |
| grower機能の判定 | 登録から1か月以内のユーザーはプラン1のAccountでも編集できる。1か月を過ぎるとプラン1では`POST`・`PUT`・`DELETE`が`403 GROWER_FEATURE_REQUIRED`になり、`GET`は保存済みの内容と`canEdit: false`を返す。プラン2以上なら1か月を過ぎても編集できる | FR-024、FR-024a、SC-008 |
| 公開範囲の切り替え | `THREADS_ACCESS_MODE`が未設定・`testers`なら`GET /api/me`が`threadsAccessMode: "testers"`を返し、アカウント追加画面に検証期間の案内が出る。`public`なら出ない。`foo`なら`500 CONFIG_ERROR`で`details`に`THREADS_ACCESS_MODE` | FR-028、research.md R15 |
| 無料体験の終了時刻 | 1月31日の登録は2月の最終日の同じ時刻（日本時間）まで無料体験中になる | research.md R14 |
| 未保存の警告（Web） | 課題を編集して保存せずにサイドバーで移動すると確認のダイアログが出て、「編集に戻る」で入力内容が残る。入力して元に戻した場合は出ない | FR-019 |
| 競合のダイアログ（Web） | `409`を受けると「他の場所で更新されています」が出て、「読み込み直す」と「上書きする」がそれぞれ規則5のとおりに動く | FR-020 |
| ホームの案内（Web） | 何も入力していないAccountでは「まずは「課題」から」、課題だけ入力済みなら「次は「宣伝内容」」になる | FR-017、US4 |

## 手動の確認

`pnpm dev:fake`で起動した画面で、次を確かめる。画面幅は、ブラウザの開発者ツールで375px（iPhone）、768px（iPad縦）、1024px（iPad横）、1440px（PC）に切り替える。

### 1. 課題（US1）

1. Accountのホームに「まずは「課題」から埋めましょう」と3枚のカードが出る。
2. サイドバーの「課題」を開く。区分の見出しと、各項目のラベル・説明・記入例・「未入力」・文字数が出ている（[ui-routes.md](./contracts/ui-routes.md)の項目の文言の表）。
3. いくつかの項目に入力し、近い人間性を選ぶ。上部バーの「{n}/16 入力済み」が増える。
4. 下までスクロールしても「保存」が上部バーに見えている。保存すると「保存しました」と最終更新日時が出る。
5. ログアウト → ログインして同じ画面を開くと、入力内容が復元されている。
6. 1つの項目に2,001文字を貼り付けると、文字数が注意の色になり、保存できない。入力内容は消えない。
7. 入力して保存せずにサイドバーの「ホーム」を押すと、確認のダイアログが出る。

### 2. 別のタブでの更新（FR-020）

1. 同じAccountの課題を2つのタブで開く。
2. タブAで1項目を書き換えて保存する。
3. タブBで別の項目を書き換えて保存すると、「他の場所で更新されています」のダイアログが出る。
4. 「最新の内容を読み込み直す」でタブAの内容が出る。もう一度やり直して「自分の内容で上書きする」を選ぶと、タブBの内容で保存される。

### 3. 宣伝内容（US2）

1. 「宣伝内容」を開き、「＋ 追加」から1件追加する。PCでは中央のダイアログ、375pxでは全画面のシートで開く。
2. 管理用タイトルを空にして追加しようとすると、「入力してください」が出る。
3. 2件目を追加して「⋯」から「一時停止」にすると、「対象外」に1行で移る。
4. 掲載期限を昨日にした宣伝内容は、状態が有効でも「期限切れ」として「対象外」に出る。
5. 宣伝投稿の割合を30にして保存し、再読み込みしても30のまま。

### 4. リサーチ（US3）

1. 「リサーチ」を開き、「参考投稿」タブで本文だけの参考投稿を1件、「なぜ良いか」付きを1件保存する。新しい順に並び、「なぜ良いか：未入力」が出る。
2. 「キーワード」タブで「AI」を追加し、続けて「ＡＩ」を追加しようとすると、重複の案内が出る。

### 5. ホームと複数Account（US3・US4、FR-023）

1. 課題・宣伝内容・リサーチを入力した後のホームで、3枚のカードの数字が合っている。
2. Accountを2件持つユーザーで、Account Aの課題を保存してからAccountの切り替え（ドロップダウン）でAccount Bを開くと、Bの課題はAの影響を受けていない。

### 6. 無料体験とプラン（FR-024）

1. 登録したばかりのユーザーのホームに「無料体験中：{終了日}まで」が出て、課題を編集できる。
2. `pnpm --filter api db:psql`で、そのユーザーの`users.created_at`を1か月以上前に書き換える。
3. 課題・宣伝内容・リサーチの画面が、読むだけの表示と「プラン2以上で使えます」の案内に変わり、保存済みの内容は読める。
4. `pnpm --filter api admin:set-plan <accountId> auto-grower`でプランを上げると、編集できるようになる。

### 7. 画面幅（docs/ui-design.md）

| 幅 | 確かめること |
|---|---|
| 1440px | サイドバーが常に出ている。左上のボタンで畳むと、再読み込みしても畳んだまま |
| 1024px | 1440pxと同じ |
| 768px | サイドバーは隠れていて、左上のボタンで画面の上に重ねて開く |
| 375px | 上部バーが`[≡] 画面名 [主な操作]`の形。ドロワーのいちばん上にAccountの切り替えがある。課題の区分のチップが横にスクロールする。入力欄を押しても画面が拡大されない（iPhoneの実機かシミュレーターで確認）。設定画面が「一覧 → 中身」の2段になる |
