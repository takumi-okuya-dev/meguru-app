# 契約：画面（ステージングの帯）

**Feature**：[spec.md](../spec.md) | **UI全体設計**：[docs/ui-design.md](../../../docs/ui-design.md) | **調べ**：[research.md](../research.md) R8

## 1. 環境の帯

| 環境 | 出すか | 文言 |
|---|---|---|
| `production` | 出さない | — |
| `staging` | 出す | 「テスト環境です。本番のデータではありません。ここでの投稿は、つないだThreadsアカウントに実際に投稿されます」 |
| `development` | 出す | 「開発環境です（手元）」 |

- **置き場所**（2026-10-31に変更。前は、画面の外枠になる骨格すべての一番上に帯を出していた）：
  - **帯**：最初の画面と読みもののページだけ。`CenteredLayout`（ログイン・招待の確認・Accountが0件のときのアカウントを作る）と、読みもののページの入れ物（`PlainPage`。利用規約など）の一番上に出す。
  - **印**：アプリの画面（`AppShell`）では帯を出さず、サイドバーのユーザーメニュー（`UserMenu`）の名前の横に短い印を出す。`staging`は「テスト版」、`development`は「開発版」、`production`は出さない。知らない値・未設定は「テスト版」（黙って本番の見た目にしない）。
  - `SettingsLayout`・`TeamSharedAccountPage`も、アプリの画面なので帯を出さない。
  - スマートフォンの幅では、印はドロワーの中（サイドバー）に出る。
  - 理由：帯がずっと出ていると、アプリの画面が見にくい（運営者の判断）。投稿が実際にThreadsに出ることは、最初の画面の帯で伝える。
- **見た目**：帯は注意の色（`warning`）の細い帯で、閉じられない。印は同じ色の小さな札。
- **スマートフォンの幅**：1行に収まらないときは折り返す。上部バーの操作に重ならない。

**言葉づかい**：画面に出す文言は「テスト環境」、文書（仕様・計画・手順書）では「ステージング」と書く。利用者はブランチの名前を知らないため。

## 2. 検索に載せない

- `staging`のときだけ、`index.html`に`<meta name="robots" content="noindex, nofollow">`を入れる（ビルドのときに差し込む）。
- `production`では入れない。

## 3. 変えないこと

- 今ある帯（無料体験・読むだけ・要再接続）の文言と出す条件は変えない。
- 画面の並び・操作は変えない（帯が1本増えるだけ）。
