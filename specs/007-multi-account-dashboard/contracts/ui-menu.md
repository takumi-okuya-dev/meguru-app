# UI契約：アカウント切り替えメニュー

**対象**：[spec.md](../spec.md) ／ **画面イメージ**：[PC](../../../docs/mockups/007-account-switcher-desktop.png)・[スマートフォン](../../../docs/mockups/007-account-switcher-mobile.png)

## 入口と遷移

- 既存のAccount画面のサイドバー上部の切り替えボタンから開く。新しい専用画面・URLは作らない。
- 所有Accountが0件なら切り替えメニューは表示されず、既存の初回追加画面で「Threadsアカウントを接続」を示す。
- メニュー内のAccount行を選ぶと、従来どおりそのAccountのホームへ移る。移動先で最後に使ったAccountを記録する既存の動作を保つ。
- 要再接続のAccount行を選んだ場合もそのAccountのホームへ移り、既存の「再接続」案内から再接続へ進める。
- 「アカウントを追加」は従来どおり既存の追加画面へ移る。追加可否の判断や課金は変更しない。
- スマートフォンのドロワーで選んだ場合、メニューとドロワーを閉じて移動する。
- 既存の並び順（最後に使った順、次に追加した順）を保ち、要確認件数では並べ替えない。

## 行の内容

各Accountの行には、アイコン、表示名、`@ユーザー名`、「要確認 N件」を表示する。0件も「要確認 0件」と表示する。表示中のAccountはチェック印と「表示中」を示す。接続が切れたと判明しているAccountは「要再接続」を文字で示す。これらは同時に表示できる（例：表示中かつ要再接続、要確認0件）。

表示名がない場合は `@ユーザー名` から識別できるようにする。表示名やユーザー名が長い場合は省略しても、行の識別・件数・状態が失われないようにする。アバター画像がなくても文字のアバターを使える。

## 読み込みとエラー

| 状態 | メニューの表示 | 行の操作 |
|---|---|---|
| アカウント一覧の読み直し中 | 「アカウントを確認中」。前回の一覧を現在の一覧として見せない | 一覧の確定まで待つ |
| 件数の取得中 | 最新のAccount行を表示し、件数欄は「取得中」 | 切り替え・追加は可能 |
| 件数の取得成功 | 各行に「要確認 N件」 | 切り替え・追加は可能 |
| 件数の取得失敗 | 件数欄は「取得できません」。メニューに「件数を再試行」を出す | 切り替え・追加は可能 |
| アカウント一覧の読み直し失敗 | 「アカウントを読み込めません」「再試行」。古い一覧を最新として表示しない | 読み直し成功後に選べる |

- 件数応答に現在のAccountのIDがない場合、0件とみなさずアカウント一覧をもう一度確認する。削除済みのAccount行は表示せず、一覧に残るAccountの件数がなお欠ける場合はその行を「取得できません」とする。
- メニューを開くたびにアカウント一覧、続いて件数を新たに取得する。古い応答が後の開き直し結果を上書きしない。
- メニューを開いたままバックグラウンドで数だけが更新されることは要件に含めない。再度開いたときに新しい数を読む。

## 幅・操作・読み上げ

- PCでは既存のサイドバー上部に沿って開く。スマートフォンでは画面幅を超えない。
- 20件あってもメニューの高さを表示領域内に収め、項目部分をスクロールして最後のAccountと追加操作に到達できる。安全領域も考慮する。
- 行は44px以上の押しやすい高さにし、キーボードの上下移動、Enterで選択、Escで閉じる操作を保つ。フォーカス位置が見える。
- 読み上げではAccount名、@ユーザー名、要確認件数、表示中、要再接続の意味が分かる。色やアイコンだけで状態を伝えない。
- ライト・ダークの既存配色を使う。新たな画面のナビゲーション項目を増やさない。
