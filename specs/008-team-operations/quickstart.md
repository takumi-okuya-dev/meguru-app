# 動作確認ガイド：チーム運用

**対象**：[spec.md](./spec.md) ／ **契約**：[権限](./contracts/permissions.md)・[API](./contracts/api.md)・[画面](./contracts/ui-routes.md) ／ **データ**：[data-model.md](./data-model.md)

008が端から端まで動くことを確かめる手順。テストの中身は`tasks.md`で決める。

## 前提と起動

- [README.md](../../README.md)のとおり、Node.js 22、pnpm、Docker（OrbStack）、Clerkの開発用設定を済ませる。
- Googleアカウントを3つ用意する（オーナー役・パートナー役・編集者役）。ブラウザは、別のプロファイルかシークレットウィンドウで同時にログインする。
- パートナー役・編集者役は、Metaのテスターに招待しなくてよい（Threadsに接続しないため）。

```bash
pnpm install
docker compose up -d
pnpm --filter api db:migrate   # 0009_team_operations を適用
pnpm dev:fake
```

## 1. マイグレーション

- ローカルのPostgres 17で`0009_team_operations`が通る。`membership_role`に`partner`・`editor`が足され、既存の`memberships`の行はすべて`owner`・`team_id`はNULLのまま。
- ステージングのNeonにも同じマイグレーションを当て、通ることを確かめる（data-model.md「マイグレーションの注意」）。

## 3. オーナーがパートナーを招く（US1）

1. オーナー役でログインし、偽のThreadsでAccountを1件接続する。
2. 「このアカウントの設定」に「運用を手伝ってもらう」があり、ほかの画面に役割やチームの表示がないことを確かめる。
3. 「招待リンクを作る」→ リンク・コピー・QRコード・説明・「リンクを作り直す」が出る。「閉じる」→「パートナーを招待中」になる。
4. パートナー役のブラウザ（未ログイン）でリンクを開く → 確認画面が見える。「参加する」→ Googleでログイン → 確認画面に戻り、チーム名に「A社」を入れて「参加する」→ そのAccountのホームへ。サイドバーに「パートナーとして手伝っています・オーナー：…」。
5. 同じリンクを別のブラウザで開く → 「このリンクは使えません」。
6. パートナー役で投稿の案を貼り付けて登録・編集できる。承認・却下のボタンがなく、「オーナーの確認待ち」と出る。設定は読むだけ。
7. オーナー役のホームに「…さん（A社）がパートナーとして参加しました」。設定に、パートナー・任せる範囲・手伝っている人が出る。
8. 開始から手順4の完了までが3分以内（SC-001）。

## 4. 編集者を招いて担当を決める（US2）

1. パートナー役で切り替えメニュー →「手伝っているアカウントをまとめて見る」→「編集者と担当」。招待リンクの行がある。
2. 編集者役でチームのリンクから参加 → 待機の案内（Threadsの接続を求めない）。パートナー役の画面に「担当を決めてください」と、メニューに「担当未定 1人」。
3. パートナー役でチェックを付ける → 編集者役で「読み込み直す」→ 担当のAccountが開ける。「編集者として担当しています」。要確認の案を消せ、承認済みは消せない。
4. 担当でないAccountのURLを直接開く → 開けない。
5. パートナー役が自分のAccountを接続し、表に「自社」の列が出て、編集者を担当にできる（Clarifications）。
6. 「作り直す」→ 前のリンクは使えない。参加済みの編集者は残る。

## 5. 任せる範囲（US3）

1. オーナー役で「投稿の承認・却下」をオン → パートナー役で投稿ストックを読み直すと承認できる。編集者役には出ない。
2. パートナー役の画面を開いたまま、オーナー役でオフ → パートナー役で承認を押すと「この操作はオーナーだけができるようになりました」と出て、ボタンが消える。
3. 「設定」をオン → パートナー役で自動投稿・NGワード・投稿のルールを変えられる。Threadsの再接続・パートナーの操作は出ない。

## 6. 操作の記録（US4）

1. 手順3〜5の操作が、オーナー役・パートナー役の「チーム > 操作の記録」に、名前・役割・時刻つきで新しい順に出る。編集者役のサイドバーには「操作の記録」がない。
2. まとめて承認（3件）が1行で、開くと3件の書き出しが出る。
3. 種類と人で絞り込める。
4. 投稿ストックのカードに「作成 …」「編集 …」が出る。個人運用のAccountでは出ない。

## 7. パートナーのまとめと切り替え（US5）

1. オーナー役をもう1人用意するか、偽のThreadsでAccountを足して、パートナー役が2件以上を手伝う。
2. 切り替えメニューが「自分のアカウント」「手伝っているアカウント」に分かれ、オーナー名が出る。
3. 「手伝っているアカウント」に、要確認の多い順で、要確認・承認済み・次の投稿・伸び・任された範囲・担当・接続状態が出る。偽のThreadsで1件を要再接続にすると「オーナーの再接続待ち」と出て、再接続のボタンがない（SC-007）。

## 8. 外す

1. オーナー役で「外す」→ 確認 →「外す」。パートナー役・編集者役が次に操作すると「このアカウントを開けなくなりました」と出て、`/`へ。
2. 操作の記録に、外す前の記録と「パートナーを外した」が残っている（FR-054）。
3. 「運用を手伝ってもらう」が招待前に戻り、任せる範囲はオフ。

## 9. スマートフォンの通知（US6、SC-008）

1. 375px・390px幅（Chromeの端末表示とiPhoneの実機）で投稿ストックを開き、下書きを1件消す。
2. 「元に戻す」の通知が出ている間に、メニューボタンを押してドロワーが開く。画面名と主な操作が見える。貼り付け欄とセーフエリアが隠れていない。
3. 「元に戻す」を押すと下書きが戻る。

## 10. 後片づけ

- 動作確認で作ったチーム・招待は、オーナー役の「外す」、パートナー役の「外す」、Accountの削除で消える。
