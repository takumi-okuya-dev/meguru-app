# Quickstart：決済＋退会

**日付**：2026-10-15 | **計画**：[plan.md](./plan.md)

本featureが動くことを確かめる手順。準備は001〜012と同じ（[README](../../README.md)、OrbStackで`orb start`と`docker compose up -d --wait`）。

## 1. 自動のテスト

```bash
pnpm --filter api db:migrate   # 0014_billing（契約・退会・料金なしの印。accounts.plan を消す）
pnpm lint && pnpm typecheck
pnpm test                      # 共通・Web・API（決済のテストは偽のStripeで BILLING_ENABLED=true）
pnpm e2e -- billing            # 偽のStripeで：無料体験 → 2件目で止まる → 契約 → 2件目を作る → 読むだけ
pnpm e2e -- withdraw           # 退会：管理者の引き継ぎ → データが消える → 同じGoogleで新しく始まる
pnpm e2e                       # 001〜012の流れ（BILLING_ENABLED=false で今のまま通る）
```

確かめること（対応するテストはtasks.md）：

| 確かめること | 出どころ |
|---|---|
| 使える状態の表（R1）のすべての行。支払いの失敗が無料体験より先。`incomplete`は契約なし | FR-001〜FR-003、research.md R1 |
| 読むだけのオーナーのアカウントで、オーナー・担当の人・見せてもらっている人のどの書き込みのAPIも`403 BILLING_REQUIRED`。読む・CSV・操作の記録・アカウントの削除は通る | SC-003、FR-040・FR-042 |
| 担当の人が読むだけでも、オーナーがすべて使えるアカウントでは書き込める | spec Edge Cases、Constitution原則IV |
| 読むだけのオーナーのアカウントで、自動投稿の時刻にThreadsへの問い合わせが0回。確定の時に読むだけになったら`billing_inactive`で飛ばす。戻った後は次の時刻から投稿し、過ぎた時刻はまとめて投稿しない | FR-041、research.md R8 |
| 読むだけのオーナーのアカウントで、パフォーマンスの取得が0回 | FR-041 |
| 無料体験中は2件目が`ACCOUNT_LIMIT_REACHED`（同時に2つ作っても1件まで）。未接続のアカウントも数える。契約・料金なし・決済OFFなら上限なし | FR-010〜FR-014、SC-001 |
| 読むだけの人は、アカウントを作る・チームを作る・参加するが`BILLING_REQUIRED`。チームの操作（招待・ロール・担当・外す・引き継ぎ）は通る | FR-043・FR-044 |
| Checkout：無料体験の残りが48時間以上なら試用の終わり＝無料体験の終わり、48時間未満なら1日、終わっていれば試用なし。数は`max(n,1)` | FR-012・FR-025、research.md R4 |
| 2つの画面で「契約する」：前のセッションが期限切れになり、契約は1つ | FR-022 |
| Webhook：署名が違えば400。同じ知らせ2回・順番の入れ替わりで、状態が1回ずつ正しい順と同じ。知らない顧客は200で何もしない | FR-035・FR-056、SC-006 |
| アカウントを作る・削除するとStripeの数が`max(n,1)`になり、日割りなし。Stripeに届かなければ印が残り、日次で合う | FR-030、research.md R6 |
| 退会：契約が止まる → チームの管理者が引き継がれる（いなければチームが消える）→ アカウントとトークンが消える → ほかの人の記録が「退会した人」→ Clerkのユーザーが消える。Stripeの失敗では何も消えない。途中で止まっても2回目・日次で終わる | FR-050〜FR-056、SC-007 |
| 退会の後、同じClerkのユーザーIDの要求で`users`が作り直されない | research.md R10 |
| `BILLING_ENABLED`がない・違う値なら`CONFIG_ERROR`。ONでStripeの設定が欠けていても`CONFIG_ERROR` | FR-063 |
| 決済OFFで、全員が上限なくすべて使え、`/api/billing/*`（`GET`を除く）とWebhookが404 | FR-061、SC-008 |
| マイグレーションの前後で、アカウント・データの件数が同じで、`accounts.plan`がなくなる | data-model.md |
| 帯：無料体験の残り7日から出て、閉じるとその日は出ない。読むだけの帯の文言が理由ごと・チームの人は支払いの詳細を出さない | FR-045・FR-046 |

## 2. 手で確かめる（Stripeのテスト用環境）

準備：Stripeのテスト用環境で、[docs/external-services-setup.md](../../docs/external-services-setup.md)の「Stripe」の手順（段階制の料金、カスタマーポータル、Smart Retries、メール）を済ませ、`apps/api/.dev.vars`に`BILLING_ENABLED=true`と`sk_test_`のキー・料金のIDを入れる。Webhookは`stripe listen --forward-to localhost:8787/api/stripe/webhook`で転送し、表示された`whsec_`を`STRIPE_WEBHOOK_SECRET`に入れる。

1. **無料体験（US1）**：新しいGoogleアカウントでログインし、アカウントを1件作る。ホームに「無料体験中：〇月〇日まで（あと〇日）」。2件目を作ろうとすると上限の案内と「契約する」。
2. **契約（US2）**：「契約と支払い」→「契約する」→ Stripeの画面でテスト用のカード`4242 4242 4242 4242`。戻ると10秒以内に「無料体験中（契約済み）」と最初の請求日（無料体験の終わる日）。2件目を作ると「1件につき月500円」の確認が出て、見込みが1,500円になる。Stripeの画面で契約の数が2、日割りの請求がない。
3. **支払いの失敗（US3-4）**：Stripeのテスト用の時計（Test clock）か、支払いに失敗するカード（`4000 0000 0000 0341`）に替えて請求を進める。アプリがすぐに読むだけになり、「支払いに失敗しました」の帯。チームの編集者で開くと「オーナーの契約の状態により…」。カードを直して払うと戻る。
4. **解約（US4-5）**：「支払いの画面を開く」→ 解約。「〇月〇日に終わります（解約済み）」。Test clockで期間の終わりを過ぎると読むだけ。もう一度「契約する」で、その場で請求があり戻る。
5. **無料体験の終わり（US3-1）**：`users.created_at`を1か月前にした利用者で、帯・読むだけの画面・自動投稿が動かないこと。
6. **退会（US5）**：契約中・チームの管理者の利用者で退会する。確認の画面の内容が正しく、メールアドレスを入れて退会すると入口に「退会しました」。Stripeで契約が止まり、チームの管理者が移り、同じGoogleでログインすると「アカウントを作る」から始まる。
7. **料金なし（US6）**：`pnpm --filter api admin:set-billing-exempt <email> on`で、契約なしで2件以上作れ、「契約と支払い」が「料金なし」。
8. **規約（US7）**：ログアウトした状態で、入口の下から利用規約と特定商取引法に基づく表記を開ける。
9. **スマートフォンの幅**：「契約と支払い」・退会のダイアログ・帯が、幅375pxで崩れない。
