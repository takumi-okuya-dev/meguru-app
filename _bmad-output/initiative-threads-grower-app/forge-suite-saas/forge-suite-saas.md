# 鍛えた構想：イベント・コミュニティの流れを埋めるスイート

## 決めたこと
- **中心**：イベント・コミュニティの流れ（集客 → 集金 → 参加 → 人の記録 → 次回の告知）を、自分の痛みから順に埋める。Google Workspace型の「無関係なアプリの束」ではない。
- **価値**：買い手がまとめて使う価値（A）を狙う。成り立つのは、流れの複数の段を1人で担う主催者・運営者に対してだけ。
- **港**：最初の顧客・検証の場・売り場・共同事業者。外販はリーダーの許可あり（都度確認）。港経由の客の売上の数%を港へ納める。
- **外販版のコード**：港のアプリは参考にとどめる。ユーザーが作り直し、権利と保守を持つ。
- **収益**：港への送客（1人約3,000円）＋フリーミアム＋外販の月額。
- **今の検証**：送客の実験と、今のThreadsアプリ（集客・外部媒体展開021・紹介リンク017）を港と関係者に使ってもらうことを並行する。準備は済んだ。
- **次のアプリの候補**：人物メモ、集金管理。
- **人物メモ**：LINE・Instagramは置き換えない。顔・会った場所・話した内容・検索を足す。入れ方は、その場でデジタル名刺のQRを相手に読んでもらい相手が自分で登録する形と、後から自分で入れる形。

## 外したこと（理由）
- **バドミントン試合表を2作目にすること**：収益イベントの主催者には効かない。
- **港のアプリをもう1本作り直すこと（今は）**：外部媒体展開はもう021にある。誰が払うかが見えてからにする。
- **広告**：個人開発の規模では利用者が足りない。
- **アプリ別のまとめ買いの料金（1,500円・2,000円）を先に決めること**：払う人が出てからにする。

## 決まっていないこと
- 外販の買い手（コミュニティ運営事業者か、個人の収益イベント主催者か）。
- 成功と失敗の基準。叩き台は、2027-01-11に判定する・送客5人以上・4週後も週1回以上使う人が3人以上で、そのうち1人以上が月1,000円を払う。
- 「ユーザー経由」の数え方（紹介コード・専用リンクなど）と、港との書面での取り決め。
- 人物メモの法務（他人の写真・会話メモ）。デジタル名刺の競合（プレーリーカード等）との差。
- 人物メモと集金管理のどちらを先に作るか。
