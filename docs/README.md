# 文書の一覧

このリポジトリの文書が、どこに何を書いているかの一覧。**迷ったら、ここから探す**。何をどこに書くか・何を作らないかの決まりは[文書の決まり](./rules/documents.md)。文書を足す・消す・役目を変えたときは、同じPRでこの一覧も直す。

- 同じことを2つの文書に書かない。書くなら片方を「正本」にして、もう片方はリンクと1行の要約だけにする（正本の列）。
- 機能ごとの仕様（`specs/<アプリ>/NNN-…`。`specs/001`〜`028`はThreadsの初めの分）は、ここには1つずつ載せない（5章）。

## 6. アジャイル開発の文書との対応

よく挙げられるアジャイル開発の文書と、このリポジトリで代わりに使うもの。作らないものの理由は[文書の決まり](./rules/documents.md) 2。

| 分類 | よく挙げられる文書 | このリポジトリ |
|---|---|---|
| 計画 | ユーザーストーリー | 各仕様の`spec.md`の「User Scenarios」（受け入れの条件つき） |
| 計画 | プロダクトバックログ | [バックログ](./next-features.md) |
| 計画 | スプリント計画書 | 作らない（各仕様の`tasks.md`） |
| 計画 | 振り返りの記録 | 作らない（進め方を変えたら`docs/rules/`と[決めたことの記録](./decisions.md)） |
| 要件・設計 | 要件定義書 | 各仕様の`spec.md`（機能の要件・成功の基準） |
| 要件・設計 | システム構成図 | [技術ドキュメント](./architecture.md)・[モジュール地図](./module-map.md)・[アプリを分けて作る決まり](./app-separation.md)の図 |
| 要件・設計 | ER図 | 作らない（表は`docs/apps/<アプリ>.md`と`schema.ts`、機能ごとの`data-model.md`） |
| 要件・設計 | API仕様書 | 各仕様の`contracts/api.md`と、入口の一覧`apps/api/test/repo/routes.snapshot.txt` |
| 要件・設計 | 画面仕様書 | [UI全体設計](./ui-design.md)と、各仕様の`contracts/ui-routes.md` |
| 開発・運用 | 意思決定記録（ADR） | [決めたことの記録](./decisions.md)（技術の判断と理由の今の形は[技術ドキュメント](./architecture.md)） |
| 開発・運用 | コーディング規約 | [コードの書き方の決まり](./rules/coding.md) |
| 開発・運用 | テスト仕様書 | 作らない（自動のテストと、各仕様の`quickstart.md`） |
| 開発・運用 | 運用手順書 | [リリースの手順書](./release-runbook.md)・[外部サービスの準備手順](./external-services-setup.md) |
| 関係者向け | 進捗レポート | [開発のご報告](./project-report.md) |
| 関係者向け | ユーザーマニュアル | [ご利用ガイド](./user-guide.md)・[集金の使い方](./apps/collect-guide.md) |
| 作りすぎない | 詳細設計書・技術仕様書 | 作らない（コード・テスト・各仕様の`plan.md`） |
