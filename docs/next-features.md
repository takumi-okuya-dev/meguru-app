## G. プランで機能を分けて売る（2026-11-04）

2026-11-04に、ユーザーが料金のプランの分け方を挙げた。**まだ合意が取れていないので後回し**にした（仕様は作っていない）。決まったら仕様にする。

**ねらい**：戦略（課題・宣伝内容・リサーチ）にはThreadsのノウハウが詰まっていて、まねされやすい。真似されたら困る部分で切り分け、渡す相手を選ぶ。

**今のところの案（ユーザー）**：
- **プランA**：サブスク。自動投稿とチーム運用だけ。気軽に試してもらう入り口。
- **プランB**：形（払い方）は検討中。すべての機能が使える想定。信頼できる人だけに売る。

**最初の話（プランを「戦略なし」「戦略あり」の2つにする案）で決めかけたこと**：
- 対象はサイドバーの「戦略」の3つすべて（課題の考えるヒント・AIと深掘り・AIと壁打ち・全体をAIと整理する、宣伝内容、リサーチと参考投稿のAI解説を含む）。
- 料金はまだ決めていない。あとから変えやすくする（コードを直さずに、決済の側と環境の設定で変える）。
- 無料体験（登録から1か月）では、戦略は使えない。
- 上のプランから下げたとき、書いた内容は残すが、画面は開けず、プロンプトにも入れない。戻すとそのまま使える。

**決めること（2026-11-04に挙げた）**：
1. 「投稿をつくる」（AIのプロンプトのコピー）をプランAでも使えるか。プロンプトの文にもノウハウ（投稿の型・長さの配分など）が入っている。Bだけにすると、Aの人は投稿の案を自分で用意して貼ることになる。
2. パフォーマンス（反応数と判定）をプランAでも使えるか。Threads本体にも予約投稿があるので、Aの価値をどこに置くか。
3. プランBの渡し方。案：利用者が自分で契約するのではなく、運営者が運営者の画面で付ける（016の料金なしの印に近い形）。払い方は決まってから足し、それまではアプリの外で受け取る。
4. 今ある契約（プランが1つのころ）を、どちらのプランとして扱うか。
5. チームの人が手伝う・見せてもらうアカウントでは、見る人ではなく、そのアカウントのオーナーのプランに従う（013の「オーナーが未払いなら、チームの人も読むだけ」と同じ考え方）でよいか。

2026-11-04、プランを決める前の仕組みとして、019（機能のまとまりごとのON/OFF、[specs/019-feature-switches](../specs/019-feature-switches/spec.md)）を作った。運営者が、人ごと・組織（グループ）ごとに「自動投稿」「戦略」「チーム」をON/OFFできる（どちらかでOFFなら使えない）。プランは、ONにするまとまりの組み合わせと料金として、あとで決める（上の「決めること」の1・2は「投稿をつくる」「パフォーマンス」を自動投稿のまとまりに入れることにした。5は019で「オーナーに従う」にした。3は、組織のグループで機能を付ける形で試せる）。

**守れないこと**：プランBの人がプロンプトをコピーして人に渡すことは、仕組みでは止められない。渡す相手を選ぶことと、利用規約（配布の禁止）で守る。

**Constitutionとの関係**：原則IVの「有料の契約中か無料体験中なら、すべての機能を使える」と食い違う。仕様にする前に、原則IVの改定が要る。
