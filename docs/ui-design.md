# UI全体設計

ThreadsGrower Appの画面の骨格・画面の型・見た目と操作の約束をまとめる。002以降の各featureの仕様（spec.md）と計画（plan.md）は、画面について本書を前提にする。

- **画面イメージ**：[ThreadsGrower UI案](https://claude.ai/artifact/6qfyUCRkpF7RxUKWJ6Ebsy)（PCとスマートフォン、ライトとダーク。▶ Playで操作できる。非公開のため、開けるのはオーナーだけ）
- **決定日**：2026-10-02
- **001との関係**：001の[contracts/ui-routes.md](../specs/001-login-account-setup/contracts/ui-routes.md)の「レイアウトの骨格」「設定画面の骨格」を引き継いで広げる。食い違う部分は本書を正とし、変更点は「[8. 001からの変更点](#8-001からの変更点)」にまとめる。認証・遷移の規則（ガード、Accountを開いたときの記録など）は001のものをそのまま使う。

## 1. 基本方針

- **ChatGPT風にする。** 左サイドバーと中央寄せのメインパネル、ニュートラルなグレーと白、丸いボタン、ダークモード対応。
- **参考プロダクト（Threads Growth OS）の画面には寄せない。** 参考にするのは入力項目と運用の流れだけで、画面の構成・見た目は本書に従う。
- **画面の型を4つに絞る**（[3. 画面の型](#3-画面の型)）。新しい画面は、まずどの型に当てはまるかを決めてから作る。
- **PC・タブレット・スマートフォンのどれでも使える**ようにする（[5. 画面幅ごとの振る舞い](#5-画面幅ごとの振る舞い)）。

│ ────────────────────── │──────────────────────────────────────────────│
│ ✏ 投稿をつくる          │                                              │
│ ⌂ ホーム                │          画面の中身（中央寄せの1カラム）          │
│ ▤ 投稿ストック      3   │                                              │
│                        │                                              │
│ 戦略                    │                                              │
│ ◎ 課題                  │                                              │
│ 📣 宣伝内容              │                                              │
│ ⌕ リサーチ              │                                              │
│                        │                                              │
│ 分析                    │                                              │
│ ▥ パフォーマンス         │                                              │
│ ────────────────────── │                                              │

└────────────────────────┴──────────────────────────────────────────────┘

### サイドバー（幅260px）

上から順に次を置く。

1. **Accountの切り替え**：表示中のAccount（アイコン・表示名・@ユーザー名）のボタン。押すとドロップダウンが開き、次を出す。
   - 全Accountの一覧（表示名・@ユーザー名・「要確認 N件」を各行に表示する。0件も「要確認 0件」。表示中はチェックと「表示中」、接続が切れたものは警告アイコンと「要再接続」を文字で示す）
   - 「＋ アカウントを追加」
   - 右隣には、サイドバーを畳むボタンを置く。
   - メニューを開くたびにAccount一覧と要確認件数を読み直す。件数の取得中は「取得中」、失敗時は「取得できません」と「件数を再試行」を示し、切り替えと追加は使えるようにする。
   - 20件でも画面内の高さに収め、スクロールして末尾のAccountと追加に到達できる。専用のダッシュボード画面は作らない（チームは、サイドバーの「チーム」から開くチームの画面で見る。011）。
   - **チーム（011）**：担当しているAccountがあるユーザーには、見出し「自分のアカウント」「担当しているアカウント」で分け、担当の行に「@ユーザー名 · オーナー （名前）」を出す。要再接続は「オーナーの再接続待ち」。担当のAccountがなければ見出しは出さない（個人運用の画面は変えない）。見せてもらっているAccountはメニューに出さない（チームの画面から開く）。
   - 担当の人には、切り替えの下に「担当しています」と「オーナー：（名前）」の枠を出す。オーナーには出さない。
2. **「投稿をつくる」**：ChatGPTの「新しいチャット」にあたる、いちばん目立つ操作。投稿ストックの画面に移り、プロンプトのカードの「コピー」にフォーカスを当てる（作る流れの最初の一歩から始める。004で決定）。プロンプトを作れないAccount（grower機能を使えない。2026-10-08の料金の見直し後は、無料体験が終わり契約していないAccount）では、貼り付け欄にフォーカスを当てる。「投稿ストック」は機能の移動先で、承認待ちの件数を出す。
3. **機能の移動**：見出しなしで「ホーム」「投稿ストック」、小さな灰色の見出し「戦略」の下に「課題」「宣伝内容」「リサーチ」、見出し「分析」の下に「パフォーマンス」を並べる。
   - **チーム（011）**：チームに入っている人には、見出し「チーム」の下に、入っているチーム（色の四角・チーム名・人数）を参加した順に並べる。押すとチームの画面（メンバー一覧）。開いているチームは背景をグレーにする。どれかのチームの管理者には「チームを作る」も出す。その下に、今のAccountで操作の記録を見られる人（オーナーと、担当の管理者）に「操作の記録」。チームに入っていない人には、チームのものを何も出さない（Constitution原則V）。スマートフォンの引き出しも同じ並び。
   - 表示中の画面は背景をグレーにする。
   - 投稿ストックの右には承認待ちの件数を出す（004から）。
   - **まだ作っていない機能はサイドバーに出さない。** 各featureで画面を作ったときに足す。
4. **下部**（区切り線の下）：「このアカウントの設定」と、ユーザーメニュー（アプリ全体の設定、ログアウト。001で作ったもの）。

### 上部バー（高さ56px、スクロールしても固定）

- 左に画面名、右にその画面の主な操作（保存、追加など）を置く。
- 主な操作を上部バーに置くことで、画面のどこまでスクロールしていても押せるようにする（002のFR-003a「保存はいつでも押せる位置」を満たす）。
- サイドバーを畳んでいるときは、画面名の左に「サイドバーを開く」ボタンを出す。
- 「要再接続」のAccountでは、上部バーの下に001の再接続バナーを出す。

### メインパネル

- 中身は中央寄せの1カラムにし、幅は最大720〜760pxとする。
- 画面の外側の余白は、PCで左右32px、スマートフォンで16pxとする。

## 3. 画面の型

### A. フォーム型（例：課題）

ChatGPTの「カスタム指示」のような、縦に並んだ入力欄の画面。

- 画面上部に1〜2文の案内を置く。長い手順説明は置かない。
- その下に「区分へ移動」のチップを並べる。押すとその区分の見出しへスクロールする。
- 区分ごとに見出しを付け、項目を上から順に並べる。区分を枠で囲まず、見出しと余白で区切る。
- 各項目には次の4つだけを出す。
  - ラベル（入力されていなければ横に「未入力」の小さなラベル）
  - 1行の説明
  - 入力欄（記入例は空の欄の中に薄く表示する）
  - 文字数（入力欄の右下に「34/2000」）
- 入力済みの項目数は上部バーに出す（例：「11/16 入力済み」）。
- 保存ボタンは上部バーに1つだけにし、画面内の全項目をまとめて保存する。

### B. 一覧＋追加型（例：宣伝内容、リサーチ）

カードを縦に並べる画面。

- 追加は上部バーの「＋ 追加」から行う。
- 追加・編集の入力欄は、PCでは画面中央のダイアログ、スマートフォンでは全画面のシートに出す。
- 編集・状態の変更・削除は、各カードの右上の「⋯」メニューにまとめる。
- 一覧は「対象のもの」と「対象外のもの」の見出しで分ける。対象外のもの（宣伝内容の一時停止・終了・期限切れなど）は、1行の小さなカードにして下にまとめる。
- Accountごとに1つだけの設定値（例：宣伝投稿の割合）は、一覧の上に設定の行として置く。
- 種類が2つある画面（リサーチの「参考投稿」と「キーワード」）は、上部のタブで切り替える。

### C. 作業画面型（例：投稿ストック、003から）

ChatGPTのチャット画面のような画面。

- 画面の上部に、外部LLMに送るプロンプトのカードと「コピー」ボタンを置く。
- その下に状態のタブ（要確認／承認済み／却下／投稿済み）と、投稿の一覧を置く。
  - 各投稿にはチェックボックス、本文、類似度のラベル、「却下」「承認」のボタンを付ける。
  - 類似度が高い投稿は、ラベルをオレンジにして「過去の投稿と似ています」と添える。
- **画面下部に、ChatGPTの入力欄と同じ形の貼り付け欄を固定する。** 外部LLMの返信をここに貼って送ると、まとめて「要確認」に登録される。
- 投稿を選択している間は、貼り付け欄の位置を「まとめて承認／却下」のバーに切り替える。
- 承認済みは投稿の順に並べ、予定の日時を添える。先頭以外は「次に投稿する」で移せる。持ち越しは注意色、処理中はスピナーを出して操作を無効にする。
- 承認済みのタブの先頭に「投稿に失敗」のまとまりを置く。失敗したカードは選択対象にせず、「もう一度投稿の順に入れる」と「要確認に戻す」を出す。
- 投稿済みはタブを開いたときに50件ずつ読み込み、本文・投稿日時・Threadsへのリンクを出す。編集や削除の操作は出さない。
- 細部は[005の画面契約](../specs/005-auto-post/contracts/ui-routes.md)に従う。

### D. 設定型（例：アプリ全体の設定）

001で作った、ChatGPTの設定画面と同じ2列の画面。Accountのサイドバーは出さない。

- **左**：「← アプリに戻る」、丸い検索欄、小さな灰色のグループ見出し（「個人設定」など）、アイコン付きの項目の一覧。選択中の項目は背景をグレーにする。
- **右**：画面名（例：「外観」）、小見出し（例：「表示スタイル」）、角の丸い枠。枠の中は「名前・説明」と「操作」を1行に並べ、行の間を線で区切る。
- このアカウントの設定は、2列にせず、Accountのサイドバーの中で右側と同じ見た目（小見出し・角の丸い枠・線で区切った行）にそろえる（004で決定）。
- 「投稿のスケジュール」で、自動投稿のオン・オフ、1日最大10時刻、時刻をずらす設定を編集する。「接続を確かめる」はテスト投稿をせず権限と投稿数を確認する（005）。
- **チームの画面（011）**：サイドバーの中に出す。ヘッダーにチーム名と人数、管理者には「メンバーを招待」「担当を決める」「チームを抜ける」と「⋯」（チーム名を直す・チームを削除する）。メンバー一覧の各行に名前・ロール・チームに入れているアカウントのチップ（開けるものは「見る」、開けないものは点線の「見せていません」）。メンバー・編集者には上に「チームに入れている、あなたのアカウント」と「チームに見せる」のスイッチ。担当を決める表（`/teams/:id/assign`）もサイドバーの中に出す。細部は[011の画面契約](../specs/011-team-revision/contracts/ui-routes.md)。
- **見せてもらっているアカウント（011）**：Accountのサイドバーには入れず、上部に「（名前）さんのアカウントを見ています（読むだけ）」の帯と「チームに戻る」を置いた1カラムの画面。タブ「投稿ストック」「戦略」だけで、操作のボタンは出さない。
- このアカウントの設定に「チーム」の区分を「Threadsとの接続」の後に置く（011。008の「運用を手伝ってもらう」を置き換えた）。チームに入っていないオーナーには「チームに入っていません」と「チームを作る」の1行だけ（Constitution 4.0.1 原則Vの例外の1区分）。入っていれば、チーム名・「チームに見せる」・このアカウントの担当、「ロールと、できることを見る」でロールの図を開ける。招待の確認の画面にも同じ図を出す（011 FR-056。ロールの説明は[team-roles.md](team-roles.md)）。

### ホーム

ChatGPTの最初の画面（中央に1つのメッセージと、その下の提案）を手本にする。

- 上から順に次を並べる。
  - Accountのアイコン、表示名、@ユーザー名と接続状態
  - 次にやることを1つだけ大きく出す（例：「次は「リサーチ」がおすすめです」と1文の理由）
  - 「次の投稿」のカード（日時・本文の書き出し・承認済みの件数と残りの日数。オフ・停止・承認済み0件はそれぞれ案内）
  - ホームと投稿ストック共通の自動投稿の知らせ（再接続・上限・失敗・差し戻し・下書きなし）
  - 「課題」「宣伝内容」「リサーチ」の3枚のカード（入力状況つき。002のFR-017）
- おすすめの画面のカードは、枠線を濃くして目立たせる。
- 予定のカードは1列で全幅にし、材料のカードと同じ角丸・余白にそろえる（005）。

## 4. 見た目の約束

### 色

shadcn/uiの色の変数（`apps/web/src/index.css`）を使う。画面イメージの値を正とし、002の実装で変数の値をこれに合わせる。

|---|---|---|---|
| 背景 | `--background` | `#FFFFFF` | `#212121` |
| サイドバー | `--sidebar` | `#F9F9F9` | `#181818` |
| カード・入力欄 | `--card` / `--input`の背景 | `#FFFFFF` | `#2A2A2A` |
| 選択中・ホバーの背景 | `--accent` | `#ECECEC` | `#303030` |
| チップ・小さなラベルの背景 | `--muted` | `#F0F0F0` | `#303030` |
| 枠線 | `--border` | `#E3E3E3` | `#3A3A3A` |
| 文字 | `--foreground` | `#0D0D0D` | `#ECECEC` |
| 補足の文字 | `--muted-foreground` | `#5D5D5D` | `#B4B4B4` |
| 主なボタン | `--primary` / `--primary-foreground` | 黒地に白 | 白地に黒 |

- 補足の文字の色も、背景に対して4.5:1以上のコントラストを保つ。
- 状態を色だけで区別しない。必ず「有効」「一時停止」などの文字を添える。

### 文字

- 書体は、OSの日本語フォントを使う（`'Hiragino Sans', 'Noto Sans JP', system-ui, sans-serif`）。Webフォントは読み込まない。
  - 画面イメージではNoto Sans JPを読み込んでいるが、表示速度と月額固定費$0の制約を優先する。
- 本文はPCで14〜15px、スマートフォンで15〜16pxにする。
- 画面名は16px、区分の見出しは17px、ホームの大見出しは22〜26pxにする。いずれも太さは600。

### 形

- 角の丸み：入力欄・小さなカードは12px、カードは16px、ダイアログは20pxにする。ボタンとチップは完全な丸（`rounded-full`）にする。
- 主なボタン（保存・追加・承認・送信）は黒（ダークでは白）の丸いボタンにする。それ以外のボタンは枠線だけ、またはアイコンだけにする。
- 影は、浮いているもの（ドロップダウン、ダイアログ、貼り付け欄）にだけ付ける。

## 5. 画面幅ごとの振る舞い

| 画面幅 | 想定する端末 | サイドバー |
|---|---|---|
| 1024px以上 | PC、iPad横向き | 常に表示する。左上のボタンで畳め、畳んだ状態はブラウザに保存する |
| 768〜1023px | iPad縦向き | 普段は隠し、左上のボタンで画面の上に重ねて開く |
| 767px以下 | スマートフォン | 左から出るドロワーにする |

### スマートフォンの上部バー

- 高さ52pxで、`[≡] 画面名 [主な操作]` の3列にし、画面名は中央に置く。
- 主な操作は、保存なら小さな黒い丸ボタン、追加なら「＋」アイコンにする。
- Accountの切り替えは、ドロワーのいちばん上に置く。

### 型ごとの違い

| 型 | PC・タブレット | スマートフォン |
|---|---|---|
| A. フォーム型 | 区分のチップは折り返して並べる | 区分のチップは上部バーの下に固定し、横にスクロールする。入力済みの項目数もチップの列の先頭に出す |
| B. 一覧＋追加型 | 追加・編集は中央のダイアログ。属性などの短い入力欄は横に並べる | 追加・編集は全画面のシート（左上に✕、右上に「追加」）。入力欄はすべて縦に並べる |
| C. 作業画面型 | 却下・承認のボタンは投稿の右下に小さく並べる | 却下・承認のボタンは投稿の下に横幅いっぱいで2つ並べる。貼り付け欄は画面下端の操作バーの領域を避けて固定する |
| D. 設定型 | 2列 | 「項目の一覧の画面」→「項目の中身の画面（左上に「← 設定」）」の2段にする |
| ホーム | 3枚のカードを横に並べる | 3枚のカードを縦に並べ、右端に「›」を付ける |

### 全体の約束

- タッチ操作の端末では、押せる範囲を44px角以上にする（スマートフォンのサイドバーの項目、「⋯」ボタン、承認・却下ボタンなど）。
- スマートフォンの入力欄の文字は16px以上にする（iPhoneで入力時に画面が拡大されないようにするため）。
- ホバーしないと出ない操作は作らない（「⋯」ボタンは常に表示する）。
- 文字入力中にキーボードで隠れる位置（画面下部）に、保存ボタンを置かない。保存は上部バーに置く。
- 確認は次の4つの幅で行う：375px（iPhone）、768px（iPad縦）、1024px（iPad横）、1440px（PC）。

## 6. 操作の約束

- **保存**：明示的な保存操作で保存し、自動保存はしない。保存の成功・失敗はトースト（`sonner`）で知らせる。失敗時も入力内容は消さない。
- **未保存の警告**：未保存の変更がある状態で画面・Accountを移動しようとしたら、確認のダイアログを出す。
- **削除**：「⋯」メニューから選び、確認のダイアログで確定する。Accountの削除のような取り消せない重い操作は、001と同じく名前の入力で確認する。
  - 例外：投稿ストックの下書き（003）とNGワード（004）は、選んでは消す操作を繰り返すため、確認のダイアログの代わりにトーストの「元に戻す」を出す。
- **ダイアログ・シート**：右上（スマートフォンでは左上）の✕、「キャンセル」、Escキーで閉じられるようにする。
- **空の状態**：一覧が空のときは、何をする画面かを1文で説明し、最初の操作（「＋ 追加」など）を置く。

## 8. 001からの変更点

002の実装の最初にまとめて行う。

1. **Accountの一覧を、サイドバーからドロップダウンに移す。** サイドバーには表示中のAccountだけを出し、そこから切り替える（[2. 画面の骨格](#2-画面の骨格)）。
2. **サイドバーを畳むボタンを付け、タブレットでの開き方を変える**（[5. 画面幅ごとの振る舞い](#5-画面幅ごとの振る舞い)）。
3. **設定画面を、スマートフォンでは2段の形にする。** 001では「一覧が上、中身が下」に縦に並べていた。
4. **色の変数の値を、[4. 見た目の約束](#4-見た目の約束)の表に合わせる。** 特にダークの背景を`#212121`系にし、成功・注意の色を足す。

## 9. 新しい画面を足すとき

1. [3. 画面の型](#3-画面の型)のどれに当てはまるかを決める。どれにも当てはまらない場合は、本書に型を足してから作る。
2. サイドバーのどの見出し（見出しなし／戦略／分析）に入れるかを決める。サイドバーに出すのは、その画面ができたときにする。
3. URLを[7. 画面のURL](#7-画面のurl)に足す。
4. スマートフォンでの見え方を、[5. 画面幅ごとの振る舞い](#5-画面幅ごとの振る舞い)の型ごとの違いに沿って決める。
